# pushes

Push contention stats, as SQL over the op-store's `op_log_ops` table
(`_opLogOps` from `op-log/plugins/op-store/server` — the DB fold of
`op-log.jsonl`). Every loader reads through `completedPushes(bucket)`
(`machine/internal/read-pushes.ts`), so they cannot disagree on what counts.

## What counts

- `kind = 'push'`, closed (`closed_by IS NOT NULL`) with an outcome.
- **Not in flight.** An unfinished push has no final outcome, its wait is still
  growing and it has no steps yet — counting it would make a chart depend on
  when it was loaded.
- **Not interrupted.** Hard-killed and closed by the reconciler (or a worktree's
  ingest-gap close): a synthetic zero, not a measurement.

History is the op store's: 30 days (its retention), from the ingester's first
seed onward — the frozen pre-op-log legacy files are not in it.

Buckets key on `requested_at` in UTC (`YYYY-MM-DD`; the ISO week's Monday;
`YYYY-MM`). The wait is `closed_wait_ms` = `sum(waits.durationMs)` — every wait
the push blocked on, including the nested host-grant wait inside its `checks`
step.

Three live values (`shared/values.ts`), each with a typed `bucket` param
(`day | week | month`, required), read with `useLive(value, { bucket })`:

- **Wait time** (`stats.pushes.wait-time`) — avg/max wait (seconds) over the
  contested pushes, plus `contested` / `total` counts.
- **Throughput** (`stats.pushes.throughput`) — success vs failed pushes per
  bucket (every non-success terminal is failed).
- **Step breakdown** (`stats.pushes.step-breakdown`) — avg seconds per push in
  each step group (fetch, rebase, checks, push, other); steps come from
  `jsonb_array_elements(steps)`, grouped by the `STEP_GROUPS` name map in TS.

Served `source: "db"` from `machine/` with `reads: [op_log_ops]` (change-feed
covered — any ingested op line may move any bucket, so whole-table), throttled
to one flush per 5 s. `needsMachine` like op-store's own collections: the rows
are this machine's op log, so a host without the computer reads `unavailable`.
**Bound:** one point per bucket holding a completed push, within the op store's
30-day retention sweep. No exact count is promised: a forked worktree DB keeps
what its fork copied until its own sweep runs.

These are interim values: metrics P2/P3 replace them.
