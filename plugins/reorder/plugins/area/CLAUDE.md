# area

What a reorder area DRAWS, shared by the two sides of `reorder`: applying a
slot layout (`reorder`, in every bundle) and editing one (`reorder/editor`,
`reorder/edit-mode`, opt-in).

- `ReorderAreaContext` / `ReorderAreaCtxValue` — the area's orientation, its
  hide / remove-node writes, and the `ItemChrome` an editable item mounts
  (`null` where no editor ships).
- `ReorderItemBox` — one item: a `DeferredSortableItem` around a content wrapper,
  both `display: contents` at rest. Editable, it mounts `ItemChrome` ahead of its
  content (a sibling, never a wrapper) and wears the classes it publishes, so
  toggling edit mode remounts nothing.
- The entry types (`ReorderEntry`) and the item-chrome contract.

A leaf on purpose: `reorder` imports `fields/reorder-tree/config`, which imports
`reorder/editor`, so the editor cannot import `reorder/web` without a cycle. It
imports no drag code (`sortable-list/deferred-item` only).
