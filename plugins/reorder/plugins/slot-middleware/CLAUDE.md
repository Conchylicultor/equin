# slot-middleware

Sub-plugin of `reorder`. Contributes reorder's list middleware to
`primitives/slot-render` (`SlotRender.ListMiddleware`) as a **companion**
(`companion: true`), so it ships in every composition that ships slot-render.
Without it every render slot silently falls back to raw registration order and
ignores its committed `config/**/<slot>.jsonc` layout (equin.ai once shipped
that way).

Why a sub-plugin rather than reorder's own barrel: reorder's `contributions` is
the live array the slot-declaration pass rewrites (one config directive per
reorderable slot), and a companion must sit in an inline `contributions: [ … ]`
literal for the closure engine to read it (`companions-visible` check). Its
import of `@plugins/reorder/web` pulls reorder itself into the bundle.

There is no item middleware: applying a layout never wraps a contribution, so a
slot item pays nothing for reorder. Editing a layout is the Config pane's
reorder-tree field (`reorder.editor`, dnd-kit), which `reorder:apply-is-lean`
keeps out of slot-render's closure.

The list middleware renders **nothing until the slot's layout is known** (its
config document loaded): drawing raw registration order meanwhile is a flash of
hidden items and the wrong order. `SlotRender.Order` (`useLayoutOrder`) answers
the same state as a read (`loading`), so a host drawing its own rows waits too.
