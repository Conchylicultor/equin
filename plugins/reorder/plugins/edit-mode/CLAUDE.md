# edit-mode

Sub-plugin of `reorder`: **slot-layout editing**, the opt-in half of reorder.
`reorder` itself (a companion of `slot-render`) applies every slot's committed
layout in every bundle; this plugin is how a layout is *edited*, and it ships
only where a composition selects it (today: main's `**`).

- An "Edit layout" switch row in the action bar's view-options (gear) popover
  (`ActionBar.ViewOption`), `excludeFromReorder` so it stays clickable while every
  other item is a drag target, plus an Escape shortcut that exits edit mode
  (priority above fullscreen's own Esc: the innermost mode goes first).
- The e2e helper `setEditMode(page, on)` (`e2e/`): on through the switch, off
  through Esc, confirmed off the editor's chrome. Scripts that need edit mode
  use it rather than finding the switch themselves.
- The area editor (`ReorderSlots.AreaEditor`): `AreaEditor`, mounted by each
  reorder area beside its items while edit mode is on — the dnd-kit drag host
  (`DeferredSortableHost`), the restore / insert button, the narrow-row popover —
  and `ReorderItemChrome` (from `reorder/editor`), which each editable item box
  mounts ahead of its content. Neither is ever an ancestor of a contribution, so
  toggling edit mode remounts nothing in a vertical area.

The switch and the editor live together on purpose: the switch is the only
`setEditMode(true)` caller, so wherever edit mode can turn on, the editor ships.
`reorder` throws if edit mode is on with no editor registered.

It is separate from `reorder` for two reasons: the import cycle (shell's slots are
reorderable, so reorder cannot contribute to shell's action bar) and the bundle —
everything here stays out of a composition that cannot edit layouts
(`reorder:apply-is-lean` guards that).
