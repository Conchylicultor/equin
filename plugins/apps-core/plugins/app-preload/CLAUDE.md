# app-preload

Puts the active app's code in the page's head, so it downloads from t0 with
the shell's own preloads instead of after the eager tier has evaluated.

- **`core/`** — `appRootOf(pluginPath)` (`apps/plugins/<app>/`): the unit an
  app's code is loaded by. web-core's `App.tsx` loads every deferred plugin
  under the active app's root as its priority batch, and the compose step keys
  the batch's preloads by the same root. Plus the `.app-preloads.json` format.
- **web-artifacts compose** writes `.app-preloads.json` into every dist: per app
  root, the static import closure of its deferred plugins (dependencies
  first), minus the modules the shell already preloads.
- **`machine/`** — a `DocumentHead.Fragment` source: per app base path, one
  `<link rel=modulepreload>` per URL of the served dist's `.app-preloads.json`
  (absent in a dist composed before it existed → no preloads, logged). Every
  app gets a key (a nested base path does not inherit its parent's list), and
  each tab app is also keyed under a surface-mode app's base path
  (`/desktop/agents`). Re-rendered when the backend adopts a deploy without a
  restart. Desktop-only: the head is published by document-head's `machine/`
  half, from the dist the gateway serves; every served composition gets it
  through the `served-baseline` row (`plugin-meta/composition`).

The boot then imports the batch while the boot tasks run — as a boot task of
its own, "App code", so the boot screen names it while it is pending, an
overdue one is reported and Continue anyway paints without it — and commits it
with the first frame: the app paints whole, never chrome first.

## Plugin reference

- Description: Starts the active app's code downloading at t0: a DocumentHead.Fragment that puts, per app base path, a <link rel=modulepreload> for every module of that app's deferred plugins — read from the served dist's .app-preloads.json, which web-artifacts' compose writes — so the boot's priority batch is in the HTTP cache by the time it is imported, instead of being fetched after the eager tier. Desktop-only: the head is published by document-head's machine half, from the dist the gateway serves. In every served composition through the served-baseline row.
