# app-icon

Canonical, serializable identity of an app's icon. One descriptor authored once
per app, rendered everywhere an app's glyph appears (rail, tab bar, window
chrome, launcher).

## `AppIcon` — the serializable descriptor

`AppIcon` (in `core/`) is a plain, JSON-serializable discriminated union:

```ts
type AppIcon = { kind: "symbol"; symbol: SymbolRef; color?: AppTileColor };
```

It carries the icon as data — a Material Symbols `SymbolRef` from
[`ui/icons`](../../../ui/plugins/icons/CLAUDE.md) — not a React component, so
a non-React consumer (a generated favicon, a Tauri window-icon) can read the
same value the UI does. The `kind` discriminant is the seam: a future
`{ kind: "image"; src }` variant drops in with one extra render branch and zero
changes to existing `kind: "symbol"` authors.

## Authoring

- An app's icon is authored once, in its shell's `defineApp({ icon:
  symbol("…"), iconColor })` (core). `iconColor` is an `AppTileColor` from the
  `tile-colors` leaf (below) — one of its own: no two listed apps share a
  colour (`apps-core/server/internal/app-colors.test.ts`). Omitted, a surface
  picks one from the app id. `Apps.App` derives the entry's `AppIcon` from it
  with `appIcon(symbol, { color })`, the server's manifest / PNG routes
  (`apps-core/app-manifest`) and the release CLI (statically) read the same
  field, so no two surfaces can draw different icons.
- `DEFAULT_APP_ICON` (web) — fallback glyph for tabs/windows whose owning app
  cannot be resolved.

## Rendering

- `<AppIconView icon active? className />` draws an `AppIcon` through `<Icon>`,
  in the theme scope's icon style (`active` = the focused app).
- Anything taking an `icon: IconRef` (the `ui/tab-bar` `Tab`, `IconButton`) takes
  `appIcon.symbol` directly.
- `appIconToSvg(glyph, opts)` (core) — rasterizable SVG markup for the release
  CLI and the app-manifest PNG route, from the glyph `symbolBody(name)`
  (`ui/icons/server`) reads out of the installed Iconify JSON in the default
  icon style.
- `<AppIconTile icon appId className />` — THE app tile, everywhere an app is
  drawn (Home, the launcher grid, the desktop, the menu bar, the website): the
  glyph, white, at 46% of a squircle painted with the app's colour as a
  diagonal gradient (deep end top-left, base bottom-right) inside a
  hairline inner edge — bounded and flat, like a phone's app icon: no gloss,
  no drop shadow. `AppIconAvatar` is the same tile sized by the ambient avatar
  presentation (filling a tile view's box, avatar-sized in a row).
- `appTileFill(icon, appId)` (core) — the tile's base colour as sRGB hex (a
  manifest's theme colour, the island's building hue); `appTileGradient` — its
  two stops, for the icon PNGs (`appIconToSvg` takes `{ from, to }`).

## Tile colours (`plugins/tile-colors`)

The closed set of colours a tile can wear (`APP_TILE_COLORS`, `AppTileColor`):
the website's vivid palette with its hue circle filled in (19 hues and `slate`),
each a base in OKLCH whose gradient runs from the base darkened 0.28. How
intense a tile wears its colour is the THEME's, not the app's: the tile scales
the chroma by `--app-tile-intensity` (`ui/tokens/app-tile`, a select of
`APP_TILE_INTENSITIES`) — calm (0.7, the default) on equin's own launchers,
vivid (1) on the website (`equinTheme`). A painter with no theme (the icon
PNGs) takes the default. The same
in light and dark mode — a tile is its own fill. A leaf, so `defineApp`
(`primitives/pane`) can type `iconColor` without a cycle. A new app picks a
colour no listed app wears; when every colour is taken, add one here.
