# phone-actions

The phone action button: on a phone (`useIsMobile()`, below 768px) the one
thumb-reachable way to switch apps and file a wish. Spec: prototype
`proto-1794375712-lso8wv` (switcher `fab`, fab-menu `stack`, fab-icon `dots`).

- **Mounted at `Apps.Overlay`** (inside the tab state, which switching apps
  needs), drawn only on the page itself: not inside an `AppEmbed`
  (`useTabs().contained`) nor in a chromeless document (a companion panel).
  Desktop draws nothing.
- **The sub-actions are `PhoneActions.Action`** — `{ id, label, icon,
  component }`, a render slot ordered by
  `config/apps-core/phone-actions/action.jsonc`. The button names no
  contributor: `apps-core/app-launcher` contributes Apps (the app grid),
  `wish` contributes Wish (`WishField`). The host owns the chrome around each
  — the bubble, the bottom sheet (grabber, scrim, slide) — and the
  contribution's `component` is only the sheet's body, handed `close`.
- **Place** — dragged anywhere (a press moving 6px is a drag, else a tap),
  it snaps to the nearer side edge; `{ side, top }` is kept in a page-wide
  web-storage store, and the top is clamped to the viewport on every render,
  so a resize never loses it.
- **Menu** — a tap fans the bubbles toward the open side (down from the top
  half, up from the bottom half), labelled on the inner side; ⋯ turns into ×.
- **Tuck** — any scrolling gesture on the page (touchmove or wheel, never a
  pane scrolling itself) tucks it into a
  10px edge tab, back 900ms after the last scroll or on a tap. Hidden while
  one of its sheets is open. It is one `ViewportOverlay` (the popover layer,
  click-through but on what it draws), mounted with the page: a sheet or
  drawer portaled later paints over it (the sidebar drawer covers it).
