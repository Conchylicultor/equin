# task-marks

A frozen main thread cannot say what it is doing — so a task says it **before**
it starts. `runMarked(source, describe, fn)` wraps an entry point (a socket
frame's handler, a queue's runner); `onTaskMark(listener)` installs the one
listener, which hears `begin` before `fn` runs and `end` one microtask after it
returns or throws.

- **Who listens:** `reports/main-thread-stall`'s tab watch, which posts both
  to its out-of-thread SharedWorker watchdog. `postMessage` hands them to the
  worker's thread at once, so a task that freezes the thread leaves its mark
  **open** — begun, never ended: the stall report's `frozenIn`. A task that
  finished just before an unmarked freeze is closed, so it is never blamed.
- **Microtasks:** the end is queued as a microtask after `fn`, so microtasks
  `fn` queued itself run inside the mark (LoAF counts them in the entry
  point's script time too). Deeper promise chains end outside it.
- **Nesting:** only the outermost marked task is heard.
- **Cost:** with no listener, a call is `fn()` — `describe` never runs. The tab
  watch keeps a mark (calls `describe`, posts two small messages) only while
  the tab is visible and attached; hidden tabs' stalls are never reported.
- **Grain:** `what` is what a recurring freeze is grouped by (it joins the
  stall fingerprint); `detail` tells one occurrence apart (params, bytes).
  Keep `what` free of ids and sizes.

Marked today: every live-state socket frame (`live-state`, `<kind> <key>`)
and every watchdog message the stall detector's tab half handles
(`main-thread-stall`, `<kind>`).
