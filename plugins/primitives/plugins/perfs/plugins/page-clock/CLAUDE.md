# page-clock

A page (or worker) has two clocks, and they drift apart every time the device
sleeps:

| Type      | Read by                                                                                    | While the device sleeps |
| --------- | ------------------------------------------------------------------------------------------ | ----------------------- |
| `EpochMs` | `Date.now()` — the wall clock every thread and process agrees on                           | keeps running           |
| `PerfMs`  | `performance.now()`, an entry's `startTime`, an event's `timeStamp`, a profiler sample's `timestamp` | **pauses** (Chrome on Android: CLOCK_MONOTONIC; macOS) |

So `performance.timeOrigin + stamp` is **not** the wall clock: after a sleep it
lags `Date.now()` by every sleep since the page loaded. A stall report's
profiler samples landed 2.2 h before the stall they sampled
(report-1795091821-xwqzky), so the report had no stacks.

```ts
import { asPerfMs, clockOffset, perfToEpoch } from "@plugins/primitives/plugins/perfs/plugins/page-clock/core";

// An entry delivered just after its frame: read the offset now.
const at = perfToEpoch(asPerfMs(entry.startTime));

// Stamps converted later (a profiler trace): read the offset when they were
// collected, and keep it with them.
const offset = clockOffset(); // at the trace's stop
const sampleAt = perfToEpoch(asPerfMs(sample.timestamp), offset);
```

- **One conversion.** `perfToEpoch` / `epochToPerf` go through `clockOffset()`
  (`Date.now() − performance.now()`, read in one go). It is exact for every
  stamp taken since the device last woke; a stamp from before lands no later
  than the wake — never inside a span that began after it.
- **Along a record.** A long-running record (a profiler trace) keeps
  `readClocks()` readings as it goes (its start, each 1 Hz pulse, its stop);
  `perfToEpochAlong(stamp, readings)` places each stamp through the next
  reading after it, so a record the device slept through puts both sides of
  the sleep where they ran (within the second the sleep began in).
- **Branded.** `asPerfMs` names a number an API handed over as a timeline
  stamp, `asEpochMs` one read back from storage or a message as a wall-clock
  instant; a function that takes a window types it `EpochMs`, so a raw timeline
  stamp is a type error there.
- **Lint.** `page-clock/no-time-origin-arithmetic` refuses `timeOrigin ± x`
  (`performance.timeOrigin`, `x.timeOrigin`, a binding named `timeOrigin`).
  Reading `performance.timeOrigin` alone — when the realm started, on the wall
  clock — stays allowed.
- `core/testing`'s `clockReadingAt(epoch, perf)` makes a reading for a test
  that does not stub the clocks.
- Tests simulate a device by stubbing `Date.now` and `performance.now` and
  advancing only the first while asleep (`core/internal/clock.test.ts`,
  `reports/main-thread-stall` `stall-after-sleep.test.ts`).

## Plugin reference

- Description: The two clocks a page (or worker) reads, as branded types: EpochMs (the wall clock, Date.now — keeps running while the device sleeps) and PerfMs (the performance timeline — entry.startTime, event.timeStamp, a profiler sample — which pauses while it sleeps on Android and macOS). perfToEpoch / epochToPerf are the only conversion, through the clocks' offset read at once (a ClockOffset), so a stamp taken since the last sleep lands where it happened; `performance.timeOrigin + stamp`, which lags by every sleep since the page loaded, is refused by the page-clock/no-time-origin-arithmetic lint rule.
