# hover-card

`<WithHoverCard card={…} beside? side?>` — a non-interactive card shown on
hover / focus that describes its trigger in parts. The tooltip's state machine
(describe semantics, the shared delay group), drawn as ui-kit's
`TooltipCardContent`: the shared `OverlayPanel` at the fixed `card` width role
(`popoverWidthCard` density token), so a card looks like the menu it often
hangs off.

- **The card is data, not markup.** `card` is a `HoverCardContent` —
  `title`, `code` (an id inline after it), `description`, `chips`
  (`{ label, off? }`, `off` drawn as Badge `absent`), `steps` (a path with
  the current step lit), `lists` (headed lists of short lines), `notice`, `meta`
  (mono footer parts). There is no `className` and no body slot: a new kind of
  part is a new field here, never markup at a call site. That is the point —
  every rich hover in the app reads as one card.
- **`pinOnClick`** — a click pins the card open (tooltip's `usePinOnClick`).
- **`beside="panel"`** places the card against the floating panel its trigger
  is a row of (found through `closestOverlayPanel`), top level with the row,
  flipping sides when there is no room. `PickerPill.Item`'s `info` uses it.
  It throws when the trigger is in no panel.
- A one-line label stays `tooltip`'s `WithTooltip`; a control's name + what it
  does stays `TooltipDoc`. Something you can click inside is not a hover card —
  that is `hover-popover`.
