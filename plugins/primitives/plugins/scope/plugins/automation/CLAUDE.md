# automation

`AUTOMATED_BROWSER`: is this page driven by automation (`navigator.webdriver` —
Playwright, an e2e run, the agent browser)? The one definition every browser
beacon stamps its signals with (slow-ops' reports, the latency ledger's
interactions), so an automated browser is **marked, never muted**: it runs the
code a visitor does, and what it does is judged like any other client.

Every report a page files through `report()` (`plugins/reports`) opens with
`(automated browser) ` when this is true — whatever the kind and the channel,
so a report from an agent's headless browser on the public site reads as one
in Reports, its notification and the investigation task.

**One place filters on it: a public site's report intake**
(`apps/deploy/site-reports`). Its store exists to diagnose what strangers'
browsers hit, so the site's channel sends the flag with each batch and the
intake counts an automated batch as an `automated` drop instead of storing it
(the owner's request, 2026-11-19). An agent checking the site sees its batch
answered and counted; a script verifying the store poses as a visitor
(`navigator.webdriver` false). Everywhere else the rule above holds.
