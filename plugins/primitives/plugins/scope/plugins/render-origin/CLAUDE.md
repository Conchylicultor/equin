# render-origin

Some content is raised by one piece of code and shown by another: a toast's
body sits in the page's toast stack, an imperative dialog in a modal layer.
If the host renders that content in ITS tree, the content reads the host's
React contexts — inside `/demo` (`<DemoScope>` → `<PluginScope>` →
`<AppEmbed>`) that is the page's transport (the real server), the page's
plugin registry and the page's tabs navigator.

So raised content renders in the **caller's origin**, and the host only
places it:

```tsx
<RenderOrigin>{children}</RenderOrigin>         // a subtree's own origin
const origin = useRenderOrigin();               // the caller's, captured by a hook
const raised = origin.raise(node, { onGone });  // { update, remove, mounted }
```

- `<RenderOrigin>` renders its children, then every node raised into it, at
  its own place in the tree. Mount one wherever a subtree stands for another
  world than the page around it: `DemoScope` (inside its `PluginScope`) and
  `AppEmbed` (inside its tab set and theme) do. The nearest one wins.
- Outside every origin and every `PluginScope`, the origin is the page's —
  this plugin's `Core.Root` host, where the toast and dialog hosts rendered
  content before.
- **Inside a `PluginScope`, the origin must be the scope's own.**
  `useRenderOrigin()` throws, naming the scope, when the nearest origin was
  mounted outside it (or there is none) — never a fall-through to the page's.
- An origin that unmounts takes what was raised into it along, calling each
  raise's `onGone` (a dialog's promise settles, a toast is dismissed).
- `raised.mounted` settles once the node committed — a host that adopts DOM
  the node portals into (the toast stack) waits for it, so the host measures
  real content.

Users: `shell/toast`'s `useShowCustomToast` (a notification's body),
`overlay/imperative-dialog`'s `useOpenDialog` / `useConfirmDialog`. Design:
`research/2026-11-05-global-raised-content-renders-in-its-scope.md`.
