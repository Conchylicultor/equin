# map

The **map** view child of the `data-view` primitive. Contributes one
`DataViewSlots.View("map")` entry: every row holding a location drawn as a pin
on a full-bleed `<MapView>` (`plugins/map`), clustered by default.

## What it renders

- **Rows → pins.** Rows go through `useFlatRows` (search → filter → sort), then
  `rowsToPins` (`web/internal/row-pins.ts`, pure, unit-tested) makes one
  `MapPin` per row whose location parses through `LocationSchema`
  (`fields/location`). The pin id is the row key. A row with no valid location
  is skipped and counted; when some rows are on the map and some are not, a
  muted `N without location` badge sits in the bottom-left corner.
- **Which field.** The instance option `locationField` (a field id, from the
  view's config row / options sub-form), else the first field whose type chain
  (`resolveTypeChain` over the registered field identities, so a type that
  `extends` location counts) reaches `location`. A configured id naming no
  field, or a schema with no location field, renders an error placeholder —
  never a silent fallback to another field or an empty map.
- **Which projection.** The field's structured `data` projection when it
  declares one (a `Location` object is not a scalar `FieldValue`), else its
  `value`.
- **Activation.** Clicking a pin runs that row's `rowActivation` (the same
  per-row `Activation` the other views spread onto a click), falling back to
  `onRowOpen` when the row does not activate. `selectedRowId` is the map's
  `activeId` (its pin renders active) and `focusId` (panned into view when
  off-screen).
- **Empty.** No pin at all → the map stays mounted (narrowing and widening a
  filter never unmounts or moves it), with a notice floated over it
  (`MapView`'s `empty`) only when there is something to explain: the host's
  `emptyState` when the list itself is empty, "None of these have a location
  yet." when rows show but none is placed. A list the search or filter
  emptied is a bare map — the surface's own counts say so.

## Layout

The view is `relative size-full` and declares `fullBleed: true`: under an
`overlay` toolbar arrangement (`floating-toolbar`) it starts at the surface's
top-left edge, under the floating band and the aside, in an `h-full` box. It
needs a definite height from its host: beside an in-flow band the DataView is
natural-height, so a map there collapses unless the surface gives the body a
height.

It declares `supportsGroupBy: false`, `supportsFold: false`,
`supportsManualOrder: false` — a pin's position is its location, so there is
no section, fold line or rank axis. Sort still applies (it orders the pins,
which decides which one draws on top).

## Options

`options` (= `viewOptions.map`, merged with the instance's config options) is a
`MapViewOptions<TRow>` (core):

- `pinType?` — the `pinType` every pin carries, the key `GeoMap.Pin` and
  `GeoMap.Cluster` dispatch on. A consumer contributes its own pin and cluster
  look under a type it owns. Absent → `data-view.row`, which no plugin claims,
  so the map primitive's default pin and count disc draw it.
- `pinData?(row)` — the opaque `MapPin.data` handed to that pin component.
- `label?(row)` — the pin's name (accessible label; what the default pin
  shows). Default: the primary field's value (`pickPrimaryField`, location
  field excluded).
- `fitPadding?` — `MapPadding` (px per edge) the surface's floating chrome
  covers; passed to `MapView`, so the fit and the selected-pin pan keep pins
  out from under the aside, the band and a detail card. Default none.
- `crowd?` — how crowding pins are drawn (`MapCrowdRequest` from `map/core`):
  `{ kind: "cluster", radiusPx? }` (the default) merges them into cluster
  marks; `{ kind: "spots", radiusPx?, nearZoom? }` keeps every pin drawn —
  far out as compact centred marks with each spot's size beside its lead
  (Places). `false` draws every pin on its own.
- `rank?(row)` — the row's importance (`MapPin.rank`): draws above lower ranks
  where pins overlap and leads its spot. Default 0.

```tsx
<DataView
  rows={places}
  fields={[nameField, { id: "location", label: "Location", type: "location", data: (p) => p.location }]}
  views={["map", "list"]}
  rowActivation={(p) => openPane.to(placePane, { id: p.id }, { mode: "push" })}
  viewOptions={{ map: { pinType: "saved-place", pinData: (p) => p } satisfies MapViewOptions<Place> }}
/>
```

## Paging

Pins are not DOM rows, so the view stamps no `data-row-key`: a paged read
behind a map view never releases its pages (they stay live, never stale). The
map draws every loaded row; it is meant for in-memory or bounded sets.
