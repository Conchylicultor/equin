# breadcrumb

A quiet trail: muted ancestor crumbs, a themed separator
(`BreadcrumbSlots.Separator`), and the current page as the leaf. Options:
`leafWeight` (`medium` default | `semibold` | `normal`), `leafTone`
(`inherit` | `strong`), `text` (`inherit` | `body`), trailing `actions`. The
leaf carries `data-breadcrumb-leaf`.

## Sibling menus (required)

Every `BreadcrumbSegment` states its `siblings`: the element (a
`<BreadcrumbPlaces>`) that lists the places beside the crumb, opened by
resting the pointer on it while a click still goes to the crumb. The field is
required (`ReactElement | null`), so a new trail cannot drop the menus by
forgetting; `null` is the stated exception, for a crumb with no level to list,
with a comment saying why. The trails today:

- **Pages** (`apps/pages/page-tree`): the pages under each parent. A zoomed
  block's leaf is `null`.
- **File paths** (`path-bar`, `filepath-breadcrumb`, through
  `path-bar/folder-places`): the folders in each parent. The root crumb is
  `null`.
- **Plugins** (`plugin-meta/plugin-view`): the plugins beside each one, from
  the tree already loaded.
- **Spend breakdown** (`tasks/supervisor-roles/spend`): the levels beside
  each one. The root ("Spent this week") is `null`.

A folded crumb keeps its menu: the `…` overflow crumb opens on hover too, a
click on one of its rows still goes to that ancestor, and resting on a row
opens its siblings as a submenu.

## Motion (`motion="wipe"`)

A trail that is its surface's navigation, moved one level at a time, opts
into `motion="wipe"`. `trailChange` (pure, bun-tested) reads the change from
the keys: going deeper wipes the new crumbs in with a `clip-path` reveal at full
colour (their separator fades in) while the old leaf dims; going back up
keeps the dropped crumbs drawn after the leaf, inert and first to shrink,
while they wipe out and the new leaf brightens. Any other change draws as it
lands. `useTrailMotion` derives it during render, so the first frame of the
new trail is the first frame of the animation. The animation's own
`animationend` ends it and drops the leaving crumbs. Under reduced motion the
animations run for 1 ms, so they still end. The keyframes are in
`web/internal/breadcrumb.css`.

## The fold (`use-ancestor-collapse.ts`, `fold-plan.ts`)

The leaf never truncates while something else can give: the visible ancestors
are rigid, and when the leaf would have to truncate the OLDEST ones fold, one
by one, into a `…` menu — the fewest that let the leaf stand whole, so the
crumbs nearest the page stay as long as there is room (`… › c › d › leaf`).
A folded ancestor comes back, nearest first, when the trail's slack covers its
cached width plus a 4px margin. Each ancestor's width is measured from its
crumb (`data-crumb-index`) to the next crumb or the leaf, so it carries its
separator; the overflow crumb (`data-crumb-fold`) the same way. The decision
itself is the pure `planFold`. (It used to fold the whole run at once: a deep
path showed `… › leaf` with hundreds of pixels standing empty.)

- **It observes the trail, the ancestor run and the leaf** — every box the
  decision reads. It used to observe only the trail, so a fold taken on a
  transient (a fallback font before the web font landed, a crumb drawn before
  its theme, the separator variant arriving late) was never re-asked while the
  trail's own width stood still: the ancestors stayed behind `…` with room to
  show them. Observing the leaf cannot loop — a fold only reopens when the
  cached open width says it fits, and the open pass that follows refreshes that
  cache.
- **Widths are layout pixels**: `getBoundingClientRect` widths are divided by
  the trail's own transform scale, so an open width cached at one zoom is not
  compared against free space measured at another (a scaled canvas frame).
- Pinned by `web/__tests__/ancestor-collapse.test.tsx` against a scripted
  layout and a hand-fired `ResizeObserver`.
