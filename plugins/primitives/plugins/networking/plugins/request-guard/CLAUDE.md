# request-guard

The page request guard — rung 4 of "the browser reads the app's server only
through live values (`useLive` / `useLiveReader`) and writes only through typed
endpoints (`fetchEndpoint` / `useEndpointMutation`)". Design:
`research/2026-10-26-global-browser-reads-only-through-live.md` §5.

- **What it refuses.** Once `installRequestGuard()` runs, every same-origin
  request to `/api/*`, `/ws/*` or `/gateway/*` that page code issues by a raw
  channel: `fetch` (string, `URL` or `Request`, resolved against
  `document.baseURI`), `XMLHttpRequest.prototype.open`, `navigator.sendBeacon`,
  `EventSource`, `WebSocket` (matched by host). `fetch` rejects with a
  `RawApiRequestError`; the rest throw it. Cross-origin requests and other
  same-origin paths (`/artifacts`, `/icon*`, vite) pass untouched.
- **Installed first.** `framework/web-core`'s `main.tsx` imports
  `./install-request-guard` as its FIRST import, a side-effect module that
  calls `installRequestGuard()` — a call in `main.tsx`'s body would run after
  `App`'s whole static import graph had evaluated. That is also why this is a
  leaf plugin depending on nothing but `report-sink/core`.
- **The app's own channels hold a capability, not a mark.** `nativeFetch`
  (`page-transport`'s `fetch`) and `nativeWebSocket` (`useReconnectingWebSocket`)
  reach the natives the guard kept. With no guard installed (a jsdom suite) they
  are the globals read at call time, so a test's stub answers. The live socket
  opens in the SharedWorker's realm, which the page guard does not touch.
- **Assets pass as GET / HEAD.** `allowAssetRoute(path)` registers a route
  (and everything under it, query ignored): `assetUrlOver` (`infra/endpoints`)
  registers every URL it hands a sink that loads by URL on its own (frimousse's
  emoji data, a prototype document), `useAssetSrc` every path it hands an
  element as its `src` (so a library re-fetching the page's images by URL — the
  screenshot's `modern-screenshot` inlining every `<img>` — loads them too;
  an element's src is therefore always an `AssetPath`, never a hand-built
  `/api` string), and the entry registers
  `ASSET_MIRROR_PREFIX` once (Sonata's samplers load from it with no transport).
  Element loads (`<img>`, `<iframe>`, `new Image()`, CSS) are not requests page
  code issues, so they are never guarded.
- **Who may hold a native.** `networking/no-request-guard-capability` (this
  plugin's parent's `lint/`) flags importing `nativeFetch`, `nativeWebSocket`,
  `allowAssetRoute` or `installRequestGuard` (and a namespace import, re-export
  or dynamic import of the barrel). Sanctioned holders declare a
  `kind: "sanctioned"` entry in their own `exempt/index.ts`: page-transport,
  networking's `use-reconnecting-ws.ts`, endpoints' `asset-url.ts` and
  `asset-src.ts`, web-core's
  `install-request-guard.ts`. The rule is `noDebt`, and its inline disable is
  refused by `networking:no-inline-page-transport-disable`.
- **Loud.** Every violation is `console.error`ed, passed to `reportError`, and
  emitted on `requestGuardReportSink` — a library swallowing the rejection
  (frimousse catches its HEAD's) cannot hide it. The sink holds violations
  raised before `reports/crash`'s `CrashCollector` registers, and replays them;
  the collector files each once (`browser-error`, `errorType:
  RawApiRequestError`) and ignores the `reportError` / rejection echo.
- **Agents.** The error text points `browser_javascript` users at `query_db`,
  and e2e scripts at `pageFetch` (e2e-harness, over Playwright's
  `page.request`); `agent-origin-safety/no-unmarked-app-fetch` flags an in-page
  `fetch("/api/…")` in an e2e script statically.
- **Known ways past it (recorded, not guarded):** a same-origin iframe's own
  `contentWindow.fetch` (prototype documents are served from `/api`),
  `window.open`, a blob `new Worker`.

## Plugin reference

- Description: The page request guard: installRequestGuard (once, first thing in the app entry) refuses every same-origin /api, /ws and /gateway request page code issues by a raw channel — fetch, XMLHttpRequest, sendBeacon, EventSource, WebSocket — with a RawApiRequestError (fetch rejects, the rest throw), each also logged and filed through requestGuardReportSink (held until the crash collector registers). The app's own channels hold a capability instead: nativeFetch (the page transport) and nativeWebSocket (the per-tab socket), falling back to the globals at call time when no guard is installed; GET / HEAD of the asset routes allowAssetRoute registers pass. Importing the capability is bounded by networking/no-request-guard-capability.
