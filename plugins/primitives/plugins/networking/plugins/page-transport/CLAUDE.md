# page-transport

`pageTransport` — the page's own server as a `Transport` (`primitives/networking`):
same-origin `SharedWebSocket`s, the global `fetch`, plain asset paths,
`machine: true`, and `telemetry: true` (its subtree's telemetry is reported,
to itself).

- **Mounted once**, by the app root (`framework/web-core`'s `App.tsx`:
  `<TransportProvider transport={pageTransport}>`). Everything below resolves
  its transport with `useTransport()`; a subtree pointed elsewhere (the demo's
  browser server) must never reach the page's server.
- **Importing it is an exemption.** The `networking/no-page-transport` lint
  (this plugin's parent's `lint/`) flags every import; an importer declares a
  `kind: "sanctioned"` entry in its own `exempt/index.ts`. Sanctioned today:
  the web-core root, page-wide telemetry (reports' `report()`, latency-ledger,
  slow-ops, app-usage, deploy analytics, log-channels), boot (boot-snapshot,
  health's probe and its wedge watchdog — which also reads the page
  pipeline's client — icon sprites). No inline disable: a check refuses one. Module-level code calls endpoints through
  `fetchEndpointOver(pageTransport)` (`infra/endpoints`).
- A leaf, so the import is the one thing the lint has to see.
