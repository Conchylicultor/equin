# shortcuts

## Who gets a key

One window `keydown` listener (`ShortcutManager`) dispatches every registered
shortcut. Before matching, it yields the key to whoever already owns it:

- **An element that handled it** — an event already `defaultPrevented` (a tree
  or list walking its rows with the arrows, a row activated by Space) fires no
  shortcut. The window listener runs after React's root-delegated handlers, so
  their `preventDefault` is visible.
- **A text field / control acting on it natively** (`targetClaimsKey`) — plain
  keys only; modifier combos still fire, and a shortcut may opt in with
  `enableInInputs`.
- **Another surface** — a shortcut registered with `useSurfaceShortcuts` is
  eligible only while its surface is the focused one.

A raw key listener that bypasses the registry (allowed only with a lint
exemption, e.g. Sonata's hold-to-scrub seek) must apply the same three rules.

## Space = play / pause

Every player binds Space through `usePlayPauseShortcut(toggle)` — never its own
`"space"` descriptor — so all players agree on when the key is theirs: on top
of the three rules, it yields to a native `<video>`/`<audio>`'s own controls,
but not to a button merely left focused (the link that opened the player).

## The focused surface, and surface signals

Exactly one surface is focused per page (`setFocusedSurfaceId`, written by the
tab sets). It is page-global — the keydown dispatch reads it with
`getFocusedSurfaceId()` — so it can be a surface inside a `<PluginScope>` (the
demo's embedded app) while page chrome renders.

What a surface says about itself for global chrome to read ("the task this
conversation is about", for Wish) is a **surface signal**, never a module map
keyed by surface id:

```ts
const relateTask = defineSurfaceSignal<string>("tasks.relate-task");
useSurfaceSignal(relateTask, taskId);    // in the surface; null publishes nothing
useFocusedSurfaceSignal(relateTask);     // in chrome: the focused surface's value, or null
```

Both hooks read the plugin scope from where they render (`usePluginScopeId()`):
a value published inside a scope reaches only a reader in the same scope, so
page chrome never picks up an id that lives behind the demo's host and resolves
it through the page's transport. Neither takes a scope, and the focused surface
has no other reactive read. Design: `research/2026-11-05-global-ambient-signals-scoped.md`.
