# file-links

## Which checkout a path names: supplied by the host, never guessed

A bare path in rendered text (`research/foo.md`) only becomes a link once
something says which checkout it is relative to. That answer is **supplied by
whoever hosts the content** — `<FileLinksWorkspaceProvider workspace root?>` —
and read with `useFileLinksWorkspace()` (`undefined` outside every provider:
paths stay plain). The value is data (`{ workspace, root? }`), not an opener
callback, so a host needs no import of the pane that opens files (which would
cycle for the conversation pane) and image/asset readers get the same answer.

Never infer it from pane routes: those reads throw outside every
`PaneSurfaceProvider`, so Markdown in global chrome (a `Core.Root` card) would
crash. A new host adds a provider. Current hosts: the conversation pane,
sub-agent and workflow-node panes (`ConversationFileLinks` from
`@plugins/conversations/web`), the task detail (`"main"`), the file peek (its
own worktree). The consumer that turns a workspace into a file-peek target is
`conversations/conversation-view/markdown-extensions`.
