# z-layers/stack

The **top-layer stack**: the open set of app-wide surfaces that paint above the
popover layer — hint tips, the Ask card, the draw-on-app overlay, toasts. Each
one declares its own layer in its own plugin; the order of all of them is one
committed file. `z-layers` itself keeps only generic roles (the in-tree tier,
`popover`, `max`) and never names a contributor.

## Declaring a layer

```ts
// plugins/<you>/web/layer.ts
import { defineZLayer } from "@plugins/primitives/plugins/css/plugins/z-layers/plugins/stack/web";
export const AskLayer = defineZLayer({ id: "ask", label: "The floating Ask equin card" });

// plugins/<you>/web/index.ts
contributions: [AskLayer.contribution, …]

// your host
<ViewportOverlay layer={AskLayer}>…</ViewportOverlay>
// or, for a surface that positions itself (sonner):
const zIndex = useZStackIndex(AskLayer);
```

The handle and its contribution come from one call — there is no string or
number spelling of a stack layer. `id` must be unique across the stack (`useZStackIndex`
throws on a duplicate, and on a layer its plugin never contributed).

## Placing it — forced

`ZStack.Layer` is an ordered data slot (`defineOrderedSlot`, slot-render), so
its order is a reorder layout:
`config/primitives/css/z-layers/stack/<slot>.jsonc`, **bottom first**. A new
layer shifts the layout's origin `@hash`, so `./equin build` stamps
`// @review` into that file and `config:overrides-authored` /
`config-origins-in-sync` fail until you place the new entry and remove the
marker. At runtime an unplaced layer is appended (top of the stack) — a safety
net for the stale window, not a place to leave it.

## Values

`useZStackIndex(layer)` = `50 + 1 + position`: strictly above `--z-popover`
(50), below `--z-max` (9999). Only the order is meaningful.

`ViewportOverlay` given a stack layer also wraps its children in `PortalHost`:
a surface above the popover layer draws its own popups (a tooltip inside the
Ask card), which would otherwise portal to `<body>` at 50 — under the card.
