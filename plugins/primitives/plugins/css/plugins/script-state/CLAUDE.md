# script-state

Script-only state attributes. `defineScriptState("data-x")` (core) declares an
attribute that page code stamps on a high-up element — `<html>`, `<body>`, an
app container — for **script** to read, and that flips often enough that no
stylesheet may select on it. The returned handle (`read(el)`, `write(el, v)`)
is how the owning code writes and reads it, so the declaration lives with the
state.

## Why

A rule naming an ancestor's attribute (`[data-x="y"] .z`, `.z:not([data-x] *)`,
`in-data-[x=y]:` …) makes Chrome restyle every element the rule could match —
or the whole subtree, under `:not()` — on each change of that attribute.
`data-input-modality` on `<html>` cost ~7,000 restyled `focus-ring` hosts per
keyboard ⇄ pointer flip, until the rings moved to a mark on the one focused
element (`ui-kit/web/theme/input-modality.tsx`, measured by
`ui-kit/e2e/input-modality-flip-cost.ts`).

When styling does depend on such state, mark only the element(s) it affects
(`data-pointer-focus` on the focused element) instead of reading the root.

## The check

`script-state:no-stylesheet-reads` collects every `defineScriptState("…")`
call in `plugins/` (the attribute must be a string literal — a non-literal
call fails the check) and rejects, for each declared attribute:

- in plugin CSS: any attribute selector naming it;
- in `.ts` / `.tsx` / `.css`: the Tailwind variants that compile to one —
  arbitrary (`[[data-x]_&]:`, `[&:not([data-x]_*)]:`), data (`data-[x]:` under
  any prefix) and v4's shorthand (`data-x:`).

`querySelector` / `matches` strings, `setAttribute`, JSX attributes and
comment lines are not stylesheet reads. CSS built as a string in script (a
`<style>` template) is not scanned.

The sibling `negated-complex-selector` check catches the undeclared shape of
the same cost: a `:not()` around a complex selector.
