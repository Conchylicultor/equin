# column

The named-slot **column** primitive — a vertical stack of up to three **role
slots** — `header` / `body` / `footer` — passed as props (no `children`). It
bakes the `rigid | flexible | rigid` fill policy into one place so callers write
**roles, never mechanics**.

## Why flex (not grid)

`Column`'s requirement is the textbook flex-column: a rigid header, a
growing+scrolling body, a rigid footer — which is exactly what `<Scroll>`'s
`fill` (`min-h-0 flex-1 overflow-y-auto`) was built for. Flex keeps the body's
`Scroll` composition **honest**: `fill` is semantically correct in a flex column,
whereas in a grid cell its `flex-1` would be inert.

So `Column` owns `flex flex-col` + the rigid (`shrink-0`) header/footer wrappers,
and **delegates the scroll body to the existing `<Scroll>` primitive** —
composition. `Scroll` stays the single owner of `overflow`; the `min-h-0` /
`flex-1` fill pair
stays inside `Scroll` (or, with `scrollBody={false}`, on the plain flexible body
wrapper).

The one exception is `fit` (below): hugging content up to a max-height is the
case flex cannot express, so that mode alone lays out as a grid.

## The fill policy

- **`header`** → `shrink-0` wrapper — rigid, never crushed.
- **`body`** → the single flexible region. By default wrapped in
  `<Scroll axis="y" fill>` so it absorbs the column's slack and scrolls.
- **`footer`** → `shrink-0` wrapper — rigid, never crushed.

Only present slots render — an absent slot produces no region and no phantom gap.

## Props

- **`header`** — rigid top region (`shrink-0`).
- **`body`** — flexible middle region; scrolls by default.
- **`footer`** — rigid bottom region (`shrink-0`).
- **`scrollBody`** — wrap `body` in a `<Scroll axis="y" fill>` cell. Default
  `true`. Set `false` for a plain flexible region (`min-h-0 flex-1`) that manages
  its own overflow (e.g. an embedded `data-view`).
- **`fill`** — emit the flex-child fill pair (`min-h-0 flex-1`) on the root so the
  column fills its own flex-col parent. Default `false`. Needed when `Column` is
  itself a flex child whose height is externally clamped.
- **`fit`** — hug the content up to the column's own max-height (a `max-h-*`
  in `className`), past which the body takes what is left and scrolls (a
  floating card that grows with its thread, header and composer pinned).
  Exclusive with `fill` (tsc). Laid out as a grid — rows `auto minmax(0,1fr)
  auto` over the present slots, one `minmax(0,1fr)` column — because a grid
  with a max-height sizes its `fr` row against that max, giving the body a
  definite height its `h-full` children resolve against; a flex column's
  flexed body is not definite under an `auto`-height container.
- **`inset`** — make the column's regions REGION OWNERS at a ramp step: the
  header, the body's scroller and the footer each pay and publish it
  (`rail-x-<step>`, owed 0, plus `rail-rows` — a column's content is rows, so
  bands and labels land on the text rail) and take it as block padding, so
  two regions sit one step apart on each side of their boundary.
  Content dropped in declares no inset of its own (`rail/no-pad-under-owner`).
  Exclusive with `scrollBody={false}` (tsc): the managed `Scroll` is what owns
  the body's region. Each region owns rather than follows on purpose — a
  follower region (the app-shell sidebar's `rail-owe` + `rail-follow` split)
  makes every follower inside it, a DataView's bands, pay twice.
- **`rules`** — the hairline under the header and over the footer, drawn by
  the column across its full width (never a `border-b px-* py-*` in the slot).
- **`gap`** — gap role from the spacing ramp between regions. Default `none`
  (regions are usually flush).
- **`as`** — host element. Default `div`. **`className`** composes last;
  **`ref`** forwarded.

## `Band` — a rule-bearing strip mid-content

`<Band rule="top|bottom|both">` is the strip BETWEEN content: a toolbar between
two lists, a summary over a log. It bleeds its hairline to the region's edge
and puts its content on the region's **text rail** (`rail-band`): the rail in a
plain region, one row pad further in for a row host (`rail-rows` — a menu, an
`OverlayPanel rows`, `Column inset`). Outside any region it pads by the pane
floor `rail-follow` uses. Block padding is fixed (`py-sm`).

Not a surface's first or last strip — that is the surface's own `header` /
`footer` (`OverlayPanel` / `PopoverContent` / `DropdownMenuContent`, or a
`Column`'s with `rules`) — and not a wrapper around rows (they sit on the rail
and pad themselves; a band would indent them twice). `rail/no-adhoc-band`
flags the hand-rolled recipe it replaces.

**Migrate a band only once its host owns the inset.** In a pane that still
hand-pads its sections, a Band lands on the pane floor rather than on the
sections' edge — a few px off. Such strips stay debt disables until the host
is a region owner (slice 2's document panes).
