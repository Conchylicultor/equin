# tree-focus

`useTreeFocus()`: is DOM focus inside this component — as the user reads it,
portals included?

`root.contains(document.activeElement)` answers for the DOM, and every popover,
menu and dialog portals to `document.body`, outside the component that opened
it. A guard that pulls focus back unless "focus is already inside me" therefore
takes it from the component's own menu as soon as the menu focuses itself on
open — the table grip menu's page jump (2026-11-06) was exactly that, through
the page editor's caret host.

React bubbles a synthetic focus event up the component tree, through portals:
spread `onFocusCapture` on the root and `holdsFocus()` is true while the focused
element is one whose focus reached it.

The two containment questions are different, and both have a home:

- **focus** — "is the keyboard inside my tree?" → here (portals INCLUDED);
- **an event's origin** — "is this key / gesture my own, or did it bubble
  through React from a portal?" → `isChromeGesture` (`dom/gesture-origin`) or
  `currentTarget.contains(target)` (portals EXCLUDED: a key typed in a menu is
  the menu's).
