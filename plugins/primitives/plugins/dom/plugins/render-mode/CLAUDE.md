# render-mode

Is this a live page in a browser, or one **static render** of the app to HTML?

```ts
// the static-render process's entry, before it loads any app module
declareRenderMode("static");

// a building block, during render
if (renderMode() === "static") { /* write into the markup what a click would compute */ }
```

The public website is rendered once, statically, to HTML that search engines and
other robots read (design: `research/2026-11-10-global-website-crawlable-v3.md`).
That HTML is **never hydrated**: no click handler, effect or event ever runs on
it. Whatever a live control leaves to an event — a link's destination is a
click-time thunk (`link-gesture`), a fold's content mounts on open
(`collapsible`) — is invisible to a robot unless the building block writes it
into the markup. `renderMode()` is how a building block knows to.

- **Declared once, at the process's entry.** A second declaration throws, and so
  does a declaration after anything already read the mode: a component that
  rendered `"live"` and a later one that renders `"static"` would disagree
  inside one page. Same shape as `browser-server/host-storage`'s
  `declareHostStorage` — a fact handed to the process at its entry.
- **Defaults to `"live"`.** The app never declares anything; only the static
  renderer does.
- **Only a building block reads it**, for what a robot must find in the markup
  (a link's `data-link`, a closed fold's content). A feature does not branch on
  it — fix the building block instead.
- **A leaf with no imports** (core), so leaves like `link-gesture` can read it.
- Tests: vitest runs each `web/__tests__/` file in its own module registry, so a
  suite that declares `"static"` at its top reaches no other suite (see
  `link-gesture/web/__tests__/link-props-static.test.ts`).
