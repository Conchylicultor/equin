# reload-readiness

**May this tab reload now, and what would stop if it did?** The contract the
reload policy (quiet auto-update into a new build) reads. Design:
[`research/2026-11-17-global-lossless-reload.md`](../../../../../../research/2026-11-17-global-lossless-reload.md)
§2 and "The policy".

```ts
holdReload(label): () => void                    // a process holds the page; call the release once
useReloadHold(active, { label })                 // the same, while `active`
useReloadReadiness(): { holds, engaged, hidden } // read live (readReloadReadiness / subscribeReloadReadiness outside React)
quietReload(): Promise<never>                    // flushKept → wait until holds = [] → flushKept → reload
```

## Persist state, hold only for processes

Anything that can be serialized is **kept** (`primitives/kept-state`), so it
never blocks a reload — a draft can sit for days. Only what cannot be
serialized, a **running process**, takes a **hold**, and a hold ends with its
process, so it is short-lived by construction.

| Hold | Taken by |
|---|---|
| `Playback` | every playing `<video>` / `<audio>` on the page (the gesture watcher, at the document); the YouTube player (`integrations/youtube`) while playing; Sonata's audio engine while the transport plays; `music/ambient` while its music plays; the Chord piano and Keyboard Party while a sound rings |
| `Upload` | `infra/attachments` `uploadAttachment`, per request |
| `Saving` | `network/live`'s send lane, while any write on it is unsettled |
| `Drag` | the gesture watcher: a pressed pointer that moved 4 px (dnd-kit, a movable, a slider — whatever library), and a native HTML drag |

**Take a hold inside the primitive that runs the process, never at a feature's
call site** — a feature then cannot start the process without it. A new kind of
process (a mic recording, a long export) gets its hold in the engine that runs
it.

A label is what stops, in the user's words: the policy shows it ("Update waits
for: Playback"). Several holds may share one; dedupe for display.

## Engagement

`engaged` is true while the user is mid-interaction, so a reload would
interrupt them even though it loses nothing: a popup is open
(`overlay/popup-open`'s `anyPopupOpen`), focus is in something that takes text
(a text-like `<input>`, a `<textarea>`, a contentEditable), a pointer is
pressed, or there was input (key, pointer press, wheel, drag) in the last 10 s.
"Idle for 30 s" is the policy's: `engaged` false for 20 s after its 10 s window.

`hidden` is `document.visibilityState === "hidden"`.

All three are fed by one gesture watcher on the document (`Core.Root`, page
scope): capture-phase, passive listeners, and one deadline timer for the
recent-input window, re-armed only when it fires early.

## `quietReload` does not pick the moment

It flushes, waits for holds and reloads — it does not wait for the user to look
away or stop typing. Choosing when (hidden; or visible, not engaged, idle; or
forced) is the policy's, read from `useReloadReadiness()`.
