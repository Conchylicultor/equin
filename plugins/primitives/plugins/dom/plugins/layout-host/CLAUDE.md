# layout-host

Which box lays a node out, and along which axis — for code that reads its
host's layout from a hidden sentinel (the slot renderer's cell wrapping, the
reorder middleware's orientation and width regimes).

## API

- `useHostFlowAxis(sentinelRef, { followResize? })` → `"row" | "column"` — the
  axis the box laying `sentinelRef` out flows its children along, read in the
  frame's after-layout phase ([`dom/after-layout`](../after-layout/CLAUDE.md))
  and committed before paint. `followResize` re-reads it when the host resizes.

It is a hook, not the two functions it is built from, on purpose: called from a
layout effect, the `getComputedStyle` walk forced a full style recalc per slot
mounted after a large style change. Internally:

- the host is the nearest ancestor that draws a box. `display: contents`
  wrappers are skipped: they draw nothing (their children join the
  grandparent's layout), report `clientWidth` 0 and never fire a
  `ResizeObserver`;
- the axis is `row` only for a `flex` / `inline-flex` container whose
  direction is `row` / `row-reverse`.

## Why

Both traps bit at once in the app shell: the sidebar slot sits in a
`display: contents` wrapper (it carries `--chrome-mask` / `--hover-fill`), whose
computed `flex-direction` is the initial `row` and whose width is 0. Reading
`parentElement` made the reorder middleware treat the sidebar as a 0px-wide
horizontal row and fold every sidebar's edit mode into the narrow-row popover.
