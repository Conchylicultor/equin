# latest-ref

`useLatestRef(value)` returns a stable `useRef`-backed ref whose identity never
changes; `useEventCallback(fn)` returns a permanently-stable function. Read
`.current` only in callbacks / effects, never during render.

## Registered as known-stable for exhaustive-deps

Both `useLatestRef` and `useEventCallback` are listed in the `stableHooks`
setting of [`build-lint-config.ts`](../../../framework/plugins/tooling/plugins/lint/core/build-lint-config.ts)
(`settings["react-hooks"].stableHooks`), which our patch to
`eslint-plugin-react-hooks` (`patches/eslint-plugin-react-hooks@*.patch`) feeds
into `exhaustive-deps`. The returned ref / callback is therefore treated exactly
like a bare `useRef` return: **do NOT list it in a `useCallback`/`useMemo`/`useEffect`
dependency array** — it is neither required nor flagged. (A separate cleanup
warning can still fire when an effect's *cleanup* reads `someRef.current`; that is
stability-independent and is suppressed at the site with an inline disable.)

## One value, many memoized readers: `useLatestStore` / `useLatestSelector`

`useLatestStore(value)` publishes a value a component computes each render
(a selection, an index rebuilt per render, host callbacks) to a store of
stable identity; `useLatestSelector(store, select)` reads ONE answer from it
and re-renders its caller only when that answer changes. Hand the store down
(a context, a prop) instead of the value, and a hundred memoized rows reading
it re-render only where their own answer changed — the tree's rows
(`TreeContextValue.state`), the flat table's manual-order section and `×N`
badge.

- The value is published after the commit (a layout effect, before paint); a
  reader whose answer changed re-renders in the same task. Readers subscribe
  in a layout effect (not `useSyncExternalStore`, which subscribes after
  paint), so a reader mounting in the render that changed the value — it
  reads the previous one — is corrected by that publish before paint.
- `select` must answer a primitive or a reference stable while the answer is
  the same (answers are compared with `Object.is`).
- An event handler reads the current value with `store.get()`.
