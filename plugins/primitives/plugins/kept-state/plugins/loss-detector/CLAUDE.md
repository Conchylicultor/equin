# loss-detector

The dev unmount detector — the net under kept-state that finds a surface still
losing state on a remount (design:
[`research/2026-11-17-global-lossless-reload.md`](../../../../../../research/2026-11-17-global-lossless-reload.md),
"Coverage", net 2). `watchStateLoss(onLoss)` returns its stop;
`reports/reload-loss` runs it for a developer and files each loss.

## How it decides what was lost

1. **Baselines, per commit.** It subscribes to the page's React commit bridge
   (`index.html` installs `__REACT_DEVTOOLS_GLOBAL_HOOK__.__commitSubscribers`
   before React loads; it throws without one) and walks only the subtrees that
   did work in the commit (`subtreeFlags`). A state hook seen for the first
   time records its value as its baseline, keyed by the hook's update queue
   (the one object React keeps for the hook's life), with the value it last
   committed. A change — a value that differs from the last committed one, so
   a component re-rendering for another reason absorbs nothing — is the
   user's when its commit happens inside a user event (`isUserEvent(window.event)`:
   a key, a press or click, typed / pasted / dropped text, a drag — not hover,
   focus or scroll), and keeps the baseline; any other change — data arriving,
   an effect settling, a ResizeObserver measuring, a timer — commits with no
   current event and moves the baseline. React flushes a discrete event's
   updates in a microtask, which the browser runs before it clears
   `window.event`, so the attribution is exact. (A first version used "within
   100 ms of an input": a click's relayout re-measured within a frame and every
   measured size read as the user's.)
2. **The walk, at unmount.** Every `KeepScope` renders a probe whose
   `componentWillUnmount` runs while the deleted subtree is still linked
   (`onKeepScopeUnmount`). Only an **outermost** place is judged (a path with
   no `/`: a tab's app, the global action bar) — a pane inside a tab goes
   with it or with a navigation that replaced it — and only when it was not
   **closed** first (`forgetKeepScope`: a closed tab is gone for good), nor
   unmounting with a **popup open** (`anyPopupOpen`): the reload policy never
   reloads then, and an open popup's flags and position are transient by
   design (the global action bar remounting under its own View options
   popover filed a dozen such false losses).
3. **What counts.** Each `useState` / `useReducer` in the subtree whose value
   differs from its baseline (`Object.is`, else equal JSON) and is not
   **marked**: the hook just before it is a `useRef` holding a `StateMark`
   (`kept` from `useKept` / `useDraft`, `transient` from
   `useTransient("<why>")`), and whose value is **data** (`isUserData`): not
   a DOM node, a function, or an object holding one — a portal's mount node or
   a positioning reference is wiring any mount rebuilds. A hook with no baseline (mounted before the
   detector started) is not judged. Each (component, state index, source)
   is reported once per page.

A loss names the component (`fiber.type` name — the build keeps names), the
named components above it, the state's index among the component's
`useState` / `useReducer` calls, the first element it renders' `data-source` /
`data-ui-owner` (element-picker's build stamps — the file), and the value's
**shape** (`string(15)`, `array(3)`, `object {a, b}`), never its content.

## Limits

- Fiber internals are private React; every read is defensive (`internal/fiber.ts`).
- State that lives only in the DOM (an uncontrolled input, scroll) is the
  reload drill's to find; state that never reaches React (a module store) is
  neither net's.
- A change the user caused that commits in a later task (a click whose result
  arrives with a server answer, a `startTransition` update) is read as not the
  user's.
- Pane-only unmounts (a Miller column replaced in place) are not judged.
