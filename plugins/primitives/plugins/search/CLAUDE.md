# search

`SearchInput` has three appearances (`appearance`):

- `field` (default) — a bordered `sm` input with a leading search icon.
- `filled` — the same box as a quiet grey well: `bg-muted`, no visible border,
  the theme radius, faint icon and placeholder; focus lifts it to the surface
  colour with a `primary` border instead of the focus ring. For a toolbar
  filter that should recede until used (the File Explorer's Filter).
- `bare` — no box of its own, filling a host cell that already draws one, with
  a `/` hint; Escape clears and leaves.
- `menu` — the search row leading a menu or picker panel (data-view options,
  filter and field lists, the icon / emoji / tag / page-link pickers, the
  command palette and quick-find): one
  panel row tall, laid out as a row (`menu-field`: as wide as a row's fill, glyph in the icon column, text on the label rail). Its
  paint is the surface's published field fill/outline, which inside a popover
  is the theme's `popoverField` / `popoverFieldBorder` — so a theme can sink
  the row into the panel, as Mist does.

Every search field is a `SearchInput` — never a hand-rolled `<input>` with a
pinned search glyph. A headless library that owns its query input (frimousse's
emoji search) is drawn through `render={<Lib.Search />}`, keeping this chrome.
