# bundled-layer

The `ConfigGitLayer` (`config_v2/server`) of a host without the repo on disk:
the repo's whole `config/`, inlined into the bundle as text at build time
(`import.meta.glob("/config/**/*.jsonc", { query: "?raw", eager: true })`),
indexed once by `committedFilesFromMap` and resolved per storePath by
`committedDocument` — the same rule the desktop reads the checkout's `config/`
with (`config_v2#machine`'s `repoConfigLayer`).

- All of `config/`, not a composition's share: the committed layer is
  composition-invariant, and the memory store (`config_v2/browser-store`) seeds
  a storePath lazily, on first touch, so an unread document is inert bytes.
- Only a vite-built bundle can boot it — `import.meta.glob` is vite's — which
  is exactly the browser worker host (`framework/tooling/web-artifacts`'
  browser hosts, whose `root` is the repo, so the root-absolute pattern names
  `config/`). The host's address lists the glob's static base recursively
  (`globRoots`), so a new config file re-addresses the host.
- An empty bundle throws: it is a bundler that stopped expanding the glob,
  never a repo without config.
- The desktop never boots it: it is in `base-exclusions`
  (`plugin-meta/composition`), and `config_v2#machine` is the desktop's
  provider. Same shape as `database/migrations/bundled-source`.
