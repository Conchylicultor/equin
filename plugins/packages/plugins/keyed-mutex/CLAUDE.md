# keyed-mutex

Per-key FIFO mutex: `createKeyedMutex()` returns `{ run(key, fn), size }`.
`run` starts `fn` once every earlier `run` for the same key has settled, in
arrival order; different keys never wait on each other. Each call runs its own
`fn` exactly once and gets its own result or rejection — a failure never stalls
the calls queued behind it. A key's entry is deleted by the run that is still
its queue's tail when it settles, so an idle key holds nothing.

Neighbours, and why they do not fit a mutation that must not interleave:

- `packages/coalesce` FOLDS the triggers that land mid-run into one trailing
  run — a second send would be merged into the first.
- `packages/inflight` SHARES one execution among concurrent callers — a second
  send would be dropped.
- `packages/semaphore` bounds concurrency across all callers, with no per-key
  queue.

In-process only. It orders the callers of one process; two processes need a
lock both can see (a pg advisory lock, `packages/flock`).

Used by `conversations` to serialize everything typed into one agent's terminal
(send, answer, interrupt, Stop): two sends to one pane interleaved their
keystrokes into one concatenated turn.
