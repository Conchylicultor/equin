# floor-compat

Floor-safe spellings of built-ins newer than equin's browser floor
([`framework/tooling/lint/browser-floor`](../../../framework/plugins/tooling/plugins/lint/plugins/browser-floor/CLAUDE.md):
Chrome / Edge 111, Firefox 115, Safari / iOS Safari 16.4). Each answers as the
built-in does (`core/internal/*.test.ts` hold them equal), on every host:

| Helper | Spells | Built-in needs |
| --- | --- | --- |
| `canParseUrl(raw, base?)` | `URL.canParse` | Safari 17, Chrome 120 |
| `parseUrl(raw, base?)` | `URL.parse` | Safari 18, Chrome / Firefox 126 |
| `jsonResponse(body, init?)` | `Response.json` | Safari 17 |
| `promiseWithResolvers<T>()` | `Promise.withResolvers` | Safari 17.4, Chrome 119, Firefox 121 |

`browser-floor/no-api-above-floor` refuses the built-in in browser-built code
and names the helper here when there is one. equin.ai's home page crashed on
`URL.canParse` for a visitor on an older Safari (2026-11-19).

A newer built-in with no equivalent spelling (a view transition, the CSS
highlight registry) is feature-tested at its use site instead — the rule
accepts a use behind a test.

`canParseUrl` answers `false` only for a `TypeError` (what the constructor
throws on an invalid URL); anything else is rethrown.
