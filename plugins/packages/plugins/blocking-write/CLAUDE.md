# blocking-write

`writeAllSync(fd, data)` (`machine`) — every byte of `data` written to `fd`
before it returns, on a blocking or a non-blocking fd alike. The one
synchronous writer for a host process's stdout / stderr.

**Why a bare `writeSync(1, …)` is wrong.** Bun sets `O_NONBLOCK` on a piped
stdout / stderr the first time `process.stdout` / `process.stderr` is touched
(any `console.log` does), and the flag lives on the open file description, so
every later write to that fd is non-blocking. Into a pipe whose reader is
slower than the writer (`./equin build 2>&1 | tail -40`), `writeSync` then
throws `EAGAIN` once the pipe's 64 KiB buffer is full, or returns a short
count the caller drops. That crashed a build with a Bun stack instead of its
verdict (a check printing a long failure, 2026-11-15).

`EAGAIN` is normal non-blocking semantics, so the fix waits: on `EAGAIN` the
thread blocks in `poll(2)` (`POLLOUT`, no timeout) until the reader drains the
pipe, then writes again; short writes loop. No spin, no retry budget, nothing
dropped; any other error (`EPIPE` once the reader is gone) throws as is.
`poll` is dlopen'd on the first `EAGAIN` only.

Use it wherever a synchronous write must be all out before `process.exit` —
the attached-run transcript echo, the foreground-handoff pump, the build
verdict.
