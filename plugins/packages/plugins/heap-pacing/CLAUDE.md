# heap-pacing

`pacedHeapEnv(env)` returns a child's environment with `BUN_JSC_forceRAMSize`
set to `HEAVY_PROCESS_RAM_BYTES` (4 GB), unless `env` already names a value.
Pass it as the `env` of a spawn that starts a heavy bun process — one that holds
GBs of live heap, such as a TypeScript program with typed ESLint.

## Why

JavaScriptCore collects when the heap has grown by a factor of the live size
that depends on the heap's size against the machine's RAM. After a full
collection with H bytes live, the heap may reach about
`(1 + heapGrowthMaxIncrease · e^(−heapGrowthSteepnessFactor · H / ram)) · H`.
Bun ships `heapGrowthMaxIncrease` 2 and steepness 2 (oven-sh/bun#39844). JSC
assumes the process has the whole machine to itself. On a 64 GB host a 4.4 GB
heap may therefore grow ~2.7× before a collection. Every heavy process does
this at once.

With `ram` = 4 GB:

- a heap far below 4 GB (a script, a keyed type-check run) still grows ~2–3×
  and collects as rarely as before;
- a heap of several GB grows ~1.1–1.3×.

The processes that hold the host's memory are the ones that pay for collecting
more often.

## Measured

The heaviest batch of a cold whole-tree type check: 2,000 sources, 4.4 GB live
after a full GC. Peak RSS went from 8.6–9.7 GB to 6.95–7.2 GB, CPU +0–10 %.
`--smol`, `Bun.gc(true)` at phase boundaries or between lint files, a lower
`heapGrowthMaxIncrease`, no concurrent GC and `MIMALLOC_PURGE_DELAY=0` each
moved the peak by less than run-to-run noise. See
`research/2026-11-08-global-type-check-bun-heap-pacing.md`.

## Not a cap

Bun has no heap limit: `--max-old-space-size` is ignored (oven-sh/bun#34917,
fix in review as oven-sh/bun#34924). This setting paces the collector; it
bounds nothing. A process whose live data exceeds 4 GB still runs, with a
growth factor near 1 (more frequent collections).

## Where it applies

- the type-check worker (`spawnTypeCheckWorker`) and its batch processes;
- every `./equin run` script. A one-off script that builds a whole-repo
  program (an inventory, a rename) is the same workload; a small script is far
  below the pacing size and does not notice.

A paced process's children inherit the value through the environment. The
value an environment already carries always wins, so a measurement can set its
own (`type-check/scripts/batch-memory-bench.ts`).
