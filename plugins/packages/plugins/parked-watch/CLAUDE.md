# parked-watch

`createParkedWatches<T>({ onOpenError })` → `{ watch, resolved }`: a watch held
on a KEY whose target is not known yet — a live value subscribed for a
conversation before its row (or its attempt's) exists, so there is no worktree
to watch. Nothing in it knows conversations or files; the key, the target and
the open are the caller's.

- **`watch(key, resolveNow, open, onChange)`** — the subscribe. The park is
  taken BEFORE `resolveNow` (the subscribe's own resolve) runs, so a load that
  resolves the target while that resolve is in flight (the row's insert re-ran
  it) still opens the watch. A target found by `resolveNow` opens at once — the
  promise resolves once it is open, and rejects with the open's own failure.
  None parks the watch.
- **`resolved(key, target)`** — every load that resolves the target calls it,
  so the load a row's insert re-runs is the one that opens the parked watch;
  `onChange` then runs once it is open, so a change between that load and the
  watch going live is not lost.
- **A parked open that fails** is handed to `onOpenError(key, err)` (required:
  the caller reports it) and RE-PARKED, so the next load that resolves the
  target retries it. It never notifies on failure: a notify would re-run the
  loaders, whose resolve would retry at once — a loop for as long as the open
  keeps failing.
- A watch opens once, whichever finds the target first; a stop before a parked
  open settles closes it as soon as it opens, and notifies nobody.

Modelled on code-explorer's `rootWaiters`
(`code-explorer/machine/internal/workspace.ts`). Users:
`conversations/conversation-view/code` (`edited-files`) and
`conversations/conversation-view/allow-monitor` (`allow-files`) — both resolve
the worktree through tasks-core's gated `workspaceOfConversationLookup`, so no
unrelated conversations write re-runs their loaders to hide a missed open.
