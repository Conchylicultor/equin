# shared-work

`sharedWork(name, fn)` marks work as SHARED: started by one caller and reused
by every later one — a per-process memo (the plugin tree a check pass builds
once, the codegen pass's trees), a record a content-keyed store keeps. Which
caller starts it is an accident of order and of what the store already held,
so a per-unit meter must not charge it to that caller.

A meter installs the scope shared work runs in (`installSharedWorkScope`):
`packages/timed-fs` does, as it loads, so the file calls of shared work are
counted under `name` (`sharedFsCallTallies()`) and into no enclosing unit's
tally. That is what makes a check's own file-call count — the one its
`wholeTreeRead` declaration is judged on (`tooling/checks` CLAUDE.md) — a
function of the tree, not of which check reached a memo first.

Portable on purpose: `core/` code everywhere (plugin-records, the codegen
memos, the plugin tree) marks its memos with it, and may not import a platform
API such as timed-fs. With no scope installed it simply runs `fn`.

Wrap the producer where the memo is filled — `cached ??= sharedWork("…", () =>
build())` — so the whole promise chain of the work runs in the scope.

## `sharedMemo`: a per-run memo that is shared work by construction

`sharedMemo(name, produce, { owner? })` is the one spelling of a memo keyed by
an input object (a run's file set, a codegen pass over one): `produce(key,
...args)` runs once per key, with the first caller's `args`, under
`sharedWork(name, …)` — so no memo can forget the wrap and charge a whole
tree's work to the check that asked first (`serverPortabilityOf` was a bare
`WeakMap` and did exactly that). A module-level `Map` / `WeakMap` keyed by a
run's file set is a lint error (`shared-work-safety/per-run-memo`).

**One unit's own input.** An input-keyed check's `ctx.repo()` is a recording
set of its own (`checks/core`'s `recordingRepoFiles` calls `markOwnInput` on
it): a memo keyed on it serves that check alone, its reads land in that
check's read-set, and so they are that check's own work, not shared. So
`sharedMemo` runs the producer in the caller's scope when the key's owner (the
key, or `owner(key)` — the set a pass is over) is an own input
(`isOwnInput`), and `sharedWorkOver(input, name, fn)` does the same for the
lazy work a memoized value does later (the registry context's `<dir>` scans
and browser-host derivations, keyed on a ctx that is itself marked own when
its set is). Before, the codegen caches counted such a check's reads as
shared, so they were in no check's meter. The consequence to expect: an
input-keyed check that builds its own codegen pass (`codegenPassOver(await
ctx.repo())`) is now judged on the trees' whole-tree reads as its own — which
they are — so it must be O(changes) through records or declare
`wholeTreeRead` (none does today).
