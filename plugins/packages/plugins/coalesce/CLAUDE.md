# coalesce

`createCoalescer({ run })` / `createKeyedCoalescer({ run })` — the one way to
react to a trigger that can fire faster than its work finishes (a file watch, a
change feed). Per key: at most **one run in flight and one pending**. A trigger
while idle starts a run at once; a trigger while running folds into the single
pending run (its items appended), started when the current run settles.

- **Bounded:** N triggers against slow work cost at most two runs per key.
- **Never stale:** a trigger is always answered by a run that STARTED after it —
  unlike `inflight`, which joins the flight already running.
- `trigger(items?)` is fire-and-forget (a failing run with nobody waiting is an
  unhandled rejection); `run(items?)` resolves when its covering run settles.
  A failure never wedges the key: the pending run still starts.
- `idle()` for tests and shutdown; `stats()` counts triggers, runs and folds.

The file-watch layer (`infra/file-watcher`, `infra/git/checkout-watch`) wraps
every subscriber's callback in one, so a watcher that RETURNS its work's promise
is bounded by construction.
