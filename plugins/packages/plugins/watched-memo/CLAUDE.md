# watched-memo

`createWatchedMemo({ name, facts, signatureOf, compute, changes, equals? })` →
`{ get, watch, evict }`: a per-key result memo whose freshness authority is its
**watch**, not a probe on every read. Nothing in it knows git — every input is
injected. Built from `coalesce` (one pass at a time, mid-pass triggers folded
into one trailing pass), `refcount-hub` (one change source per key) and
`inflight` (the probe path's single-flight).

- **Watched** (`watch(key, onChange)` held): `changes(key, trigger)` opens the
  source; once it is live, pass 1 runs. Each pass is `facts` → `compute(key,
  facts)`. `get` returns the held value — no probe, no spawn
  (`memo-watched-hit:<name>`); while pass 1 runs it awaits it.
- **Every pass computes.** No skip on an equal signature: a write read mid-pass
  and then undone puts the signature back while the value still shows it.
- Pass 1 notifies nobody. A later pass with an `equals` value keeps the held
  object (identity) and notifies nobody; otherwise it sets the value, then
  notifies. A pass after close writes nothing.
- **A failed pass demotes** the key and notifies; it never rethrows (that would
  be an unhandled rejection in the coalescer). `get` then takes the probe path,
  which raises the real error. The next successful pass restores it.
- **Probe path** (unwatched, or demoted): `facts` → `signatureOf(key, facts)` →
  the cached value on a hit, else a compute single-flighted per `key\0signature`
  over the probe's own facts — one scan per miss — cached only when a re-probe
  after it still reads the same signature.
- `trigger(true)` is a resync: the source lost events (`file-watcher`'s
  `onLost`, `checkout-watch`'s `onResync`), so anything may have moved.
- The last watcher leaving drops the key's value and its probe entry at once
  (readers awaiting pass 1 fall to the probe path). There is no warm-on-close
  and no `prime`.

Freshness: every change after the source is live is heard after it, pass 1
starts after that, and the value is set before the notify — so readers see the
newest value, stale by at most one pass in flight. That holds because the value
is **pushed**. Do not mint an ETag from a fresh probe beside it: a revalidate
must return the entry's own signature.

`git-read-cache`'s `createSignedMemo` / `createGitStateMemo` stay for keys
nothing watches (probe-on-get).

User: `conversations/conversation-view/code` (`edited-files`).
