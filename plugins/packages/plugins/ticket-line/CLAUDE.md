# ticket-line

A first-come-first-served line across processes, built from files and kernel
flocks only.

```ts
import { createTicketLine } from "@plugins/packages/plugins/ticket-line/core";

const line = createTicketLine(dir);           // every process naming `dir` shares it
const ticket = await line.join({ signal });   // resolves at the head of the line
try {
  /* take what the line orders (a slot, a lock) */
} finally {
  ticket.leave();                             // the next waiter becomes the head
}
line.isEmpty();                               // nobody waiting? (may I skip the line?)
```

**Why it exists.** A bare flock wakes an *arbitrary* waiter when it frees, and a
non-blocking sweep lets a newcomer barge past every waiter. Every host queue
(`packages/host-semaphore`: the CPU grant, push, e2e, …) and the agent-build
duress gate (`cli/op-runtime`) need arrival order instead.

## How

- **A ticket is a file** `t-<monotonic ns>-<pid>-<seq>.lock`. Its name is its
  place: `process.hrtime` is the machine-wide monotonic clock, the fields are
  zero-padded so string order is arrival order, and a name is never reused. It
  is created under a temp name, flocked exclusive in-process, and only then
  renamed into place — so a visible ticket is always held by a live owner.
- **A waiter blocks on the ticket just ahead of it** (one `waitForFlock` child,
  `packages/flock`). A leave wakes exactly the next waiter — no thundering herd,
  no arbitrary pick.
- **A ticket whose lock can be taken has no owner** (it left, or its process
  died — the kernel drops a flock with its process): whoever finds one reaps the
  file and looks again. So a SIGKILLed waiter leaves the line by itself, and no
  pid is consulted.
- **Leave** unlinks, then closes: the close wakes the successor, which by then no
  longer sees the file.
- `signal` aborts a pending `join`: the ticket is removed and the call throws
  `signal.reason`; the waiter behind moves up.

## Accepted fuzz

Two callers that read the clock within the same few microseconds (between the
clock read and the rename) can each see no predecessor; their relative order is
then arbitrary. A temp file of a process killed inside that window is left
behind (harmless, never read as a ticket).

Cost: one `flock-wait` child (~37 MB, `bun --smol`) per queued waiter.
