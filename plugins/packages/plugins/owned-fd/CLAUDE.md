# owned-fd

A file descriptor is a bare number, and a number has no owner. Close it twice
and the second close lands on whatever reused the number in between — a pooled
Postgres socket, a pipe, a temp file — which dies with no error where it
happened; the symptom shows up at the victim, never at the culprit
([`research/2026-09-11-global-live-updates-frozen-by-stray-fd-close.md`](../../../../research/2026-09-11-global-live-updates-frozen-by-stray-fd-close.md)).

So app code holds descriptors as an `OwnedFd`:

```ts
import { openOwnedFd, adoptFd } from "@plugins/packages/plugins/owned-fd/core";

const out = openOwnedFd(path, "w"); // openSync, owned
try {
  Bun.spawn(argv, { stdout: out.fd }); // the child gets its own copy
} finally {
  out.close(); // exactly once
}
const pipe = adoptFd(child.stdio[3] as number); // a number you were handed and must close
```

- `close()` closes the descriptor exactly once. A second call never reaches the
  kernel: it throws `FdAlreadyClosedError`, carrying the first close's stack —
  the culprit named at the culprit.
- A close the kernel refuses (EBADF: someone else closed the number) still
  spends the handle and throws.
- `.fd` is the number, for calls that take one (read / write / fstat / flock, a
  child's stdio). Nobody but `close()` closes it.

## Enforced

- **`owned-fd/no-raw-fd-close`** — no `closeSync` / `close` from `node:fs`
  outside this plugin's `owned-fd.ts` (named import, or `fs.closeSync(…)` on a
  namespace / default import). `fs/promises`' `FileHandle#close` is already an
  owned handle and is allowed.
- **`owned-fd/no-raw-spawn-stdio-fd`** (type-aware) — a value given as a child's
  `stdin` / `stdout` / `stderr` or a `stdio` slot, in the options of a call
  named `spawn` / `spawnSync`, whose type includes `number`, must be an
  `OwnedFd`'s `.fd` (judged per branch of `??` / `||` / `?:`).

Both are out of scope in tests (throwaway processes holding no pooled sockets),
research and generated files. The stdio rule reads what is written at the call:
options built in a variable, or a `stdio` array held in one, are not followed;
and `OwnedFd` is recognised by its type's name.

`core/` here means runtime-neutral node (`node:fs`), not web-safe: never import
it from `web/`. Like `packages/timed-fs`, it is sanctioned out of
`boundaries/no-platform-api` because every process kind must reach it.

## Why it exists

The 2026-09 stray closes were Bun's own (oven-sh/bun#33828: a finished child's
extra stdio fds closed again at GC; guarded since by the `bun-runtime` check).
Since 2026-11-04 a database connection lost to its deadline is closed rather
than abandoned (`database/connection`), so a stray close anywhere in the
process costs more than a leak: the close of a lost client could land on
whatever reused its number. Owning every descriptor the app opens makes a
double close in our own code loud at its source.
