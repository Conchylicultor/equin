# systemd-scope

A command in a systemd user scope of its own, and the one fact about how that
scope ended that nothing else records: **systemd-oomd killed it**.

systemd-oomd (on by default on Ubuntu desktop) SIGKILLs every process of a
whole leaf cgroup under memory pressure. It is not the kernel's OOM killer, so
`/proc/vmstat`'s `oom_kill` (`host-memory`'s `readOomKillCount`) never moves,
and the parent sees a plain SIGKILL. Measured on Ubuntu 24.04 / systemd 255
(`research/2026-11-19-global-oomd-deploy-kill.md`):

- a child left in its parent's service cgroup dies with the WHOLE service —
  oomd took the gateway's unit, with Postgres, every backend and the build;
- in a scope of its own the child is its own leaf: oomd took the scope alone;
- the user manager then writes a structured record to the user's journal —
  `MESSAGE_ID=d989611b15e44c9dbf31e3c81256e4ed` (`SD_MESSAGE_UNIT_OOMD_KILL`),
  `USER_UNIT=<scope>`, `N_PROCESSES` — readable with `journalctl --user` (no
  `adm` group), whatever the scope's `OOMPolicy`.

The scope's `Result=oom-kill` is NOT the signal: it needs `OOMPolicy=stop`,
which stops the whole scope on any kernel OOM kill inside it (one type-check
worker killed would SIGTERM the build). Scopes here run `OOMPolicy=continue`.

## API (`core/`)

- `userScopeHost({ platform, uid, exists })` — `systemd` (Linux, the user
  manager's socket at `/run/user/<uid>/systemd/private`) or `none` with why.
- `inOwnScope(host, { argv, env, unit, description })` — the argv wrapped in
  `systemd-run --user --scope --collect -p OOMPolicy=continue`, which execs
  the command (same pid). `XDG_RUNTIME_DIR` (how `systemd-run` reaches the
  manager; the runtime tree's declared environment does not carry it) is set
  for `systemd-run` and taken back out before the command when the caller did
  not have it.
- `readScopeOomdKill(host, unit, { run, wait, now })` — reads the unit's
  records until they settle: `oomd-killed` (with the count), `not-oomd` (the
  unit's stop recorded with no oomd kill before it), or `unknown` (unreadable
  journal, or nothing settled within 10 s — a bound on the user manager and
  journald, which write the records a moment after the caller's wait returns).

`core/` spawns and reads nothing itself: the caller hands it a runner and an
`exists`. User: main's convergence run (`framework/cli/build`'s
`converge.ts`), whose build runs in `<build id>.scope`.

macOS has no counterpart: jetsam's kills are in the unified log only.
