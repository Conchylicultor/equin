# places-core

## A place's name, and places Google does not know

- **`placeName(place)`** (core) is the name every surface shows, searches and
  sorts by: the user's `title` when set, else `name`. Never spell
  `title ?? name` anywhere else.
- **Google place**: `googlePlaceId` set, `name` is Google's (re-fetched with
  its details by `places.refresh-details`, which never writes `title`),
  `title` the user's own name over it (null shows Google's; a title equal to
  Google's name is stored as null).
- **Custom place** (`isCustomPlace`: `googlePlaceId` null): a pin the user
  named and placed (a closed venue, a bunker, an event). `name` is the user's;
  `title`, `primaryType`, `mapsUrl`, `businessStatus`, `googleLostAt` are null and `types`
  empty — the `places_custom_no_google` CHECK makes any other pairing
  unwritable. The refresh job skips it; Haiku picks its icon from the name.
- **Lost Google place** (`googleLostAt` set): the refresh got NOT_FOUND for
  its `googlePlaceId` — Google retired the id and names no successor. The row
  keeps its last snapshot and is never re-linked automatically (a successor
  found by searching is a guess for the user to confirm); a later successful
  refresh clears it.
- **Writes**: `insertPlace(NewPlace, extras)` is the one insert, `NewPlace` =
  `{kind:"google", snapshot, title?} | {kind:"custom", name, address, lat,
  lng}` (Save, `POST /api/places/custom-places`, the Mapstr import's
  `replaceAllPlaces`). `PATCH /api/places/places/:id` takes `title` (a Google
  place's title — null/blank clears; a custom place's name — blank refused)
  and `location` (a custom place's pin only; refused on a Google place).

## The tag tree

`place_tags` is a `tag-tree` tree (`plugins/tag-tree`): `placeTagsEntityRef =
tagTreeEntityRef("place_tags", { idKind: placeTagIdKind, extraFields })` — the
base tag columns plus `googleTypes` (Google place types that auto-set the tag
on save) and `role` (`been` / `want`, unique where set). The table is
`defineTagTreeTable` with the rank column named `tree_rank` (a fractional
`rank_text` key; migration `place_tags_tree_rank` replaced the integer `rank`,
keeping each parent's order). `placeTagTree` (`:tree` id `places`) is served
with `serveTagTree`: carriers `placeTagsCarrier` (a deleted tag is replaced on
every place by its parent and leaves `autoTags`), `editableExtras:
["googleTypes"]`, and `refuseDelete` for a role tag. Every tag write goes
through the engine's `/api/tag-trees/places/…` endpoints; Places has none of
its own.

- Generic tree helpers (`tagPath`, `tagColor`, `flattenTagTree`,
  `tagDescendants`, `isTagUnder`, `wouldCycle`, `tagPathLabel`, …) are the
  engine's — import its core barrel. `core/internal/tag-tree.ts` keeps only the
  Places semantics over `PlaceTagNode`: `TAG_ROLES`, `tagIdByRole`,
  `isRoleTag`, `placeFlags`, `ringColors`, `mainColor`, `NEUTRAL_PLACE_COLOR`,
  `autoTagsFor`, `tagPlaceCounts` (= `rolledUpTagCounts` over the places).
- The starter tree (`SEED_TAGS`, `seed-tags.ts`) is small and standard: Want
  to go / Been (by role), Favorites, Food › Restaurant / Café / Bar, Museum ›
  Art, Sights, Nature, Nightlife & shows, Shopping, Price › € / €€ / €€€. It
  is written only on an empty `place_tags` (the `places.seed-tags` warm-up), so
  changing it never touches an install that has tags. `replaceAllPlaces` seeds
  it too, unless the import brings its own tree (the Mapstr import seeds
  `MAPSTR_TREE`, the Mapstr categories its tags map onto). Every seeding
  (`seedTagTree`) mints each rank with `Rank.between(previousSibling, null)`.
