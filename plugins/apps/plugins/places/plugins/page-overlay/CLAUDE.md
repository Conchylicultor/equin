# page-overlay

A page's places laid over the Places map, read live by page id — nothing is
written until the user saves one. Plan:
`research/2026-10-31-apps-places-page-overlay.md`; reference UI: prototype
`proto-1793376812-x39bpd` at `overlay-tpin=ghost`, `overlay-others=dim`,
`overlay-list=panel`, `overlay-numbers=on`.

Dependency direction: Places → page only. Nothing under `page/` names Places
(the page map block draws `PageMap.Action` contributions it does not know),
and `places-map` imports this plugin, never the reverse — so the screen, the
panel and the pins live in `places-map` (they are drawn from its own cards,
pins and photo wash); this plugin owns the contract and the page-side entry.

## Core

- `placesMapRoute` — the Places app's index route (`segment: ";page"`): bare
  `/places` is the plain map, `/places;page=<pageId>` lays one page's places
  over it. A keyed param of the index (plan
  `research/2026-11-02-apps-places-page-overlay-v2.md`), so the layer is a
  view of the one mounted map pane, never a second pane that remounts it.
  Owned here rather than by `places-map` (whose `placesMapPane` it is): the
  page-side action links to it, and `places-map` → `page-overlay` is the only
  allowed direction.
- `joinPageOverlay(located, places)` (pure, tested) — the page's located
  places (`page/place`'s `locatedPlaces`, in page order) joined with your
  saved places: Google places only (`GOOGLE_PLACE_PROVIDER_ID`), numbered
  1…N in page order, each matched to the saved place with its Google id
  (`places-core`'s `placesByGoogleId`). `unplaced` = what `locatedPlaces`
  could not locate plus every located place of another provider — the
  summary's "N not on the map".
- `PageOverlayItem` — `{ n, blockId, googlePlaceId, name, address, category,
  position, kind, family, saved }`; keyed by block (a place may sit twice on a
  page). `pageOverlayItemKind` is its row kind (name, number), what the
  panel's DataView lists.

## Web

- `usePageOverlay(pageId)` — the page row (`useLiveRow(pagesTree)`: title,
  icon), its blocks (`useLive(pageBlocks, { where: { pageId } })`, the page's
  own, in document order) and your places (`usePlaces`), joined. A
  `ResourceResult` — loading until all three land, a failed read's error, then
  `{ kind: "missing" }` (a page gone since the link was made) or
  `{ kind: "page", page, items, unplaced }`. An edit to the page re-joins at
  once.
- `OpenInPlacesAction` (`PageMap.Action`) — an icon-only floating button in
  the map block's top-right corner, drawing `navIcons.expand` — the glyph a
  pane's own cross-app Expand ("Open in <App>") draws — labelled "Open in
  Places"; a link (`useAppLink`, `isolate`d from the editor) to
  `placesMapRoute.link(placesApp, { page: pageId })` → `/places;page=<id>`
  (cross-app, so `inAppLink`; inside Places, `;page` is changed with the
  pane's own `useSetParams`). The map block reveals it on hover and draws it in the
  map's chrome theme; the button itself styles neither.
