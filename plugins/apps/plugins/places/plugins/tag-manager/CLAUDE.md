# tag-manager

The Places app's **Manage tags** panel, and `TagMark` — how a tag shows beside
its name on every Places surface.

## `TagManagerPanel`

A floating card (`Surface level="overlay"`) the map screen
(`places-map`) lays over the map, right of the tag sidebar, when the sidebar's
"Manage tags" or "+ New tag" is clicked. It holds a `DataView` (surface id
`places.tags`, one `table` view authored in
`config/apps/places/tag-manager/places.tags.jsonc`) over `flattenTagTree(tags)`
— the tree in depth-first rank order, so the table reads as the tree:

| Column | Cell |
|---|---|
| Tag | indent by depth · `TagColorButton` (palette of 18 + Inherit / No colour) · `TagIconButton` (`IconPicker` + No icon) · `TagNameInput` (saved on blur / Enter) |
| Parent | `TagParentSelect`: Top level or any tag but itself and its descendants (`wouldCycle`) |
| Auto-set from Google types | the tag's `googleTypes` as mono chips, else "manual" (read-only) |
| Places | `tagPlaceCounts` over every place — nested tags included |
| (actions) | Shade children (parents only: `childColors: "ramp"` — the colourless children as light → deep shades of its colour, by rank) · + Child · Delete (`confirmDialog`; not offered for the role tags Been / Want to go, which the endpoint refuses) |

Every edit calls the tag endpoint directly (`useUpdatePlaceTag` /
`useCreatePlaceTag` / `useDeletePlaceTag`); the live `places.tags` collection
carries the result back. A tag made by "New tag" / "+ Child" is named "New
tag" and its name field takes focus when its row arrives (`focusTagId`, or
the panel's own state after a create).

Sorting by a column breaks the tree reading; the order the rows arrive in is
the meaning, so the view config sets no sort.

## `TagMark`

The tag's icon (`runtimeSymbol`, filled) tinted with its colour (`tagColor`:
own, else the nearest ancestor's), else a dot: full-size for an own colour,
small and faded for an inherited one, a dashed ring when no colour reaches it.
The colour is user data (a stored hex), painted through `style`.
