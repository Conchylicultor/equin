# tag-manager

The Places app's **Manage tags** panel. `TagMark` (how a tag shows beside its
name) and the palette are the tag-tree picker's / engine's (`tag-tree`).

## `TagManagerPanel`

A floating card (`Surface level="overlay"`) the map screen
(`places-map`) lays over the map, right of the tag sidebar, when the sidebar's
"Manage tags" or "+ New tag" is clicked. It holds a `DataView` (surface id
`places.tags`, one `table` view authored in
`config/apps/places/tag-manager/places.tags.jsonc`) over the `places.tags.all`
collection, nested by `parentId` (`hierarchy`; siblings in rank order, open on
first paint; `getRank` = the stored fractional `rank`) — the table reads as
the tree. The tag and the Google types are
the collection's derived fields (cells overridden); the parent, the place
count and the actions are the manager's own `extraFields`:

| Column | Cell |
|---|---|
| Tag | `TagColorButton` (`TAG_PALETTE` of 18 + Inherit / No colour) · `TagIconButton` (`IconPicker` + No icon) · `TagNameInput` (saved on blur / Enter) |
| Parent | `TagParentSelect`: Top level or any tag but itself and its descendants (`wouldCycle`); a pick is a `move` to the new parent's end |
| Auto-set from Google types | the tag's `googleTypes` as mono chips, else "manual" (read-only) |
| Places | `tagPlaceCounts` over every place — nested tags included |
| (actions) | Shade children (parents only: `childColors: "ramp"` — the colourless children as light → deep shades of its colour, by rank) · + Child · Delete (`confirmDialog`; not offered for the role tags Been / Want to go, which the tree's `refuseDelete` refuses) |

Every edit goes through the tag-tree engine's endpoints
(`useTagTreeActions(placeTagTree)`: `create` / `update` / `move` / `remove`);
the live `places.tags.all` collection carries the result back. A tag made by
"New tag" / "+ Child" is named "New tag" (or "New tag 2", …: sibling names are
unique, `freeSiblingName`) and its name field takes focus when its row arrives
(`focusTagId`, or the panel's own state after a create). The Google types a
tag auto-sets are shown read-only; the tree serves them as its one
client-editable extra (`editableExtras: ["googleTypes"]`).

Sorting by a column breaks the tree reading; the order the rows arrive in is
the meaning, so the view config sets no sort.
