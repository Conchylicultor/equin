# fixtures

Some prototypes with their history, written into a host through the app's
real write path — for a demo's seed or a test. The app owns the fixture's
format and its writer; the data belongs to whoever uses it (a demo keeps its
own `data/`). Design: `research/2026-10-28-global-per-app-demo-seeds-v2.md` §2.

## The fixture (`core`)

A fixture directory holds `prototypes/` and `thumbnails/`:

- `prototypes/` is laid out like the app's data dir: one folder per prototype
  (named by a prototype id, flat, with an `index.html`) — its files are `v0`
  — plus `_`-prefixed record dirs taken as they are (`_picks/<id>.json`).
  A folder's history is its `steps/`: `steps/v<N>.txt` (the subject on its
  first line, the body below) and `steps/v<N>/` (the files that version
  changes, laid over the one before). The newest step is what the folder
  holds now.
- `thumbnails/<fingerprint>.png`: every version's gallery picture, rendered
  ahead of time and named by the fingerprint the gallery computes over that
  version's folder.

`PrototypeTreeFixture` is the `prototypes/` tree as text (path → text);
`PrototypeFixtureData` adds the thumbnails; `PrototypeFixture` adds the
gallery rows about them — `tags` (in gallery order, each with its
`carriers`; a prototype carries at most one) and `pinned`. Pure functions over
them, so a worker (its bundle), a test, the check and the script (disk) agree
on every version and its fingerprint:

- `parsePrototypeTree(tree)` → `{ prototypes, records }`, loud on anything the
  layout does not allow. It asks only for prototype ids: a rule about WHICH
  ids (a demo's `…-demoNN`) is the fixture owner's.
- `prototypeFixtureVersionFingerprint(version)` — the cache key of a version.
- `auditPrototypeFixtureThumbnails(parsed, thumbnails)` — versions with no PNG,
  PNGs no version names.
- `prototypeFixtureStates(parsed, { tags, pinned })` — the `prototype_state`
  rows asked for, loud on a carrier or pin the tree does not hold.
- `prototypeFixtureDataOf(files)` — the data from a directory listing.

## The writer (`server`, portable)

`writePrototypeFixture(fixture)` writes into a host that is **up** — booted
and past `onReady`, so the files watcher, its history adoption and the
thumbnails sync are live and derive what they derive on any tree:

1. the thumbnails into the cache root, **first** — a host with no renderer
   answers a cache miss `unavailable` and never looks again; a version with
   no PNG is refused before anything is written;
2. each folder's `v0`, built out of sight and renamed into the
   `prototypesFiles` root (`stageThenRename`, as a mint does) so the watcher
   never adopts a half-written folder;
3. `settlePrototypesWatcher()` (`files/server`): the watcher has adopted each
   history — the real path for a folder that appeared without the mint —
   asserted through the stamps (`readVersionCounts`, not `readHistory`, which
   would adopt on read);
4. each step's files, then `checkpoint({ kind: "turn" })`;
5. the records, and the watcher settled again;
6. the tag rows (ranked in the order given) and the state rows.

Through the roots' own writes, so it runs on any host's store. It contributes
nothing; a host boots it because its seed imports it. The thumbnails sync is
fire-and-forget from the watcher's listener: a caller that needs every card
`ready` waits on `prototypes.thumbnails`.

## The thumbnails check and the render script (host processes)

- `machine`: `prototypeFixtureThumbnailsCheck({ id, dir })` — the check a
  fixture's owner returns from its own `check/index.ts`, naming its fixture
  directory; it fails on a missing or unused PNG, with the command that fixes
  it. `readPrototypeFixtureDir(dir)` reads a fixture directory off disk. A
  `machine` barrel because a check reads the disk (and `check/` may import
  `machine`); it contributes nothing to a running host.
- `scripts/render-fixture-thumbnails.ts --fixture <dir>` (`./equin run …`, the
  directory from the repo root) — renders every version with the gallery's
  renderer (`./equin prototype thumbnails`) into `<dir>/thumbnails/` and drops
  the unused PNGs. A script cannot import `machine`, so it reads the
  directory itself.

## Tests

`./equin test plugins/apps/plugins/prototypes/plugins/fixtures`:

- `core/internal/tree.test.ts` — the parser, the audit, the state rows.
- `server/internal/write.test.ts` — the writer's server closure booted on a
  browser host's providers (PGlite, the in-process queue, memory data-files,
  snapshot history, no renderer) PAST its post-ready phases, in a fresh bun
  process; the test's own small fixture (two prototypes, one with a two-step
  history and a pick) written, then read back through
  the served resources and routes: each history's steps, the picks, the tags
  and pin, every version's thumbnail, each card `ready`.
