# state

What the user says ABOUT a prototype — pinned, Done, its one tag, deleted —
and the prototypes' tag tree, as rows in the instance's DB. Design:
`research/2026-10-21-global-tag-tree.md` §6.1.

## Mental model

- **Files are host-global; state is per-instance.** The prototype folders
  under `~/.equin/apps/prototypes/` are shared by main and every
  worktree. This state is not: `prototype_state` and `prototype_tags` live in
  the instance's own DB, so a worktree (or an E2E run in it) changes them in
  its DB fork without touching main's. Intended — no agent-write ledger.
- **One row per prototype the user marked** (`prototype_state`, keyed by the
  folder's `proto-…` id). No row = `NO_PROTOTYPE_STATE` (not pinned, not Done,
  untagged, not deleted). A removed folder's row stays (every consumer joins from
  `prototypesList`; a restored folder regains its state) — no cleanup job.
- **Deleted is a field, not a move** (`deletedAt`, `null` while live). The
  folder, its history and picks stay; every link resolves; the readers hide it
  (the gallery lists it in its Trash, the canvas shows "Deleted · Restore").
  `DELETE /api/prototypes/:name` stamps now — a deleted prototype deleted again
  keeps its FIRST instant (`COALESCE`) — and `POST …/restore` clears it. A
  client cannot write the field through the PATCH. Per instance like the rest:
  a delete in a worktree (or its E2E run) never deletes on main, which is why
  there is no agent-write ledger (the file-store era undid an automated
  session's delete through one).
- **One tag per prototype, or none** (`tagId`), out of `prototypeTagTree` — a
  `tag-tree` declaration (`plugins/tag-tree/CLAUDE.md`): `prototype_tags`
  (`prtag-…` ids), served and written through the tag-tree engine's one
  endpoint set (`/api/tag-trees/prototypes/…`). A deleted tag's prototypes
  move to its parent (the `singleTagCarrier` over `tagId`, in the delete's
  transaction; the FK's `ON DELETE SET NULL` is the backstop).

## API

- core: `prototypeTagIdKind`, `prototypeTagsEntityRef`, `prototypeTags`
  (`prototypes.tags.all`), `prototypeTagTree`; `prototypeStateEntityRef`,
  `prototypeStates` (`prototypes.state.all`, the whole set), `PrototypeState`,
  `NO_PROTOTYPE_STATE`, `PrototypeStateChangeSchema`, `setPrototypeState`
  (`PATCH /api/prototypes/:name/state`, body: the fields it sets of `{ done,
  pinned, tagId }`; 404 unless the folder exists — `files`' `prototypeExists`;
  400 for an unknown tag; an upsert of only the given fields);
  `deletePrototype` (`DELETE /api/prototypes/:name`) and `restorePrototype`
  (`POST /api/prototypes/:name/restore`), both 404 unless the folder exists.
- web: `usePrototypeStates()` (`useLive`), `usePrototypeState(name)` (a
  `ResourceResult<PrototypeState>` — pending stays pending, no row reads
  `NO_PROTOTYPE_STATE`), `useSetPrototypeState()`.
- The UI is `gallery`'s (the cards' pin / Done / Delete, the Tag field
  (grouped nested), the Trash pane, the detail header's tag chip, pin, Done and
  Delete / Restore) and `canvas`' deleted notice.
- cli: `readDeletedPrototypes(namespace)` — the deleted ids in that
  instance's DB, for a CLI process with no backend (`read`, or `unavailable`
  with a reason: DB down, never created, or older than the table). A raw `pg`
  query on the database named after the namespace; its table and column names
  are hand-spelled and pinned to the drizzle table by
  `deleted-prototypes.test.ts`. `./equin prototype list` (`commands`) reads it
  for the checkout's own instance, so the terminal hides what that gallery's
  Trash holds.

## The old `_trash/` (main only)

`server/internal/legacy-trash.ts` — the `prototypes.adopt-legacy-trash`
warm-up (`host` scope: main only). An older delete renamed the folder into
`<prototypes>/_trash/<id>/`. Each such folder (a `proto-…` name) is recorded
deleted in main's DB at its ctime (an already-deleted row keeps its instant),
then renamed back; a live folder under the same id throws. Main only, because
the folders are host-global but the state is per instance: whichever DB
adopted a folder would be the only one knowing it was deleted, and that must be
main's (a fork made after inherits the row). Kept while branches with the old
move-to-trash delete may still run against the shared tree.
