# snapshot-history

The prototypes' version history for a host without the computer (the browser
composition): provides `PrototypeHistoryStore` (declared in `files/server`) as
content-addressed snapshots over the `prototypesFiles` root. Base-excluded
(`!apps.prototypes.files.snapshot-history.**`), so no desktop composition boots
it beside `files#machine`'s git store.

Per prototype, `_history/<id>.snapshots/`:

- `log.json` — every version, oldest → newest: kind, subject, body, conversation
  and message ids, time, and `files` (name → sha256 of its bytes). Written
  atomically; it is what makes a version exist.
- `blobs/<sha256>` — each distinct file content, once.
- `latest.json` — `{ n, sha }` of the newest version, the stamp the tree's
  watch classifies as `version-recorded` (any `_history/<id>.<format>/latest.json`).

A version's sha is the sha256 of its parent, time, message and files, so it
addresses the content like a commit and passes `isVersionSha`. Dot-files are
never part of a version. One writer per prototype: the `_history/<id>` lock, the
git store's key. The message fields go through `checkpointMessage`, so a
snapshot version reads like a git one.

Held to the same `describeHistoryContract` (`files/server/testing`) as the git
store, over a memory root (`server/internal/snapshot-store.test.ts`).
