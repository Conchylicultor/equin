# switcher

The desktop's window switcher (mockup `#switcher`), contributed to
`Desktop.Overlay`. ⌘\` opens a panel of snapshots (at most 210×140) of the active
desktop's windows, front-most first (`geo.z` descending; at least two windows),
with the selected window's "App — title" under it. Each press steps the
selection (⌘⇧\` back, wrapping); the first press of the forward key selects the
window behind the front one.

- **Commit**: releasing the modifier (a `keyup` with no meta / ctrl / alt) brings
  the selected window forward, restoring it first if minimised. Clicking a
  snapshot commits that window.
- **Cancel**: Esc (heard in the capture phase so no other Esc binding fires), or
  the window losing focus.

## Shape

- `web/internal/switcher-model.ts` — the pure part: `switcherOrder` and
  `stepIndex` (wrapping step). Tested.
- `web/internal/switcher-controls.ts` — `stepSwitcher`, reaching the overlay's
  session state through an install sink the overlay fills while mounted.
- `web/components/switcher-overlay.tsx` — the session, and the two page-wide key
  listeners that exist only while it is open. They are a sanctioned hatch from
  `shortcuts/no-window-key-listener` (the registry hears keydown only, and a
  modifier's release is the commit): a transient mode that owns the keyboard.
- `web/components/switcher-thumb.tsx` — one window: app tile, title, "N tabs",
  and a `WindowSnapshot` (from `desktop/windows`).

The shortcuts sit in the `"Switching"` group so the launcher (which lists the
`"Window"` / `"Desktop"` groups as commands) does not offer a switcher that has
no modifier held to release. `mod+shift+~` is registered beside `mod+shift+\``
because the registry matches `KeyboardEvent.key`, which is the shifted
character on a US keyboard.
