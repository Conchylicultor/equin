# wallpaper

## What the wallpaper can be

`wallpaperConfig.state.kind` is one of: `builtin` (the default, `id: "elarun"`),
`image` (an uploaded / imported / Openverse image in the server store, below), or
`default` (the legacy theme-gradient state, still rendered as the gradient).

Built-ins are data: `core/builtin.ts` holds the catalog (id, title, creator,
source, sourceUrl, license — the desktop mockup's credits) and
`web/builtin/*.jpg` the bundled pictures, mapped by `builtinWallpaperUrl(id)`.
`id: "gradient"` is the theme-following SVG, reachable as a built-in choice.
The `builtin` sub-plugin is the picker tab; picking writes `{ kind: "builtin", id }`
directly, with no server round trip. "Reset to default" returns to Elarun.
The corner credit (`WallpaperAttribution`) is the mockup's `#wall-credit`.

## Where the image lives

The current wallpaper (the image bytes plus a `current.json` sidecar with its
mime and version) is stored at `wallpaper/` in the desktop app's one data dir,
through a data-files root (`desktopFiles` over `apps/desktop`, declared in the
portable `server/`): the computer's disk on the desktop (`machine/` binds it to
`desktopDir`), memory in a browser host (the `/demo` worker), where an upload
lasts the session. Upload and the image route run on every host; importing an
image from a link is an SSRF-guarded download only the computer's server makes
(`machine/`, `importWallpaperUrl` is `needsMachine`), so the picker says "not
available" for it there. The wallpaper is part of the desktop, not an app of
its own, so it declares no data dir; see `apps-core/CLAUDE.md`.
