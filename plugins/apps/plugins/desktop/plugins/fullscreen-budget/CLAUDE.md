# fullscreen-budget

A work budget on the desktop ↔ full screen switch: how many elements each
switch restyles (Chrome's trace, `UpdateLayoutTree`), for entering and leaving
full screen with one window and with four. The report kind, the verdict and the
commit-range state are `plugins/reports/plugins/interaction-budget`'s.

## Why

A series of fixes cut the switch from ~34k elements restyled (≈ 1–2 s of
forced style recalc) to ~1k enter / ~2k exit. Each regression it had was a jump
of about the document's element count — a custom property written on `<html>`,
the root theme following the focused app, a `:not(.class *)` selector toggled
on a tab, hidden tabs back to `display: none` (per window), icon sprites
rendered — and none is slow enough for the stall report to see.

## How it runs

- `e2e/fullscreen-switch-budget.ts` opens `/demo` maximized at the desktop
  with Sonata (the real app's code on the demo's seeded data, in a worker),
  traces `--rounds` round trips per window count, and judges the warm median
  (round 1 is cold) against `BUDGETS` — ~2× today's numbers, far under one
  whole-document restyle (~18–20k on that page).
- `machine/`: the `desktop.fullscreen-budget` supervised job runs it in main's
  checkout with `--file-reports --commit <sha>`. Main only; enqueued when a
  build run's exit marker lands (`onRunTerminal`) for a successful plain build,
  and at boot for the latest deploy — once per commit (`lock` = commit,
  checked with `latestSupervisedRun`). Not on every push: it needs the deploy
  and a browser (~2 min).
- On demand from any worktree: `./equin run <the script>` against your own
  build; exits 1 while over budget.

To find the cause of a jump:
`plugins/apps/plugins/desktop/plugins/windows/e2e/fullscreen-switch-profile.ts`
(both share `windows/e2e`'s `traceSwitch` / `styleRecalcs`).
