# shelf

The desktop's one bottom shelf: a port of the mockup's `#shelf` in its `dock`
variant (the `prototype-option`s `shelf: dock`, `instances: grouped`). It is a
`Desktop.Overlay` contribution, so it renders only in desktop mode, inside the
desktop's own theme (`app:desktop`).

## Design

- **The shelf is the launcher.** The desktop has no rail and no tab bar, so the
  shelf is where apps start: the launcher button (`toggleLauncher`), the pinned
  apps, then the running apps that are not pinned. A running entry appears with
  its app's first window and leaves with its last.
- **Pinned apps are global config** (`shelfConfig.pinnedApps`, owned by the
  desktop shell's `core/`): the dock belongs to the desktop, so it is the same in
  every app and worktree. The shell registers it on both runtimes; the shelf and
  the launcher's "Keep in dock" both write it — which is why neither owns it (the
  launcher opens from the shelf, so either owner would close an import cycle).
- **A window is filed under its active tab's app.** Windows mix apps, so the
  shelf groups by the app of the tab each window shows. The grouping, the order
  and what a click does are pure functions in `web/internal/shelf-model.ts`,
  tested beside it. The hook in `use-shelf-model.ts` only feeds them live data.
- **Clicks** follow the mockup's `clickGroup` / `activateWindow`. No window opens
  one (a new tab is a new window in this mode). One window is focused, restored,
  or minimised when it is already in front. With several, the first click brings
  the front-most forward and later clicks cycle. Shift-, Alt- and middle-click
  open a new window.
- **The shelf tells the windows where it is**, through two windows-plugin
  channels, so the windows plugin never names the shelf:
  `setWorkAreaReserve(dock height + 16)` keeps maximised and snapped windows off
  the dock, and `setMinimizeTargetResolver` aims a minimising window at its app's
  entry.
- **Popovers are in-layer, menus portal.** The peek (thumbnails, the app-name tip,
  the desktop preview) is drawn in the shelf's own layer and placed from the
  anchor's rect (`ShelfPopover`). That keeps it in the desktop's stacking order
  and theme. The app and desktop menus are `CursorAnchoredMenu`s opened 10px
  above their element, and they wear the desktop theme through the portal
  forward.
- **Snapshots are taken on every show.** The peek is keyed by its target, so each
  hover mounts fresh `WindowSnapshot`s. Nothing is cached.
- **The clock is a clock, not polling.** `useMinuteClock` re-arms a timeout at
  each minute boundary.
- **Mockup literals.** Lengths the spacing ramp or the radius scale cannot spell
  (the dock's 6px padding, the 5px pager gap, the pips' 3px) are kept as
  arbitrary values, each with a named disable. Radii take the nearest
  `--radius` step instead: dock `3xl`, tiles `xl`, peek `2xl`, thumbnails `xl`
  and `md`. They track the desktop theme's shape that way.
