# explorer

Sidebar entry and filterable tree pane for browsing and inspecting the plugin tree. Shows
the full plugin tree with stats; selecting a plugin opens the plugin-view
detail pane as the adjacent Miller column. No server component — data is
served by the plugin-meta/plugin-view plugin.

Expand state is the `data-view` primitive's own per-view-instance map, with
`defaultExpanded: true` so the tree opens fully on first paint while a user
collapse still wins and survives reload. The former `PluginTreeContext`, which
shared a hand-rolled `Set` of expanded ids with the row-badge sub-plugins, is
**deleted**: a badge that needs expand state reads
`useOptionalTreeContext()` from the `tree` primitive instead. That also
fixes a seeding bug the local `useState` had: its lazy initializer never
re-ran, so plugins arriving after first mount stayed collapsed.

The fold/unfold-this-subtree button is not the explorer's to ship either: the
`tree` primitive renders it on every row that has children, so the
`expand-collapse` sub-plugin that contributed it as a badge is **deleted**.
