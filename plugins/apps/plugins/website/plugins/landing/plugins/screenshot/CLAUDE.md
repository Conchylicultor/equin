# screenshot

The homepage's live demo, in the band where the drawn desktop picture was
(the plugin keeps its old name; its section is labelled Demo): equin itself —
its real server code in a worker, on the workspace demo's data
(`apps/website/demos/workspace`) — as `<DemoScope>` around `<AppEmbed>`,
opening on its home app.

- **Downloaded on demand.** Nothing downloads until the visitor clicks Enter
  equin (`DemoScope`'s gate, drawn by `apps/demo/chrome`'s boot screen),
  shown on every visit; a browser that already holds the demo's data starts
  the host behind it, so entering is instant. While it starts, the boot
  screen's bar shows the worker's progress.
- **Entering grows the frame in place, for good** — out of the reading
  measure, nearly as wide and as tall as the window, the page below moving
  down and scrolling to it; never a layer above the site. There is no
  Collapse. Its sizes are measured
  (`useElementSize` on the measure) so the growth animates between lengths.
- **Once it runs**, the row under it offers Maximize (the demo grows over the
  tab's surface, above the site, through a `SurfaceOverlay` —
  `apps/demo/chrome`'s `morphDemoFrame`, and its `MaximizedChrome`: Restore at
  the top edge, the Esc notice, Esc) and Reset demo.
- **Its place is the homepage's URL** (`web/internal/demo-place.ts`): the
  embed's location and whether it is maximized are two surface view keys of
  the landing pane (`;view.website.demo=…;view.website.demo.full=1`), so a
  reload comes back there — /demo's rule: framed, moves rewrite the current
  entry; maximized, they are the tab's history (`usePaneViewParam`'s `set(v,
  "push")`); Maximize / Restore are pushed steps. A new browser tab opened
  from inside opens this page there, maximized.
- The frame's paint follows the site's theme tokens, as every website
  component does; the boot screen's colours are the logo's (`ui/logo`).

- **The standalone site ships it too.** The `website` composition bundles
  only the demo's scenario (`demos/workspace`'s `core`); the demo's page scope
  is its web registry's on-demand entries, loaded on Enter beside the worker
  and visible only inside the scope, so the site's own boot and backend are
  unchanged (`research/2026-11-10-global-website-composition-carries-live-demo.md`).

`e2e/live-demo.ts` drives a first visit: the gate (nothing of the host
requested before it), the growth, the running demo, its place in the URL,
Maximize (view transition, notice) / Esc / Back / Restore, and a reload (the
gate again, the host behind it, back on the same place), with screenshots.
