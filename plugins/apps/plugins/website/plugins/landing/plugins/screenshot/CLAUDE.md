The homepage's live demo band, where the drawn desktop picture was (the
plugin keeps its old name; its section is labelled Demo): a frame the band
claims for the live demo (`apps/website/live-demo`'s `DemoTarget`) — the
demo's server is the site's resident, so it outlives the page.

- **Downloaded on demand.** Nothing downloads until the visitor clicks Enter
  equin (the gate, drawn by `landing/screenshot/chrome`'s boot screen), shown on every
  visit; a browser that already holds the demo's data starts the host behind
  it, so entering is instant.
- **Entering grows the frame in place, for good** — out of the reading
  measure, nearly as wide and as tall as the window, the page below moving
  down and scrolling to it. There is no Collapse. Its sizes are measured
  (`useElementSize` on the measure) so the growth animates between lengths.
- **Once it runs**, the row under it offers Maximize (the demo page,
  `/about/demo` — see `live-demo`) and Reset demo.
- **The homepage's URL never names the demo.** Where the visitor is inside
  the framed demo is kept in memory; coming back from the demo page (Back to
  equin, the browser's Back) shows the frame grown, at that place, scrolled to it.
- The frame's paint follows the site's theme tokens, as every website
  component does; the boot screen's colours are the logo's (`ui/logo`).

- **The standalone site ships it too.** The `website` composition bundles
  only the demo's scenario (`demos/workspace`'s `core`); the demo's page scope
  is its web registry's on-demand entries, loaded on Enter beside the worker
  and visible only inside the scope, so the site's own boot and backend are
  unchanged (`research/2026-11-10-global-website-composition-carries-live-demo.md`).

`e2e/live-demo.ts` drives a first visit: the gate (nothing of the host
requested before it), the growth, the running demo, the URL staying `/about`,
Maximize onto the demo page (view transition, nothing of the homepage
mounted, the same server, the draggable Back to equin pill; Esc stays) /
Back to equin / the browser's Back, a reload (the gate
again), the demo page loaded fresh (no gate, no hero film) and a second tab
joining it, with screenshots.

`e2e/home-load.ts` measures what a phone pays for the homepage before any
click (FCP, LCP, TBT, TTI, bytes, what finished before the first paint),
cold and on a repeat visit, over the same shaped link as `e2e/enter-cost.ts`
(`e2e/internal/shaper.ts`) with Chrome's CPU throttled 4×.

## Did the demo leak? — one rule, every script

The demo runs in the page's own document, so a page-origin `/api` request's
URL cannot say who sent it: the page's chrome (Full screen, Reset demo, the
video player, Copy address, an icon it draws) legitimately reads the page's
server; code inside `<DemoScope>` must never. Every demo script checks the
same rule through `e2e/internal/page-origin.ts` — `watchPageOrigin(page, r)`,
then `finish()` while the demo shows. No script keeps its own allow-list or a
"page chrome" time window.

- **Attributed by its issuer.** Every request the page transport sends carries
  `X-Equin-Issuer` (`primitives/networking`'s request issuer, ignored by the
  server): `page`, or `scope:<id>` when it was issued from inside a scope that
  names itself (`DemoScope` mounts `RequestIssuerScope`; a page transport
  provided inside it stamps the scope). The head scripts' t0 fetches stamp
  `page` too. An element's load (an image, a video, a font) is attributed by
  the element holding its URL: inside the embed or the scope's theme
  boundaries is the demo's, elsewhere the page's.
- **The verdicts** (`finish()`): telemetry (D3's routes) and the page's own
  chrome are logged as notes, never failed. `REAL LEAK` — a request issued
  from inside the scope, or an icon inside the embed drawn from the page's
  glyph sheet (a `#msr-` / `#lucide-` id: the scope's store prefixes its own)
  — fails, and is a real bug. A request nothing attributes fails as
  **unattributed**, which says "NOT a confirmed leak": make the channel that
  sent it name its issuer; never allow-list it.
- An agent seeing `the page's own chrome, not a leak` in a run's notes has
  nothing to report.
