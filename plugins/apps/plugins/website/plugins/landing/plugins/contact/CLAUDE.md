# contact

The homepage's closing band: two cards, one per reader — a message form for
anyone who wants to support the vision, and GitHub issues for anyone with a bug
report, a feature request or a question. The two lead to two DIFFERENT places.

## The first card — the address and the form

Prototype `proto-1788797350-gqju`, variant `contact: expand`.

- **The address is in the sentence** ("Write to hello@equin.ai.") — a `mailto:`
  link with a copy icon (`primitives/copy-to-clipboard`) that appears on hover
  or keyboard focus just past the full stop, placed outside the text's box so
  it takes no room at rest (`mail-address.tsx`). The address itself is the
  shell's `CONTACT_EMAIL` (`shell/core/site.ts`).
- **"Get in touch" grows the card into the form, in place** — the button folds
  away as the form folds in (two `FoldMotion`s from `primitives/collapsible`,
  so only the card's bottom edge moves; no bespoke height animation). Once the
  form has settled (`FoldMotion`'s `onOpened`) the page scrolls just enough to
  bring Send into view (`revealElement`, `block: "nearest"`).
- **The form** (`contact-reach.tsx`): a message and an email, Cancel and Send.
  Send is enabled only for a message and a valid address — the server's own
  schema fields (`internal/draft.ts`). ⌘/Ctrl+Enter clicks Send (so it pends
  like a click); Esc closes and returns focus to "Get in touch". The draft
  survives closing.
- **Abuse signals** the server reads: a visually hidden `website` honeypot
  (`tabIndex=-1`, `autocomplete=off`, `aria-hidden`) and `elapsedMs` since the
  form (or "Send another") opened. Nothing else is decided client-side.
- **States**: Send auto-pends (`Button`); `sent` folds the form into "Message
  sent — Thanks, a copy is on its way to <email>, and we'll reply there" (the
  intake's confirmation email) with "Send another"; `rate-limited`
  and a failed request are said inline under the fields, the typed text kept.
  A message is never lost silently.

The backend is `apps/deploy/site-messages/intake`, reached through its `web`
barrel's `useSendSiteMessage()` — importing the web barrel is what puts the
intake's server half (endpoint, table, notify job) in the website's
composition. The site's own server stores the message, emails it on through
Resend, and emails the visitor a copy — see its CLAUDE.md.

## The second card

GitHub issues, opening beside the site. The header's Improve button is not a
form either: it hands the visitor's idea off to GitHub as a prefilled issue.
