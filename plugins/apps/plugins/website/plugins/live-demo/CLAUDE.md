# live-demo

The website's live demo runtime: equin itself — its real server code in a
worker, on the workspace demo's data (`apps/website/demos/workspace`) — as
`<DemoScope>` around `<AppEmbed>`, kept for the whole visit and drawn on
whichever page asks for it. Design:
`research/2026-11-15-apps-website-demo-page-not-overlay.md`.

**A URL names one screen.**

- `/about` — the homepage, the demo framed in its band
  (`landing/screenshot`). Moving inside the framed demo never touches the
  URL: its place is kept in memory, and a reload shows the gate again.
- `/about/demo` — the demo alone, filling the page; nothing of the homepage
  is mounted (no hero film, no bands). Its place is the page's embed tail
  (`/about/demo/at/agents/c/x`, `demoPagePath`), each move a history entry,
  so Back walks the demo's moves, then leaves. Restore (the top edge), Esc
  and the notice are `landing/screenshot/chrome`'s `MaximizedChrome`.
- Maximize (under the frame) opens the demo page where the visitor is;
  Restore / Esc go back to `/about`, scrolled to the frame. Both run as
  `morphDemoFrame`'s view transition (a `flushSync` navigation).
- A new browser tab opened from inside the demo, framed or not, opens the
  demo page there.

**The server outlives the page switch.** `DemoScope` unmounting would retire
the worker, so the scope is not in either page: `DemoResident`, a
`Website.Resident` (the site's surface, kept across pages), mounts it the
first time a page claims the demo and keeps it for the visit. A page claims
it with `<DemoTarget kind="framed" | "page">` (a layout effect, so the claim
lands inside the morph's `flushSync`); the resident portals the boot screen
or the running demo into that box. A site page with no target draws no demo
and starts no worker; one visited after the demo keeps the server running.
Moving between the two boxes remounts the embed (a new portal container),
which reopens at its binding's place — `AppEmbed`'s `place` prop: memory for
the frame, the pane's embed tail for the page.

The state for the visit (current target, controls row, entered, place, the
return to the frame) is module state in `web/internal/demo-store.ts`.

`landing/screenshot/e2e/live-demo.ts` drives the whole flow.
