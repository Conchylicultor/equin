# circle

**Circle**, the P2P messaging app the showcase film's user asks for. The film
makes its prototype (`proto-1792779833-4wgtuf`, the seed's fixture), the user
says "Good, implement it", and Circle appears in Home. This plugin is the
film's stand-in for that implementation: an app entry (`/circle`) whose one
page is the prototype, framed full surface in its light theme.

- **In the `promo-film` composition only.** Every other composition inherits
  the default exclusion set, `all-exclusions`, which carries
  `!apps.website.promo-film.circle` (and the seed); `promo-film` names the
  narrower `base-exclusions` in its `exclusions` field, so it is the one
  composition that ships Circle. Main's registries never list it. See
  [`composition`](../../../../../../../plugin-meta/plugins/composition/CLAUDE.md)'s
  exclusion sets.
- **Hidden until "implement it".** The committed app layout
  (`config/apps-core/app.jsonc`) is main's and does not name Circle; the
  film's seed writes the promo-film instance's own (user layer) with Circle
  placed after Browser and hidden (the layout's own `hidden` flag), and the
  "implement it" time-lapse drops the flag — the Config pane's own write, the
  seed's `filmAppLayout` — so the tile appears in Home after Browser. No
  setting of its own: hiding an app from the launchers is what the layout
  already does.
- **Why a composition exclusion, not a launcher setting.** A launcher-only
  hide would still ship Circle's code, entry and URL in main and in every
  composition built from `**`. An inherited exclusion takes it out of their
  bundles, and a composition takes it back by choosing a narrower exclusion
  set — a negative a `**` row cannot otherwise contradict (`composition-closure`
  refuses a named positive against an inherited negative).
