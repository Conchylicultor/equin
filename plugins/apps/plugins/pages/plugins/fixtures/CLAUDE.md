# fixtures

Pages' fixture format and its writer: "some pages", in Pages' own terms, written
through the app's real write path — for a demo's seed or a test. The format is
the app's; the data is never here (a demo owns its own pages — e.g.
`apps/website/demos/lumen`). Design:
`research/2026-10-28-global-per-app-demo-seeds-v2.md` §2.

- **`core`: `PageTreeFixture`** — the workspace's root pages in sidebar order,
  each a `PageFixture` (caller-chosen `id`, `title`, optional `tags`
  `{ name, color }` and `starred`, `children` in document order) whose
  children are content blocks (`text` / `heading-2` / `prompt` / `to-do`) or
  sub-pages. Ids are the caller's, so a fixture can name its own pages in its
  text (`pageLinkToken`) or from other data (the prompt block a task was
  launched from). `fixturePages(tree)` lists every page in document order.
- **`server`: `writePageTree(tree)`** writes the whole forest in ONE
  `applyPageBlockPatch(null, …)` at the workspace root (the editor's sanctioned
  forest write, which emits `blocksChanged` for every page it creates), then
  each page's tags (`resolveTagNames`, creating a missing name with the
  fixture's colour, then `writeResolvedPageTags`) and star (`setPageStarred`).
- **It derives nothing.** The backlinks edges, the search documents and the
  history snapshots are the `blocksChanged` consumers' (`page/links`,
  `pages/content-search`, `pages/history`), run as jobs once the host's
  triggers are live — a browser host seeds after its post-ready phases. Never
  add a `reindexPage` / `reindexPageSearch` call here: a caller that needs the
  derivations in place before it goes on settles the queue
  (`settleJobQueue`, `infra/jobs/in-process`), which also fast-forwards the
  history's 4 s debounce.
- **Portable** (`server` is `portable: true`), so it joins a browser host's
  graph through the seed's import. Its test
  (`server/internal/write-page-tree.test.ts`) boots the writer's closure plus
  those consumers through `bootBrowserHost` on PGlite, writes a small tree,
  settles, and reads back the backlinks edge, the search docs, a snapshot per
  page, the tags and the star.
- **Growing it**: a new content-block kind is a new arm of `PageFixtureBlock`
  and of the writer's row mapping; keep the format pure data, the write path
  the editor's.
