# musicxml

`shared/parse.ts` is the one reader (`parseMusicXml` / `parseMusicXmlDocument`),
pure TS over `fast-xml-parser` so the web compile, the import button and the
server share it. Its header lists what maps to what and what is ignored;
anything that would change the timing and that the Score cannot represent
(timewise documents, D.C./D.S. jumps, unmetered time, microtones, a swing change
mid-piece, functional chord kinds, …) throws a `MusicXmlParseError` naming the
element, the measure and the part.

Two ways a document reaches a song, both funnelled through one writer
(`server/internal/import.ts`):

- **Library import** (`Import MusicXML` in the "+" menu): the browser parses to
  fail early, uploads the file and POSTs the attachment id; the server re-reads
  it, derives the metadata and dedupes by the document's content hash.
- **`importMusicXmlForSong({ songId, xml, fileName })`** (server barrel): fills
  an EXISTING song created with the `musicxml` source — the transcription flow
  creates the song before its score exists. Throws on a parse error before
  writing anything.

Swing (`meta.swing`) is read here but applied at playback only — see
`score/core/swing.ts`.

Creates MusicXML-backed songs from an uploaded document (content-hash dedup) and fills an existing MusicXML song with a document (importMusicXmlForSong, for the transcription flow).
