# midi

The track count reaches the library as a field its extension EXPOSES, not a
per-card widget: the shape (`songMidiShape`, `core/shape.ts` — public, so the
`folders` sub-plugin can present a field of it) exposes two fields of the
songs entity to every list of songs:

- `trackCount` — "Tracks"; filterable, sortable; no default, so a non-MIDI
  song reads `null` and its cell (`web/internal/presentation.tsx`) renders
  nothing — the shared card stays source-agnostic;
- `sourceMissing` — "File"; filterable, sortable; declares its default
  (`false`, the column's too), which a song with no MIDI row reads. Its "File
  missing" badge is the `folders` sub-plugin's presentation of it.

The server folds the extension (`LiveColumns.Expose(songMidi)`; the
server-only `contentHash` is no wire column, so it is never exposed). Every
library row carries them under `$columns.sonata_songs_ext_midi`. One song's
MIDI for playback is the `getSongMidi` endpoint.

## Plugin reference

- Description: MIDI file input source for Sonata. Dropzone accepts .mid/.midi files; compile() parses them into a Score via @tonejs/midi. Persists per-song MIDI (attachment + track count) and contributes the library Import affordance, hydration, and the cell of the Tracks field its extension exposes on every list of songs. Owns the sonata_songs_ext_midi side-table: per-song MIDI attachment + track count. Creates MIDI-backed songs, exposes its track count and file-missing flag to every list of songs (LiveColumns.Expose), and seeds the bundled public-domain MIDI starters at boot.
