# fixtures

Sonata's fixture format and its writer: "some songs", in Sonata's own terms,
written through each source's real write path — for a demo's seed or a test.
The format is the app's; the data is never here (a demo owns its own songs —
e.g. `apps/website/demos/workspace`). Same shape as `apps/pages/fixtures`.

- **`core`: `SongFixture`** — one arm per source a fixture can author, each
  with a caller-chosen `id` (a `song-…` id, parsed on write), `title` and
  `composer`: a chord grid (`chordText` in the chord-grid mini-language —
  exactly what a user types in the grid editor), a MIDI file (`bytes`) or a
  MusicXML score (`xml`) — exactly what a user imports.
- **`server`: `writeSongFixtures(songs)`** writes each through its source's
  real write: a grid through its create write (`createChordGridSongRow`),
  measured the way the editor does before creating one (the compiled score's
  end beat, `chord-grid/core`'s `compile`); a file by creating the song row
  under the fixture's id and filling it the way the source fills an existing
  song (`importMidiSong`'s re-import, `importMusicXmlForSong`), then naming it
  as the fixture does.
- **It derives nothing else**, and it is **portable**: it joins a browser
  host's graph through the seed's import.
- The MIDI starters are not a fixture: the MIDI source seeds them itself, on
  every host, as a fresh install has them.

## Plugin reference

- Description: Sonata fixtures, server half: writeSongFixtures writes SongFixtures through each source's real write path — a chord grid through the chord-grid source's create write (measured as the editor does), a MIDI or MusicXML file through its source's import into a song created under the fixture's id.
