# fixtures

Sonata's fixture format and its writer: "some songs", in Sonata's own terms,
written through each source's real write path — for a demo's seed or a test.
The format is the app's; the data is never here (a demo owns its own songs —
e.g. `apps/website/demos/lumen`). Same shape as `apps/pages/fixtures`.

- **`core`: `SongFixture`** — one arm per source a fixture can author. Today a
  chord grid: caller-chosen `id` (a `song-…` id, parsed on write), `title`,
  `composer`, and `chordText` in the chord-grid mini-language — exactly what a
  user types in the grid editor.
- **`server`: `writeSongFixtures(songs)`** writes each through its source's
  create write (`createChordGridSongRow`, the create route's write), measuring
  a grid's length the way the editor does before creating one (the compiled
  score's end beat, `chord-grid/core`'s `compile`).
- **It derives nothing else**, and it is **portable**: it joins a browser
  host's graph through the seed's import.
- The MIDI starters are not a fixture: the MIDI source seeds them itself, on
  every host, as a fresh install has them.
