# piano-roll

## The drawn axis (show loop ahead)

The roll draws an AXIS score, not necessarily the song: with an A–B loop
enabled and the session's `loopOptions.ahead` on, it draws
`unrollLoop(score, session.loopCycle)` (score/core) — the song up to B, then
the loop's own repeats, each opened by its rest — so past B the falling notes
are what will really play next, and during a repeat the song before A never
shows. Every renderer stays loop-agnostic: the visuals, bar lines, onset
tracker and overlays all take the axis score, the cursor is placed at its axis
beat (`timeline.axisBeat(cursor.getPosition())`, also what FX read as
`getPlaybackBeats`), and wheel / drag seeks map an axis beat back to the play
position shown there (`timeline.at`). The projection publishes the timeline
(`Projection.timeline`) for transport overlays. Without the option the axis is
the song itself; a rest then parks the cursor on A (the roll holds still for a
bar).

## Render on demand

The Pixi app is created with `autoStart: false`: the ticker runs only while
something can change the picture, so an idle (paused, settled) roll draws no
frames at all. The contract lives in `web/internal/pixi/render-scheduler.ts`:

- **Every `PianoRollScene` mutator requests a frame** (`setScroll`, `resize`,
  `setScore`, `setLook`, `setSpread`, `setShowLabels`, `refreshColors`, `reset`,
  and every note-on). A new scene mutator must call the scheduler's `request()`.
  The cursor store reaches the scene only through `setScroll`, so each cursor
  change (playback, scrub, wheel, inertia) wakes a frame; playback keeps the
  loop alive by requesting every frame, and it stops one frame after the last
  request.
- **FX declare animation, they do not tick.** `FxContext.onFrame(update)`
  replaces the old shared `ticker`: `update(dtSec)` returns whether the effect
  is still animating (`emitter.liveCount() > 0`, an active comet, ...). The loop
  lives exactly while any updater returns true. Note-ons and resets wake the
  loop before the updater next runs, so an effect spawned from `onNoteOn` is
  never starved; effects driven by the playback cursor (fx-core's brighten)
  must NOT return true for it — the cursor wakes them.
- Context loss calls `scene.halt()`; requests after that are ignored.
- Updaters only see time while frames run, so wall-clock they accumulate does
  not advance during idle gaps.
