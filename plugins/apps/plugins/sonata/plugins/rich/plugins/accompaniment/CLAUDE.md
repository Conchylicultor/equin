# accompaniment

The Sonata **Accompaniment** section: one `Sonata.Section` (`id:
"accompaniment"`, player area) composing the three accompaniment parts, top to
bottom — chord-mode's "Play the detected chords" row, a rule, then EITHER the
groove body (`RhythmControls`, while the groove is on) OR the block-chord
voicing rows (`VoicingControls`, while it is off). The groove's
on/off switch (`GrooveSwitch`) sits in the section header, so it stays
reachable while the section is collapsed.

## Design

- **A fixed composite, not an open set.** The parts are named imports from
  their own barrels (`chord-mode`, `rhythm-controls`, `voicing-controls`); no
  slot. Each part renders no chrome and no gate of its own.
- **This plugin owns the gates.** The chord-mode row shows while
  `useChordModeAvailable()`; the groove and voicing parts while the song
  document voices chords (`useHasVoicedChords()`). The section is available
  when either holds — both hooks are called unconditionally.
- **Groove or voicing rows, never both.** With the groove on, each hand of the
  groove carries its own octave and voice-leading (the hand blocks), and the
  global voicing config does nothing; with it off, the chords are block chords
  voiced by that global config. So the body shows the groove (on, or not known
  yet — the body's loading / error state) or the voicing rows (known off, or a
  file document, which has no groove) — never two Octave controls of which one
  is dead.
