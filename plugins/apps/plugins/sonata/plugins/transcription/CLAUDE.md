# transcription

Sonata transcription (design: `research/2026-10-13-global-agent-workspaces-and-sonata-transcription.md`
§4): an agent you can watch turns sheet music in a video, photos or a PDF into a MusicXML song.

## The flow

1. **Transcribe…** (library "+" menu, `web/components/transcribe-dialog.tsx`): a link, or page images
   / PDFs uploaded as attachments → `POST /api/sonata/transcribe`.
2. The handler (`server/internal/routes.ts`) creates the song (`musicxml` source, placeholder title),
   its `sonata_songs_ext_transcription` row (`status`, `input`, `taskId`, `conversationId`, `error`), a
   task in the **Sonata** category, and launches the agent (`launch.ts`) with
   `workspace: { kind: "scratch", profile: "sonata.transcription", input: { songId, source } }`.
3. The profile (`profile.ts`) writes the agent's CLAUDE.md (`instructions.ts` — THE product: the
   render → side-by-side → fix loop and the MusicXML conventions), waits for `transcriptionDep`
   (`dep-ready.ts`: `requestDep` + `onDepInstallSettled`, since the spawn job has no `ExecContext`),
   writes `./bin/st` (the checkout's `bin/st` with `ST_PYTHON` set) and copies uploads to
   `input/NN-<name>`. The agent sees only `sonata_submit_transcription`, `exit_clean` and
   `flag_raise`.
4. `sonata_submit_transcription({ path })` (`mcp-tool.ts` / `submit.ts`): the song comes from the
   conversation's workspace spec, never from the agent; `path` must resolve inside the workspace
   (symlinks included, `workspace-file.ts`); `importMusicXmlForSong` — a `MusicXmlParseError` goes
   back to the agent as the tool's error — then status `ready` and `recordScratchDelivery` (tasks-core's
   `attempt_deliveries` fact, which counts like a push). The agent then calls `exit_clean`.
5. A conversation closed (`done`) while still transcribing marks the song `failed`
   (`conversation-ended.ts`, on `conversation.statusChanged`); **Retry** relaunches on the same
   task and song.

Every status write stamps the song row (`updateSongMeta`), which is what re-hydrates an open player.
The browser reads the run state as the library's `transcription` columns (`core/columns.ts`): the
card badge (`Library.Fields`) and the player's pending body (`Library.Source` `hydrate` →
`pending` with `TranscriptionBody`, which reads the song row live) — Open conversation, error, Retry.

The task derives `done` from the delivery fact once the conversation closes (`exit_clean`): a
scratch attempt never pushes, so the delivery is its "completed" evidence.

## The `st` toolkit

- **Dep**: `transcriptionDep` (id `sonata-transcription`, `deps/`), a `pythonEnv` over `python/`.
  `bin/st` runs with `ST_PYTHON=<ready.dir>/bin/python`; the profile writes the agent a `./bin/st`
  wrapper setting it. The source runs from the checkout (PYTHONPATH), the env is shared.
- **Contract**: each subcommand is deterministic, prints a short summary of what it wrote, and on an
  expected failure exits 1 with one `st: <reason>` line on stderr (no traceback).

| command | does |
|---|---|
| `st fetch <url> --out <dir> [--cookies-from-browser <b>]` | `<dir>/video.mp4` + `meta.json` (title, caption, uploader, duration) via yt-dlp |
| `st frames <video> --out <dir> [--region x,y,w,h] [--threshold N]` | finds the sheet band (stable, bright, high-contrast rows), keeps a crop whenever it changes: `NN.png`, `thumbnail.png`, `frames.json` |
| `st pages <pdf> --out <dir> [--scale 2]` | `NN.png` per PDF page |
| `st render <score.musicxml> --out <dir>` | verovio → SVG → `NN.png` per page |
| `st side-by-side <a.png> <b.png> --out <c.png>` | `a` stacked over `b` |

Manual check: `scripts/smoke.sh` (needs the dep installed).

## Plugin reference

- Description: Sonata transcription in the library: a 'Transcribe…' entry in the + menu (a video/post link, or page images and PDFs) that creates the song and starts the transcribing agent; a transcribed song shows its live run state in the player until the score is in (Open conversation, and the error + Retry when it failed); and a Transcribing / Failed badge on its card. Owns the sonata_songs_ext_transcription side-table: a transcribed song's run state (status, input, task, latest conversation, error). POST transcribe creates the song (MusicXML source), a Sonata task and a transcribing agent in a `sonata.transcription` scratch workspace (CLAUDE.md = the instructions, ./bin/st = the toolkit); its sonata_submit_transcription MCP tool imports the agent's MusicXML into the song. Serves the library's `transcription` columns; a conversation closed before submitting marks the song failed (retry relaunches).
