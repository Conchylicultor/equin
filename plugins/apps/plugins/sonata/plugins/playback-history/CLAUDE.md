# playback-history

Play stats reach the library as fields the extension EXPOSES — one
projection, so the card, the table column, the Sort pill and the Filter pill
can't disagree. `playCount`'s cell (`web/internal/presentation.tsx`) says
"3 plays" / "Not played yet"; that sentence therefore shows in the TABLE's
Plays column too, which is deliberate.

The stats are fields of every list of songs, not a side read: the extension
shape (`shared/shape.ts`, the server table is built from it) exposes
`playCount` ("Plays") and `lastPlayedAt` ("Last played") on the songs entity,
both filterable and sortable, and the server folds the extension
(`LiveColumns.Expose(songPlayback)`). Every library row carries them under
`$columns.sonata_songs_ext_playback`, and the library sorts and filters by them
on the server. `playCount` declares its default (0, the column's too), read for
a song never played (the join `COALESCE`s it), so "Unplayed" (`playCount = 0`)
and "Most played" keep their meaning; `lastPlayedAt` has none, so it is null
until the first play and sorts last. A recorded play
(`POST /api/sonata/songs/:id/play`) refills exactly that song in the library
tuples that read the join.
