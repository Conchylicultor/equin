# demo

**Temporary.** A sandbox app at `/demo` that hosts the in-app demo while it is
prototyped: equin rendered in-process on made-up data, starting on its Home
(the app gallery) — `<DemoScope scenario={workspaceDemo}>`
(`framework/browser-server/demo/scope`) around `<AppEmbed>`
(`apps-core/app-embed`).

**Its location is the page's URL** (`shell`'s routes): `/demo` settles on
`/demo/at/<location>` — the embed's app-rooted URL, `/demo/at/agents/c/<id>`,
`/demo/at/desktop/sonata` — rewritten in place as the visitor moves (one pane
instance, history replaced, the embed never remounting), so a reload comes
back there. `;full=1` is the same place maximized: the embed is the whole
page, no caption bar (the caption's Maximize button; Restore is
revealed by the pointer at the page's top edge). A new browser tab opened from
inside (⌘/middle-click, Open in a new tab) opens `/demo/at/<there>;full=1` —
the demo, never the real app, joining the same data through the demo's
SharedWorker. Reset sends the resetting tab back to the start. Only the
focused desktop window's place is kept in the URL.

Every live read and endpoint call inside the scope is answered by the scenario's browser worker (the
`agent-manager-demo` composition's portable server barrels over PGlite), or is
`needsMachine` and renders its unavailable state.

The website's homepage now carries the same demo in its landing band
(`apps/website/landing/screenshot`); `/demo` stays as the demo's own page.
Both open on a gate (`DemoScope`'s `boot`, drawn by
[`chrome`](plugins/chrome/CLAUDE.md)): a first visit downloads nothing until
Enter equin; a browser already holding the demo's data starts it at once (and
`/demo`'s head start runs only then). The gate is asked once per visit, which lasts
while the visitor is in the demo in any tab of this browser: a tab opened
meanwhile (a link from inside opened in a new tab) joins with no gate (a
shared Web Lock per scenario, `DemoScope`'s `internal/presence.ts`). The gate
is drawn where the demo will be: maximized when the URL is (`;full=1`).

**Sealed.** Nothing inside the scope reaches the real server: there is no
transportless fetcher (every call goes through the scope's transport), and the
build's coverage guard (codegen's `browser-host-coverage.ts`) fails when the
scope uses a read or endpoint its worker cannot answer
(`research/2026-10-22-global-demo-scope-sealed.md`). Only the page's own
telemetry (logs, latency samples, crash reports, …) still goes to the page's
server, a sanctioned exception. `e2e/no-leak.ts` drives the demo's write
affordances (new task, title edit, prerequisite, launch options, image paste, a
send) and asserts no other `/api` request left the page and no row landed in
this deploy's database:
`./equin run plugins/apps/plugins/demo/e2e/no-leak.ts`. `e2e/location-in-demo.ts`
covers the start on Home, a reload, a ⌘-click new tab and the full-screen switch. `e2e/tips-in-demo.ts` covers the
first-time tips inside the demo (Switch apps, Leave the desktop): shown once,
remembered in the demo's worker, never a `/api/hints` request to the page. The
other scripts answer any tip as it shows (`bootDemo` →
`hints/e2e`'s `answerTipsAsTheyShow`).

- [`shell`](plugins/shell/CLAUDE.md) — the app entry and its one page.
- [`chrome`](plugins/chrome/CLAUDE.md) — the boot screen (gate and progress bar), Restore and Reset, shared with the website.
