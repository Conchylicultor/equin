# tour

Home's onboarding tour, on the `hints` engine (`plugins/hints/CLAUDE.md`).
Declared here, not in `app-cards`, so the gallery stays tour-free; every
element it points at is an anchor exported by the core of the plugin that
owns it (`home/app-cards`, `shell/global-action-bar`, `improve`,
`conversations-view/data-view`). Copy follows the onboarding mockup
(`proto-1792668692-5ijcs8`, "tour" direction, first prompt "daylight").

Steps: welcome → `apps` (gallery) → `bar` (toolbar: floating, "folded into
this dot", advancing on hover; docked, always open, so plain copy and Next) →
`improve` ("Try it" = `openImprove({ seed: FIRST_PROMPT })`, which seeds only
an empty draft; clicking the real Improve button is the same move —
`advanceOn: "anchor-click"` runs "Try it" on the popover the click opened) →
`ask` (the open popover, Send cued; `improveSent` stores the task id and goes
to `agents`; closing unsent — a click elsewhere, Esc, Cancel — goes back to
`improve`) →
`agents` (Agent Manager tile; Back → `improve`) → `handoff` (in the Agent
Manager, on the request's conversation row; no Back; clicking the row ends
the tour — its run skips opening the row on `ctl.via === "anchor"`, the
row's own click already did).

Two pieces of the tour's data are known only to the page, each written by a
`Core.Root` tracker of this plugin with `setTourData`:

- **`barFloating`** — `ActionBarTracker` reads `useActionBarPinned()`
  (`shell/global-action-bar`) for the whole run (the surface mode can change
  mid-tour). The `bar` step's copy and its data-dependent `advanceOn` read it.
- **`conversationId` / `ready`** — `HandoffTracker` reads `useTourRun(homeTour)`
  and, only on `agents` / `handoff` with a task id, resolves the task's live
  conversation through `useConversations()`.

"Open Agent Manager" goes on to `handoff` whenever a request was sent
(`taskId`); without one the tour ends at `agents`. The launch is asynchronous
(and with auto-start off never comes), so until the conversation exists the
handoff's anchor is `null`: the card waits centered ("the agent is starting on
it"), offering Finish tour, then moves onto the row once it appears.

## Plugin reference

- Description: Home's onboarding tour (Hints.Tour, primary, auto-started once): the welcome card, then the app gallery, the toolbar (hover to unfold while it floats; Next while docked), Improve — 'Try it' opens it with a first request filled in, sending moves on — the Agent Manager tile, and inside the Agent Manager the row of the conversation that request started ('Here's your request' / 'Your request is ready' → Open it). Until that conversation exists the handoff card waits centered, with Finish tour. Two Core.Root trackers feed the tour page-only data: the request's conversation (from the filed task, while the tour is near it) and whether the toolbar floats or is docked.
