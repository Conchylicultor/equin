# isle

Isle — the island launcher (plan: `research/2026-11-13-home-island-gallery-v2.md`). Every installed
app is a building on an illustrated archipelago you walk around.

Phases 1–3 are in: the pure core, the shell / plots / renderer / world view, and the 14 bespoke buildings
(each in its own app's `isle-building` sub-plugin, contributed to `Isle.Building`).

- `world` — islands, districts, plots, placement (append-only), roads, walk grid + A*, labels.
- `buildings` — the `BuildingSpec` contract, the painting kit, `kitBuilding` (generated buildings).
- `characters` — the hero and villagers, and their walk cycle.

Phase 5 is in: the bakes run in module workers, and the `dev` plugin's growth exhibit reviews growth.

- **Workers** (`renderer/web/internal/bake.worker.ts`, pooled by `bake-pool.ts`): ground tiles' per-pixel
  colour and water mask (`ground-pixels.ts`), island previews, island shapes and the home carve (built ahead
  by `useIslandShapes` for `islandsInPlay`, restored with `IslandPlan.restore` / `adoptHomeCarve`), each
  island's furniture, and buildings' hit masks (`hit-mask.ts`, handed over in idle time). The worker runs the
  page's own modules, so every bake is bit-identical (`dev/e2e/bake-identity.ts`); where workers cannot run,
  everything bakes on the page. The worker bundles cross-plugin code (`world/core`), which web-artifacts
  allows because a page worker's whole closure is its artifact's address (web-artifacts `CLAUDE.md`).
- **Not in a worker: building paint and the object layer.** Bespoke painters come from `Isle.Building`
  contributions in each app's plugin; a page worker is bundled whole at build time, so it cannot load a module
  the page names at run time. That needs the browser-host worker link tree generalised to page workers
  (each `isle-building/core` linked into a per-build worker tree, loaded by specifier). Until then the engine
  paints buildings ahead, nearest first, within the bake budget, so one tile never paints them all at once.
- **Measuring**: `world-view/e2e/perf-sweep.ts` (long tasks before ready, a pan/zoom sweep's frames; `/isle`
  or the exhibit at `--apps N`, `--bake workers|page`).

Isle owns the world; each app owns its building (an `Isle.Building` contribution in its own
`isle-building` sub-plugin). Isle code never names an app.
