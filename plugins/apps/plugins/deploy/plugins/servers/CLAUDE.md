# servers

## The detail pane is ONE slot

`ServerDetail` (`web/slots.ts`, a `defineDetailSections<{ server: Server }>`) is
the whole body of `serverDetailPane` — identity, status, SSH setup and
deployments are peer contributions and the host owns every card. Add a region by
contributing a section, never by wrapping the pane.

- **Entity prop is the whole `Server` row**, not a `serverId`: the pane has it in
  hand, so re-deriving it per section would be a resource read per card.
- The identity form (`server-edit-form.tsx`) is itself a contribution — that is
  what makes "one slot" literal here — and is carded like every other section.
- `health` contributes `status` rather than `servers` rendering a badge:
  `health` already imports `servers`, so the reverse edge would be a cycle. The
  registry owns identity, `health` owns liveness.

## The registry is a collection; the key is a value beside it

`servers` (`shared/resources.ts`, key `deploy.servers.all`) is an `all`
collection over the `deploy_servers` entity (`deployServersEntityRef`,
`core/entity-ref.ts`): its fields are DERIVED — `name`, plus every field an
extension of the entity exposes (`health`'s probe verdict, as `status`). The
list (`servers-list.tsx`) is `collection={servers}` and one `extraFields`
entry (`address`, host:port). The table stays the hand-written
`deriveUpdatedAt` pgTable (`server/internal/tables.ts`); only the ref is
declared in `core/`, and `serveCollection(servers, { from: _deployServers })`
serves it.

The derived `sshKey` is NOT a column of the list: it is a stored public key
parsed, and only when a private half exists in the central secrets store, which
a column projection cannot express. It is read per server as a parameterized
`liveValue` (`serverSshKey`, `useLive(serverSshKey, { serverId })`), served by
a DB-arm loader; `ExistingServerBody` (`web/panes.tsx`) joins the row and the key
into the `Server` every `ServerDetail` section is handed. The change feed is its
only invalidation: storing a key also writes the row's `ssh_public_key`, so no
hand-notify exists. `Server` (the endpoints' response) is the entity's fields
plus `sshKey`.
