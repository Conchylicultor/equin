# site-mirror/box

The box half: `GET /api/host-only/table-mirror/{changes,copy,keys,rows}`, each
behind `hostOnly` (and Caddy's host-only 404), each one page of
`table-mirror/source`'s reader for the set its question names. The source's
registry is the allowlist: a set this release does not contribute answers
`unknown-set` (and an unknown table `unknown-table`) — what the pull's
freshness line shows as "redeploy the site". A release without these routes
answers 404, which host-query reports as `route-missing`.

**How it ships.** Nothing imports it: it is a **server companion** of
`table-mirror/source` (`MirrorReaderRoutes({ companion: true })`), so the
closure engine bundles it wherever the source is bundled — every composition
holding a mirror set (collect's `analytics` on the website), and the local app,
whose own routes a demo's stand-in box is read through. The source's `onReady`
asserts a serving host mirroring a set boots one.
