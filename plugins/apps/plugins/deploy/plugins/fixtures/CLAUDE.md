# fixtures

Some Deploy state — servers, their last check, the deployments they serve and
a history of finished runs — written into an instance through the rows the
app's own handlers write, for a demo's seed. The app owns the format
(`core`: `DeployFixture`, times as offsets before the write) and the writer
(`server`: `writeDeployFixture`); the data belongs to whoever uses it (the
showcase film's `apps/website/promo-film/seed`). Same recipe as
`apps/pages/fixtures` and `apps/prototypes/fixtures`
(`research/2026-10-28-global-per-app-demo-seeds-v2.md`).

Runs are always finished: a `running` row would claim a live CLI leg the
supervised-run reconciler then tries to adopt. A deployment's composition must
be one the instance knows, as the create handler requires.
