# inbox

The site page's **Messages** tab (and the Overview's messages card and the
tab's badge): what visitors sent through the deployed site's contact form
([`intake`](../intake/CLAUDE.md)) — every message, read from this computer's
copy of the site's `site_messages` ([`site-mirror`](../../../site-mirror/CLAUDE.md),
the intake's `site_messages` mirror set). It stores nothing of its own.

- **Read**: `siteMessagesInbox` (`deploy-site-messages.inbox`,
  `core/internal/inbox.ts`), a live window collection — newest first, 50 rows
  by default, up to 200 per page, read as key-range pages (no cap past the
  paging), `count: true`. Every read names one deployment
  (`where: { deploymentId }`, a listed field, so `scoped({ where })` can state
  it). Row ids are `<deploymentId>/<messageId>` (`siteMessageRowId`), so a
  `:rows` read names which site's copy to open.
- **Served** external (`server/internal/served.ts`), `changes: "notified"`:
  each callback runs the inbox's SQL (`reads.ts`, the intake's own table
  names, never `ip_hash`) inside site-mirror's `readSiteMirror` — a read-only
  snapshot whose search_path is the copy's schema. Keyset `(created_at cut to
  ms, id COLLATE "C")`; filters through the filter language's `filterSql`;
  groups on the text fields. `onSiteMirrorApplied` notifies every held tuple
  when a sync applies a page (throttled to 1 s). A read before a whole copy is
  in place throws: the surfaces below never ask one.
- **Gate** (`web/internal/use-messages-copy.ts`): every surface reads
  `site-mirror.status` and reads the list only once the copy is `copied`;
  before that, the freshness line (`MirrorFreshness`, which also asks for a
  sync on open) says why — copying, not synced yet, a failed pull, or a site
  whose release predates the mirror set ("deploy it again").
- **Shown** only when the deployment's composition closure contains the intake
  (`useDeploymentShips` with `INTAKE_PLUGIN_ID`, pinned to its folder by a
  test). No composition is named.
- **List**: a live DataView (`deploy.site-messages`; views Messages / Spam /
  All in `config/apps/deploy/site-messages/inbox/`, each a server-side filter)
  over `liveDataSource(siteMessagesInbox)` scoped to the deployment, searching
  sender and message in SQL. Fields are the collection's (from as a reply
  link, the message on one line, received, verdict, notification state).
  Activating a row opens the full text below the list (read live by id), with
  the spam reason and the last email error.
- **Overview card**: the newest three accepted messages (`useLive` window,
  limit 3). **Badge**: accepted messages of the last 7 days, a `:count` read.

Tests: `server/internal/reads.db.test.ts` (the SQL on real Postgres: paging
both ways at its own cuts over colliding instants, until cuts, filters,
search, count, groups, `:rows`, an unscoped read refused).

## Plugin reference

- Description: Messages tab of a site's page, shown only when the deployment's composition ships the site-messages intake: every message visitors sent through the site, from this computer's copy of the site's messages (site-mirror), as a live DataView paged, searched and filtered in SQL (received, from as a reply link, the message with its full text on open, verdict, notification state), under the copy's freshness line; the Overview's newest-messages card and the tab's 7-day badge read the same copy.
