# inbox

The site page's **Messages** tab (and the Overview's messages card): what visitors sent through the
deployed site's contact form ([`intake`](../intake/CLAUDE.md)), read from the
box. It stores nothing.

- **Read**: `deploy-site-messages.list` (`core/internal/inbox.ts`), a
  typed-query live value `{ deploymentId }`, `load: "snapshot"`, served
  external with `changes: { snapshot }` (`server/internal/served.ts`) through
  [`host-query`](../../../host-query/CLAUDE.md)'s `hostOnlyQueryOverSsh` —
  the intake's host-only list, the newest 200 of every verdict. Measured on
  mount and on Refresh, never on a timer (each measure is an SSH session).
- **Answer**: the page, or one of host-query's failure arms rendered by
  `HostQueryFailureState` (no SSH key, unverified host, SSH failed, request
  failed — curl 22 usually means the release predates the intake —, an
  unreadable answer). A missing deployment is refused `missing`.
- **Shown** only when the deployment's composition closure contains the intake
  (`useDeploymentShips` with `INTAKE_PLUGIN_ID`, pinned to its folder by a
  test). No composition is named.
- **List**: a DataView (`deploy.site-messages`; views Messages / Spam / All in
  `config/apps/deploy/site-messages/inbox/`): received, from (a `mailto:` reply
  link), the message (one line), verdict, notification state. Activating a row
  opens the full text below the list, with the spam reason and the last email
  error.

## Plugin reference

- Description: Messages tab of a site's page, shown only when the deployment's composition ships the site-messages intake: the messages visitors sent through the site, read over SSH from the box on demand, as a DataView (received, from as a reply link, the message with its full text on open, verdict, notification state), with explicit states for every way the read can fail.
