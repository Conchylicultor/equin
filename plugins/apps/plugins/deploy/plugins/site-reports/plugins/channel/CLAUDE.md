# channel

Where `report()` sends on a site page. In its register phase it installs
`siteReportChannel` with reports/web's `reportChannel`, so every collector on the
page reaches the site's [`intake`](../intake/CLAUDE.md) instead of a reports
engine the site's server does not have. That includes the collectors catching
what the live demo raises.

**Held only where a composition names it.** `base-exclusions` lists
`!apps.deploy.site-reports.channel.**`, and the website names the plugin back.
Everywhere else, main included, `report()` keeps its default: the engine.

The batcher (`web/internal/batcher.ts`) is pure and bounded per visit (page
load):

- **Dedupe.** It keeps one entry per fingerprint (kind, source, message, top of
  stack). A repeat only bumps the entry's count.
- **Caps.** At most 20 fingerprints and 10 POSTs per visit.
- **Batching.** The first report waits 5 s for others. What is left is flushed
  on `pagehide` with `keepalive`.
- **Back-off.** Each failure doubles the wait, up to 5 min. A `rate-limited`
  answer waits the server's `retryAfterS`. Five failures in a row stop the
  visit.
- **Failures stay quiet.** A failed batch is only warned to the console, never
  thrown: the crash collector would report it through this very channel.

`toSiteReport` makes each report anonymous before it is batched:

- It drops the client id and the user agent.
- It keeps only the pathname, never the query or hash.
- It clamps the message and every string of the payload.
