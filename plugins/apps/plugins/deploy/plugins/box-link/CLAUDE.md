# box-link

The permanent link from this computer to every deployed site's server (the
*box*). Design: [`research/2026-11-19-global-box-link-permanent-site-connection.md`](../../../../../../research/2026-11-19-global-box-link-permanent-site-connection.md).

**A doorbell, not a pipe.** The link carries small SIGNALS ("a mirror set's
log advanced", a 15 s heartbeat with the box's metrics), never data: data
keeps flowing through the cursored table-mirror pull
([`site-mirror`](../site-mirror/CLAUDE.md)), so a lost signal costs nothing —
every reconnect runs one catch-up pull.

- **`core/`** — the stream protocol v1 (zod): `hello { v, startedAt, buildId,
  signals }`, `beat { at, seq, host }`, `signal { source, payload }`;
  `readBoxFrame` reads one streamed value as a known frame, a kind to skip (a
  newer box), the box producer's `{ error }`, or a malformed frame (loud).
  The route (`boxLinkStreamEndpoint`, `GET /api/host-only/box-link/stream`),
  the link-state union (`LinkStateSchema`) and `BoxLinkSchema`, and the
  `deploy.box-links` live value.
- **`plugins/box`** — ships on the box (imported by `site-mirror/box`): the
  `BoxSignal` contribution kind and, in its machine half, the stream route.
- **`plugins/link`** — local: the tunnels, the stream clients, the pure
  state reducer, the side-table, `deploy.box-links` / `deploy.site-health`,
  `onBoxSignal` / `onBoxHello`, the retry endpoint.
- **`plugins/site-row`** — web: the health report's row per deployed site
  (`deploy.site-health`), its body and footer drawn from the `SiteLive.Glance`
  / `Section` / `Action` render slots the owning plugins contribute to; its
  own Server block, Retry now and Open site; exhibits of the six states.

## Live values

- **`deploy.box-links`** (`boxLinks`, this core) — `Record<deploymentId,
  BoxLink>`, one value for the handful of deployments; only the deployments
  THIS instance links (main: every one; a worktree: demo stand-ins only).
  `BoxLink = { deploymentId, state, since, lastHeardAt, lastBeat, lastError,
  hello }` — `state` the `LinkState` union, `since` / `lastHeardAt` epoch ms
  (this computer's clock), `lastBeat` the last beat as sent (`{ at, seq, host:
  { cpu: { busyPct | null, cores, load1 }, mem: { used, total }, disk: { used,
  total }, uptimeSec } }`), `hello` `{ buildId, startedAt, v }`. Pushed on
  every frame that changes a link (beats included). `needsMachine`.
- **`deploy.site-health`** (`siteHealth`, `link/core`) — see
  [`plugins/link`](plugins/link/CLAUDE.md).

## Link states

| State | When |
|---|---|
| `connecting` | started (tunnel spawned / stream opened), no hello yet |
| `live` | hello received, beats current |
| `reconnecting { cause, graceUntil, then, sshKind }` | was live, lost, within its 2 min grace. `cause`: `slept` (this computer slept since the box was last heard), `restarting` (a deploy run of the deployment is active), `network` (otherwise). `then`: what it settles on once the grace runs out |
| `down` | SSH answers, equin does not (stream refused, 502, closed, 45 s silent) |
| `unreachable { sshKind }` | the SSH transport fails |
| `refused { reason }` | `auth`, `host-key-mismatch`, `forwarding-refused`, `no-ssh-key`, `unverified` — the user must act; nothing retries it |
| `outdated { reason }` | the box answers 404 (`route-missing`: its release predates the stream) or another protocol `v` — deploy it again; retried after the next successful deploy run |

Deploying, failed and behind-main are not link states: `deploy.site-health`
overlays them from the deploy runs and the running commit.
