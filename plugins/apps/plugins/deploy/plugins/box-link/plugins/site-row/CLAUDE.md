# box-link/site-row

The health report's **deployed-site rows** — one per deployment — the UI phase
of [`research/2026-11-19-global-box-link-permanent-site-connection.md`](../../../../../../../../research/2026-11-19-global-box-link-permanent-site-connection.md),
drawn after the prototype `proto-1792516777-e95kao` (*Deployed site*).

## The row set

`HealthReport.Row({ kind: "set", id: "sites" })`. `useSiteRows` reads ONE
value, `deploy.site-health` (`link/core`), and maps each entry to an item:
key = deployment id, title = hostname ?? composition, status = `siteStatus`
(`web/internal/status.ts`, pure, bun-tested):

| Site | Status | Summary |
|---|---|---|
| live, up to date | `ok` | Live · a1b2c3d · up to date |
| behind main | `ok` | Live · a1b2c3d · 142 commits behind main |
| deploying | `ok`, transitioning | Deploying · since 7:01 PM |
| reconnecting | `attention`, transitioning | Live · a1b2c3d · reconnecting… |
| deploy failed | `attention` | Live · a1b2c3d · deploy failed |
| outdated | `attention` | a1b2c3d · … · too old for the live link |
| down / unreachable / refused | `critical` | Not answering since … / Unreachable since … / Can't connect · why |
| connecting | `unknown` (pending) | Checking… |

The link's state wins over the run (a box that does not answer is not
"deploying"). A real box seen from a **worktree** is `main-only` (only main
holds real links): no link state, so the line says "Linked from main · …"
from the runs and the running commit, nothing is dimmed, and the box's
meters (Server) and Retry are absent. A host without the computer
(`unavailable`) has no sites: the set is `ready` with none.

Deviations from the design table, both for the prototype's sake: the title
stays the hostname in every state (the design's "N commits behind main" is
the summary), and every `ok` is the theme's success green — the report has
no info / blue level (the prototype's blue dot for behind / deploying).

## The parts — three render slots, contributed by their owners

The row knows none of its contributors (collection-consumer separation). Each
part is `{ id, component, exhibit? }` with props `{ deploymentId, site }`
(`site` the item's `SiteHealth`, so a part needs no second read of it), its
order the slot's reorder config (`config/apps/deploy/box-link/site-row/`):

- **`SiteLive.Glance`** — the title line's figure, drawn as the set's
  `actions`: "7 visitors now" (`analytics/dashboard`).
- **`SiteLive.Section`** — the body's blocks, under the alert (`siteAlert`:
  the link's loss or the failed run's own message, in one sentence):
  Visitors (`analytics/dashboard`, with `SiteVisitors.Note` notes — "2 new
  messages" from `site-messages/inbox`), Server (this plugin), the deploy in
  progress (`remote-deploy/site-live`).
- **`SiteLive.Action`** — the footer: Deploy (`remote-deploy/site-live`),
  Investigate (`deploy-history/investigate-failure`), Retry now (this
  plugin), Open run (`deploy-history`), Open site (this plugin). Each decides
  for itself whether it applies to the site now (`null` otherwise); the
  footer hides while none drew a control.

`SiteLiveBlock` / `SiteLiveAside` (web barrel) are the block frame every
section draws through (small-caps name, a figure at the line's end, content
under), and `siteFreshness(site)` is the one answer to "dim the box's
numbers?" (`live` / `stale` with when it was last heard / `elsewhere`).

**Server** reads `deploy.box-links` itself (pushed on every beat, which
`deploy.site-health` is not): CPU / memory / disk meters (`Meter`, success
green, amber past 60 %), "Up 6 d" — or, once the link is not live, "Last
heard 4m ago" with every meter dimmed. **Retry now** (`POST
/api/box-link/:deploymentId/retry`) while the link is reconnecting, down,
unreachable, refused or outdated. **Open site** (`NewTabButton`) while the
site is up, settled and current.

## Exhibits — `site-row/<state>`

`live`, `deploying`, `behind`, `reconnecting`, `down`, `failed`, `two-sites`
(app exhibits, `home: "chrome"`, 380 px): the row expanded, drawn through
health-report's own `HealthLineView` — the line the report draws, never a
lookalike — on a fixture `SiteHealth` per state (`exhibits/internal/
fixtures.ts`). A part whose live component reads more than `site` (visitors,
messages, the deployment record) supplies its own `exhibit`, drawing the same
view from its own fixture for the `SiteExhibitState`; the rest draw their
live component on the fixture site. The exhibit is `inert`: it never deploys,
retries or opens anything.

```bash
./equin run plugins/plugin-meta/plugins/exhibits/e2e/exhibit-shot.ts --id site-row/failed --theme chrome --color-scheme dark
```
