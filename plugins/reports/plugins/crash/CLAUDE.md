# crash

## What makes one crash one row

`crashFingerprint` hashes the first identity the occurrence actually carries:

1. **Its stack** — top 3 normalized frames, prefixed by the error type.
2. **A caller-declared `errorType`, no stack** — `PaneRestoreCorrupt`,
   `JobDeadline`, `LiveStateWedge:<disc>`, `PluginLoadError <path>`,
   `EndpointError <status> <route>` pass this ON PURPOSE so a family of varying
   messages collapses onto one row. Don't "improve" it by folding the message in.
3. **The message**, when there is neither (browser `window.onerror` with no
   `Error`, server call sites passing `stack: null`), with the per-occurrence
   tokens normalized away so a recurring failure still accumulates on one row.

`core/crash-kind.test.ts` pins branch 1 and 2 as literal hashes: they reproduce
the pre-2026-09 input byte for byte, so live report rows keep their identity.
Add a case there before changing any of this.
