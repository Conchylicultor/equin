# interaction-budget

The report a **work budget** files: an interaction (a switch, an open, a
scroll) measured by a count of the work it does — elements restyled, nodes
created — rather than a time, against a budget per case. A count is stable
run to run where CPU time drifts 2–3× with the host's load, so a budget over it
is a regression guard, not a flake; and none of these regressions is slow
enough for the stall report (≥ 5 s) to catch.

## Shape

- **A scenario** is a budget script (`<plugin>/e2e/*-budget.ts`) that drives
  the deployed app on deterministic content (the `/demo` page's seeded data,
  never the user's live library), measures each case several times, and hands
  the cases (median, budget, samples) to `settleBudget` (`e2e/`).
- **On demand** (`./equin run <script>`) it prints the verdict and exits 1
  while a case is over budget.
- **Main's run** (the scenario's own supervised job, after each of main's
  builds) adds `--file-reports --commit <sha>`: over budget files one
  `interaction-budget` report through the report outbox
  (`plugins/reports/plugins/outbox`), within budget records the commit as the
  scenario's last within budget (`data-dirs/`: `state/interaction-budget/<scenario>.json`).
  The report names the range `lastWithinBudget..commit` — every commit in it is
  a candidate.

One row per scenario (fingerprint `interaction-budget:<scenario>`): each
over-budget run bumps its count and replaces the payload. Warning variant, the
bell re-arms at most every 6 h per row. A row does not clear itself when the
scenario is back within budget.

Scenarios today: `desktop.fullscreen-switch`
(`plugins/apps/plugins/desktop/plugins/fullscreen-budget`).

## Raising a budget

Only when the added work is intended, with the reason in the commit — never to
make a report go away. The budget sits in the scenario's script, next to the
numbers it was set from.
