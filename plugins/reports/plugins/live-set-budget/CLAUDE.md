# live-set-budget

The loud signal for a **whole live set that outgrew its reason**. A
`liveCollection(key, { all: { …, unbounded: { reason, budget } } })` is held
whole and sent to every reader; `budget` (required, measured on main) is how
many rows per tuple the reason promises. network/live checks every load that
reads a whole tuple and emits `liveSetOverBudgetSink` past it
(`network/live/plugins/query-resource/core`, since a primitive cannot import
`reports`). This plugin drains it.

- **One row per key** (`live-set-over-budget:<key>`): one declaration is one
  claim, whichever tuple broke it. Debounced 10 min per key (an over-budget
  set emits on every entrant), re-alerting every 6 h.
- **Served, never refused**: a budget is a claim made checkable, not a cap —
  `all: { max }` is the cap.
- **Fix**: bound the set (a window, `by`, `max`), or re-measure and raise the
  budget with a reason saying what bounds it.
