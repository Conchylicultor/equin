# host-check

The report a failing **host-scoped** check files. A host check
(`Check.scope: "host"` — `paths:no-undeclared-data-dirs`,
`paths:logs-claimed`, `codesign:identity`) is about the MACHINE: the shared data
root, the keychain. Its subject is shared by every checkout on the box, so no
worktree's check pass asserts it — a bare `./equin check` selects
`tree,deploy` — and its verdict is delivered here instead, to whoever triages
Reports.

## How it is filed

Main's hourly `checks.host-audit` job
(`plugins/framework/plugins/tooling/plugins/checks/plugins/host-audit`) runs
`./equin check --scope host --file-reports --no-cache` in main's checkout. Each
failing check becomes one outbox entry (`plugins/reports/plugins/outbox`), which
main's drain records. The entry carries no `code`: the report is about the
machine's state, not a source file, so the staleness rule does not apply.

One row per check (fingerprint `host-check:<id>`); each failing audit bumps its
count and replaces the payload, so the row shows the latest message. Warning
variant, bell re-arms at most every 6 h per row. A row does not clear itself
when the check passes again — read `lastSeenAt`, or run the check.
