# file

The report outbox's WRITING half, core-only: `fileReportFromProcess` /
`fileReportFromProcessSync`, the entry format (`OutboxEntrySchema`, entry and
temp names) the drain reads back, `mergeBaseWithMain` / `headCommitOf` for the
staleness stamp, and the outbox directory's declaration (`data-dirs/`).

Split out of [`reports/outbox`](../../CLAUDE.md) (which keeps the drain and the
sink writers, its `server/`) so a writer bundles only this: a composition takes
a plugin whole, and the outbox's `server/` reaches the reports engine and the
git watcher. Every desktop composition holds a writer — the serving backend's
boot-crash filer (`debug/boot-events`' `machine/`, run from server-core's
`bin/`, a host root) — including the self-contained website and Sonata.

Keep it light: no `server/`, nothing that reaches the engine. How writing works
(one file per report, never throws, bounded, the repository and commit stamps)
is documented in the parent's CLAUDE.md.
