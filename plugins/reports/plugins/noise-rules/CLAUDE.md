# noise-rules

Built-in noise classification rules for the reports plugin.

Some reports are structurally benign and high-frequency — the canonical example
is the `ResizeObserver loop completed with undelivered notifications` browser
warning. These are recorded and visible like any other report, but classified as
"noise" so the notification they file is `muted` (it stays out of the bell's
unread surface). The deduped report is still recorded — noise classification governs
notification loudness, not whether the report is tracked.

This plugin contributes one `ReportNoiseRule` per known low-signal pattern via
the generic `ReportNoiseRule` slot owned by the parent `reports` plugin.
`recordReport` enumerates all rules and stamps a `noise` boolean on the report
row — it never names a specific rule.

## How to add a rule

Add a spec to `server/internal/rules.ts` and contribute it in
`server/index.ts` (`ReportNoiseRule(myRule)`):

```ts
export const myRule: ReportNoiseRuleSpec = {
  id: "my-benign-pattern",
  matches: ({ message, errorType, source, stack, versionSkew }) =>
    message.includes("…"),
  code: import.meta,
};
```

`matches` receives the report's `source`, `errorType`, `message`, `stack` and
`versionSkew` — reports/core's `versionSkewMayExplain`: every occurrence came
from an outdated tab (the row's sticky `staleOrigin` fact) AND the report is
about that tab loading what the server serves now (a chunk, the boot snapshot,
a stored entry). A bug in an outdated tab's own code (an exception, a render
loop, a stall) or what it saw the server do (a failed loader, a 5xx) is never
version skew: main deploys on every push, so nearly every long-lived tab is
outdated, and muting those reports muted real bugs (2026-11-12 audit: all 7
stale-muted reports of a day were real). Return `true` to mark the
report as noise. A thrown error in `matches` is caught and treated as "no
match", so a buggy rule never breaks the report pipeline.

`code: import.meta` names the module the rule lives in. The engine reclassifies
the stored reports once whenever the source digest of the rules' code changes
(adding, editing or removing a rule) and not otherwise, so keep `rules.ts`
importing nothing but types: everything it loads counts.
