# faceted

Build tooling (the facet extractors, run over the plugin tree) — and the
worker that keeps a backend's faceted tree up to date by what changed: the
`FacetedIndex` (`core/internal/faceted-index.ts`), run by plugin-tree's
`bin/faceted-tree-worker.ts` on a thread plugin-tree's `machine/` provider
starts through the daemon primitive. See `plugin-tree/CLAUDE.md` ("The faceted
tree follows what changed") for the design and its measurements.

- This plugin has no `machine/` (or `server/`) barrel on purpose: a backend
  registry entry warms its plugin's `core` barrel, which here is tooling
  loaded by a computed path (`boot:closure-digestable`).
- `facet-extraction.ts` is the extraction HARNESS — the strict snapshot and
  the extraction job body, i.e. only the code that shapes a facet VALUE: its
  Merkle key is in every facet record of every plugin. Keying, the record
  store and worker scheduling live in `facet-records.ts`, which keys nothing
  (a change there cannot change a value), and the index builds on that from
  `faceted-index.ts`. Never import key/store/worker code into the harness:
  `faceted:facet-key-width` sees only unused barrel code, not a used import
  that cannot shape a value. Measure with
  `plugin-records/scripts/key-closures.ts` (2026-11-06: before the split the
  harness key covered 42 modules, moved by 13 of the last 200 main commits;
  after it, 29 modules and 7 commits).
