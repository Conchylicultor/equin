# source-files

What a scanner reads off a plugin's tree: `walkFilesSync` / `sourceFilesIn`
(the source files under a dir — sub-plugin trees, `__tests__/`, `testing/`
and `*.test.ts(x)` skipped) and `readIfExistsSync` / `pathExistsSync` (a file's
bytes, whether a path exists) — each answered from the ambient FS snapshot
(`parse-utils`' `runWithFsSnapshot`) when it covers the path, from disk
otherwise.

Apart from `parse-utils` on purpose. `parse-utils` is the pure source
parsers (`maskSource`, `findImports`, `matchBracket`, …) that the per-file
scans run (`*.scan.ts`, `plugin-meta/plugin-records`), and a scan's records
are keyed by its module's whole import closure: while these lived in
`parse-utils`, every scan's key named `timed-fs`, `user-path`, `plugin-id`
and `product-name` — 11 modules no scan calls, edited on ~1.6 main commits a
day, each edit re-keying every file's record of six scans. Nothing a scan
imports may read the disk; put a file-system helper here.
