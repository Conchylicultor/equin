# specifier

The one reading of an import specifier as a repo path. `specifierPath`
(`@plugins/<p>` → `plugins/<p>`, a relative one joined onto the importer's
directory, a `?query` dropped), `specifierCandidates` (that path, with each
extension, then its `index` file with each — the runtime's order) and
`resolveSpecifier(fromRel, spec, has)` (the first candidate in a file set).

The plugin-records module graph resolves every edge with it. Every other
reader takes resolved imports from the graph (`fileSetImports`,
`fileSetRuntimeReach`, `fileSetImportTargets`, `fileSetBindings`); this leaf
is for a specifier the graph has no edge for: an `import type` (erased from
the graph), a CSS `@import`, a barrel named as data, or a lint rule that
judges one file with no file set (it resolves against the set of files it is
asking about). `import-scan-safety/no-hand-import-resolution` rejects any
other resolver.

A leaf with no imports, so a lint rule (or anything else) can load it
without the record store.
