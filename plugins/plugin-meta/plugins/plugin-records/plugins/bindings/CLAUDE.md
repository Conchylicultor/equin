# bindings

`fileSetBindings(repo, modules)`: each module's imports as the plugin-records
module graph resolves them (static and dynamic edges), each with the names its
statements bind (`"all"` for an `import()`, a `require()`, a namespace or
default import), and a pure re-export module's `export … from`s resolved. The
graph decides which edges exist; the per-blob `bindings.scan.ts` record only
narrows the names, joined onto the graph's edges by specifier. Its reader
(type-check's lint-group closures) walks closures by name through barrels and
never parses or resolves an import itself.

A sub-plugin, not part of `plugin-records/core`: its scan runs parse-utils'
`findImports`, and in that barrel parse-utils' core would key every record
producer that imports `plugin-records/core` (the barrel evaluator's
`evaluate:evaluator-key-width` failed at +10 modules it never calls).
