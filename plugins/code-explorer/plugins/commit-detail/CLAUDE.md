# commit-detail

The one commit-diff pane, parameterized by worktree: any surface that can name a
`(worktree, sha)` pair pushes it — a conversation's commits graph, a commit-sha
chip in agent prose. Lives under `code-explorer` because it is the viewer half of
the `/api/code/:worktree/*` contracts; consumers open it the way `AttemptChip`
opens `attemptPane`.

**The worktree is a pane param, never an ancestor lookup.** Its predecessor
(`commits-graph`'s `convCommitDiffPane`) read the worktree off an ancestor
`conversationPane` and so rendered `null` anywhere without a conversation in
scope. `commit/:worktree/:sha` (the shape `code/:worktree` already uses) is read
from the body's own `useParams()`; keep it that way — a conversation lookup here
re-breaks every conversation-less surface.

**`useCommitInfo` is four-armed**: `loading | found | not-found | error`.
`not-found` (the read refused `missing` — a determinate answer about the
repository) and `error` (we could not ask) must not collapse — only `not-found`
suppresses the diff body. Both reads are live values declared in `code-api`
(`code.commit-info`, `code.commit-files`), served external and `immutable` by
`code-explorer`: a commit's content is addressed by its sha. Every linked
worktree shares one object store, so any non-path `worktree` resolves the sha in
this repository — a reaped attempt's commits stay readable.

**The pane is one scroll** (PaneChrome's): `CommitMessage` heads it and
scrolls away; the changed files are a `<DataView>` (`CommitDiffView`,
storage key `commit-files`) whose toolbar pins at the top and whose open
row pins under it while its diff scrolls (the list view's sticky `detail`
rows). Never wrap the two in a `Column` with a body scroller of its own — the
DataView owns no scroll, and a nested one would bound its sticky toolbar.

- **Rows** are `code.commit-files`' `EditedFile`s, in memory, keyed by path,
  enriched client-side: `kind` (`file-kind`'s `fileKindOf`), `plugin` (the
  plugin's path form, or the top-level directory outside `plugins/`),
  `folder`, `churn` (additions + deletions).
- **Views are config**, authored in
  `config/code-explorer/commit-detail/commit-files.jsonc`: All files (the
  `viewEdits` home), Code, Tests, Docs — each nothing but a `kind` filter,
  grouped by plugin, most changed first. Edits are drafts (dirty dot, Save
  view); Group by is promoted to its own toolbar control.
- The toolbar's `actions` carry the visible totals (`23 of 29 +a −d`, from
  the view's own rows via `useDataViewControls` + `useFlatRows`); group
  headers carry their `+a −d` (`sectionSummary`); `revealHidden` says what
  the view's filter hides. A read cut at `COMMIT_FILES_MAX` says so in the
  surface's `notice`.
- The path renders as the full repo path (muted directory, basename): a cell
  cannot know the active grouping, so it is never shortened relative to its
  group header.
