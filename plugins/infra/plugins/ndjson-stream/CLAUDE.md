# ndjson-stream

The shared NDJSON streaming primitive. On the server, `ndjsonResponse(produce)`
wraps a producer that calls `emit(frame)` into an `application/x-ndjson` chunked
`Response`, framing an unexpected throw as `{error}` and always closing the
stream. On the web, `readNdjson(route, url, init?)` consumes it as an async
generator, yielding one parsed JSON frame per line while guarding `res.ok` and
reporting failures via `EndpointError`.

It is for streaming a MUTATION's progress (a POST / DELETE whose steps the
caller shows as they run — worktree-cleanup's per-row delete), which
`implement()`/`fetchEndpoint`'s single-JSON-response model can't express, and
which must survive Bun's 10s idle timeout.

It is never a READ. A progressive read — a heavy fan-out whose rows should
render as they arrive — is a `notified` live value filled by its
`whileSubscribed` and pushed as it goes (`debug.timeline.scan` is the
pattern; `network/live`), and a GET NDJSON stream is a `live/no-endpoint-read`
hit.
