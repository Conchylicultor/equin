# ndjson-stream

The shared NDJSON streaming primitive.

- **Server, write side** — `ndjsonResponse(produce, { signal? })` wraps a
  producer that calls `emit(frame)` into an `application/x-ndjson` chunked
  `Response`, framing an unexpected throw as `{error}` and always closing the
  stream. `produce(emit, signal)` is handed an AbortSignal that fires when the
  reader goes away — the stream cancelled (a client disconnect) or the
  request's own `signal` (pass `req.signal`) aborted — so a long-lived
  producer drops its LISTEN and timers and returns. After it fired, `emit`
  drops frames, and a producer error other than the abort is rethrown as an
  unhandled rejection (never lost with the stream).
- **Server, read side** — `readNdjson(body, signal?)` iterates a streamed
  body (a `fetch` response's) one parsed JSON value per non-blank line (lines
  and multi-byte characters split across chunks joined first). A malformed
  line throws `NdjsonParseError`; `signal` cancels the body and throws its
  reason; leaving the loop early cancels the body. The values are `unknown`:
  the caller parses them with its own schema.
- **Web** — `readNdjson(transport, endpoint, params, opts?)` consumes a
  stream — the request built from the endpoint's contract, which must be a
  write (`& WriteEndpoint`: a GET def is a tsc error, and throws if cast
  through) — as an async generator, yielding one parsed JSON frame per line
  (the same line parser, `shared/ndjson-lines.ts`) while guarding `res.ok`
  and reporting failures via `EndpointError`.

It has exactly two uses:

1. **A mutation's progress** (a POST / DELETE whose steps the caller shows as
   they run — worktree-cleanup's per-row delete), which
   `implement()`/`fetchEndpoint`'s single-JSON-response model can't express,
   and which must survive Bun's idle timeout.
2. **A host-only stream read by a peer process** — a long-lived stream
   another equin process holds open to this one (the deploy box link: main
   reads a box's signals over an SSH tunnel). It carries signals, not data
   the browser renders. Its producer must heartbeat well inside Bun's 60 s
   `idleTimeout` (the box link beats every 15 s) and release everything on
   its abort signal.

It is never a browser READ. A progressive read — a heavy fan-out whose rows
should render as they arrive — is a `notified` live value filled by its
`whileSubscribed` and pushed as it goes (`debug.timeline.scan` is the
pattern; `network/live`), and a GET def passed to the web `readNdjson` does
not compile.
