# usage-ledger/pricing

Claude pricing as dated data, and the one function that turns the usage
ledger's tokens into dollars. Design:
[`research/2026-11-16-global-unified-claude-cost.md`](../../../../../../../../research/2026-11-16-global-unified-claude-cost.md) § 1.

- **The price table** (`core`: `ModelPrice`, `PriceTable`, `resolveModel`,
  `priceBucket`) — its file and fetch live in the `price-table` child
  (`parseLiteLlmTable`, `mergePriceTable` — merge-only, never drops a key —
  `loadPriceTable` / `savePriceTable`, `fetchPriceTable`,
  `loadFallbackPriceTable`, the vendored `litellm-fallback.json`), which is
  not portable (file persistence); this plugin's `server/` is, so a portable
  reader of the priced view (conversations/usage) does not pull in the
  file system. The child also runs the daily refresh
  (`claude-cli.pricing.refresh`, on main: fetch, merge, save, record a
  version when a rate moved, file `cost-unpriced-model`) and the boot warm-up
  recording the held table as the first version.
- **`claude_price_versions`** `(id pricev-…, effective_from, source
  litellm|fallback|correction, models, recorded_at)` — each table in force
  from `effective_from`. `recordPriceVersion(exec, table, source)` records one
  only when some rate differs from the newest refreshed (non-correction)
  version; the first ever is effective from `-infinity` (LiteLLM has no
  history). `models` keeps the whole table so a model first seen later is
  resolved against each version's own prices. A correction is a version with a
  past `effective_from`, written by hand (a script or a settings surface) —
  never by the refresh.
- **`claude_model_rates`** `(version_id, model, speed, 10 per-token rates)` —
  per version, per OBSERVED model string: `resolveModel` (exact, prefix,
  substring) runs once, in TS, when a version is recorded (every model the
  ledger holds) or a model is first seen (`ensureModelRates`, called by the
  ledger's writers after their write; `recordPriceVersion` sweeps what a lost
  call missed). Rates are materialized: an untiered `_above` is its base, a
  `fast` row carries the multiplier.
- **`claude_spend_hours_v`** (`claudeSpendHoursView`, a derived view) — every
  `claude_usage_hours` row with `price_version_id` and `cost_usd`, priced with
  the newest version whose `effective_from <= hour`. `cost_usd` is NULL when
  that version has no rate for the model — never 0.

**Price in force then.** A refresh never re-prices the past: its version is
effective from now. A wrong price is corrected by a version effective from a
past instant, and every surface re-prices — the derived rollups (the Cost
column, Stats → Cost) are re-aggregated by their triggers on
`claude_price_versions` / `claude_model_rates`.
