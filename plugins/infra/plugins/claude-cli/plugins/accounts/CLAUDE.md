# Claude accounts

The Claude accounts agents can run on, and which one new agents launch on.

- **The system account** (`SYSTEM_ACCOUNT_ID`) is always there: whatever the computer's Claude Code is signed into (`claude auth login`). It has no token here.
- **Token accounts** are added with a long-lived token from `claude setup-token`. The token goes to the secrets store (namespace `claude-accounts`, key = account id); `accounts.json` (data-dir `state/claude-accounts`) holds only names, the active id and `autoSwitch`.
- **Machine-wide.** Every worktree's agents launch on the active account. The choice is read at agent-process start (`runtime-sdk`), which passes the account id to the agent; the agent fetches the token itself and hands it to Claude Code as `CLAUDE_CODE_OAUTH_TOKEN`. The token never sits in argv, the options file or the login shell's environment.
- A running agent keeps the account it started on until its process restarts.
- Usage limits are per account and recorded by `conversations/runtime-sdk` (it owns the rate-limit events); the health row's account picker lives there too.
