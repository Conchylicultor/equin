# claude-cli/sdk

The one way a backend opens a Claude Code session: the Agent SDK, on an account
its caller chose. Nothing in the repo drives the `claude` executable by hand.

- `claudeSessionEnv(account, base?)` — the environment: `base` (default the host
  facts, `pickHostEnv`) plus an added account's credential (`claudeCredentialEnv`:
  a plan token or an API key). The
  system account adds nothing (the computer's own login). Branded
  `ClaudeSessionEnv`, so a session that skipped the account choice does not
  type-check.
- `claudeQuery({ env, bin, prompt, options })` — the only `query()` call
  (agents, the usage probe, everything below).
- `runClaudeTurn({ env, bin, prompt, options, timeoutMs })` — one prompt to its
  result message, under a real deadline (aborted, and rejected through
  `withDeadline` whether or not the stream settles). Returns an error result
  as a result; throws `ClaudeTurnError` only when there is none.
- `readClaudeInitialize({ env, bin, cwd, timeoutMs, signal? })` — a no-prompt session's
  `initialize` answer: version, signed-in account, model menu. No turn, nothing
  billed.

Which account: one-shot generations take `activeClaudeAccountId()`
(`plugins/accounts`); an agent the account its launch chose; availability and the
model menu the system account (they describe the computer's login).

Lint (`claude-sdk/…`): `no-direct-sdk-query` (a value import of `query` / the v2
session openers from the SDK; `session.ts` is the sanctioned exemption) and
`no-claude-bin-spawn` (a spawn whose argv[0] is `requireClaudeBin()` /
`resolveClaudeBin()`).
