# cargo-updater

The `cargo` updater of `infra/deps`: plans and applies moves of every `rust/`
crate's `Cargo.lock` (`git ls-files plugins/**/rust/Cargo.lock`), under a
3-day release cooldown, with `CARGO_HOLDS` (`core/`) for releases known to be
broken — the shared bounded `Hold` of `infra/deps/updates` (held by
`deps-cargo:holds`).

- **Detect**: `cargo update --dry-run` per crate names what each lock could
  move to within its `Cargo.toml` requirements; crates.io's versions API says
  when each release was published. A move goes to the newest release above the
  lock's, at most cargo's ceiling, published before the cooldown cutoff, not
  yanked, not a pre-release, not held. A held release is still detected, as a
  HELD row. Only crates.io packages move; a git or path dependency is pinned
  by hand. Requirements (`Cargo.toml`) are never moved — a new semver major is
  a code change.
- **Apply**: `cargo update -p <crate>@<from> --precise <to>` per move, then the
  lock is read back to prove it.
- **Smoke**: `cargo check --locked` of each touched crate, in its dir of the
  shared target cache.
- Every cargo command is spelled through the rust kind's `cargoCommand`
  (`rust/no-bare-cargo`).

A sub-plugin so the installer kind carries no edge to the updater registry,
which files tasks (the python/uv-updater split).
