# rust

The `rust` installer kind of `infra/deps`, built ON the `build` kind
([`../build`](../build/CLAUDE.md)) — see the parent's
[`CLAUDE.md`](../../CLAUDE.md) for the engine.

```ts
// plugins/<feature>/deps/index.ts — the crate is the plugin's rust/ folder
export const helper = defineDep({
  id: "my-helper", owner: "…", description: "…", sizeHint: "≈10 MB",
  source: cargoBuild({ crate: "plugins/<feature>/rust", bin: "my-helper" }),
  // or assemble something around the binary (a macOS .app):
  // cargoBuild({ crate, bin, output: "My.app", binary: "My.app/Contents/MacOS/my-helper",
  //              then: async (ctx, built) => { /* copy `built` into ctx.output */ } })
  updates: { none: "built from this checkout's own source" },
});

// after ensureDep / readyNow:
const path = cargoBinary(ready);
```

- **A crate is a `rust/` folder** (`plugin-id`'s `LEAF_FOLDERS`): one Cargo
  crate — `Cargo.toml`, a committed `Cargo.lock`, `src/` — no TypeScript,
  imported by nothing. `cargoBuild` refuses any other path. Self-contained: a
  path dependency outside the folder is not an identity input.
- **Identity** (the build kind's): every file of the crate as `git ls-files`
  sees it (`target/` is ignored, `.gitignore`), `Cargo.lock` required, plus
  `rustc -vV` through the mise shims from the repo root.
- **Install**: `cargo build --release --locked --bin <bin> --manifest-path
  <crate>/Cargo.toml` from the repo root (so the root's `mise.toml` picks the
  toolchain — the `rust` entry, moved by the mise updater — never rustup's
  default or a crate's `rust-toolchain.toml`), with `CARGO_TARGET_DIR` the
  crate's own dir in the shared `cargo-target` cache (`data-dirs/`), so every
  checkout compiles incrementally. The binary is then copied into `env/` (or
  handed to `then`, which must leave `output` and the declared `binary`).
- **Host only**: no `targets` (cross-compiling needs a rustup target and a
  foreign linker), so a cargo build cannot be `bundle`d yet.
- **`rust/no-bare-cargo`** (`lint/`): TypeScript spawns cargo only through this
  kind — `cargoBuild`, or `cargoCommand(args)` for any other command (the
  argv and the mise-pinned env). The kind needs no exemption: it returns its
  argvs as values (`cargoBuildArgv`, `cargoCommand`), which the rule — like
  `python/no-system-python` — reads as data; only an argv literal handed
  straight to a call, or a shell string, is a spawn.
- `plugins/cargo-updater` — the `cargo` updater (every `rust/` crate's
  `Cargo.lock`).

Not yet on this kind: the release's Tauri shell (`tauri/`, built by the Tauri
CLI in `framework/cli/release`), and the toolchain updater's `cargo check
(tauri)` smoke — moving `tauri/` under a plugin is a follow-up.

## Plugin reference

- Description: The rust installer kind of infra/deps, on top of the build kind: cargoBuild({ crate, bin }) (its deps barrel) builds a plugin's rust/ crate with cargo build --release --locked under the mise-pinned toolchain into a shared cargo target dir (the cargo-target cache data dir), its identity every crate file plus rustc -vV; cargoBinary(ready) is the built binary.
