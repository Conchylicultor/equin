# package-copy

The `package-copy` installer kind of `infra/deps` — see the parent's
[`CLAUDE.md`](../../CLAUDE.md) for the engine.

```ts
// plugins/<feature>/deps/index.ts
export const daemonBinary = defineDep({
  id: "daemon-binary", owner: "…", description: "…", sizeHint: "≈1 MB",
  source: npmPackageCopy({
    workspace: "plugins/<feature>",             // whose node_modules holds it
    package: (target) => `@scope/daemon-${tagOf(target)}`,
  }),
  pin: { holder: "machine-daemon", appliesAt: "the daemon's next start" },
});

// after pinnedDep / ensureDep:
join(packageCopyDir(ready), "native/bin/daemon");
await packageCopyVersion(ready);               // its package.json version
```

- For an npm package something outside the checkout RUNS (a host daemon's
  native binary): the copy is the daemon's, so a `bun install` in the checkout
  can no longer replace the bytes under it. Pair it with `pin` so the next
  start does not silently follow the checkout either.
- **Identity** = the package's own `bun.lock` entry (name, version,
  integrity) + the host target. Another package moving in the lock, or a
  workspace added, is not a new install. Only the package itself is copied,
  so a package whose entry declares dependencies is refused (a native binary
  package declares none). The lock is read here, not through
  `npm/lock-closure`: the database plugins every composition loads import this
  kind, and a child of `npm` drags the updater subtree in with it.
- **Install** = `cp -R` of the directory the workspace's `node_modules` link
  resolves to (symlinks and modes kept) into `env/package/`, after checking
  that its `package.json` version is the lock's (a checkout whose install is
  behind its lock fails, naming `bun install`), and re-checking the copy.
- Its updater is `npm` (which moves the lock); no `forTarget`: a release
  vendors its natives itself.
