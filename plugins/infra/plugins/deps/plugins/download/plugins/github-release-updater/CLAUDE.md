# github-release-updater

The `github-release` updater of `infra/deps`: keeps every
`githubReleaseDownload` (the `download` kind's `deps/` barrel) on its
repository's newest GitHub release.

```ts
// plugins/<feature>/deps/internal/x.ts
import pin from "./x.pin.json"; // { repo, asset: "name_{tag}.zip", tag, publishedAt, sha256 }
source: githubReleaseDownload({ name: "x.zip", pin, pinFile: "plugins/…/x.pin.json", derive? })
```

- **Detect / plan**: every declared dependency whose source is a
  `githubReleaseDownload` (`declaredDeps()`, nothing named), its pin read from
  the checkout's `pinFile`; GitHub's releases API (latest 30, drafts and
  pre-releases left out) gives each release's publish instant and asset
  digests. A move goes to the newest release after the pin's carrying the
  pin's asset, published before the 3-day cooldown cutoff, not held; a newer
  one still cooling down is a WAITING row, a held one a HELD row. Move name =
  the dependency id.
- **Apply**: rewrites `pinFile` with the release's tag, publish instant and
  the asset's sha256 as GitHub's digest reports it (a release with no digest
  is refused — nothing to pin by). A moved pin is a new identity, so a new
  install beside the old one.
- **Smoke**: `./equin deps install <id>` — the download, its digest and the
  declaration's derive.
- **Holds**: `GITHUB_RELEASE_HOLDS` (`core/`), names = dependency ids,
  versions = tags ordered by their dotted numbers (`deps-github-release:holds`).

A sub-plugin so the installer kind carries no edge to the updater registry,
which files tasks (the python/uv-updater split). First user:
`framework/tooling/web-artifacts/blocker-scan`'s `blocker-rulesets`.
