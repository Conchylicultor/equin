# health

Watches this page's connection to its backends and says so.

- **Connection row** — contributes the health report's `connection` status row
  (`HealthReport.Row`, `shell/health-report`). `connectionHealth`
  (`web/internal/connection-health.ts`, bun-tested) folds the two notification
  sockets — this worktree's server and central — into one status: both open is
  ok, any closed is critical and names which, and any still (re)connecting is
  attention with `transitioning` set so the dot pulses. An open socket whose
  server's heartbeat reports a change undelivered for ≥ 30 s
  (`ChannelStatuses.serverPushStallMs`) is critical too — "live updates stuck":
  the socket looks healthy but no push gets through. Closed outranks stuck;
  stuck outranks (re)connecting. One resource whose own push is stuck ≥ 30 s
  while the rest flow (`ChannelStatuses.serverStalledResources`, a leaf's
  hung drain) is attention, naming the resources ("Live updates stuck for
  1 min on host-fs.peek — everything else is still updating") — the least of
  the four.
- **`ReconnectWatcher`** — the toast when the server restarts.
- **`WedgeWatchdog`** — detects a live-state channel that stopped delivering,
  including a server stalled past the Connection row's threshold
  (`push-stall:<channel>`, one report per channel per episode), and one
  resource's push stuck (`push-stall-resource:<channel>:<key>`, one report per
  resource per episode — each stuck resource is its own bug).
- **`getHealth` / `waitForRestart`** — the `/api/health` client helpers.
