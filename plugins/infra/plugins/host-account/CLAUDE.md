# host-account

Who is the user, as the machine knows them? Singularity runs one instance per
user (`research/2026-07-02-global-adr-single-instance-per-user.md`), so the OS
account the backend runs as IS the user's own account. This plugin owns that
answer: a surface that greets the user or names their workspace ("Etienne's
pages") reads it here instead of asking for a name or guessing one.

## The value

`hostAccount` (core) — a `liveValue` keyed `host-account`:
`{ username, fullName }` (`HostAccount`). `fullName` is `null` when the account
records none — a fact about the account, never a failed read (a failed read
throws). `accountFirstName` / `accountInitial` (core) are the one spelling of
the name to show, derived from the full name, else the login name.

`hostHome` (core) — a sibling `liveValue` keyed `host-account.home`: the
account's home directory, absolute (`HOME_DIR`, the same one host-fs expands
`~` against). A separate value, not a field of `hostAccount`, so a surface that
only needs `~` (the file explorer) never waits on — or fails with — the
full-name spawn. Read with `useLive(hostHome)` directly — no wrapper hook;
`fixed` for the same reason. Declared `needsMachine` ("Your home folder") and
served by `machine/`: a host without the computer has no home folder, so its
readers get the `unavailable` arm.

## The read

The portable `server/` serves `hostAccount` through the **`HostAccountSource`**
host service (`{ read(): Promise<HostAccount> }`). Its providers:

- `machine/` (the desktop) — the OS account, below;
- `plugins/guest` (a host without the computer, excluded from every desktop
  composition by `base-exclusions`) — a fixed demo account, so the Pages brand
  renders in the demo as it does on the desktop.

The desktop read is `machine/internal/read-account.ts`, through `infra/spawn`'s
`spawnCaptured`:

- macOS: `id -F <user>` — the account's RealName;
- elsewhere: `getent passwd <user>` — the first comma-separated part of the
  GECOS field, `&` expanded to the capitalised login name (exit 2, "no such
  key", is an account without a name);
- the login name itself is `os.userInfo().username`.

The parsers are pure (`machine/internal/parse.ts`) and tested on their own.

## Freshness

Read once per backend, on first demand, and shared — the account a process
runs as does not change while it runs, so the value is served on the external
arm and never notified. A failed read is not cached: the next load retries.

## Reading it

`useHostAccount()` (web) is `useLive(hostAccount)`: `loading` until the value
arrives. Render a loading state there — never a placeholder name, which would
be a claim about the user that then reverses itself.
