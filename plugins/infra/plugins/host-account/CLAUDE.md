# host-account

Who is the user, as the machine knows them? equin runs one instance per
user (`research/2026-07-02-global-adr-single-instance-per-user.md`), so the OS
account the backend runs as IS the user's own account. This plugin owns that
answer: a surface that greets the user or names their workspace ("Jane's
pages") reads it here instead of asking for a name or guessing one.

## The value

`hostAccount` (core) — a `liveValue` keyed `host-account`:
`{ username, fullName }` (`HostAccount`). `fullName` is `null` when the account
records none — a fact about the account, never a failed read (a failed read
throws). A surface never shows it directly: it shows the user's **profile
name** (below).

`hostHome` (core) — a sibling `liveValue` keyed `host-account.home`:
`{ dir, standIn }` — the folder `~` stands for, absolute (the account's
`HOME_DIR`, or the `home-folder` config's `standIn` folder when an instance
sets one: the showcase film's, so the real home is never shown). `standIn`
tells a surface not to name anything of the machine outside it (Files drops
its checkout, volume and Trash places and the storage meter). host-fs expands
the server's `~` against the same folder through `setHostHomeResolver`,
installed by `machine/`. It follows the config (`changes: "notified"`). A separate value, not a field of `hostAccount`, so a surface that
only needs `~` (the file explorer) never waits on — or fails with — the
full-name spawn. Read with `useLive(hostHome)` directly — no wrapper hook. Declared `needsMachine` ("Your home folder") and
served by `machine/`: a host without the computer has no home folder, so its
readers get the `unavailable` arm.

## The read

The portable `server/` serves `hostAccount` through the **`HostAccountSource`**
host service (`{ read(): Promise<HostAccount> }`). Its providers:

- `machine/` (the desktop) — the OS account, below;
- `plugins/guest` (a host without the computer; a host provider, which no
  composition bundles) — a fixed demo account, so the Pages brand
  renders in the demo as it does on the desktop.

The desktop read is `machine/internal/read-account.ts`, through `infra/spawn`'s
`spawnCaptured`:

- macOS: `id -F <user>` — the account's RealName;
- elsewhere: `getent passwd <user>` — the first comma-separated part of the
  GECOS field, `&` expanded to the capitalised login name (exit 2, "no such
  key", is an account without a name);
- the login name itself is `os.userInfo().username`.

The parsers are pure (`machine/internal/parse.ts`) and tested on their own.

## Freshness

Read once per backend, on first demand, and shared — the account a process
runs as does not change while it runs, so the value is served on the external
arm and never notified. A failed read is not cached: the next load retries.

## Reading it

`useHostAccount()` (web) is `useLive(hostAccount)`: `loading` until the value
arrives. Render a loading state there — never a placeholder name, which would
be a claim about the user that then reverses itself.

## The user's name on screen

ONE setting says how equin names the user — `profileNameConfig` (core, the
`profile-name` config, an ordinary config_v2 setting edited in Settings → Config):

- `displayName` — the name to show; empty (the default) is the account's full
  name, else its login name;
- `showName` — off: no surface shows a person's name at all (for a screen
  shared or recorded — the showcase film's seed turns it off).

`profileName(account, settings)` (core) folds the two into a `ProfileName`:
`{ kind: "named", name }` or `{ kind: "anonymous" }`; `firstName` / `nameInitial`
are the one spelling of a name's first word and initial. `useProfileName()`
(web) reads it live, `loading` until both halves are known. Every surface that
names the user reads it and renders an `anonymous` user generically, never as a
placeholder name: the Pages workspace ("<first name>'s pages" / "My pages", its
tile the initial / the pages glyph), and the Claude accounts' names
(`claude-cli/accounts` serves them under a generic, numbered name while the name
is off — the accounts file itself untouched).
