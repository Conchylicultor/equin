# warmup

Declared heavy boot warm-ups: `defineWarmup({ name, description, scope, run })`
registers a catch-up step (a backfill, an index build) that runs once per boot,
after the host is already serving. Mount the token in `register: [...]`, exactly
like `defineJob`.

- **On every host.** The barrel is portable. Its `onSettled` (`drainWarmups`,
  not exported) drains every registered warm-up in the serving host's settled
  phase (`server-core`'s `runSettledPhase`): the desktop's `serve` after its
  signal handlers are installed, the browser host without blocking readiness
  (`BrowserHost.settled`). No composition root names warm-ups, and an `exec`
  child has no path to the settled phase, so it never runs one.
- **Admission is the host's answer** — the `WarmupHost` host service
  (`warmup.host`): `runs(scope)` and `withSlot(fn)`. Never `isMain()`: a browser
  host's namespace is its composition name, so `isMain()` is false there and
  every `host` warm-up would be skipped silently.
  - Desktop: `warmup#machine` — `host` scope on main only (N worktree backends
    share the machine), every body under the host-wide heavy-read slot
    (`withHeavyReadSlot`, reentrant).
  - Sole host (the browser composition, portable boot tests):
    `warmup/plugins/sole-host` — every scope, no slot. Excluded from desktop
    apps by the composition config's base-exclusions row.
- **Executor.** A bounded concurrency gate (`WARMUP_CONCURRENCY`), a macrotask
  yield before each body, the host's slot around it; a throw is logged and the
  drain continues (a warm-up is an optimization, never a correctness
  dependency). Each run is recorded in memory (`warmupRunOf` / `onWarmupRun`) —
  `background-arm` shows it in Background activity.
- **Profile.** Each body is a `warmup:<name>` span under the framework's
  `settled` span.
- **A barrel turning portable brings its warm-ups to the browser.** A warm-up
  declared in a server barrel runs on every host that boots it; one that needs
  the computer belongs in a `machine/` half.
