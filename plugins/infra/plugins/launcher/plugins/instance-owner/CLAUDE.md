# launcher/instance-owner

One equin per account
([ADR](../../../../../../research/2026-07-02-global-adr-single-instance-per-user.md)),
enforced where a second copy could take over the first.

Everything an install sets up is per account, not per checkout: the data root
(`~/.equin` — database cluster, deploy registry, the main namespace), the
background service's label, the Keychain entry, the app bundles. A second
checkout of the repo (a second `curl … | bash` into another folder, a copy)
shares all of it, so letting it start or deploy main silently replaces the
running app — possibly with older code on a database already migrated past it.

## Who holds the account

`instanceClaims()` reads the two records that name the checkout, each written
by a different step — either one is enough:

| source | record | written by |
|---|---|---|
| `deploy` | main's `spec.json` `server` (`paths/core` `mainNamespaceOwner`) | every main deploy |
| `service` | `-main-checkout` in the installed background-service job (`login-services` `installedJob`, through its light `cli` barrel) | `./equin start`, before the first build |

A record naming a folder that no longer exists claims nothing (the code was
moved or deleted): the next checkout to start or build takes over, as before.
`judgeInstance` is the pure verdict — `unclaimed` / `this` / `other`; any record
naming another checkout wins, since two records disagreeing is a takeover half
done.

## Who refuses

`assertThisInstance(checkout, action)` throws an `InstallerNoticeError` (the
installer message rules, `installer-notice`) when another checkout holds the
account:

- `./equin start` — with the main checkout it starts from, after the host
  checks, before anything is built, registered or restarted;
- `./equin build` on branch `main` (the `--allow-main` deploy, the converge run
  included) — with the checkout it builds, right after the branch guard. A
  feature branch in a second clone still builds its own namespace
  (`paths` `checkoutRef` names it by its directory); only main is the account's.

`install.sh` reads the same two records itself (`other_instance`), before
anything is downloaded — the early, cheap refusal; these two are the guard every
other route goes through.
