# gateway-logs

The gateway's log directory (`logs/gateway`, handed to the Go process as
`-log-dir`) and the contract of the **service log relay** — in a leaf, because
the database plugins the launcher boots name their daemons' log files here and
the launcher imports them (a declaration in the launcher itself is a cycle).

- `gatewayLogs` — the data dir, with its log claims for `paths:logs-claimed`:
  `gateway.log` and each namespace's `<name>.log` (deleted with the namespace,
  `gateway/namespace_logs.go`), `services/<service>.log`, and the truncated
  `gateway-stdio.log`.
- `GATEWAY_LOG_BOUND` — every channel's rotation (50 MB × 5), and
  `serviceLogFile(service)` — a supervised daemon's channel,
  `services/<service>.log` (`PG_LOG_FILE`, `PGBOUNCER_LOG_FILE`).
- `serviceLogTarget(argv)` (`core`) — what a start script reads off its argv:
  `--log-fd <n>`, the relay pipe the supervisor hands it, or `absent` behind a
  gateway older than the relay.
- `adoptLegacyLogSync(legacy, live)` — the one-shot move of a daemon's pre-relay
  log file into its channel's rotation, on a fresh start (task-1793827129-t489g4
  deletes it).

How the relay works and what it trades: `gateway/CLAUDE.md` → "A service's
output: the log relay". The Go constants are pinned here by
`gateway-logs:in-sync`.
