# image

Images on the host filesystem, made cheap to show. A folder of camera photos is
dozens of 30-megapixel JPEGs; drawing each one's original for a thumbnail or a
screen-sized view downloads and decodes 7 MB per tile. This plugin serves
smaller copies and the true sizes, so the image viewer
(`primitives/overlay/image-viewer`) can draw a grid, a strip or a slideshow
from copies and keep the original for zooming in, copying and downloading.
Plan: [`research/2026-10-07-primitives-image-viewer-fast-large-folders.md`](../../../../../../research/2026-10-07-primitives-image-viewer-fast-large-folders.md).

| Endpoint | Answers |
|---|---|
| `GET /api/host-fs/image/resized?path&edge&v` (`hostFsImageResized`, build URLs with `hostResizedUrl`) | the image with a long edge of `edge` (one of `RESIZED_EDGES`: 160 … 2560), never enlarged, EXIF-rotated upright; JPEG q82, WebP when it has transparency. 404 / 403 / 400 (a directory, or an edge outside the set) / 422 (an unreadable archive member) / **415** (sharp cannot decode it — the client shows the original) |

- **Sizes (live only):** `hostFsFolderImageSizes` (`host-fs.image-sizes`,
  core; served by `machine/`) — the same question as host-fs's
  `hostFsListing` (`{ path? }`), key-range-paged by name (code-point order,
  `limit` 200, `maxLimit` 10 000), only the read pages' headers measured,
  pushed from `watchHostDir` while read; failures are refusals (`invalid-path`,
  `missing`, `denied`, `not-a-dir`, `unreadable-archive`).
- **Which files.** `RESIZABLE_EXTENSIONS` (core): jpg, jpeg, png, webp, avif,
  tif, tiff. Not SVG (it scales by itself), not GIF (a copy would drop the
  animation).
- **Versioned URLs.** `v` is `resizedVersion({ mtimeMs, size })` from the
  listing. When it matches the file's current version the response is
  `immutable` for a year, so a revisit costs no request; otherwise it is served
  `no-cache` (the copy is always of the current file).
- **Cache.** `host-fs-resized-images` (`data-dirs/`): host-wide, one file per
  `sha256(path, version, edge)`, written to a temp file and renamed. Concurrent
  requests for one copy share one build (`packages/inflight`); builds are
  bounded per process (`packages/semaphore`, half the cores) — only the backend
  whose page is browsing images serves them. A hit touches its file at most
  daily; the daily `host-fs-image.sweep` removes copies unused for 30 days, then
  the oldest past 1 GB.
- **Archives.** A member (`…/x.zip/a.jpg`) is read whole through host-fs's
  `openHostFile` and resized the same way.
- **sharp** (libvips, N-API, prebuilt per platform) decodes a 30 MP JPEG at a
  reduced scale in ~140 ms; HEIC and RAW are not in the prebuilt build and
  answer 415.
