# user-path

A path the user (or their config) chose — not one the app owns — is a
`UserPath` (core: a branded `string`; `UserPathSchema` reads one from JSON,
`asUserPath` brands one). Such a path may sit in a folder macOS gates behind
Files & Folders (Downloads, Documents, Desktop, removable and network
volumes). While macOS's "allow access?" prompt is up, a **synchronous** fs call
on it (`realpathSync`, `readdirSync`, `statSync`, `opendirSync`, …) blocks the
backend's whole JS thread until someone answers: on 2026-10-11 one
`realpathSync` of `~/Downloads` froze main for 5.5 h
(`research/2026-10-30-apps-sonata-midi-folder-probe-off-the-js-thread.md`).

## Where the brand comes from

- **Config** — a `dirPathField` value is a `UserPath` (`fields/directory-path`).
- **Requests** — host-fs's `resolveHostPath` / `resolveOrRefuse` /
  `resolvedOrNull` answer one, and every host-fs read, watch and action takes
  one from there down (`openHostFile`, `locateHostPath`, `watchHostPath`, …).
- **Derived paths** — `asUserPath(join(dir, name))`, `asUserPath(await
  realpath(p))`: re-brand what you build from one before handing it on.

## The lint: `user-path/no-sync-fs`

Type-aware, so the taint is the TYPE and crosses files through declarations
only (a type-aware rule may not read another file's source —
`research/2026-10-17-global-lint-keyed-on-what-it-reads.md`).

- **sync** (everywhere) — a user-chosen argument to a `node:fs` `*Sync`
  function. User-chosen: branded, or derived from a branded value through
  `node:path` (not `basename` / `extname`), `realpath` / `readlink`, a
  template literal, a `+`, a conditional or logical branch, `await`, a cast, or
  a `const` of the file bound to one of those.
- **widened** (in `server/`, `machine/`, `central/` files) — a user-chosen value
  handed to a place typed as a plain `string`: a parameter of a backend
  function, a return, an annotated binding or an assignment to one. That is
  where the brand would be lost, so the next function could no longer be
  checked: declare the receiver `UserPath`. A library (`node:path`, a logger)
  and a `core/` / `shared/` function (no `node:fs` there —
  `boundaries/no-platform-api`) are not widening, nor is a field of an object:
  a result or wire shape carries the path out, not into another fs call.

The fix for a **sync** report is the async call, bounded so no caller waits on
the prompt: the pattern is Sonata's MIDI folders
(`createFolderStatusStore`: probes deduplicated per path, a refresh waits
`PROBE_ANSWER_MS`, a folder still unanswered reads `checking` and publishes
its answer when it lands). host-fs is already async throughout.

**Not covered** (best effort, against accidents): a path laundered through a
non-path library call (`String(p)`, `p.slice(0)`), an object field, or a
path that never carried the brand — a watcher event naming a file inside a
user folder, say. Brand those where they enter.
