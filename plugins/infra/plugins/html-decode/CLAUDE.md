# html-decode

Reading HTML as values, on every host, decoded **exactly once**.

## The portable scanner (`scanHtml`, `rewriteStartTag`, `replaceElementText`)

Plain JS on [`htmlparser2`](https://www.npmjs.com/package/htmlparser2)'s
streaming `Parser`, so it runs where Bun's `HTMLRewriter` and `DOMParser` do
not (a browser worker). Use it for any new HTML read.

```ts
import { scanHtml, rewriteStartTag, replaceElementText } from "@plugins/infra/plugins/html-decode/core";

scanHtml(html, {
  elements: { meta: (el) => el.attr("content") }, // decoded; undefined ⇔ absent
  text: { title: (text) => text },                // whole text, decoded once
});

const r = rewriteStartTag(html, "html", (el) => el.setAttribute("data-x", "y"));
// { kind: "edited", html } | { kind: "absent" }
replaceElementText(html, "title", "New title"); // same result shape
```

- **No raw read exists.** The parser runs with `decodeEntities: false` and the
  scanner decodes every value itself through `decodeHtmlText`, so a caller
  cannot reach undecoded source, nor decode twice. Text is accumulated per
  element and decoded once when it closes (a reference can straddle text
  events).
- **Elements:** each start tag of the name, in document order; tag and
  attribute names lower-cased; a repeated attribute reads its first
  occurrence. `<script>`, `<style>`, `<textarea>` and an HTML `<title>` hold
  text, never tags; comments report nothing. **Text:** every element of the
  name reports on close, an empty one as `""`.
- **Edits splice by source index** and touch only the bytes they change:
  `rewriteStartTag` rewrites a set attribute in place as `name="value"` (the
  author's spelling of the name kept, `&` and `"` escaped), appends a new one
  after the last, and leaves the tag's other attributes and whitespace as
  written; `replaceElementText` escapes `&`, `<`, `>`. Both edit the FIRST
  element of the name only. `replaceElementText` throws when that element has
  no end tag of its own.
- It replaced `HTMLRewriter` in `apps/prototypes/files` with byte-identical
  output over every local prototype (a one-off parity run, since deleted).

## Reading through Bun's `HTMLRewriter` (`decodeHtmlText`, `readHtmlAttr`)

Bun's `HTMLRewriter` is a **streaming rewriter over source bytes: it decodes
NOTHING.** Both `el.getAttribute(name)` and text chunks come back as raw,
undecoded HTML source. Verified experimentally:

```
<meta property="og:title" content="single &#x27;quote&#39; &amp; amp">
  → getAttribute("content") === "single &#x27;quote&#39; &amp; amp"

<title>tag &#x27;quote&#x27; &amp; amp</title>
  → text chunk === "tag &#x27;quote&#x27; &amp; amp"
```

That is not a bug in the rewriter — a rewriter's job is to hand markup back
verbatim so the untouched parts round-trip byte-for-byte. It IS a trap for every
caller that treats a rewriter read as a *value*: a scraped title renders as the
literal `d&#x27;entretien`, and a URL attribute carrying `&amp;` resolves to a
wrong query string. Every value read out of an `HTMLRewriter` therefore needs
decoding **exactly once**, and this plugin is the single place that happens.

`HTMLRewriter` is a Bun global, so it is a platform value
(`boundaries/core/platform-apis.ts`): a portable closure may not use it. The
remaining users are host-only (`machine/` halves and not-yet-portable
`server/`s).

```ts
import { decodeHtmlText, readHtmlAttr } from "@plugins/infra/plugins/html-decode/core";

// The only sanctioned way to read an attribute in a rewriter handler.
const content = readHtmlAttr(el, "content"); // string | undefined (undefined ⇔ absent)

// For text chunks, which must be accumulated FIRST and decoded once at the end.
const title = decodeHtmlText(accumulated);
```

Reading attributes only through `readHtmlAttr` is what makes correctness
structural rather than a rule to remember: a newly handled attribute cannot
forget to decode, because there is no undecoded read to reach for.

`decodeHtmlText` decodes **once**, not to a fixed point: `&amp;#x27;` becomes
`&#x27;`, never `'`. The source really did encode a literal `&#x27;`, and
re-decoding would corrupt it.

> **Text chunks: accumulate, then decode.** The rewriter splits text on its own
> buffer boundaries, so a character reference can straddle two chunks. Decode
> the whole accumulated string once at `lastInTextNode`, never per chunk.

## Shape

Core-only (no `web/`, no `server/`): pure string functions usable from any
runtime. `readHtmlAttr`'s element parameter is typed **structurally**
(`{ getAttribute(name: string): string | null }`) rather than against Bun's
ambient `HTMLRewriterTypes` global, so the primitive depends on no ambient type
name and is unit-testable with a plain object.

Decoding is delegated to [`entities`](https://www.npmjs.com/package/entities)
(`decodeHTML`) — zero-dep, and the decoder behind parse5/cheerio — for both
attribute values and text, as the `HTMLRewriter` callers always did.
