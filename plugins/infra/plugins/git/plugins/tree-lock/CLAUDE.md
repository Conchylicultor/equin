# tree-lock

`git merge --ff-only` rewrites a checkout's files one by one, in index order. A
process that loads code from that checkout at the same moment — main's
supervised-exec children (`worktree.prepare`, `database.fork`, …) boot the plugin
graph straight out of main's live tree — can read some modules at the old commit
and others at the new one. 2026-11-05 16:15:49Z: a push fast-forwarded main to
`eecaca44b5` (carrying `848075b3ae`); two children booting at that second loaded the new
`runtime-sdk/machine` (importing `WorkspaceReclaimed`) beside the old
`workspace/server` barrel (not yet rewritten — `runtime-sdk` < `workspace`), and
died with `SyntaxError: Export named 'WorkspaceReclaimed' not found`.

So the tree is a reader/writer lock, one per checkout, in that checkout's own git
dir (`<git dir>/<lock dir>/tree.lock`). A `core/` barrel, since its first reader is
`server-core`'s exec boot, below every `server/` barrel:

- `holdTreeRead(root)` — shared. Taken by a process for as long as it LOADS code
  from the tree (`server-core`'s `runExec`: from the registry import to the end of
  the module load waves), released before anything slow (the ready barrier).
  In-process fast path: one open + non-blocking `flock(LOCK_SH)`; only while a
  writer holds it does it wait, in a `flock-wait` child.
- `withTreeWrite(root, write)` — exclusive. Wraps every git command that rewrites
  main's working tree (`./equin push`'s two fast-forwards). Waits for the readers
  (seconds); a reader held past 120 s is a wedged boot and fails the write loudly
  with nothing written.

`treeLockPath` answers `null` for a root that is not a git checkout (a compiled
release): nothing rewrites it, so both calls do nothing there.

Not covered: modules a process imports lazily after boot, and the serving
backend's own boot. And a lock cannot fix version skew — after a fast-forward,
children boot the NEW commit while main's backend and database still run the old
one until main's auto-build lands.

**An interim bound, not the end state.** It covers the dominant writer (push)
and the most frequent loaders (~200 exec boots a day on main), at the cost of a
few seconds' wait for a fast-forward. The structural fix — main's runtime runs
from an immutable per-commit snapshot, so nothing it loads can be rewritten
under it and skew has no spelling — is task-1793896151-00k5ry; once it lands,
delete this plugin.
