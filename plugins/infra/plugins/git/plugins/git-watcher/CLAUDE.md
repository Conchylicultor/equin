# git-watcher

## Two signals per advance — pick deliberately

The watcher offers two ways to react to a ref moving, and choosing the wrong one
is a real bug class (it left the `pushes` ledger permanently frozen in every
worktree backend — see `research/2026-08-18-global-push-ledger-git-projection.md`).

| | `refAdvanced` (durable) | `defineRefReaction` (in-process) |
| --- | --- | --- |
| Delivery | trigger event → job in the shared graphile pool | the watcher's own callback, awaited |
| Backends | **main only** (`isMain()` gates `emit`) | **every** backend |
| Survives a crash | yes, with retries | no |
| Can queue behind other work | yes | no |

Use `refAdvanced` for work that must survive a crash, may be slow, or wants
retries. Use a reaction for a cheap, idempotent refresh whose correctness is
independently guaranteed by an on-read fallback — and which therefore must not be
able to queue behind unrelated work.

**A reaction that needs durability is a job in disguise.** It has no retry, no
persistence, and it is skipped entirely while the backend is down. Only register
one when a missed run costs latency rather than correctness. A reaction that
throws is reported through `reportServerError` and does not stop its siblings or
the durable emit that follows.

## How an advance is heard: the ref files are followed, not the refs tree

`git-watcher.refs` is a `writesWhileOpen` follow (kqueue on macOS: ~150 ms,
parcel's native debounce) of exactly the tracked loose refs and `packed-refs`
(`server/internal/ref-files.ts`) — never a recursive watch of `<common>/refs`,
which on macOS is an FSEvents stream as late as fseventsd's queue (25 s seen on
main, 2026-11-09).

- **An advance** renames `<ref>.lock` over the loose file: heard as the ref file
  changing. Any change re-reads every tracked sha.
- **`packed-refs`** is followed: a packed ref's deletion rewrites only it.
- **A branch name with `/`** lives in a nested dir git removes once its last
  loose ref is packed. A missing nesting dir is followed as an entry of the
  deepest existing dir; its appearing, or a followed dir going
  (`WatchedDirGoneError`), re-plans the follow (new one opened before the old
  closes — they share each dir's subscription).
- **A ref deleted** → its sha goes `null` (announced). **A branch renamed** is
  its old name deleted; tracked refs are computed at boot, so the new name is
  followed only after a restart.

Measure: `scripts/measure-ref-delivery.ts`; in the app, the
`watch-delivery:kqueue` slow-ops row's `git-watcher.refs` variant.
