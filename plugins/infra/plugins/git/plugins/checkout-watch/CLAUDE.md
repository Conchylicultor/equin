# checkout-watch

`acquireCheckoutWatch(root, { refs, onChange }) → Promise<release>` — the one way a live
value watches a git checkout while it is read. It hears the working tree AND the
git dir, which a linked worktree keeps outside its root (`<main>/.git/worktrees/<name>`
for HEAD and the index, `<common>/refs` for the branches): watching only the root
misses a `git add`, a commit that leaves the tree untouched, and a `main` advance
that moves a merge-base.

- One watch per checkout root, refcounted; built on `infra/file-watcher`'s
  `acquireDirWatch`, so a linked worktree's git dirs ride the main checkout's
  watch when that one is open.
- Each change is tagged `area: "worktree" | "git"`. Dropped as noise for every
  reader: `objects/`, `logs/`, `worktrees/` inside a git dir, anything in a
  `node_modules`, and **every working-tree path git ignores** — a build's `dist/`,
  the main checkout's `.claude/worktrees/**`. An ignored, untracked path cannot
  move a checkout's state, so no reader recomputes on it. The answer is git's own:
  one `git check-ignore --stdin` per batch, shared by every reader (no second
  matcher to drift from `.gitignore` / `info/exclude` / `core.excludesFile`). A
  tracked file matching a pattern is kept, as `git status` shows it. When the
  check fails, the batch is delivered unfiltered and the failure is thrown. A
  reader that wants raw tree churn uses `acquireDirWatch`.
- **Refs are declared, not all heard.** The refs dir is shared by every worktree
  of the repo, so hearing all of it means recomputing on every other worktree's
  commit, rebase or push. A reader hears its checkout's **own branch** (HEAD's
  target, re-read before a batch that rewrites HEAD is filtered), the branch's
  upstream when `refs.upstream`, and the full ref names in `refs.also`
  (`refs/heads/main` for a merge-base). A ref change carries `ref`; HEAD, the
  index and `packed-refs` reach every reader. Edited-files asks for
  `{ also: ["refs/heads/main"] }`, file-explorer git status (ahead/behind) for
  `{ also: [], upstream: true }`.
- **Each reader's reaction is coalesced** (`packages/coalesce`): return the
  work's promise, and one call runs at a time for that reader while the batches
  landing meanwhile fold into one trailing call. A slow reader holds only its own
  later batches.
- `root` is the checkout's toplevel; validating that is the caller's job.
