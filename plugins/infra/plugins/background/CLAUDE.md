# background

What does the app run on its own, and does the person know? Every mechanism
that runs work without being asked — jobs, warm-ups, timers — reports into one
catalog, and Debug → Background activity lists it.

- `catalog` — the provider registry (`defineBackgroundKind`, server and
  central), the merged live values, recent runs, Run now, trigger sources, and
  the page.
- `timer` — `defineTimer`, the one sanctioned in-process interval, and its
  provider.

The other kinds are arms living beside the primitive they list: jobs
(`infra/jobs/background-arm`), warm-ups (`infra/warmup/background-arm`), file
watchers (`infra/file-watcher/background-arm`) and long-lived processes
(`infra/spawn/daemon/background-arm`).
