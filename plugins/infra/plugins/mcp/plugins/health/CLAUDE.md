# mcp/health

The health report's **MCP server** row: is this backend's MCP server (the one
the agents it launches connect to, `.mcp.json`'s `EQUIN_PARENT_URL`)
answering them?

## The signal (`infra/mcp` server, `mcp.health`)

Observed from real traffic, never probed: `handleMcpRequest` records each
request's outcome (a throw or a 5xx is failing; a JSON-RPC error answer is the
server answering), and `runContribution` records each per-connection
contribution's run (a throw lists it as degraded, its next clean run clears
it). In memory, per process; pushed only when it changes, so a healthy
server's traffic pushes nothing.

## The row (`web/`)

`critical` while the latest request failed, `attention` while a contribution
is degraded, `ok` otherwise (also before any agent connected). One line; what
failed lives in its `remedy`, `InvestigateMcpButton`: the standard launch
popover listing it, launching a System-category agent briefed with it
(`web/internal/investigate-prompt.ts`). A remedy is drawn only while the row is
not ok, so the row folds into the quiet card while fine.
