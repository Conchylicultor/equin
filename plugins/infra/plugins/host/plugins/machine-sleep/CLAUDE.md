# machine-sleep

The machine's sleep clock as a live value, so a browser can tell a nap from work.

- `core` — `machineSleep` (`liveValue("machine.sleep")`) holding `SleepNow`:
  `{ boot, asleepMs, wakeAtMs } | null`, where `null` means the platform cannot
  tell (never "did not sleep"). `SleepNow` is the one definition every consumer
  shares (op-log's fold takes it as its `sleepNow` parameter).
- `server` — owns the reading: `publishSleepReading()` re-reads
  `packages/sleep-clock`'s `readSleepClock()` and tells its listeners only when the
  reading changed (a new boot, a new `wakeAtMs`, or ≥1 ms more sleep — read jitter
  never pushes). In practice it pushes once per wake. `currentSleepReading()` /
  `onSleepReadingChanged()` are what the machine half serves from. Over the
  sleeps it has placed: `sleptDuring(start, end)` (slow-ops, the stuck-turn
  bound, a pre-stamp boot line), `awakeSpanStart`
  (the job sweeper's grace) and `wakeBefore(at, within)` — the sleep whose wake
  came just before an instant (the reports engine stamps it on an occurrence). A process
  knows the sleeps it lived through, plus the one before its first reading:
  the clock's own last sleep (`kern.sleeptime` → `kern.waketime`), so a
  backend booted on a wake still takes that nap off what crossed it. It stays in
  `server/` because health-monitor's server calls `publishSleepReading()`.
- `machine` — serves the value (`source: "external"`, `live/machine`): the
  declaration is `needsMachine` (the clock is the computer's), so a host without
  one (the demo's browser worker) answers it `unavailable` without a request.
- `web` — `useSleepNow()`: the `useLive` result, loading until the first reading.
  `useSleepNowForFold()`: the same reading as op-log's `sleepNow` fold parameter —
  `null` (the fold's "unknown": no live tail sleep) while loading, failed or
  unavailable, so
  a live op surface never blocks on it. Used by the op detail, the op Gantt and
  the op-status banner/chip.

**Why a live value.** The browser cannot read the OS clocks, and a sleeping op's
last event can be hours old, so nothing it already holds says the machine just
slept. The backend publishes the reading.

**Which tool for an age** (an awake timer, a stored stamp, or this
process's `sleptDuring`): `packages/sleep-clock/CLAUDE.md`. A timer that a
sleep does not spend is `packages/deadline`'s `armAwakeDeadline` (this plugin's
own `setAwakeTimeout` folded into it).

**No poller here.** The health-monitor process sampler, which already ticks every
10 s, calls `publishSleepReading()` on each tick and once at startup. A wake
reaches the browser within one tick.
