# idle

Whether nothing on the machine is working — no agent, no op, no duress —
sustained for `IDLE_SUSTAIN_MS` (10 min). Design:
`research/2026-11-11-global-test-status-page.md` §7.

- **Blockers are contributions.** `IdleBlocker({ id, read })` (server): a
  reading is `{ busy, label, recheckAt }`. The core names no contributor
  (today: `idle/ops`, `idle/duress`, `conversations/idle-blocker`). A blocker
  calls `requestIdleEvaluation()` when its input changes (a watch, a trigger);
  what no event announces (a lease lapsing) it answers as `recheckAt`.
- **One evaluator, the host singleton** (main). `host-idle.evaluate`
  (singleton, serial) reads every blocker, runs the pure `nextIdleState`
  (busy → settling → idle), writes `host_idle_state` and emits
  `host.idleBegan` / `host.idleEnded` in one transaction. A blocker whose
  read throws counts as busy and fails the run after the write (loud, safe).
- **The sustain timer is its own job**, `host-idle.wake` (singleton,
  `runAt`). A singleton enqueue with `runAt` does move the pending row
  (graphile `add_job`'s default `replace` mode), but a RUNNING row releases
  its key: a blocker's request landing mid-evaluation is a fresh row due now,
  and the evaluation re-enqueueing ITSELF with `runAt = sustain end` would
  push that request minutes out. Moving the wake row never moves a request.
- **`hostIdle`** (`host.idle`) is refused `main-only` off the host singleton,
  and `host_idle_state` is excluded from forks: a fork's copy is never
  evaluated again and would claim an idle host forever.
- **Opportunistic ops don't count.** An op run under `EQUIN_OP_OPPORTUNISTIC=1`
  (the idle test batch) is marked on its marker and op-log record; the ops
  blocker skips it, or it would end the idle period it runs in.
