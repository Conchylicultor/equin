# in-process

An in-memory `JobQueue` (`infra/jobs`' host service) for a host without the
desktop's graphile queue — the browser composition and the portable boot test.
The desktop never boots it: it is in `base-exclusions`
(`plugin-meta/composition`), and `jobs#machine` provides the desktop's queue.

- **A row runs in this process when it is due**, through the jobs plugin's
  portable row runner (`UNSAFE_runJobRow`: schema-drift check, the durable
  `ctx`, suspension, failure classification, step/wait-log teardown). No slot
  ladder, no advisory lock, no hold-class deadline.
- **A `tx` enqueue inserts its row only once the transaction commits**
  (`database`'s `afterCommit`), so a rollback drops the job with the caller's
  writes, as on the desktop.
- **A `jobKey` collapses onto the pending row holding it** (graphile's replace
  mode): newer payload and due time, same id.
- **Retries** back off like graphile's (`exp(min(attempts, 10))` s); a
  permanently-failed row stays listed `dead` until retried or removed.
- **Scheduled jobs** fire on a one-shot timer to their next due minute (the
  portable crontab reading in jobs `core`), re-armed after each tick — every
  resolvable schedule, since this host is its own instance.
- **Nothing survives a reload**: a durable queue for the local app is follow-up
  work.
