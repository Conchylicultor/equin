# root-migration

`./equin data-dir migrate`. Design: [`research/2026-10-26-global-equin-data-dir-migration-v2.md`](../../../../../../research/2026-10-26-global-equin-data-dir-migration-v2.md).

- `cli/plan.ts` — the pure planner (`planRootMigration(facts)` → refuse / done / migrate) and `describePlan`, which the dry run prints and `--apply` executes. Every state is a unit test in `plan.test.ts`.
- `cli/migrate.ts` — gathers the facts and applies the plan.
- `cli/checkouts.ts` — the `staleCheckouts` fact: every checkout of the repo whose HEAD lacks `paths/core`'s data-root-layout module (a capability probe, one `git cat-file --batch-check` for all heads).

**The legacy links outlive pre-move code.** Code from before the move resolves the legacy root (`~/` + `LEGACY_IDS.dataDirName`) and the legacy backups dir unconditionally. Removing those links while any worktree still has such code lets its `./equin`, hooks, backend or a relaunched agent create a real legacy dir, a split every later start refuses (`DataRootSplitError`). So while `staleCheckouts` is non-empty the plan keeps every legacy link (`keptLinks`) whatever the leftover scan finds. It also defers the migrated-with-link rewrite: stale code would write legacy paths through the link again. The plan names a sample of the stale checkouts and how to clear them (rebase + `./equin build`, or delete the worktree). A rerun once none is left removes the links.

## Plugin reference

- Description: `./equin data-dir migrate`: moves an install's data root from the legacy home dir to ~/.equin (and its local backups beside it) in one run, with every other process of the app stopped — rewrites every stored copy of the old path (each database in the cluster, the files under the root, Claude Code's transcript dirs), drops the cache entries that hold it, removes the legacy name once a scan finds none left and no checkout of the repo still runs code from before the move (otherwise keeps it as a link and names those checkouts), and relabels the gateway's login service dev.equin.gateway. A dry run by default; --apply executes.
