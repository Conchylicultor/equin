# repo-root

`REPO_ROOT` — the checkout this code runs from (main's or a worktree's) — and
the rule that makes it the only way a file reaches the repo.

## Why a file may not count `../` to the repo

`join(import.meta.dir, "../../../../..")` encodes how deep the file sits. When
`./equin plugin move` changes a plugin's depth, the chain points somewhere
else, and the mover cannot rewrite it: the path is computed, not written.
Nothing fails until the code runs — a test can read the wrong directory and
pass. So:

- **Reach the repo through `REPO_ROOT`** and a repo-relative path:
  `join(REPO_ROOT, "plugins/packages/plugins/flock/core/index.ts")`. A
  repo-relative path is a path mention the mover rewrites.
- **`repo-root/no-depth-counted-path`** (this plugin's `lint/`, repo-wide)
  rejects a path built from the file's own location (`import.meta.dir` /
  `.dirname` / `.url` / `.filename` / `.path`, `__dirname`, `__filename`,
  through `join` / `resolve` / `normalize` / `dirname` / `fileURLToPath` /
  `new URL(rel, base)` / `.pathname` / `.href` / `"../".repeat(n)`, and a
  `const` bound to one) whose `../` climbs out of the file's own plugin. A
  `../` that stays inside the plugin is fine: the plugin moves as a whole.
  A path it cannot read (a computed segment) is not reported.

## How the root is found without counting

`core/internal/repo-root.ts` holds its own repo-relative directory as a
literal (`OWN_DIR`) and strips it off its real location
(`new URL(".", import.meta.url)`). That literal is a path mention of this
plugin, so moving it (or an ancestor) rewrites it, and
`relocate:moved-plugins-unnamed` fails on a stale one; if it is still wrong,
the module throws at load rather than answering a wrong directory.

Read from `import.meta.url`, not Bun's `import.meta.dir`, so vitest and eslint
under Node answer the same. A `bun build --compile` binary flattens every
module to `/$bunfs/root`, which has no checkout around it: `REPO_ROOT` is that
virtual root there (a read under it finds nothing, as a read of an un-shipped
repo file must; `launch.ts` points the reads a release needs elsewhere by env).
Never imported by code that runs in a browser page: a page's module URL is not
a checkout path, so the module throws.

A leaf (its one import is `user-path/core`'s types), so `tooling/lint/core`'s
`lintRuleCreator` and web-folder tests can import it without reaching
`paths/core`, which reads the home directory at module eval.
