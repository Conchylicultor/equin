# infra

## Do not add a new top-level infra plugin without approval

This list is already too long to scan. Never create
`plugins/infra/plugins/<new-name>/` on your own initiative — ask first. Prefer
nesting the new plugin under the one it is built from, or grouping it with its
relatives under an umbrella.

This holds even when a plan or design doc already names a `plugins/infra/plugins/<new-name>/`
path, or the user approved that plan: an approved plan is not approval of the
top-level slot. Before creating the folder, re-think where the plugin belongs —
the plugin it is built from, an existing sub-umbrella, or a domain umbrella
outside `infra/` — and pick the more relevant home. Only create it top-level if
the user explicitly approved that specific placement.
