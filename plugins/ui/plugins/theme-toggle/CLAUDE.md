# theme-toggle

Light/dark, as one switch row inside the **quick-theme popover** — not a second
toolbar button beside the palette one.

It used to be its own `ActionBar.Item`, which put two controls answering the same
question ("how should this look?") side by side in the global bar, one of them
spending a permanent toolbar slot on a single boolean. The popover is where that
question is already being answered, so the scheme now sits above the swatches it
paints.

It stays its own plugin rather than a few lines inside `quick-theme`: the panel
assembles itself from `QuickTheme.Section` contributions and names none of them,
so the scheme row is added, reordered or removed without touching the panel.
`config/ui/theme-engine/quick-theme/section.jsonc` places it directly under the
theme catalog — that file's own rationale is that the catalog is what the popover
is for, so it leads and this one row follows.

`select="switch"` draws the indicator in the row's TRAILING cell, so the leading
`MdDarkMode` costs the panel nothing: the footer's ⚙ already opens the icon
column (control-panel invariant #4).

Two switches: **Dark mode** reads the RESOLVED colour mode (`system` collapsed
against the OS, live listener), which is what the class applier uses — so it
always describes the scheme actually on screen, and a click sets an explicit
light / dark; **Match system** is on while the effective setting is `system`.
Both edit the scope the document wears — the focused app's per-app override, or
the global setting when no app fills the surface — through theme-engine's hooks,
which name that scope once; when this control picked the scope itself it wrote
the active app's layer while `<html>.dark` read global, and flipping it changed
a value nothing painted from. `e2e/theme-toggle-verify.ts` opens the popover and
asserts the class and the switch move together.

The customizer's **Color mode** section (`ThemeCustomizer.Section`) edits the
two layers by name: the current app's choice (`Default` = its
`defineApp({ colorMode })`, or Global / System / Light / Dark) and the global
setting. Neither forks the app's theme.
