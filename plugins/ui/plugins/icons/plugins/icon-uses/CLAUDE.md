# icon-uses

Where a module uses the icon constructors (`symbol` / `brand` / `seti`):
`iconUsesIn` follows each constructor import through ESLint's scope analysis,
`isIconRefModule` answers whether an import specifier names the module that
exports them (the icons core barrel, or `icons/core/icon-ref` by a relative
path).

A leaf with no imports. Two file scans
run it (`codegen/core/icon-manifest.scan.ts`, `icons/check/icon-uses.scan.ts`),
and a file scan's records are keyed by its module's whole import closure
(`plugin-meta/plugin-records`): importing these from the icons barrel keyed
every file's icon records by the barrel's 15 modules — the Lucide map, the
glyph tables, the style keys — so each icon added anywhere re-keyed ~26k
records of the shared store. Keep it free of imports.
