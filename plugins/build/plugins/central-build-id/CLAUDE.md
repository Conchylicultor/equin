# central-build-id

Central's code build: the identity a central live value is shaped by, so a tab
whose schema rejects one can judge it by build (`contractVerdict`) the way it
judges a worktree value — another build is skew (the tab is out of date: the
`client-outdated` state and the Reload advice), the same build a real bug (a
loud crash).

A worktree server names its web graph; central cannot. It serves every
worktree, each on another build, and has no web dist of its own. What shapes
its values is its own code, so its build is the **source digest of its entry
closure** (`packages/source-digest`, over `CENTRAL_ENTRY` — the walk follows
the registry's literal imports, so it reaches every central plugin):

- **Central's half** (`central/`) digests the entry it runs (`Bun.main`,
  realpath'd, which must end with `CENTRAL_ENTRY`), started at register and
  not awaited (a closure walk takes seconds; central serves every worktree's
  auth), then names it through central-core's `setCentralBuildIdentity` — the
  `graph` on central's ack frames and read envelopes. Until it lands, or if it
  cannot be computed (logged), central names no build: every verdict is
  `unknown`, a decode failure stays loud. Central adopts a deploy without
  restarting only when nothing its closure loads changed
  (`build/restart-skip`), so one digest per process stays true.
- **The build's half** (`cli/`'s `centralBuildOf(root)`): `./equin build`
  digests the checkout's own `CENTRAL_ENTRY`, beside the web artifacts
  pipeline, and compose bakes it into the page (`VITE_CENTRAL_BUILD`). A
  release's page bakes none (it ships no central). A digest that cannot be
  computed fails the build.
- Both sides digest through ONE spelling of the set (`shared/`'s
  `centralCodeSet`), and `boot:closure-digestable` reads the same
  `CENTRAL_ENTRY`, so the two can only differ when the code does.

The tab names it to central on every sub (`build`) and HTTP read, and judges
every central value against it (live-state's `clientBuild(kind)`). Since a
reload brings the tab the central build its page bakes, the page's identity
covers it (compose's `pagePins`, `identity: "covered"` → the `.build-graph`
every stale-tab comparison reads): a redeploy that changes only central code
marks open tabs stale, and the Build tray advises a reload.

Like the web graph, it is whole-closure: any central change is a new build.
Compose also writes it beside the page as the dist's `.central-build`, which
the backend serving the page names on its ack frames (`central`,
`build/server-build-id`) — what a reload brings. A tab whose central build is
not central's is out of date (`skew`, reload) only when that is central's
build; otherwise — a worktree whose checkout's central code differs from
main's (which central runs) — it is `deploy-skew`: no reload fixes it, so the
tab says so and the failure is reported (live-state CLAUDE.md).
