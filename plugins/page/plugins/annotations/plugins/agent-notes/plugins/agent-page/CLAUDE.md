# agent-page

The **page** kind of agent-authored block, beside the `<agent-inline>` card its
parent plugin declares: a sub-page an agent creates inside an existing page and
may write in full. What the user sees:

- in the parent page, an ordinary sub-page row (icon, title, the rail chevron
  that expands it inline) tinted with the agent-notes card's blue wash, even
  collapsed — and, expanded, a blue CARD around the row and all of the page's
  content, so the agent's lines never read as the parent's prose (`page/sub-page`
  draws it from this plugin's tint);
- at that row's right edge, always visible, a chip naming the conversation that
  **created** the page — clicking it opens that run;
- the same tint on the page's row in the Pages sidebar (no chip there);
- `/agent-page` (and the gutter `+`) turns the caret's line into one, its other
  words becoming the title (`notes /agent-page` → a page titled `notes`, like
  Turn into → Page); an otherwise-empty line gives an untitled page;
- an `<agent-inline>` card's rail menu offers **Turn into → Agent page**: the
  card becomes an agent-authored page in place, its FIRST line (its first child)
  the title and its other lines the page's content. The card keeps its id and
  its position, so its authorship rows (keyed by block id) carry over and the
  creator chip names the conversation that wrote the card.

Design: [`research/2026-09-11-page-agent-pages.md`](../../../../../../../../research/2026-09-11-page-agent-pages.md).

## Not a block type, and web-only

An agent-authored page is a `page` row whose `data.author` is `"agent"`
(`PageDataSchema`, `page/editor/core`). The page's own kind is read straight off
its row by the markdown serializer, both renderers and the write policy, which is
why it is `data` and not a side table; a second page TYPE would have meant
widening the ~46 sites that test `type === "page"`. So this plugin declares no
block type, has no `core`/`server` half, and `annotations:parties-declared` does
not apply to it.

It contributes to three generic seams and names nothing else:

- **`PageReference.Decoration`** (`page/page-reference`) — `applies` reads
  `author === "agent"`, `tint` is the card's `bg-info/10` wash (plus its
  `--scrim`), `component` is the creator chip. The sub-page row and the sidebar
  apply it without naming "agent".
- **`Editor.InsertAction`** (`page/editor`) — the `/agent-page` entry, listed
  right after the agent-notes card (`after: agentNotesBlock.type`).
- **`Editor.TurnInto`** (`page/editor`) — the "Agent page" target, declared
  `from: agentNotesBlock.type`, so the block-actions menu offers it only on an
  agent card (a void container, whose menu otherwise has no Turn into at all).

  Both call the server's turn-into-page op with `kind: agent-page`, which
  chooses the author at birth, through one function (`turnIntoAgentPage`) that
  differs only in the title: the line's words for the insert, `{ fromFirstChild:
  true }` for the card — the server consumes the card's first child (its text
  becomes the title, its row is trashed, its own children take its slot) in the
  same transaction. A first child with no text (a nested card, a sub-page) is
  kept, and the page is untitled.

  Every later data write keeps the author; only the page header's kind control
  ([`apps/pages/page-author`](../../../../../../../apps/plugins/pages/plugins/page-author/CLAUDE.md),
  the `setPageKind` op) changes it afterwards. That control is also the only
  mark on the OPEN page — by the user's choice there is no banner.

## The chip is the FIRST authorship record

The creator is the earliest row of the page's authorship
([`authorship`](../authorship/CLAUDE.md), `useAgentNotesCreator`): writes inside
an agent page stamp the page, and minting one stamps it as its own creator. A
page a human made with `/agent-page` has no record, so it shows no chip until an
agent writes into it — that first writer then counts as the creator.

Neither of the chip's two reads answers "nobody" for "not known yet": the
authorship record, then the conversation it names (`useConversation`, its
`conversations.by-id` read, which finds any conversation however old), each
wait as a chip-sized shimmer. A page whose creating conversation was deleted
shows no chip; a failed read shows the inline error with Retry.

## The name is taken

`apps/pages/agent-origin` already calls e2e-created pages "agent pages" and
exports `AgentPageRow`. In code, say **agent-authored page**, and never reuse
that symbol. The two are unrelated signals: an agent-authored page sits in the
sidebar's Private section, tinted; the Scratch section holds the e2e-origin
ones.
