# page/map

The `/map` block. It draws every overlay the `PageMap.Layer` contributions
derive from this page's blocks, on the vendor-neutral `MapView` (`plugins/map`).
It names no block type and no map vendor.

- **Nothing is stored** (`data` is `{}`, markdown `<map/>`). Overlays are
  recomputed from `useBlockEditor().blocks` on every render: the flat,
  optimistic list, including collapsed children. Only rows with the map block's
  own `pageId` count, so inline-expanded sub-pages stay off this page's map.
- **`PageMap.Layer`** = `{ id, overlays(blocks) → { overlays, unplaced },
  describeUnplaced(n), emptyHint? }`. It is a pure function, so it needs no
  hooks. `unplaced` counts items the layer owns but cannot draw (no coordinates).
  The block prints `describeUnplaced(n)` under the map instead of dropping them
  silently. Overlay ids are namespaced `<layer>:<id>` by `derivePageMap`, and a
  layer's `blockId` is how a pin click finds its block.
- **Pin click**: marks the pin active, then scrolls to the block's row (via
  `blockContentScope`, never `document`) and selects it with
  `useSelectionControl`. A block inside a collapsed toggle has no row, so the
  pin only turns active.
- **`PageMap.Action`** = a render slot of `{ id, component({ pageId }) }`:
  compact controls about the page, drawn as one row floated (`Pin`) in the
  map's top-right corner (Places' "Open in Places"). The block names none of
  them; with no contribution nothing is drawn there. Ordered by the slot's
  reorder layout like every render slot. The row is handed to `MapView` as its
  `controls`, so it sits inside the map's chrome boundary and wears the tiles'
  scheme (light over Google's light tiles, in a dark app too); and the block
  owns its reveal (`primitives/hover-reveal`: `hoverRevealGroup` on the map's
  frame, `hoverRevealTarget` on the row) — shown while the map is hovered or
  an action has keyboard focus, so a contribution never hides itself.
- The map's frame is stamped `morphOriginProps` (`primitives/pane`): an
  action that opens an app with a morph (`useMorphFromElement`) grows it out
  of the whole map, not out of its own small button.
- Read-only surfaces (version-history preview) still render the generic
  placeholder. A read-only map needs a page-forest context that `read-only-view`
  does not provide.

## Plugin reference

- Description: Map block type: draws every located item on the page on an interactive map (through the map primitive), with overlays derived on each render from the page's blocks by contributed PageMap.Layer functions — so the map cannot drift from the page and names no block type. Contributed PageMap.Action controls float in the map's top-right corner, handed the page id. Map block type: registers its (empty) `data` schema at the server write boundary.
