# restart-storm

The restart-storm benchmark: what one hot restart costs the tabs that have the
backend open. Main restarts on every push; each restart is a cold start of the
successor while every open tab reconnects and replays its whole sub set at
once. Track: the "Main restart storm: what a push costs open tabs" page
(Mental model → Performances → Boot performance).

```bash
./equin build      # the script drives (and restarts) the deploy this checkout published
./equin run plugins/debug/plugins/profiling/plugins/restart-storm/e2e/restart-storm.ts \
  [--handoff off|on] [--iterations 3] [--paths /agents,/pages,…] [--contexts 1] \
  [--settle 8000] [--timeout 180000] [--out "$EQUIN_SCRATCH/storm.json"]
```

**Own worktree only.** It restarts the backend it targets
(`POST /gateway/worktrees/<ns>/restart`, the deploy's own hot restart) — never
point it at main.

- `--handoff off` (default, the headline): turns the epoch handoff off for the
  run through live-state-snapshot's `live-state-handoff` config (an agent
  write, reverted when the run ends). The successor inherits nothing: every
  replayed sub loads, the cold case.
- `--handoff on`: a DIAGNOSTIC — what the handoff hides. Never the headline.
- `--paths`: one tab per route, all in one browser context (one SharedWorker,
  one live socket, as a person's tabs share one). `--contexts K` repeats the
  set in K contexts (K sockets).

## Per iteration

1. Every tab open and settled; restart requested (`t0`).
2. The gateway boots the successor beside the old backend, swaps it in once
   ready (the request answers), drains and stops the old one — its sockets
   close, every tab reconnects and sends its replay `sub-batch`.
3. Per tab (socket tap, `primitives/networking/e2e`, timestamped events): when
   its socket closed, reopened, the replay left, and when every replayed entry
   was answered (`sub-ack` = reloaded, `up-to-date` = answered from what the
   server holds, `sub-error`).
4. Right away, the successor's runtime profile (counts from process start:
   every loader's wall split into gate waits and own work, the gates' totals,
   the jobs) and boot profile (CPU so far); then waits for its `settled` span
   and reads the boot profile again before the next restart.

## The numbers

Wall offsets from `t0`: gateway spawn requested, successor process start,
onReadyBlocking done, ready (gateway's `readyObservedAt`), swap, first tab
socket closed, tabs reconnected, onReady done, tabs settled, settled phase done.

- **HEADLINE ready → every tab settled** — the exit criterion's number.
- **socket closed → every tab settled** — the window a tab shows stale data
  (until its socket closes, the old backend still serves it live).
- Per tab, per key (replay → answer, max / mean) — which reads the tabs wait on.
- **CPU** — process user+system ms at the boot checkpoints (`cpuMs`, recorded
  by server-core's profiler) and at the read (`cpuMsNow`): boot to ready,
  ready to onReady done, to tabs settled, to settled done. Spans overlap on
  one loop, so CPU is split by phase boundary, never per span.
- Boot spans: the slowest onReadyBlocking / onReady / warm-up / onSettled.
- Gates and loaders: wait vs own work — a loader with high wait and low self is
  head-of-line blocked, not slow.
- **The replay's read path, per key** — from the successor's flight window
  (`GET /api/debug/profiling/flight-window?maxCompleted=4096`, read right after
  the tabs settled): every `sub` span (≥ 5 ms, the ring's floor) that started
  after the socket closed, as replay → span start (the frame's transit plus
  everything the server's thread ran before handling it), span wall, and the
  wall split into own work, child work and gate waits by layer. A tab's
  replay → answer minus those two is the send and the thread's backlog after
  the read.
- **Event-loop stalls** between the first replay and the last tab settled —
  the loop probe's registered stalls (a turn > 100 ms late), from the same
  window: how long the thread ran one piece of work at a time.
- `--out` also keeps each iteration's raw flight window (`flight`), for a
  split the printout does not make (gate occupancy over time, the background
  work sharing the thread).

## What a worktree restart does not reproduce

Host-scoped warm-ups (`infra/warmup` `scope: "host"` — plugin-tree,
restart-skip closure, …) and other `isMain()`-only work run on main only; read
them off main's own last boot (`GET /api/debug/profiling/boot` on main, or
`get_runtime_profile` with `worktree: "equin"`), read-only. The tab set is a
choice (`--paths`), not the user's real tabs.
