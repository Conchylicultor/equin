# boot

The server boot profile (Debug → Profiling → Boot), and the check that keeps
the boot's import closure free of build tooling:
`boot:closure-no-dev-tooling` measures the backend's static closure (its bin
plus every server/machine registry barrel, dynamic imports cut) and fails on
typescript, eslint, @typescript-eslint, prettier, babel or vite. Whatever a
server or machine module imports at module scope is paid on every boot. Code
that needs the tooling at runtime loads it with `await import(…)` where it
runs (`worktree/reclaim`, `serve-composition`'s reset, `type-check`'s
spawn-worker).

`boot:closure-digestable` measures the same entries with literal dynamic
imports FOLLOWED (code loaded later is still code the process runs) and fails
on any module `sourceDigest` would refuse — an `import(x)` / `require(x)`
whose path is computed (read with source-digest's own `computedLoads`). Each
finding is charged to the entry (the bin, or one registry barrel) whose own
subgraph reaches it; the owning plugin fixes the edge or holds it as debt in
its `exempt/`. Build tooling runs out of process (a supervised `argv` body, a
CLI command), never in the serving backend. Why: a deploy can skip
restarting a backend only when the code it runs is measurable —
`research/2026-11-05-global-backend-code-identity.md`.
