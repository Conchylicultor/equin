# logs

Debug → Logs: **where to find and read what the app logs.** Two panes, side by
side (Miller columns): the catalog of every log of a worktree, and a reader for
one. Design: `research/2026-10-15-debug-logs-v2.md` (prototype
`proto-1792068187-7q6uwt`).

## The catalog — `debug.logs.catalog` (params `{ worktree }`)

Every log the viewer can open, from four places (`server/internal/sources.ts`,
in this precedence when two share an id):

| scope | what | from |
|---|---|---|
| `worktree` | each `defineLogSink` channel — listed even before it has written | `getFileSinks()` (sinks are declared at import) |
| `backend` | the backend process's own stdout / stderr | the gateway's capture, `logs/gateway/<worktree>.log` |
| `host` | each `defineFileSink` outside the logs folder (the op log, …) | `getFileSinks()` |
| `undeclared` | a file in the logs folder no sink declares — a browser `clientLog` channel, or a writer that bypassed `defineLogSink` | `readdir` |

Each entry carries its description, its rotation bound and its kept files
(`statHistory`: size, birth, last write), so the list shows size against bound,
rotated files kept, a "rotates in ~X" estimate and the last write. Pushed by a
dir-hub watch of the folders (throttled 500 ms), never polled.

The declarations are this backend's own: they describe another worktree's folder
too, up to code that differs between the checkouts. Host sinks declared only in
CLI processes (`build-progress`, `check-progress`, `signal-origin`) are not
declared in a backend and so are not listed.

## The reader — `debug.logs.lines` (query `{ worktree, log, at }`)

A key-range-paged value: one log's lines, newest first, across the **whole kept
history** (`file-sink`'s `readHistory`), each keyed by its rotation-stable
position. The DataView pages it by viewport (`useLivePagedValuePaging`), so
scrolling down crosses into `.1`, `.2`, … — each line says which file holds it —
until the oldest kept line; nothing silently ends at a rotation. A watch of the
log's folder pushes new lines into page 0. Search and the stream / file filters
run over the loaded rows.

`at` reads back from an instant (`historyCutAt`) instead of the newest line, the
newest line at or before it selected. The URL carries it: `;wt` on the catalog,
`;at` on the reader — `/debug/logs;wt=<worktree>/ch/<log>;at=<ms>` is how a
report links to its evidence. A log never declares its readers; the link goes
from the report to the log.

## What belongs here and what does not

A log is evidence: prose and transcripts read by people and agents. A sink whose
lines a screen parses into a chart or a list (the health samples, slow-op
markers, boot events, duress episodes) is a table with `defineRetention`
waiting to happen — it shows here like any file, but its screen should read a
table. The op log is already right: the file is the journal CLI processes
without a DB append to, and screens read its `op_log_ops` fold.
