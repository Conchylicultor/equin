# backend-liveness

Notices a **frozen backend from outside its process**. Plan:
`research/2026-10-30-debug-backend-liveness-frozen-backend-watchdog.md`.

On 2026-10-11 main's JS thread froze 1 s after boot, for 5.5 h, and nothing
was reported: every in-process detector (stall-monitor, stuck-spans,
boot-monitor) froze with it, and boot-watchdog only judges boots that never
write `ready`. A process cannot report its own freeze.

## Detect on central, file through the outbox

- **Probe — `central/`.** A central timer (`debug.backend-liveness-probe`,
  every 15 s) reads the gateway fleet and asks each `starting` / `running` /
  `restarting` backend (central excluded) for `GET /api/health/ready` **on its
  own socket**, 5 s timeout. Any HTTP answer, whatever its status (503 while
  booting included), was written by the backend's JS thread. Never through the
  gateway: that would cold-start a stopped backend and count as activity
  against its idle sweep.
- **Judge — `detect.ts`** (pure). Frozen once unanswered for
  `FROZEN_AFTER_MS` (60 s) of observed-awake time; re-reported every
  `HEARTBEAT_MS` while it lasts; one closing report when it `answered`,
  `exited` or was `paused`. A short stall that recovers reports nothing.
- **File — `reports/outbox`.** Central has no reports table, so it writes each
  `backend-frozen` report with `fileReportFromProcess`; main drains the outbox
  on the file change. Fingerprint `backend-frozen:<worktree>`.

A frozen worktree is reported within ~1 min of crossing the threshold. **Main's
own freeze waits in the outbox until main's thread runs again** (or the next
main process boots): nothing can file into main's reports while main is frozen.

## What is not a freeze

- **Machine sleep.** Only an interval the observer was awake through counts
  (≤ 3 × cadence between ticks, and the tick's own probes not overrunning).
  A backend answers at once on wake, which resets the streak.
- **A paused process.** On a miss the probe reads `ps -o stat=` for the pid in
  the gateway's socket sidecar (`<socket>.pid`): `T` (SIGSTOP, a debugger) is
  paused, never frozen.
- **A stopped backend.** Not in a probed state, or its process gone: not
  judged; an open episode closes `exited`.
- **A boot not listening yet.** No socket file: `unserved`, not judged. A bound
  socket that refuses (full accept backlog) still counts as unanswered.

## Reproduce

`POST /api/debug/backend-liveness/freeze {"seconds": 240}` on a **worktree**
backend (refused on main) blocks its JS thread with `Atomics.wait` right after
answering. A `backend-frozen` row appears in main's `reports` about 75 s in,
re-filed each minute, and a final `answered` one after it resumes.

## Not covered

Central itself is not watched.
