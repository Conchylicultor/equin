# machine-usage

Where the machine's CPU and memory go, by who the processes work for — a closed
list of buckets (`MACHINE_USAGE_BUCKETS`): your Chrome, agent ops, the agent
browser, the agents, the backends, Postgres, other. Two readers of one
attribution (`core/internal/attribute.ts`):

- **Now** — `sentinel.machine-usage`, sampled when the Machine watcher card
  opens (`ps` %cpu, the kernel's decaying average).
- **Then** — main's `machine-usage.owner-sampler` timer writes one line every
  30 s to the `health-owners` log (`OwnerSampleSchema`): each bucket's CPU in
  cores over the window and memory in MB, plus the largest processes by memory
  and by CPU, named. Debug → Health charts it beside the host sample
  (`health-host`), so a contention window reads as who, not only how much.
  Read it on demand with `scripts/owners-now.ts`.

**Who owns a process.** Roots claim their whole subtree, in precedence order:
the agent browser host, each running op's CLI process (op markers — so an
agent's build is the op's), then processes heading a bucket by name — Postgres
and PgBouncer (executable name), the app bundle (`equin.app`: the gateway, and
through it every backend), a `equin · server · …` / `equin · central` backend,
an `equin · agent · conv-…` agent (and its `equin · conv-… · <title>` Claude
Code) — the names `packages/process-name` gives, read back with its
`processKindOf`. The rest is Chrome by its bundle, else other.

**CPU is CPU time, reaped children included.** On a busy host ~30 processes
start every second (hooks, `git`, `rg`, test workers); a `ps` snapshot lists
none of them, and diffing two snapshots attributed 23 % of what the host
actually ran (2026-11-06). Each process's kernel record
(`packages/proc-rusage`, through the host's `peerProcUsage` probe) carries the
CPU of every child it reaped, so a window charges each live process its own
delta plus its reaped-children delta, less the last-seen total of every
descendant that vanished since (those windows already charged it; a process
that exits rolls what it reaped into its parent, so the subtraction goes to the
nearest ancestor still alive). Measured: 88 % of the host's busy time
attributed. Missed: another account's processes' children, orphans launchd
reaps, the kernel itself.

**Memory is the physical footprint**, which counts a page each process has
touched in shared memory once per process. Postgres is the case that matters,
and the only one measured to matter (Chrome's and the Bun processes' footprints
equal their private memory): every backend charges the part of the cluster's
shared segment (`shared_buffers` and the rest, ~210–240 MB) it has touched, up
to ~156 MB each. So the Postgres bucket **over-states ~4–5×** (2026-11-06:
11.3 GB reported, ~2.4–3.5 GB real). Its real private part averages ~11 MB a
session; a busy one reaches ~70 MB, mostly the allocator keeping freed memory.
Measured, with the exact method that would count it once and its cost:
`research/2026-11-06-global-postgres-idle-connections-memory.md`.
