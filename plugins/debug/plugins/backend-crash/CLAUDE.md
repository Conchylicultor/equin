# backend-crash

A backend that **dies by a signal** is a report. Main segfaulted three times
between 2026-11-06 and 11-08 (inside @parcel/watcher's kqueue thread —
research/2026-11-08-infra-main-segfaults-parcel-watcher.md) and nothing said
so: each one read as a silent restart, its jobs reclaimed a minute later, its
tabs queueing to reconnect.

## Why the gateway files it

A process killed by a signal runs none of its own handlers — no `exit`
listener, no crash sink, no outbox write. Bun's crash handler only prints its
panic block (the fault, a `bun.report` link) to stderr and re-raises. The one
process that sees the death (the wait status) and holds that stderr is the
gateway, which spawned it. So `gateway/crash_report.go` writes one entry into
the report outbox (`reports/outbox`), and main drains it into `reports`:

- **any** gateway-spawned backend: every worktree, main, central;
- only a signal **the gateway did not send** (`backend.signalled`): its stop,
  hot-restart drain and readiness-deadline kills are its own acts, already in
  `gateway.log` (and a deadline kill is boot-watchdog's report);
- not an exit-code exit: that process ran its own handlers and reported itself
  (boot-events' boot crash, the reports engine's process sink).

**Main's own crash** is drained by the next main backend, on becoming the
outbox's drainer at boot. The entry waits in the outbox until then.

## The evidence

The payload (`core/kind.ts`) carries the signal, pid, start and death times,
the binary's name and the dead process's own last 60 stderr lines — read from
a pipe the gateway owns, until EOF (bounded at 2 s: a grandchild holding the
pipe open marks the tail possibly cut short). From the tail the kind reads
Bun's `panic:` line and its `bun.report` link.

**bun.report is not enough on its own.** Bun encodes a frame only when it is in
Bun's own binary; a frame in any other image (a native addon, a system
library) or in JIT code is written `_` and decodes as "unknown". All three
2026-11 crashes decoded to nothing but unknown frames. The task points at the
**macOS crash report** instead (`~/Library/Logs/DiagnosticReports[/Retired]/
<executable>-<date>.ips`): every thread, every frame, symbolized with its
image — that is what named `watcher.node`'s `KqueueBackend::compareDir`.

## A cross-language contract

The writer is Go, the schema TypeScript. `gateway/testdata/backend-crash-entry.json`
is the entry the Go writer builds (its test asserts exactly that) and the
entry `core/kind.test.ts` parses with the outbox envelope and this kind's
schema. Changing either side fails the other's test.

**Takes effect on a gateway restart.** `./equin build` neither rebuilds nor
restarts the gateway; until `./equin start --force` the running one files
nothing (the health report's Gateway drift row says it is stale: the launcher
passes it a new `-report-outbox-dir` flag).

Literals `backend-crash` (the kind, the Go `backendCrashKind`) and the
fingerprint `backend-crash:<worktree>:<signal>` are persisted — do not rename.
