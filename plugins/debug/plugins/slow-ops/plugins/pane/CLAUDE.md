# slow-ops

Debug app pane showing a **global, ranked overview** of slow operations — the
aggregate counterpart to the per-crash list in Debug → Reports. Slow ops are
metrics that often hide a *structural* issue (several slow routes bottlenecked on
one query), so this view ranks them by **aggregate impact** (total time across all
occurrences) rather than scattering them.

Reads the parent plugin's live collections (its `core`), so the table updates
as slow ops land — no Refresh button. `slow_ops` and `slow_op_callers` are fed
by the recorder's change producers, coalesced to one flush per 2 s.

**Aggregates tab** (`SlowOpsView`): a `DataView` over
`liveDataSource(slowOpsList)` — the `slow-ops.ops` scroll window, 100 slim rows
a page. Each row shows the operation (its `operationKind` badge + operation
label), the occurrence **count**, the **total**, **wait** (summed per-layer
waits), **max** and **last** durations (ms), and the **last-seen** relative
time. Default sort is **total time descending**; sort, filter and search run in
SQL server-side, and the Kind filter's options are a facet of the whole table.

**Detail pane** (`slowOpDetailPane`, route `/debug/traces/op/:id`, opened by a
row): the op's header (counters, first / last seen, the newest trace), then
its **callers** — a `DataView` over the `slow-ops.callers` window scoped to
the op's key, paged by total time, every caller named — then its waits by
layer, variants, measures and the 10 most recent samples with the box state
each tripped in.

The **Cluster** tab is contributed by the sibling `cluster` sub-plugin into the
same `SlowEvents.View` slot; it fans out across every worktree DB fork.
