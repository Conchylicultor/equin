# tests

Debug → Tests: every test file of this checkout with its last known status.
Design: `research/2026-11-11-global-test-status-page.md`.

## Verdicts are harvested, never run for the page

`./equin test` (framework/cli/test) digests the files it runs before the op
(`test/plugins/digest`) and, as the run's leader, writes one record per run to
the host-global `test-runs` dir. Every backend ingests that dir (`machine/`
`ingest.ts`: a watch plus one pass at boot; a pass skips opIds its database
already holds; a malformed record is reported once, an unknown `v` is left for
a newer reader). Nothing runs on push.

## Status = the results on the file's CURRENT digest

A result is keyed by (path, digest). The checkout's own digests
(`test_checkout_digests`) come from `./equin test-digest`, run as the
`tests.checkout-digests` supervised job only while the page is open: the
`tests.digest-generation` value's `whileSubscribed` asks for it on subscribe
and on every advance of main, and the child answers `unchanged` when the tree
hash is the stored one. The status rule is `deriveStatus` (core, pure);
`recomputeFileStatus` (server) is the ONLY writer of `test_file_status`, run
after each ingested record (its files) and each new digest set (all).

- Not known yet is a state: until the first digests land the page shows the
  computing state, never an empty tree.
- `test_file_results` is capped to the newest 32 per file daily
  (`tests.results-cap`), never TTL'd: a stable file keeps its only verdict.

## Run now / Investigate

Run now / Run stale / Run all post `tests.run-now`, which starts the
`tests.run-now` supervised job: an ordinary `./equin test <paths…>` with
`EQUIN_TEST_ORIGIN=run-now`. Its verdicts arrive like any run's, through its
record. Progress is not shown per file (JUnit exists only at the end): the
toast says how many files were started. Investigate (failing / flaky only)
files a task about the `test-file` subject under the Tests category.
