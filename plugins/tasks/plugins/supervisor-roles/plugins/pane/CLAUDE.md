# pane

The Supervisors UI (design: the wiki page "Supervisor roles — design";
prototype `proto-1794509585-7ca910`).

## Reads

Every read is a bounded read of tasks-core's `taskWindow` through the ONE
definition of a backlog and a session (`roleBacklogWhere` /
`roleSessionsWhere` in supervisor-roles core) — `web/internal/reads.ts`.

- **Backlog counts are a window, never a grouping.** The sidebar's trail
  holds them on every page. A window is routed row by row; a `:groups`
  grouping recomputes and re-pushes on every write to the tasks tables (a
  `tasks.tree.v2:groups` no-op-push report fired while it was one). One
  window over every role's backlog (oldest first, capped) is folded by owner
  into each role's count and oldest age.
- **Session tallies** (done / running / dropped of a session's tree, by the
  exposed `mandateSource`) are three groupings for all of a role's listed
  sessions at once — mounted only on a role's page, never one per row.

## Writes

Role settings `PATCH /api/supervisor-roles/:id` (inline, autosaved by
`useEditableField`); the shared prompt through `useSetConfig`; Launch
`POST …/:id/sessions`; Adopt `POST …/:id/backlog/:taskId/adopt` (into the
live session, launching one when none is live — `plugins/sessions`); Drop
the task patch; re-route `PUT /api/tasks/:taskId/supervisor`.
