# sessions

A supervisor role's sessions: launching one, and the role powers' tools. A
child of `supervisor-roles` because it needs `tasks/server`
(`armTaskAutoStart`), which the parent cannot import: `tasks`' `add_task`
imports the parent.

- `POST /api/supervisor-roles/:id/sessions` (`launchRoleSession`, body `{
  model? }`) → `{ taskId, started }`: the live session when one is (`started:
  false` — re-armed if it never ran, so a failed arm cannot hold the slot),
  else a new root task — `<name> session`, the role's prompt as its
  description, mandate `supervisor-role`, owned by the role — armed at once.
- Tools (gated on `supervisorRole`, i.e. a role session's root):
  `backlog` (the role's backlog, oldest first), `adopt_task` (a backlog task
  moves under the session root, its own interactive mandate cleared so it
  inherits the session's, its owner row dropped — the root carries the role
  — all under the task's row lock; then watched like a filed task and
  armed), `route_task` (hand a backlog task to another role or the
  fallback; never a session root).
  Editing and dropping use `edit_task` / `drop_task`, whose scope the parent's
  `MandateReach` widens to the role's tasks.
