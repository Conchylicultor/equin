# supervisor-run

The supervisor workflow (Autonomous tasks track, Mode step;
`research/2026-10-29-tasks-autonomous-run-mode.md`, renamed from
"Autonomous"). The only supervisor-specific code — a composition of the
building blocks:

- **Entry point:** the Supervisor launch option (`TaskLaunch.Option`, draft
  only), shown on every new-task composer: Interactive (unset, the pill rests
  as its icon) or Supervisor. No push variants: how a run pushes is the
  user's brief or preprompt.
- **Mandate:** its server apply states `supervisorMandate()`
  (`tasks/mandate-presets`) on the task it files. Everything else follows from
  the grants, scoped by where a conversation sits (`policy`'s grant scopes):
  - **The root's own conversation** is an ordinary interactive conversation —
    pushes when asked, may `exit_clean`, owes no report — with more powers:
    it files now / after / manual (`tasks.file`), watches what it files
    (`watch.children`) and the whole tree (`watch.tree`, taken over by each
    new conversation there), and may compact itself (`context.compact`).
  - **The workers below it** file and watch the same way, report
    (`report.required` + stop gate) instead of exiting, and may compact.
- **No supervisor prompt:** the user writes the brief (and picks a preprompt).
  Not inherited: filed tasks are covered by the root's mandate already.
