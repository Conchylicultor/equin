# message

Agents messaging agents — a supervisor replying to a worker's report ("push
it", "fix X first", "redo"), which watch events alone could not do (they flow
up, nothing flowed down), and any agent reaching another by its task or
conversation id. Plan: `research/2026-10-30-tasks-message-agents.md`.

- **`message_agent({ to, text, reopen? })`** — visible to **every** agent.
  `to` is a task id or a conversation id, of ANY task (`agentOf`, one SQL
  read); either way the message goes to that task's latest conversation, the
  one `list_agents` and event turns name. The message is an `event` turn
  (`submitTurn`; the ledger wraps it in `<equin-event>`, drawn as a system
  card) typed **now**, as a person's turn would be — not held through
  `automatic-turn` readiness (user decision): a working agent reads it at its
  next tool step, a held question is withdrawn for it. A `gone` agent is
  resumed first (`resumeConversation`; a blocked resume is refused with its
  reason); a hibernated one is resumed by `submitTurn` itself. Refused to
  oneself, to an id naming nothing, and to a task no agent ran on.
- **`reopen` is a supervisor's power, on its own tree.** A `done` (closed)
  agent is refused unless the call says `reopen: true`, and reopening needs
  the `message.tree` grant (the `capability` leaf sub-plugin, so mandate
  presets reached from `conversations` grant it without a cycle) AND a target
  task under the caller's mandate root (`isUnder`). The agent ended its own
  work, and a sender usually writes from a view taken just before ("landed,
  now close" racing the close) — resuming on that reopened the settled task
  and settled it again, a duplicate `settled` each time.
- **`list_agents`** — granted by `message.tree`: every task of the mandate's
  whole tree (`mandateOf(task).rootTaskId` down `folder_id`, siblings and the
  root's agent included) an agent ran on, with its latest conversation and
  how it stands (`agentsUnder`, one SQL read). Settled agents (task done or
  dropped, or the agent closed) pile up in a long-lived tree, so by default
  only the `SETTLED_SHOWN` (10) started last are listed — the rest are one
  `+N older settled agents` line; `all: true` lists every one. The caller's
  own line is never hidden.
- The answer comes back the way the target already reports (its reports and
  flags, as watch events, to a supervisor) — the tool does not wait.
