# message

An agent messaging the other agents of its task tree — a supervisor replying
to a worker's report ("push it", "fix X first", "redo"), which watch events
alone could not do: they flow up, nothing flowed down. Granted by the
`message.tree` mandate capability (the `capability` leaf sub-plugin, so
mandate presets reached from `conversations` grant it without a cycle).
Names no workflow. Plan: `research/2026-10-30-tasks-message-agents.md`.

- **Scope is the mandate's whole tree** (`mandateOf(task).rootTaskId` down
  `folder_id`) — the same tree `task_tree` shows, siblings and the root's
  agent included; never the caller's own conversation.
- **`list_agents`** — every task of the tree an agent ran on, with its latest
  conversation and how it stands (`agentsUnder`, one SQL read).
- **`message_agent({ to, text })`** — `to` is a task id (its latest
  conversation) or a conversation id. The message is an `event` turn
  (`submitTurn`; the ledger wraps it in `<equin-event>`, drawn as a system
  card) typed **now**, as a person's turn would be — not held through
  `automatic-turn` readiness (user decision): a working agent reads it at its
  next tool step, a held question is withdrawn for it. A `gone` / `done`
  agent is resumed first (`resumeConversation`; a blocked resume is refused
  with its reason); a hibernated one is resumed by `submitTurn` itself.
- The answer comes back the way the target already reports (its reports and
  flags, as watch events) — the tool does not wait.
