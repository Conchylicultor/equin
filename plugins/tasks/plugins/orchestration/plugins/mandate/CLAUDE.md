# mandate

A **mandate** is a policy on a task stating what an agent may do inside its
subtree. It is resolved **nearest-wins** up `tasks.folder_id`: a task with no
mandate of its own works under its nearest ancestor's. Every root task states
one (`tasks_root_has_mandate` CHECK, and tsc on `CreateTaskInput`), so every
task resolves to a policy. Plan:
`research/2026-10-28-tasks-mandate-building-block.md`.

## Pieces

- **Policy types** — the `policy` leaf (`plugins/policy/core`):
  `defineCapability`, `mandatePolicy(grants)`, `MandatePolicySchema`.
- **Storage** — the `tasks.mandate` jsonb column (server-only, off the wire and
  off `tasks_v`), with `nearestMandate` / `setMandate` / `clearMandate` in
  `tasks-core` (import them from there; this plugin re-exports nothing).
  `clearMandate` refuses on a root; `updateTask({ folderId: null })` copies the
  effective policy onto a task that had none.
- **Capabilities** — declared (core) and described (`Mandate.Capability({ cap,
  describe })`, server) by the plugin that owns the behaviour. This plugin names
  none of them.
- **Enforcement** (server):
  - `mandateOf(taskId)` → `{ kind: "found", rootTaskId, policy } | { kind: "none" }`.
  - `grantOf(cap, conversationId)` → the parsed value, or `null` when not
    granted; a stored value the cap's schema refuses **throws**. Concurrent
    calls for one conversation collapse (`createInflight`), since every gated
    tool's `when` runs on each MCP request.
  - `granted(cap)` — an `Mcp.tool` `when` gate.
  - The `mandate` `Mcp.instructions` section: `## Mandate` and one
    `describe(value)` line per granted capability.
- **Debug** — `mandate.capabilities` (core, a fixed `liveValue`): every
  contributed capability. A live collection of mandates is not served yet:
  `mandate` is a server-only column, which a collection cannot project.

Named compositions of grants (the interactive preset) live in
`tasks/mandate-presets`; automations state theirs in `defineAutomation({
mandate })`.
