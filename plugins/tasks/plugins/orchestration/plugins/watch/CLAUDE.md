# watch

What happens in a task subtree reaches the **nearest live watcher** above it —
an agent (one `event` turn per batch) or code (a `WatchHandler`). Plan:
`research/2026-10-28-tasks-watcher-report-building-block.md` §1.

## Pieces

- **Watches** — `task_watches`: a watcher (`{ kind: "conversation",
  conversationId }` | `{ kind: "code", handler, key }`) on a task's subtree.
  Live while `ended_at` is null and its conversation (if any) is not `done`.
  `watchTask(taskId, watcher, exec?)` is idempotent per (task, watcher) and
  starts with the subtree's current quiet state; `endWatch`, `retargetWatch`
  (a watcher rolling over — no caller yet), `watchesOf(conversationId)`.
- **Sources** — `watchSource({ id, on, toEvents })` returns `[WatchSource,
  Trigger]`; spread it into `contributions`, so a source is never declared
  unfed. Contributed by the plugin that owns the fact (`tasks` — created /
  started / settled / stopped / held; `outcome-report` — reported / asking; `push-and-exit` —
  flagged). `kind` is an open string. This plugin names no source.
- **Routing** (`watch.ingest`) — each event goes to the nearest live watch up
  the folder chain (the task's own first), never one its actor owns, into
  `watch_inbox`, and `watch.deliver` is enqueued on the same transaction. No
  live watch: dropped (the digest still shows ancestors what changed).
- **Quiet** (`watch.quiet`) — re-evaluated for every live watch on the chain
  on `tasks.statusChanged`, on a conversation entering or leaving a busy state,
  and after routing. Active = an agent `starting`/`working` on a subtree task
  other than the watcher's own, or an armed task that can launch
  (`listLaunchableArmedIn`: not blocked, held or dropped). Only a false → true
  flip of `task_watches.quiet` raises one `quiet` event.
- **Delivery** (`watch.deliver`, keyed by watch) — a dead watch re-routes its
  rows to the next live watch above; a conversation watcher that cannot take
  an automatic turn (`conversations/automatic-turn`'s readiness: busy,
  `waitingFor` set — an event turn would answer its question — or another
  plugin's `PendingTurn`, such as a compaction, goes first) is held. Its own
  `conversation.statusChanged` re-enqueues delivery — which fires on leaving
  a busy status AND on `waitingFor` clearing with the status unchanged (a
  question answered); a pending turn ends by making the agent busy, then
  idle. Otherwise every undelivered row is claimed into
  ONE turn whose id is derived from the row ids (`turnIdFor`), so a retried
  delivery is the same turn; the turn is the event lines plus the tree digest,
  submitted as kind `event`. A code watcher gets the batch on the claiming
  transaction; a throw rolls the claim back. A conversation turn is sent in a
  SECOND step, after the claim commits (`claimDelivery` → `sendClaimedTurn`):
  submitting a turn opens transactions of its own and may resume the agent, so
  holding the claim across it pinned a background transaction lease while
  waiting for another — three deliveries at once took all three and wedged the
  backend (2026-10-30). A failed send unclaims its rows; a claim whose turn the
  ledger never recorded (the backend died between the steps) is unclaimed by
  the next delivery.
- **Stop waiver** — a conversation owning a live, not-quiet watch may stop: the
  next event wakes it.
- **Capability** — `watch.children: true` (core). `add_task` makes the caller
  watch each task it files when granted.

- **Managed by** — `tasks_ext_manager` (`taskManagerShape`, core): a task is
  managed by the task of the nearest live agent watch up its folder chain (the
  task itself first; the oldest on one task) whose watcher is not the task's
  own agent — the same rule events route by. So a supervisor root owns its
  whole tree, and when a sub-supervisor's conversation ends, the tasks it
  managed go up one level. A root's own tree watch does not manage the root;
  code watches manage nothing. Derived only by `refreshTaskManagers` (over
  each given task's subtree) — on every watch write, on the watcher's
  conversation ending or coming back, on `tasks.created` / `tasks.refiled`
  (`watch.on-task-filed`), and by `watch.managers-reconcile` (startup warm-up
  + nightly; a cascade-deleted watch runs no app code). Exposed as `managedBy` (Agent / You) in every list
  whose rows reach a task: a Queue view filtered `Managed by is You` shows
  only what no agent is looking after. `managerTaskId` itself is exposed too
  (hidden by default): the Queue draws a managed task beneath its manager's
  row with it (DataView `attach`, `queue-attach.ts`).

Every delivering job is main-only (`isMain()`): a forked worktree DB inherits the trigger
rows and the watches. The manager refreshes run everywhere — they rewrite a
derived row from the DB's own watches and deliver nothing. Delivery logic takes ports (`claimDelivery` / `sendClaimedTurn`), so tests drive
it over the real tables with a fake agent.
