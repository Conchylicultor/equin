# github-issue

**File on GitHub** in the Wish popover's footer (`WishSlots.FooterAction`),
beside Launch — the GitHub mark alone, its label sliding out on hover or
keyboard focus: the drafted wish goes to a GitHub issue on the
product's repository (`SOURCE_REPO_URL`) instead of to an agent here — for a
request the user wants to share upstream.

The link is built by `integrations/github-issues` (`buildIssueUrl`: picks made
readable, raw `<ui-context>` tags in collapsed blocks, held under GitHub's
length cap), with the page the draft is about, the environment lines below and
a "Filed from the Wish button in the equin app" note, titled from the wish's first line, and labelled with
the repository's `Wish` label — the name must match the repository's exactly,
and GitHub applies it only for a filer with triage rights (anyone else files
unlabelled). It is a real `<a target="_blank">`: only the user's click opens
GitHub. The click also clears the draft and closes the popover
(`discard`), as a Launch does once it has filed. Disabled while the draft is
empty.

## The environment lines

A maintainer's first questions, answered in the body's closing notes (never
cut by the length cap):

```
Version: equin 2026.11.17.2 · bf902af7e2 · 3 commits ahead of upstream/main, 12 behind
System: macOS 26.4 (arm64) · Bun 1.3.2
Browser: Chrome 142 on macOS
```

- **Version and System** are the backend's: the `github-issue.environment` live
  value (`core/`, served by `machine/`). The commit is the one this backend runs
  (`serverPin`; unknown on a mixed boot, with the reason); the release is the
  newest release tag in that commit's history (upstream's mirrored tags on a
  clone, the repo's own on the canonical one); ahead / behind are counted
  against the trunk — `<upstream>/main` on a clone (as of the last update
  check's fetch), local `main` on the canonical repo or when no upstream is
  known. The OS is `sw_vers` on macOS, `/etc/os-release` on Linux, read once per
  process. Recomputed on a tracked ref moving and on an adopted deploy.
- **Browser** is the page's own `navigator.userAgent`, reduced to a name, major
  version and system (`web/internal/browser.ts`).
- While the backend's half loads the button shows a spinner rather than an
  issue missing lines; under an in-browser server (no computer) the Version line
  carries the unavailable message, and a failed read says so in the issue.
