# google-drive

## The upload resumes, it does not restart

`uploadToDrive` speaks Google's resumable upload protocol all the way: one
session, the archive sent in 64 MiB chunks (`Content-Range`), and after any
failure — a rejected fetch (ECONNRESET, DNS), a 5xx, 408 or 429 — a status
query (`Content-Range: bytes */<size>`) asks Drive how many bytes it holds and
the upload continues from there. Until 2026-11-20 the whole ~1 GB archive went
up as ONE PUT, so a reset fifteen minutes in (report-1794884443-cyv4ww) lost
the night's off-site copy.

The retry is bounded twice: more than `maxStalls` (6) failures in a row with
no new confirmed byte, or more than `maxFailures` (30) in the whole upload,
fail the target with how far it got and the last error. A chunk answered 308
without moving counts as a failure (re-sending at once would loop forever),
and each request has a 15-minute deadline, since a half-open connection hangs
instead of rejecting. Any other 4xx (a 404 is an expired session) fails at
once. A run that survived failures says so in its detail (`resumed after N
network failure(s)`).
