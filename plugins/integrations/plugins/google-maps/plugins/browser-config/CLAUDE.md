# browser-config

The public Maps browser config — the Maps JavaScript API key and the vector
map's Map ID — that every live map draws with: the `google-maps.browser-config`
live value, where each host reads it from, and the page input that hands it to
the in-page demo. Split from `google-maps` so it carries no `auth`: the public
website composition bundles it (its demo's Places needs a key).

**Map rendering only.** This key never calls the Places API: the Places client
is `google-maps/places-api`'s `machine/` barrel (never loaded by a browser
host), and page code may load only the Maps JS libraries that draw a map
(`map/google`'s `maps-js-libraries` lint). Google's own API restriction on the
key (below) is the last line, since a key in a page is public.

## Where each host reads it (`MapsBrowserConfigSource`)

`server/` serves the value (portable) from the host service; its providers:

| host | provider | source |
| --- | --- | --- |
| a deployed box (equin.ai) | `machine/` | the approved `GOOGLE_MAPS_BROWSER_KEY` deploy secret, with the optional `GOOGLE_MAPS_MAP_ID` one (`plugins/deployed-key`; unset → `mapId: null`, the raster map) |
| the computer | `machine/` | the host-global file `state/google-maps/browser-config.json` |
| a browser host (the demo) | `google-maps/page-config` | the page input the page's chrome hands over |

- **The deploy secret wins** when its credential exists (only a box has one).
  It is the site's own key, delivered by `deploy-secrets` (approved per value,
  never committed, never in a build or snapshot). A value that is not a key
  shape throws; the file's write endpoints answer 409 there.
- **The site's Map ID** is a second deploy value, `GOOGLE_MAPS_MAP_ID`,
  declared `optional` — the site's counterpart of the file's `mapId`. It is
  not secret (every page drawing the map carries it); it goes through
  `deploy-secrets` because that is how a box receives any value kept out of
  git. Unset, the site draws the raster map and its deploys are not held; set,
  it is approved like the key. A Map ID set without the key throws.
- **The file** is shared by every checkout, like the Places key. Not the
  secrets store (the value is public), not config_v2 (per-namespace user
  layer: every worktree would ask again), not central (runs main's code).
  `POST` / `DELETE /api/google-maps/browser-config` (deleting removes the Map
  ID too) and `/api/google-maps/map-id` (409 while no key) write it and notify
  their backend; every backend with a subscribed tab watches the file
  (`infra/file-watcher`). No polling.
- **The demo** gets it from its page: `web/`'s `HostInputs.Supply` makes the
  page (main's `/demo`, the website) read the value from its own server and
  hand it over (`framework/browser-server` page inputs) — never read from a
  server by the host's own code, never stored, so never in a snapshot. A page
  that supplies none reads `unset`: the map says it has no key.
  `deployed-key` is imported only from `machine/`, so `deploy-secrets` stays
  out of the demo's worker graph.

Nothing verifies a key on write: a referrer-restricted key cannot be checked
from the server, so the renderer's `gm_authFailure`, raised in the real page,
is the verifier.

## Setting up the website's key (Google Cloud)

1. APIs & Services → Credentials → Create credentials → API key, in the
   project whose billing should carry the site's maps.
2. **Application restrictions**: Websites (HTTP referrers) — the site's
   domains only (`https://equin.ai/*`, `https://*.equin.ai/*`, and any other
   domain the site is served on).
3. **API restrictions**: Restrict key → **Maps JavaScript API** only.
4. Optionally cap its daily quota (Maps JavaScript API → Quotas → Map loads
   per day).
5. Deploy app → the site's Settings → Secrets: set `GOOGLE_MAPS_BROWSER_KEY`
   to the key and approve it (or **Use this computer's value**, which takes
   the key from the browser-config file — a choice, not the default: the
   site's key is public in its pages, so a separate restricted key is advised); the next deploy delivers it (a deploy is held
   `needs-approval` until then).
6. Optional, the vector map with your style: Google Maps Platform → Map
   Management → Create Map ID, **in the same project as the key**, type
   **JavaScript**, **Vector**; attach your map style to it (Map Styles). Then
   Settings → Secrets: set `GOOGLE_MAPS_MAP_ID` to it and approve it. A Map ID
   from another project draws the raster map (the map's Map-ID notice says so).

## Plugin reference

- Description: The Maps browser config, read (useMapsBrowserConfig: loading / error / unset / set { browserKey, mapId }) and handed to a browser host as a page input (HostInputs.Supply): a page rendering the demo — main's /demo or the public website — gives it the key its own server serves, so the demo's map draws without the demo ever reaching that server. Light on purpose (no auth), so the website carries it.
