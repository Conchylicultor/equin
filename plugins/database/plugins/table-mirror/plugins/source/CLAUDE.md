# table-mirror/source

The source half of the table mirror (`../../CLAUDE.md`). Runs wherever the data
lives: a deployed box, and this instance too (the demo's stand-in box).

```ts
// a plugin owning the tables (server)
export const analyticsMirror = defineMirrorSet({
  id: "analytics",
  tables: [analyticsVisits, analyticsHits, analyticsDaily, analyticsVisitMembers],
  omit: [],                       // columns that never leave (nullable or defaulted)
});
// contributions: [MirrorSet(analyticsMirror),
//                 NeverMirrored({ tables: [analyticsSalts, analyticsVisitorLinks], reason: "…" })]
```

- **`defineMirrorSet`** reads each table's PK from drizzle and asserts at
  module eval: tables in `public`, plain lower-case identifiers, a PK, a table
  in at most one set, omitted columns nullable or defaulted and not in the PK.
  **`NeverMirrored`** marks tables whose rows must never leave; meeting one in
  a set throws at module eval (whichever runs second), and
  `assertMirrorSetsAllowed` re-checks every contribution at boot.
- **The log** (`table_mirror_log`, drizzle-declared): one row per primary key
  ever changed — `(set_id, tbl, pk jsonb, xid xid8, deleted)`, PK `(tbl, pk)`,
  indexed `(set_id, xid, tbl, pk)`. Written only by the generated triggers.
  Excluded from the change feed (written on every write to a mirrored table).
- **The triggers** (`./server/internal/triggers.ts`): one db-triggers set,
  `table-mirror`, generated from every contributed set and installed in this
  plugin's `onReadyBlocking` with `commit: "per-table"` (claimed with
  `DbTriggerClaim`). Per table, a static plpgsql function and statement-level
  `AFTER INSERT / UPDATE / DELETE` triggers with transition tables: one log
  upsert per key, the newest change winning; an UPDATE that moves a key
  tombstones the old one. **A cascaded delete fires the child's own statement
  trigger with its own transition table** — the mechanism behind "every
  deletion on the source, retention included, reaches the mirror", pinned on
  raw Postgres by `cascade-assumption.test.ts`. A `TRUNCATE` trigger drops the
  table's log rows and bumps the source's `epoch` (every replica reconciles).
  A write that bypasses triggers (`session_replication_role = replica`)
  leaves an upsert log row with no table row; the stream throws on it.
- **Identity** (`table_mirror_source`, one row seeded at boot):
  `{ sourceId, systemIdentifier (pg_control_system()), epoch }`, plus the log
  `horizon`. **Fingerprints** (`readTableFingerprints(exec, schema, tables)`):
  per table, sha256 over its sorted `(column, type, not null)` lines from the
  catalog, omitted columns left out — parametrized on the schema so a replica
  computes the same over its own.
- **Readers** — pure functions over a db, each one read-only `REPEATABLE READ`
  transaction (`xmin` taken first in the same snapshot, `TimeZone = 'UTC'`):
  - `readMirrorChanges(db, { set, cursor, maxRows?, maxBytes? })` — log rows
    with `xid >= floor AND (xid, tbl, pk) > after`, each joined to its table
    by key (an upsert with its row and `h`, or a tombstone). A floor below the
    horizon is `reconcile-required`, never a partial page.
  - `readMirrorCopy` — a keyset page of a whole table (a first sync only).
  - `readMirrorKeys(db, { set, table, columns, afterPk, maxKeys? })` —
    `(pk, h)` pages for reconciliation; the hash covers the requested columns
    this source sends (answered as `columns`).
  - `readMirrorRows(db, { set, table, columns, pks, maxBytes? })` — the rows
    for a bounded key list; `missing` (gone) and `remaining` (past the cap).
  - Every page is cut in the database at `maxRows` and a running byte sum
    (the first row always taken), after a `LIMIT maxRows + 1` keyset read.
  - `resolveMirrorSet(id)` — the contributed set, or `unknown-set`: the
    registry is the allowlist a route serves.
- **Who serves the readers** — not this plugin: the routes a replica reaches
  them by belong to whoever knows the transport (the deploy app's
  `site-mirror/box`, host-only routes over SSH). That plugin imports this one,
  so the need is a **server companion kind**, `MirrorReaderRoutes`: its
  contributor ships wherever this plugin ships, and `onReady` (serving hosts
  only) throws when a host mirrors a set but boots none.
- **Prune** (`table-mirror.prune`, daily, `perWorktree: true` — a deployed
  box is never main): records a mark `(now, snapshot xmin)`, then deletes log
  rows (upserts and tombstones) below the newest mark at least
  `TOMBSTONE_RETENTION_DAYS` old, raises the horizon to it, and drops older
  marks. So the log holds the last 30 days of changes, not the tables.

Batch sizes: the defaults (10000 rows / 4 MB a page, 20k keys) are the
measured ones (the plan's § Measured sizes); they are request parameters, so a
caller may ask for less (site-reports' 50 rows a page).
