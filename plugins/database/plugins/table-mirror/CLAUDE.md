# table-mirror

Pull a remote database's tables into local Postgres, generically: the source
sends only deltas (current rows plus tombstones) from a row-level change log,
paged by an xid8 cursor; a replica that cannot trust its deltas (fallen behind
the log horizon, another source identity, a fingerprint change) reconciles by
key and row hash, so only rows that differ travel. Knows nothing about SSH,
deployments or analytics. The design and its decisions:
[`research/2026-11-12-global-table-mirror.md`](../../../../research/2026-11-12-global-table-mirror.md).

- **`core/`** — the wire protocol both halves speak (zod; a row's content is
  its jsonb TEXT, never decoded into JS values): `MirrorCursor`
  (`{ floor, after }`), the pages (`changes`, `copy`, `keys`, `rows`),
  `SourceIdentity`, `TableFingerprints`, `MirrorRefusal`
  (`reconcile-required` | `unknown-set` | `unknown-table`), the requests, and
  the bounds (`MIRROR_PAGE_MAX_ROWS`, `MIRROR_PAGE_MAX_BYTES`,
  `MIRROR_KEYS_MAX`, `TOMBSTONE_RETENTION_DAYS` = 30).
- **`plugins/source`** — runs wherever the data lives: mirror sets, the
  change-log triggers, identity, the readers, the prune.
- **`plugins/replica`** — runs where the copy lives: one schema per replica
  (tables LIKE the local ones), the budgeted pull (first copy, delta stream,
  reconciliation, local rebuild), a custom sink with the key index,
  `withReplicaSchema`, `onReplicaApplied`, fork exclusion.

## The row hash and key order — both sides must agree

- `h` = `md5((to_jsonb(row) - <columns not hashed>)::text)` under
  `SET LOCAL TimeZone = 'UTC'`. jsonb's text form sorts keys, so it is
  canonical; the UTC zone makes a `timestamptz` render the same text.
- Keyset walks order by the PK columns with `COLLATE "C"` on text-like ones,
  so both sides visit keys in the same order whatever their collations.
- A key is `jsonb_build_object('<pk col>', <value>, …)` everywhere (log, pages,
  replica), and is read back typed with `jsonb_populate_record(NULL::<t>, pk)`.
- These fragments are written once, in the source (`mirrorSql`, its server
  barrel), and the replica spells its side with them.
