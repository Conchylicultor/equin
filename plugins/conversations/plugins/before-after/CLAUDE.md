# before-after

An agent publishes a **before / after pair** of screenshots after a visible UI
change; the user compares them by dragging a divider. Design:
[`research/2026-11-15-conversations-before-after-screenshots.md`](../../../../research/2026-11-15-conversations-before-after-screenshots.md).

## The tool — `register_before_after` (`machine/`)

Exactly one of two forms (`parseRegisterInput`, `core/`; MCP takes one flat
object, so the raw shape lists both forms' fields and the parse refuses
neither / both / a field of the other):

- **capture** — `{ title, route, width?, height?, colorScheme? }` (default
  1400×900, light): `route` captured on MAIN (before, "main") and on the
  conversation's own build (after, "this build") through the agent browser's
  `capturePair` (`infra/mcp/browser`), each page once ready. An unbuilt
  checkout is refused ("run `./equin build` first").
- **files** — `{ title, beforePath, afterPath, beforeLabel?, afterLabel? }`: two
  PNGs the agent made (a state that needs clicks; another comparison).

It mints a `ba-…` id (`baIdKind`), stores both PNGs as attachments linked to
the row (`before_after_pairs_attachments`, so the orphan sweep keeps them),
inserts the row under `ctx.toolUseId`, and answers the id (to cite) plus both
images.

## Data (`core/`, `server/`)

- `before_after_pairs` (`beforeAfterPairsEntityRef`): conversation, tool call,
  title, route, size, colour scheme, the two attachment ids and labels.
- `beforeAfterPairs` — a window, newest first: by conversation
  (`{ where: { conversationId } }`), by tool call (`{ where: { toolUseId },
  limit: 1 }`), by id (`{ id }`). Images: `GET /api/attachments/:id`.
- Artifacts: `extractBeforeAfterHits` — one `created` hit per call, keyed by its
  tool-use id (kind `before-after`, `produced`).

## Web (`web/`)

- **Tool call** — `JsonlViewerTool.Renderer` for `register_before_after`: the
  tool row, its footer the pair read back by tool-use id (`{ where:
  { toolUseId }, limit: 1 }`) as a swipe preview (title, route, id chip, Open
  in pane) — the whole capture, shrunk into a landscape box (never cropped).
  Loading while the row is not there; a failed call has no footer,
  its error in the body (`ToolOutput`).
- **Pane** — `beforeAfterPane` (`before-after/:pair`, agent manager), exported
  for the chip. The pair large (`PairViewer`: Swipe / Side by side / Flip)
  — zoomable: `useCompareZoom` + `CompareZoomControls` (fit width at first,
  fit height, 1:1, − / +, scroll to zoom, drag to pan; a new pair starts fresh)
  over the conversation's pairs as a gallery DataView in its `strip` layout
  (config `conversations.before-after.gallery`, oldest first, no band).
  Selecting rewrites `pair` in place (`useSetParams`). Full screen (header
  action) is a dark `ViewportOverlay` with ← / → (wrapping) and Esc. Mode,
  divider and full screen are one pane-wide state (`CompareStateProvider`),
  so they carry between the pane and full screen; the tool-call preview's
  divider does not carry into the pane.
- **Artifacts** — `ConversationArtifacts.Kind`: a two-up grid of split
  thumbnails, each read by its tool-use id; a tile opens the pane and closes
  the popover.
