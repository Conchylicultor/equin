# conversation-preprompt

Records the preprompt a conversation was launched with as a snapshot on the
conversation, and surfaces it as a chip in the conversation header.

The snapshot is the conversation's instructions of record. The conversation
launch (`conversations` lifecycle, `commitConversation`) writes it with
`recordConversationPreprompt` on the launch's own transaction — id, title, full
text and icon, copied into the `conversations_ext_preprompt` side-table (via
the entity-extensions primitive) — so a conversation exists iff its snapshot
does. Every spawn of the conversation reads it back with
`getConversationPreprompt` and hands the text to the runtime as an addition to
Claude Code's own system prompt (the Agent SDK's `systemPrompt.append`); a
resume re-reads the same snapshot, a fork copies its source's. The snapshot is
intentional: the agent and the chip keep exactly what the conversation was
launched with, even if the config preprompt is later edited or deleted.

The header chip (a `conversationPane.Actions` item) reads that snapshot from the
lookup-only collection `conversationPrepromptRows` (`liveCollection(
"conversation-preprompts", { row, id: "conversationId" })`, minting
`conversation-preprompts:rows` alone), served by `serveCollection` from the
extension handle. A reader subscribes to its one conversation
(`useLiveRow(conversationPrepromptRows, conversationId)` → pending / found /
not found) so a read costs O(1) rather than an O(n) lookup over the whole
table, and a write reaches only that conversation's subscribers. It is not
preloaded (a lookup-only collection cannot be): the row hydrates one
round-trip post-mount, so the chip and sidebar icon stay unrendered until it
lands. The chip renders the preprompt title; clicking it opens a popover with
the full instruction text.

## Boundary notes

`server/` is `portable: true` (the extension table, the live read, the
saved-icon source), so a browser host serves the snapshot from its own DB. It
resolves nothing from config: the launch resolves the task's preprompt (through
the preprompts library and task-preprompt) and passes the item in.
