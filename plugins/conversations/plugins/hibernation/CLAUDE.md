# hibernation

Idle conversations are hibernated (their agent session killed, the row kept
`waiting` with `hibernatedAt` set) and resumed when the user opens them.

- `server/` (portable) — `POST /api/conversations/:id/viewed` (`markViewed`):
  stamps `lastViewedAt`, which resets the idle timer. An `{ ok: true }` ack;
  any host serves it, the in-browser demo included.
- `machine/` — `POST /api/conversations/:id/resume-hibernated`
  (`resumeHibernated`, `needsMachine`): `ensureResumed`, answering the
  `ResumeOutcome` (its `blocked` arm is the only place a failed auto-resume is
  observable); the `conversations.hibernate-idle` job; the hibernation config.
- `web/` — `useMarkConversationViewed()(conversation)` always stamps, then calls
  resume only when the row's `hibernatedAt` is set. A `blocked` outcome is a
  toast; an `unavailable` one (no computer behind the transport) is a
  deliberate no-op — there is no session to resume.
