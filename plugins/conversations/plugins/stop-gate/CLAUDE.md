# stop-gate

Whether an app-launched agent may end its turn. A plugin that requires
something of an agent before it stops (a report it was asked for) blocks the
stop; a plugin that will wake the agent anyway (a watch whose next event becomes
its next turn) waives the block.

**The mechanism.**

- Every app-launched agent carries a `Stop` hook (agent-launch's
  `agentLaunchPolicy()`; entry built by `stopGateHookEntry()`, the `machine/`
  half — it checks the script on disk — so the `server/` half stays portable).
  It runs `bin/stop-gate.ts`. The repo's own `.claude/settings.json` does not
  carry it: only app-launched agents are gated.
- The script GETs `/api/conversations/:id/stop-gate` on the backend the agent
  dials (`EQUIN_PARENT_URL`) and, on `block`, prints
  `{"decision":"block","reason":…}` — the CLI sends the agent back to work with
  the reason.
- **One continuation per stop attempt.** When the hook's stdin says
  `stop_hook_active` (the agent is already continuing because of a block), the
  script allows without asking: never an infinite loop.
- **It fails open.** Missing env, unreadable stdin, a refused request, or the
  backend unreachable for 15 s: stderr, exit 0, the agent stops. A gate is a
  nudge, never a trap.

**The backstop** (`machine/internal/backstop.ts`, its table `server/internal/tables.ts`): the hook failing open means
a stop the gates would block can go through unenforced — the backend down
(two workers' outcome reports failed during main's crash loop and nothing
retried or flagged it, 11 h), or the second stop of one attempt. So the
`stop-gate.backstop` job asks the same decision again on every
`conversation.statusChanged` to a stopped status (durable, main-only, like
`self-compact.send`): `waiting` → ONE reminder turn per conversation
(`stop_gate_reminders`, event turn, gated by `automatic-turn`) carrying the
gates' reason; stopped again with the demand unmet, or `gone` / `done` (no
agent to type into) → a `stop-gate-unmet` notification. Bounded by the
table's PK: never a loop.

**The decision** (`server/internal/decide.ts`): every `StopGate` contribution's
`check(conversationId)` is asked; when one blocks, every `StopWaiver`'s
`waives(conversationId)` is. `block` iff some gate blocks and no waiver waives,
the blocking reasons joined; a waived block is an `allow` carrying the waivers'
reasons (for the log). A contribution that throws fails the request, loudly —
and the hook then fails open, saying so on stderr.

```ts
StopGate({ id: "outcome-report", check: async (conversationId) => … })
StopWaiver({ id: "watch", waives: async (conversationId) => … })
```

This plugin names no contributor.
