# agent-launch

What every app-launched agent starts with, whichever runtime hosts it (the tmux
runtime's pane, or the session the sdk runtime runs its agent process in). Both
runtimes launch through here, so a variable, setting or hook every agent needs
is stated once and cannot be left out of one of them (the SDK spike's MCP
failure was exactly that: the `-e` values were missing).

- `server/internal/agent-session-env.ts` — the session's allowlisted
  environment: `agentSessionArgs` is everything after
  `tmux new-session -d -s <id> -c <cwd>` — the `-e` values
  (`agentSessionEnv`, keyed by `AGENT_SESSION_DELIVERED_ENV`, which the
  `env -i` allowlist spreads), then the wrapper that re-execs the command under
  the account's login shell with the toolchain on PATH. Why an allowlist, and
  which names are load-bearing: the comments there and runtime-tmux's
  CLAUDE.md (*The pane starts from an allowlisted environment*).
- `server/internal/launch-settings.ts` — the launch's one settings object:
  `LAUNCH_CLI_SETTINGS`, `agentLaunchHooks()` (the hooks every runtime runs —
  compaction-context's `SessionStart` entry), and `mergeLaunchSettings`, which
  throws on a key two fragments both set. A runtime's own hooks (tmux's
  signal-file touches, the question relay, the turn ledger) stay in that
  runtime and are merged beside these.
- `core/` — `TMUX_HOSTED_BY_OPTION`, the tmux user option a session carries
  when a runtime other than tmux hosts its process; the tmux runtime's pane
  listing skips such sessions.
