# delivery-check

Did the agent get the context handed back after its compaction **whole**? This
plugin reads the answer off the agent's transcript instead of predicting it
from a copy of the Claude CLI's hook-output cap, which the CLI may change in
any release.

- **What it compares.** The endpoint records the exact text it answered
  (`compaction_context_sends`, one row per conversation). The first SessionStart
  `hook_additional_context` attachment the transcript gets after that instant
  must hold that text, character for character (`judgeDelivery`). Anything
  else is a cut, the CLI's `<persisted-output>` preview included. No SessionStart
  context before the agent's next answer is a cut too. It fails closed.
- **When it reads.** On a write to the conversation's session transcript
  (transcript-watcher's `onSessionTranscriptWritten`), only while a send is
  pending. No timer. Sends pending at boot are reloaded from the table.
- **On a cut.** It sends the whole context to the agent as an `event` turn
  (`submitTurn`, like the mandate change notice) and files
  `compaction-context-cut` (source `server-compaction-context`), saying whether
  the turn went through. Then the row is deleted.

**Bounds.**

- Each judgement reads the whole session file. That happens only while a send
  is pending, which ends at the next SessionStart context or answer, usually
  within seconds.
- A send whose conversation never writes again stays pending (one row) until a
  later compaction replaces it.
