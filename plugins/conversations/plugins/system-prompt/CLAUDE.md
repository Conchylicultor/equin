# system-prompt

What equin appends to an agent's system prompt — the channel for **context
about this agent and its task**: its Mandate, the global page instructions, its
task tree. How to use a tool is the tool's own description; this is everything
else an agent must know from its first token.

```ts
SystemPrompt.Section({ id: "mandate", label: "Mandate", render: (conversationId) => … })
```

- **Two halves.** This plugin's `server/` is the contribution only — light, so
  a contributor's (portable) closure stays small. [`composer`](plugins/composer)
  composes, records and serves the read; the conversations core calls it.
- **Rendered at every spawn** of the agent's process — first launch (the spawn
  job), fork / reuse-attempt (`finishConversation`), every resume
  (`respawnResume`) — by `composeSystemPromptAppend(conversationId)`, called
  right before `runtime.create`. Never at enqueue: a spawn job retried after a
  restart starts on what is true now.
- **Composed** as the preprompt (`<special_instructions>`, first — the
  transcript's prompt-snapshot reader lifts it from there) then every section in
  id order, each wrapped `<equin-context id="…">`. `null` / blank adds nothing.
- **A section that throws** is reported (crash report) and replaced by a notice
  that its guidance is missing; the agent still starts.
- **Recorded**: each spawn rewrites the conversation's
  `conversations_ext_system_prompt` row — every part's id, label and length.
  The context card reads it (lookup-only `conversations.system-prompt`) and
  lists the parts under its **System prompt** row, each `~chars/4` tokens, with
  Claude Code's own prompt as the measured remainder.

## Why not MCP server instructions

They were the channel until 2026-11-12. Claude Code cuts MCP server
instructions at **4,096 characters, silently**: a supervisor's Mandate (2 KB)
plus the page section (2.2 KB) cut a global instructions card mid-header —
recorded as received, so no later read re-sent it — and dropped the Task tree
whole. The system prompt has no such cap, survives a compaction, and is the
right place for instructions to the agent rather than about a server's tools.
`Mcp.instructions` was deleted with the move.

## Stated bounds

- **Fixed for the life of a process.** A change while the agent runs reaches it
  as an event turn from the plugin that owns it (the mandate change notice);
  the next spawn renders the new state anyway.
- **runtime-sdk's own relaunches** (moving to another launch account, a rewind
  through `stop`) replay the options file of their spawn, append included.
- **Every character is paid on every turn.** Write a section only for what no
  tool description, gate or CLAUDE.md already says, and point at long material
  (a global instructions page goes as a pointer) rather than inlining it.
