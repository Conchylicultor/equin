# usage

- **A live append costs its bytes and one write, not a re-read.** The sync
  (`machine/internal/sync.ts`) is the only writer of `conversation_usage_files`
  and the totals — every path goes through `requestUsageSync`, serialized per
  conversation — so it holds each live conversation's file rows, totals and
  resolved chain in memory and updates them from its own writes. Per transcript
  write: one owner lookup (`conversationsFor`, which also proves the
  conversation exists) and the write when something moved. The chain is
  re-resolved only when a write names a session the held paths do not resolve
  (an adoption). The jobs (backfill, reprice) pass no written sessions and read
  everything from the DB.
