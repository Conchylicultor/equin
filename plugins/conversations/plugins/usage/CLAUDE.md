# usage

- **A live append costs its bytes and one write, not a re-read.** The sync
  (`machine/internal/sync.ts`) is the only writer of `conversation_usage_files`
  and the totals — every path goes through `requestUsageSync`, serialized per
  conversation — so it holds each live conversation's file rows, totals and
  resolved chain in memory and updates them from its own writes. Per transcript
  write: one owner lookup (`conversationsFor`, which also proves the
  conversation exists) and the write when something moved. The chain is
  re-resolved only when a write names a session the held paths do not resolve
  (an adoption). The jobs (backfill, reprice) pass no written sessions and read
  everything from the DB.

- **Spend is filed under the account that spent it, when it is counted.** A
  live pass (`requestUsageSync` with written sessions) runs right after the
  agent's own append, so the cost `priceFile` adds on that pass
  (`addedByDate`, per UTC day of the priced bucket) is filed under the account
  the conversation's runtime runs its agent on now
  (`conversationRunningAccount`; after the agent exits, the last one this
  process saw) into `conversation_usage_account_days` — in the same statement
  as the file rows, so a failed write files nothing and the next pass the same
  delta once. A job pass (backfill, reprice) files nothing: what an account
  spent before this existed is unknown, not zero. Read as
  `conversations.usage.account-spend` (one account, one UTC month — a clock
  param the reader pins) by the agent manager's account foot. Design:
  [`research/2026-11-13-conversations-claude-account-spend.md`](../../../../research/2026-11-13-conversations-claude-account-spend.md).
