# usage

- **A live append costs its bytes and one write, not a re-read.** The sync
  (`machine/internal/sync.ts`) is the only writer of `conversation_usage_files`
  and the totals — every path goes through `requestUsageSync`, serialized per
  conversation — so it holds each live conversation's file rows, totals and
  resolved chain in memory and updates them from its own writes. Per transcript
  write: one owner lookup (`conversationsFor`, which also proves the
  conversation exists) and the write when something moved. The chain is
  re-resolved only when a write names a session the held paths do not resolve
  (an adoption). The jobs (backfill, reprice) pass no written sessions and read
  everything from the DB.

- **Spend is filed under the account that spent it, when it is counted.** A
  live pass (`requestUsageSync` with written sessions) runs right after the
  agent's own append, so the cost `priceFile` adds on that pass
  (`addedByHour`, per UTC hour of the priced bucket) is filed under the account
  the conversation's runtime runs its agent on now
  (`conversationRunningAccount`; after the agent exits, the last one this
  process saw) into the spend ledger (`claude_spend_hours`, owned by
  `infra/claude-cli/plugins/spend-ledger`), source `conv:<conversationId>` —
  in the same statement as the file rows, so a failed write files nothing and
  the next pass the same delta once. A job pass (backfill, reprice) files
  nothing: what an account spent before this existed is unknown, not zero.
  Read as `conversations.usage.account-spend` (one account, one UTC month — a
  clock param the reader pins; the ledger's hours summed per UTC day, every
  source) by the agent manager's account foot. Design:
  [`research/2026-11-13-conversations-claude-account-spend.md`](../../../../research/2026-11-13-conversations-claude-account-spend.md),
  widened to hours and sources in
  [`research/2026-11-15-global-supervisors-spend-breakdown.md`](../../../../research/2026-11-15-global-supervisors-spend-breakdown.md).

- **File buckets are per hour.** The scan folds with `emptyUsageBuckets("hour")`
  (stats/cost), so each file row's buckets are `(date, hour, model, speed)` —
  what lets a pass's cost land in its hour. A row counted before (day buckets,
  no `hour`) keeps them on an append; a re-read from the start re-buckets them,
  and `bucketDelta` takes each vanished day bucket out of the same day's hours,
  earliest first, so re-bucketing files no spend. stats/cost's own corpus index
  stays day-keyed.
