# workspace

**Where a conversation runs.** Every attempt carries a `WorkspaceSpec`
(`attempts.workspace`, decoded by its zod schema): `{kind: "worktree"}` — the
agent's own git checkout of this repo, with a forked DB — or
`{kind: "scratch", profile, input}` — a plain directory holding only what its
scratch profile provides. Design:
[`research/2026-10-13-global-agent-workspaces-and-sonata-transcription.md`](../../../../research/2026-10-13-global-agent-workspaces-and-sonata-transcription.md).

- `core/` — the closed set as data: `WorkspaceKind`, `WorkspaceCapability`,
  `WORKSPACE_KINDS` (what each kind offers), `WorkspaceSpecSchema`, and the
  capability reads (`hasCapability`, `assertCapability` for a server git read's
  boundary, `workspaceAllows` for a web slot host).
- `server/` — the `WorkspaceImpl` contract and the `Workspace` registry
  (`define` / `get` / `all`, like `Runtime`). The conversation lifecycle calls
  through it and never names a kind: `parseSpec` (a new attempt's spec, before
  any write), `onCommit` (writes on the launch transaction), `prepare` (in the
  durable spawn job), `onFinish` (after commit), `launch` (the `LaunchFragment`
  — argv and a `--settings` fragment the runtime merges), `checkResumable`.
  Also the open set: `ScratchProfile.define(defineScratchProfile({…}))`, and
  `workspaceOfConversation` for a profile's MCP tools.
- `workspace.catalog` (core declaration, served here) — every workspace a task
  can name: the worktree, then one choice per scratch profile (label, owner
  plugin via `registeringPlugin()`, MCP tool count, `unavailable` when its
  input has no defaults). Readers never name a profile.
- `plugins/<kind>/` — one impl per kind, registered with `Workspace.define`.
- `plugins/launch-option/` — the Workspace task launch option (which workspace
  a task's next attempt runs in).

**A workspace path is `<root of its kind>/<attemptId>`** — impls declare only
their `root()`; `Workspace.pathFor` / `Workspace.resolvePath` derive the path
and its inverse, so `basename(path) === attempt.id` holds for every kind. The
attempt column holding it is still named `worktreePath` (renaming it touches
~90 files across web and server).

**Gating.** Conversation-view slot contributions declare `requires:
WorkspaceCapability[]` (required); the hosts render one only where
`workspaceAllows`. The web reads the kind from tasks-core's
`attemptWorkspaces` lookup collection — not a field of the `attempts` row, which
the C39 old-bundle check pins. Server git reads (edited-files, commits-graph,
code-explorer) `assertCapability(…, "git")`; attempt-work answers `unresolved`.

**No cycle with tasks-core.** tasks-core's field record imports this `core`, so
`server/` reads the attempt's workspace with raw SQL (`workspace-of.ts`) rather
than tasks-core's table handles, and adoption resolves the workspace in the
status reconciler, not in tasks-core.

Orthogonal to the runtime (tmux | api): a runtime sees only the cwd and the
`LaunchFragment`.
