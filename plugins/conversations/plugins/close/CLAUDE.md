# close

**Closing a conversation, split by host.** Design:
`research/2026-10-22-global-demo-scope-sealed.md` (G6, *Conversation close*).

- `server/` (portable) — `POST /api/conversations/:id/close`
  (`closeConversation`, declared in `conversations/core`): the row moves to
  `done` (`markConversationClosed`) on every host, the demo's in-browser server
  included, then every `CloseTeardown` contribution runs **before the request
  returns**. The slot is how the runtime half reaches the portable endpoint: a
  host that runs no agent contributes none, so its close is the row alone.
- `machine/` — the runtime half:
  - `CloseTeardown({ id: "stop-agent", stop: deleteConversation })` — the
    endpoint's agent stop, in the request, so the agent cannot keep editing
    after the user's close came back.
  - a `Trigger` on `conversation.statusChanged` running
    `conversations.teardown-closed`, which stops the agent once the row is
    `done` however it got there (exit actions, the status reconciler's
    `closed` plan) — a backstop, a no-op for an agent already stopped. It
    re-reads the row first, so a conversation resumed in between keeps its new
    session.
