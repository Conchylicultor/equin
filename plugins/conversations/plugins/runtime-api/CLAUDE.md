# runtime-api

The SDK runtime (track: wiki *Mental model → Agent Manager → SDK Claude*). The
server half is still a stub `Runtime`; what exists is the **spike** — see
[`research/2026-10-19-conversations-sdk-agent-spike.md`](../../../../research/2026-10-19-conversations-sdk-agent-spike.md).

- `bin/agent.ts` — one detached agent process per conversation: the Agent SDK's
  `query()` in streaming-input mode, commands over
  `sockets/agents/<id>.sock`, every SDK message unchanged as a numbered line of
  `state/sdk-agents/<id>/events.jsonl`, a readable log on stdout (the terminal
  button's view). Launched inside tmux, which only supervises and shows it.
- `core/protocol.ts` — the wire: commands, replies, event lines, `PROTOCOL_VERSION`.
- `bin/spike.ts <scenario>` — the experiments (restart, ask, auth, rewind,
  terminal, latency), run with `./singularity run`; results land
  in `state/sdk-agents/_spike/results/`.

Gotchas the spike hit:

- The socket cannot sit next to `events.jsonl`: a kqueue watch of that
  directory opens every entry, and `open(2)` on a socket fails (EOPNOTSUPP).
- `fs.watch` under bun never reports appends; watch with the file-watcher
  engine (`writesWhileOpen`).
- `canUseTool` must stay set: the SDK warns it is shadowed under
  `bypassPermissions`, but it still fires for AskUserQuestion — and without
  it the CLI removes AskUserQuestion from the tool set.
- Main's tmux poller adopts any tmux session whose cwd is in a worktree as a
  `tmux` conversation. Spike agents launched in the worktree show up on main
  without a transcript, so run scenarios from scratch dirs where possible.
