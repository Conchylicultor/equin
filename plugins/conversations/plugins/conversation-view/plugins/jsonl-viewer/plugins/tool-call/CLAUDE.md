# tool-call

## A renderer reads its input through a schema — never the raw input

A call's input is whatever the model wrote: a call it got wrong (refused by the
tool, kept by the transcript), a tool whose input changed since, or a prefix
still streaming. So `JsonlViewerTool.Renderer` is a typed factory over the
private dispatch slot (`JsonlViewerToolSlots.Renderer`):

```ts
JsonlViewerTool.Renderer({ match, icon?, input: Schema, partialInput?: PartialSchema, component })
```

- `component` gets `ToolViewProps<I>` = `{ event: ToolCall, input: I }` —
  `ToolCall` is the event without `input` (stripped at runtime too).
- `input`: the finished input. `partialInput` (all fields optional): what the
  card draws while the call is written; without it, the bare card.
- `parsedToolView` dispatches: `readToolInput` (core) parses — finished →
  `input` only, writing → `partialInput` — and a finished input that does not
  parse draws `GenericToolView` with the raw input and the schema's issues
  (`· unexpected input`). That is the honest view of a call the tool did not
  take, not a fallback over a bug.
