# request-shape

Renders Claude Code's `type: "api-request-shape"` transcript lines: the system
prompt and tool set a model call was sent with. Claude Code writes one the first
time a call uses a new shape (an `api-request` line names its shape by
`shapeHash`), so in practice a session has one at its start and one more each
time a deferred tool is loaded through ToolSearch.

The transcript parser (`transcript-watcher/server/internal/parse-jsonl.ts`)
lifts each line into a `RequestShape` — tool names and system-prompt text, never
the tool descriptions or input schemas — and diffs it against the previous shape
line (`requestShapeChange`, `transcript-watcher/core`), emitting
`kind: "request-shape"` with `change: null` on the first. A shape that differs
only in what is not read is not a row. A line without `shape.tools` /
`shape.system` stays `kind: "unknown"`, keeping the investigate action.

- First row: `Tools and system prompt · 16 tools`, summary listing the tools;
  fold-out with the tools as monospace chips and the system prompt (folded, as
  markdown).
- Later row: `Tools changed · 17 tools`, summary naming only the delta
  (`+mcp__equin__query_db`); added chips tinted, removed ones struck through.
  The prompt appears only when it changed (`System prompt changed`).

The `api-request` row's `tools or system prompt changed` phrase is the same
event seen from the call's side; this row says what the change was.
