# api-request

Renders Claude Code's `type: "api-request"` transcript lines — one per model API
call, recording the settings it was sent with — as a **change log**.

The transcript parser (`transcript-watcher/server/internal/parse-jsonl.ts`) lifts
each line into a `RequestConfig` (model, effort, thinking, max tokens, permission
mode, betas, and the system-prompt/tool-set `shapeHash`) and emits a
`kind: "api-request"` event only for a caller's (`querySource`) first call and for
calls whose settings differ from that caller's previous one
(`requestConfigChanges`, `transcript-watcher/core`). Identical calls — nearly all
of them — are not rows: each is counted into the `calls` of the row before it,
shown as the card's `· N calls` note, so the reader still sees they happened.

- First call: `Request settings` card, summary `Opus 5.5 · effort medium · adaptive
  thinking · auto mode`, fold-out with every setting and the beta list.
- Later call: `Request settings changed`, summary naming only the changes
  (`effort medium → high · +1 beta · tools or system prompt changed`).
- A caller other than the main thread is named first (`compact · …`).

The line's other fields (content hashes that rebuild the exact request from
`api-request-blob` / `api-request-shape` lines, cache breakpoints, the permission
classifier's full context) are deliberately not surfaced. A line whose shape the
parser does not recognise (no `params.model`) stays `kind: "unknown"`, keeping the
investigate action.

The `api-request-shape` lines those `shapeHash`es point at — the system prompt
and tool set — are their own rows, rendered by the sibling `request-shape`
plugin.
