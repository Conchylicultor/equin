# prompt-input

Draft management only. Enter empties the editor **synchronously** and hands the
text to `useSendConversationTurn` (the `pending-turn` plugin), the one entry point
for every turn send — it owns delivery, retry, transcript-verified confirmation,
and failure surfacing. There is no local POST, no `sending` disable (the editor stays
typable so messages can queue), and no send-failure toast here: a failed send
renders as a pending-turn card in the transcript, never as a restored draft.

The send goes through kept-state's `submitKept(…, { shows: "at-once" })`: the
editor is empty at once, but the stored draft keeps the text until the
receipt's `posted` says the server recorded the turn (or a Retry did). A
reload before that — when the tab's in-memory echo and its Retry are lost —
brings the text back into the editor. Text typed since the send is never
cleared by it.
