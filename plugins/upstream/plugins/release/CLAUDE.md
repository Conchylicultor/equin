# release

What an equin release is, as web-safe data — so the CLI that cuts one, the
machine half that detects one and the web that shows one read one definition.

- `core/internal/release-tag.ts` — the grammar: an annotated tag
  `v<YYYY.MM.DD>` on main, `.<n>` (n ≥ 2) for another release the same UTC day.
  `parseReleaseTag` (a release, or some other tag — not a failure),
  `compareReleases` / `releaseTags` / `newestReleaseTag`, `nextReleaseTag(now,
existing)` (UTC, so a laptop crossing a timezone cannot name one day twice),
  `releaseVersion` (`v2026.11.14` → `2026.11.14`), `releaseTagMessage`.
- `core/internal/status-value.ts` — `upstream.release-status` (`unknown` /
  `no-upstream` / `no-release` / `current` / `behind`, with the release `main`
  is on, upstream's newest and when it was checked) and
  `POST /api/upstream/check`. Both `needsMachine`; served by `upstream#machine`.

Not under `upstream/core` because that barrel spawns git (runtime-neutral
node, never web-safe); this one imports only zod and the live/endpoint
declarations.
