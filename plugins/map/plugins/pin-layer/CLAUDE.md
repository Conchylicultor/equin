# map/pin-layer

The map's pins at rest, drawn on ONE surface instead of one DOM subtree per
pin. Vendor-neutral: a renderer (today `map/google`) hosts it on its map,
hands it a projection per frame, and lifts the pins being interacted with
into the DOM itself. Plan and measurements:
[`research/2026-10-15-map-canvas-pin-layer.md`](../../../../research/2026-10-15-map-canvas-pin-layer.md).

## core — the plan and hit testing (pure, tested)

- `planPins({ pins, crowd, zoom, world, activeId, hoveredId })` → `PlannedItem[]`:
  one item per mark — a pin (`near` / `far`, a far spot's lead with `spot`
  `{ count, hushed }`) or a cluster (`cluster:<seed>`, at its members'
  centroid) — with its `z`. The same rules the DOM renderers had: spots group in
  world pixels at the zoom (`groupSpots`, the active pin leading its spot), a
  counting lead above every non-lead, the active pin above everything, the
  active pin never clustered; `hoveredId` hushes its spot's count.
- `hitTest(boxes, x, y)` → the topmost box containing the point (ties: the one
  drawn later).

## web — `PinLayer` and the painter seam

- `new PinLayer(painter, invalidate, fail)`; `setScene(items, dpr)` with
  `SceneItem { id, position, mark, z, texts, lifted }`; `render(frame)` with
  `LayerFrame { width, height, dpr, project, tiles, text }`.
- **A scene is swapped in whole**: it is held back until every sprite it draws
  is rasterized (`SpriteCache`: the mark's SVG decoded as an image and drawn at
  the device ratio into an `ImageBitmap`, keyed `key@dpr`, so pins that look
  alike share one), then `invalidate()` — pins never appear one by one, the
  previous scene stays up meanwhile. A sprite that cannot be made calls `fail`
  (the host rethrows it into its error boundary).
- **A frame** projects each item, culls what is off screen, sorts by `z`, and
  draws each non-`lifted` item's sprite plus its texts (`beside` at the mark's
  `labelAt` in `MAP_LABEL_PAINT` with the measured label font, truncated at
  192px; `center` at the anchor in the count font). `lifted` items are not
  drawn but still hit-tested, so the pointer resting on a lifted pin keeps it
  lifted. `hitTest` / `boxOf` / `onScreen` answer from the last frame.
- **`PinPainter`** (`begin`, `sprite`, `text`) is the one seam a drawing
  backend implements; `createCanvas2dPainter(canvas)` is the only one. A WebGL
  painter (a map's own GL context, deck.gl) would implement the same three
  calls if pin counts ever outgrow Canvas 2D (~10k+).
