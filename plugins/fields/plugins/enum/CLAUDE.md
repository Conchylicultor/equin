# enum

The **enum** (select) field type of the unified fields primitive — a
single-choice value drawn from a fixed set of string options.

This barrel registers ONLY the `FieldIdentity` (label "Select", `MdList` icon,
identity `coerce` to string) in the `fields.identity` registry. The type's
capabilities live in dedicated sub-plugins under `plugins/`:

- `plugins/config` — the config-render capability: the `enumField` factory plus
  the radio/dropdown renderer, contributing to the frozen
  `config-v2.fields.renderer` slot.
- `plugins/table` — the read-only chip `EnumCell` (`data-view.cell`), resolving
  the raw value to its option label via `field.options`.
- `plugins/filter` — the multi-select `FilterContribution` (`data-view.filter`):
  one `ToggleChip` per option, toggling membership of a `selected: string[]`.
- `plugins/inline` — the single-select chip-popover `EnumEditor`
  (`data-view.cell-editor`).

The enum factory + token now live in the matrix: this barrel owns the `fields/`
enum token (id `"enum"`), and `plugins/config` owns the `enumField` factory
(`@plugins/fields/plugins/enum/plugins/config/core`), which config descriptors
import. Dispatch is by id string `"enum"`, so the renderer (whose `.type` is this
token) matches descriptors built with the factory.

## The option contract

`FieldDef.options` is `{ value, label, variant?, hint? }[]` (the shared
`FieldOption`, `primitives/data-view/core`). **An option describes how it
presents** — the read chip takes its tint from `variant` (default `"muted"`) and
its tooltip from `hint`, so a surface no longer keeps a value→label map beside a
parallel value→variant map that every render site has to join by hand.

Deliberate no-ops, so nobody "finishes the job": the inline editor and the filter
operand input draw `ToggleChip`s, whose vocabulary is not `BadgeVariant`, and
stay untinted; group-by section labels and the control summaries are text-only;
server-side filter SQL never reads `options` at all, so a tint never reaches the
server.
