# tag / data-view-group

The **tag** type's `data-view.grouping` capability: `DataViewSlots.Grouping({
match: "tag", label: "Group by", groupings: tagGroupings })` — one grouping,
`{ id: "tree", label: "Nested", oneBucketPerValue: true }`.

`plan({ field })` indexes `field.options` once:

- **key** — the value (a tag id); **label** and **swatch** — its option's.
- **order** — the option's index in `field.options` (a forest lists its
  options in tree order, so this ranks siblings in that order).
- **ancestors** — the option's `parent` chain, root first, each
  `{ key, label, order, swatch }` — which makes data-view emit NESTED sections
  (see its CLAUDE.md, "Nested sections"). Absent on a root.
- **a value naming no option** → `null`: the row joins the one "None" section.
- **Cycle-safe and consistent.** A `parent` naming no option ends the chain,
  and an option on a cycle is a root — so every bucket that mentions an option
  places it under the same chain (data-view throws on two different chains).

Over a live source the grouping is one bucket per value, so a server-sorted
column would group in row order — where data-view keeps sections FLAT
(`appearance` sectioning ignores ancestors). No live source groups by a tag
field today.
