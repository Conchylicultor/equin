# tag

The **tag** field type — ONE value out of an **option forest**: a field whose
`options` carry `parent` (`FieldOption.parent`), e.g. a tag tree flattened in
tree order with each tag's colour as `swatch` (`tag-tree/engine`'s
`tagFieldOptions`). The type knows nothing about tag trees: any forest-shaped
option set qualifies.

```ts
{ id: "tag", label: "Tag", type: "tag", options: tagFieldOptions(tags), value: (p) => p.tagId }
```

- **Identity only, `extends: enumFieldType`** — the cell (a chip), the filter
  (pick values) and the inline editor are enum's, all reading `field.options`.
  No storage capability: the column a tag field reads is the carrier's own
  (a nullable text id).
- **Grouping** — `plugins/data-view-group` contributes the type's own
  `DataViewSlots.Grouping`: sections NEST along the forest (a bucket carries its
  ancestors — `GroupBucket.ancestors`, see data-view's CLAUDE.md "Nested
  sections"), so grouping by a tag reads `app ▸ website ▸ homepage` with
  rolled-up counts, a parent's own rows above its child sections, and every
  level folding on its own.

Out of scope: a multi-tag (`tags`) field grouping, and an "is under" filter
operator.
