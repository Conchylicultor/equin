# demo

Demo scenarios for a browser server (core only). A `DemoScenario` =
`{ id, app, route, host }` — the `Apps.App` id and app-relative route an
`<AppEmbed>` opens, declared by the app's owner (`apps/<app>/plugins/demo`),
and its browser host. The story is real server code over seeded rows — there
is no recorded-answer pack (`research/2026-10-19-global-demo-story-from-browser-worker.md`).

`DemoHost = ScopedComposition & { start() }`, as the owner's codegen emits it
(`core/browser-host.generated.ts`, `browserHost`, from
`deriveBrowserHostGraph`):

- **the composition** (`id`, `home`, `plugins` — the web plugins of the
  composition the worker boots) — the scope `<DemoScope>` renders the subtree
  in (`web-sdk`'s `<PluginScope>`), so the page shows exactly the plugins the
  worker serves;
- **`start()`** — `import("@browser-host/<plugin path>")`, a Web Worker running
  that composition's portable server graph on PGlite, seeded with the story.

One derivation writes both halves, so page and worker agree by construction.
`host` is required: the host answers every read and request in the demo, and
the same derivation proves it can — the coverage guard
(`browser-host-coverage.ts`) fails the build unless everything the scoped
page reads, calls or registers is served by the graph or declared
`needsMachine`; it also emits the reads it found (`hostReads`, beside
`browserHost`), which the owner's boot test holds the booted graph to. There is no
page-side backend slot any more (`Demo.Resource` and `DemoMissingError` were
deleted once config moved into the worker:
`research/2026-10-21-global-demo-config-from-worker.md`).
