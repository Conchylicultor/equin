# demo

Demo scenarios for a browser server. A `DemoScenario` (`core`) =
`{ id, app, route, host? }` — the `Apps.App` id and app-relative route an
`<AppEmbed>` opens, declared by the app's owner (`apps/<app>/plugins/demo`),
and its browser host: `() => import("@browser-host/<plugin path>")`, a Web
Worker running that plugin's portable server graph on PGlite, seeded with the
scenario's story (see `framework/browser-server` and `demo/scope`). The story
is real server code over seeded rows — there is no recorded-answer pack (the
pack and its builders were deleted once the agent-manager story moved into its
host: `research/2026-10-19-global-demo-story-from-browser-worker.md`).

`DemoMissingError(key, params)` is what the scope's browser server answers a
known key nothing serves with (the client sees `loader-failed` naming the key).

## web/: the `Demo` slots

`Demo.Resource({ id, useBackend })` (a plugin's backend in every demo scope —
`useBackend: Hook<() => DemoBackend>`, `DemoBackend = { serve, routes? }`: the
live keys it answers and the endpoint handlers sharing its per-scope state,
e.g. config_v2's in-memory user layer and its `set-field` write) and
`Demo.Route({ route: [ep.route, implement(ep, h)] })` (a STATELESS handler). Declared here, in a
leaf barrel, not in `demo/scope`: the scope imports UI (toast, loading) that
reaches config_v2, a contributor, so the slots there would be a cycle. Read by
`<DemoScope>` (`demo/scope`), which documents the contract.

`demoResource(id, serve)` is the one-line `Demo.Resource` for an answer that
depends on nothing in the scope's tree — a plugin's NEUTRAL demo answer, the
same for every scenario ("no ops in flight", "no notes", the baseline model
catalog). The story (conversations, tasks, transcripts) is the scenario's
host; a neutral answer is its owner's. A key served twice throws; a key both a
backend and the host serve is answered by the backend.
