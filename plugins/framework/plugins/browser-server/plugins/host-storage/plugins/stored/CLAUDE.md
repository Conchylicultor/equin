# stored

Whether this browser already holds a persistent browser host's data —
`hostDataStored(name)`: its lifecycle record says `ready` — read without
booting anything and without creating the database when it is absent
(`indexedDB.databases()` first). A page asks it before deciding to start a
host: `demo/scope`'s gate (a first visit waits for Enter equin, since starting
downloads the whole server and its data).

The answer is a typed result — `stored` / `absent` / `blocked` — never a
rejection for a browser that refuses the page IndexedDB (a `SecurityError`:
cookies and site data blocked, a sandboxed frame): `blocked` is a state the
page draws (the demo says it needs browser storage), not a crash.

It also owns the IndexedDB layout it reads (`layout.ts`: the storage's
database names, the entries and meta stores, the lifecycle record), which
`host-storage`'s open writes — one spelling for both. A leaf, so the gate can
ask without loading the rest of host-storage.

It also deletes it: `deleteStorageDatabases(name)` (every database of the
storage, the stores — the lifecycle record — last; `host-storage`'s own wipe
uses it) and `wipeHostData(name)`, a page's wipe for when no host runs to ask
(a demo whose boot failed on its stored data: `demo/scope`'s Start over). It
holds the storage's lock (`storageLockName`, the one `host-storage`'s
ownership takes), so it never deletes under a host that has the storage open
— it waits for it — and marks the lifecycle record `seeding` first, so a wipe
cut short is redone by the next open.
