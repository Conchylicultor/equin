# source-read-safety

Check code reads code through **`sourceAnalysis(ctx)`** (checks/core), never
through regexes over masked text (`checks/CLAUDE.md`, "Reading code:
`sourceAnalysis`, not regexes"; API:
[`checks/plugins/source-analysis`](../../../checks/plugins/source-analysis/CLAUDE.md)).

- `no-text-source-read` — in a `check/` folder's code (`*.scan.ts` included,
  tests exempt), no value import of
  `@plugins/plugin-meta/plugins/parse-utils/core` (`maskSource`,
  `matchBracket`, `findImports`, `findMarkerCalls`, `parseBarrelExports`, …;
  named, namespace, re-exported or `import()`), nor checks/core's
  `maskedSource`. Text scanners skip what they cannot guess — an alias, a
  re-export, an `export *` barrel, a wrapper — and the check passes over it.
  - parse-utils is banned by ALLOWLIST (the fs-snapshot scope and `lineAt`
    read no code), so a text helper added there later is banned too. Type
    imports are allowed.
  - `grepCode` / `grepImports` stay allowed: they answer whether a token or an
    import spelling appears — a question about text.
  - Only `check/` folders: a `core/` helper or codegen scan a check calls is out
    of reach.
  - Checks written before the rule are debt in their own `exempt/index.ts`
    (`./equin exempt list --rule source-read-safety/no-text-source-read`).
