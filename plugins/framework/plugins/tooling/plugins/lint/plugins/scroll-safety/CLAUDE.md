# scroll-safety

Home for the three repo-wide scroll-safety ESLint rules. All close the same class
of bug — hand-rolled scroll manipulation that fights the user's scroll — by
routing every case through a scroll-owning primitive.

## `no-adhoc-scroll-into-view`

`element.scrollIntoView(...)` / `.scrollIntoViewIfNeeded(...)` is banned
everywhere except the scroll-reveal primitive.

Route "reveal an element on activation" through
[`@plugins/primitives/plugins/dom/plugins/scroll-reveal/web`](../../../../../../../primitives/plugins/dom/plugins/scroll-reveal/CLAUDE.md)
(`useRevealOnActive` / `revealElement`) — so a reveal fires on an activation
transition or explicit intent, never because an element remounted already-active.
The exemption manifest (`exempt/index.ts`) contains only the primitive's own internal
implementation file — if you think you need another exemption, extend the
primitive instead.

## `no-adhoc-scroll-write`

Raw scroll writes — `el.scrollTop = …` / `el.scrollLeft = …` assignments and
`el.scrollTo(...)` / `el.scrollBy(...)` calls — are banned everywhere except the
auto-scroll primitive. (Reads like `el.scrollHeight - el.scrollTop -
el.clientHeight` are assignment sources, not targets, and are not flagged.)

For stick-to-bottom / jump-to-bottom, use `useStickyScroll` / `scrollToBottom`
from [`@plugins/primitives/plugins/dom/plugins/auto-scroll/web`](../../../../../../../primitives/plugins/dom/plugins/auto-scroll/CLAUDE.md).
For reveal-an-element-on-activation, use `useRevealOnActive` / `revealElement`
from `@plugins/primitives/plugins/dom/plugins/scroll-reveal/web`. The exemption manifest (`exempt/index.ts`)
exempts the auto-scroll primitive's own `web/` folder (so a new scroll role
added there needs no edit) — no consumer is exempted. If you have a genuinely different need, extend those primitives
rather than copying them.

## `no-scrolling-focus`

A DOM `element.focus(...)` (type-aware: the method declared on lib.dom's
`HTMLOrSVGElement`, so a Lexical editor's or a caret surface's `focus()` is not
matched) is banned everywhere except the funnel. A bare `focus()` scrolls the
element into view — a scroll write invisible at the call site; it made the page
jump when a table grip's menu opened (the caret host pulled focus back with a
bare `.focus()`, scrolling the tall table into view).

Use `focusElement(el, { reveal })` from
`@plugins/primitives/plugins/dom/plugins/scroll-reveal/web`. Focus never scrolls
there (`preventScroll: true`); `reveal` is required, so every call states its
intent: `true` (or `RevealOptions`) when the focus FOLLOWS the user's own
navigation — arrow keys through a list, a shortcut to a search box, an undo
revealing what it changed, a caret landing with `scroll` — and `false` when
focus is moved FOR them (restored, reclaimed, handed to a just-opened control).
Even `focus({ preventScroll: true })` goes through it: one spelling. The one
exemption outside the funnel is the browser engine's page script, injected into
remote pages, which can import no app module.
