# dom-access-safety

Contributes three repo-wide ESLint rules. `no-module-scope-dom`: in `plugins/**/web/**`,
a browser global (see *What a DOM read is* below) may not be read **during module evaluation** —
that runs on import, making every importing module unloadable under `bun test`
and the docgen barrel walk. Reads inside a function/hook/component body are the
fix and are never reported. For a socket URL use `wsUrl` from
[`@plugins/primitives/plugins/networking/web`](../../../../../../../primitives/plugins/networking/CLAUDE.md).

Two deliberate holes, both load-bearing:

- **`typeof <name> !== "undefined"` guards pass.** They degrade to a skipped
  branch off-browser instead of throwing — the right shape for a module-scope
  listener registration (`primitives/pane/web/pane.ts`, `parse-keys.ts`).
- **The only exemptions are entry points** — the two Vite entries
  (`web-core/web/main.tsx`, `layout-harness/…/entry.tsx`, loaded by a
  `<script type="module">` tag) and the SharedWorker entry
  (`networking/web/shared-ws.worker.ts`, started by `new SharedWorker(…)`). None
  is ever statically imported, so no module graph can reach them. Each is a
  sanctioned entry in its own plugin's `exempt/index.ts`; `noDebt`. Nothing else
  qualifies — put the read in a function instead.

Rationale and the failure it came from:
[`research/2026-08-08-global-module-scope-dom-import-safety.md`](../../../../../../../../research/2026-08-08-global-module-scope-dom-import-safety.md).

## What a DOM read is

Both rules take their reads from one detector, [`lint/dom-reads.ts`](lint/dom-reads.ts)
(`domReads`), and decide only *when* a read is a problem — so they cannot
disagree on what a read is. A read is a value reference to `window`,
`document`, `navigator`, `localStorage`, `sessionStorage`, `matchMedia`,
`location`, `history`, `screen`, `getComputedStyle`, `Element`, `Node` or any
`HTML*Element` / `SVG*Element` class — unresolved, or declared as a global by the
lint config — including one wrapped in a TypeScript cast (`(window as X).foo`,
`document!`, `<X>navigator`, `x satisfies Y`). A type position and a `typeof`
operand are not reads. (The casts once hid three module-scope reads from
`no-module-scope-dom`, while `no-render-time-dom` saw through them.)

## `no-render-time-dom`

In `plugins/**/web/**`, a browser global (*What a DOM read is*) may not be read **while a component or
hook renders**: its body, a render-time callback (`useState` / `useMemo` /
`useReducer` initialisers, `useSyncExternalStore`'s `getServerSnapshot`), or an
IIFE in one. A static render (`primitives/dom/render-mode`: the website's
HTML for robots) has no DOM and throws there; live, the read never updates.
The fix is `render-mode/web`'s `useBrowserValue` / `useMediaQuery` /
`useViewportSize` / `useOwnedElement`, an effect or handler, or a
`renderMode()` branch in the building block. Unlike `no-module-scope-dom`, a
`typeof` guard does not pass: it no longer throws, but still never updates.

What the rule knows is safe, so it needs no disable:

- **Behind a `renderMode()` test** — the live branch of
  `renderMode() === "static" ? … : …` (any `===` / `!==` / `"live"` spelling),
  `renderMode() === "live" && …`, or everything after
  `if (renderMode() === "static") return | throw …`.
- **A live-only component** — not exported, and every use of it in its file
  is behind such a test or inside another live-only component
  (`MediaPlayer` → `LiveMediaPlayer`, `AdaptiveBarItem` → `PortaledBarItem`).

A read guarded by something else it cannot see (an element that exists only
once mounted: `el !== null && el instanceof HTMLVideoElement`) takes a
per-site disable with that reason. `noDebt`: no debt exemption is accepted.

## `no-root-style-write`

Nothing writes `<html>`'s inline style — `document.documentElement.style`, or
`.style` of a `const` bound to a `documentElement`. A custom property or style
set on the root is inherited by every element, so each write forces a
whole-document style recalc (300–450 ms on an 18k-element page). Root-level
styling is the theme engine's, through its stylesheets. Anything else sets its
value on the subtree that reads it: a rule keyed on that subtree's own class in
an adopted `CSSStyleSheet` (how `shell/global-action-bar` publishes the floating
bar's safe area — ~5 ms per write instead of ~300), or an inline style on that
element. The one exemption is `embed/frame/agent`, which styles the root of a
prototype's own frame document.
