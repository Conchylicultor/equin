# repo-walk-safety

Contributes two rules. `no-adhoc-repo-walk`: a hand-written list of build-output directory
names — `"node_modules"` alongside `"dist"` / `".git"` / `".cache"` — in an array
or `new Set([...])` is banned outside the allowlist in [`lint/index.ts`](lint/index.ts).

## Why

Such a list is a guess at what `.gitignore` already states exactly, and it is
always missing one. `type-check` held two copies that both omitted `.cache/` —
the gitignored directory it writes its own `.tsbuildinfo` into — so a `.ts` left
there counted as source and failed the coverage gate. Ask git: the file set
(`ctx.repo()` in a check, `loadRepoFiles` at a pass root) is tracked +
untracked-not-ignored, the same universe the check runner's tree hash uses.

## The allowlist has two kinds of entry

- **Bounded walks of a known subtree** (`ensure-deps`, `global-css`) skip
  `node_modules` because descending is pointless, not to define "source". Legal.
- **A one-off migration script that already ran**
  (`checks/core/scripts/fix-shared-to-relative.ts`). Nothing runs it, so its
  file set decides no verdict.

No check belongs on the list. Checks enumerate through `ctx.repo()`.

## `no-adhoc-repo-listing`

Listing the working tree — a call to `loadRepoFiles` / `loadRepoSnapshot` /
`listRepoFiles`, or an argv that runs `git ls-files` — is banned outside a
**pass root**: a `cli/` command, a `bin/` entry point, a script (the rule's
`outOfScope`; tests and e2e are out of every contributed rule's scope).

### Why

One check pass on 2026-11-05 spawned 59 `git ls-files` (~40 s summed). Most
were whole-tree listings (`--deleted` lstats every ~22k index entries,
`--others` walks every untracked directory), each adding to the host's vnode
churn — while the run already held one shared listing, read off its tree
snapshot. 27 came from the type-check lint workers rebuilding the exemption
manifests per config; the rest from shared helpers that listed when no set was
passed (`buildPluginTree`, the web-artifacts plan) and from checks spawning
their own pathspec'd `git ls-files`.

### What to do instead

- **In a check**: `ctx.repo()` — a `RepoSnapshot` (each member's blob id
  included), so even a helper that keys on content takes it.
- **In a shared helper**: take the caller's `RepoFiles` / `RepoSnapshot` as a
  required parameter. Never fall back to listing when it is absent — that
  fallback is what every hidden listing was.
- **At a pass root**: list once, hand the set down.

A listing that is genuinely its own pass — a long-lived server rebuilding on a
watcher, a read of another checkout, the file-set loaders themselves — is
declared in its plugin's `exempt/index.ts` with the reason
(`./equin exempt list --rule repo-walk-safety/no-adhoc-repo-listing`).
