# shared-work-safety

Work one check of a pass starts and every later one reuses — a per-pass memo
keyed by the run's file set (the codegen trees, the registry context, server
portability, the npm key) — runs as SHARED work (`packages/shared-work`), so
it is counted under its own name on the run's `done` record and never into the
check that happened to ask first (whose own file calls are judged against its
`wholeTreeRead` declaration; `tooling/checks` CLAUDE.md, "Shared work is
nobody's own").

- `per-run-memo` (type-aware) — a module-level `new Map(…)` / `new WeakMap(…)`
  whose key type is a file set (`RepoFiles`'s members, read structurally) or
  holds one under `repo` (`CodegenPass`) is refused: spell it
  `sharedMemo(name, produce, { owner })`, which runs the producer as shared
  work by construction — and as the asking check's own work when the key's
  owner is that check's own input (`markOwnInput`: an input-keyed check's
  recording set, so its reads land in its read-set AND its meter).

  It sees module-level memos keyed by a file set. A memo keyed by something
  else (a root path, a `RegistryGenContext`) still wraps its producer by hand
  (`sharedWork` / `sharedWorkOver`).
