# guards/agent-policy

The protections every agent runs with — hooks (guards, stop guard) and deny
rules — as one declaration (`agentPolicySettings`). Two consumers, never a third
copy:

- `.claude/settings.json`: its `hooks` and `permissions.deny` are generated from
  it by `./equin build` (codegen `claude-settings-gen.ts`);
  `guards:claude-settings-in-sync` fails on a hand edit.
- an app launch whose workspace has no project settings — a scratch dir
  outside the repo (`conversations/agent-launch`'s `agentLaunchPolicy`, when
  the workspace's `LaunchGuards` is `launch`). A worktree launch carries none of
  it: the checkout's own generated settings guard it (`LaunchGuards`
  `checkout`).

Exactly one source per session, always the same commit as the scripts it runs.
A launch spelling a worktree's hooks from the launching backend's code broke
every resumed worktree branched before a hook change: main's spelling named
`bin/run-hook.sh`, the checkout had no such file, and — the two spellings
differing, so Claude Code ran both — every tool call was refused.

Each hook command reads `${EQUIN_GUARDS_ROOT:-$CLAUDE_PROJECT_DIR}`
(the `GUARDS_ROOT` key, `envName` in `infra/launcher/env-names`): a human or
worktree session runs its own project's scripts (a worktree's own, so an agent
can edit and test its guards); a scratch launch names the launching backend's
checkout — the code that spelled the hooks.

## Every hook runs through one launcher

A hook command is a `HookCommand` (branded: only `hookCommand()` and this
policy spell one) — `/bin/sh "<checkout>/…/agent-policy/bin/run-hook.sh"
"<checkout>/<script>.ts"`. The launcher `cd`s to the script's directory (so
mise's shim picks the checkout's pinned bun), finds `bun` on PATH or else in
mise's shims dir, and when there is none prints what to install / activate and
exits 1 (the PreToolUse command turns any failure into a block, exit 2). A bare
`bun` used to exit 127 silently on every call in a Claude Code started from a
shell without mise. `guards:hook-commands-via-launcher` holds
`.claude/settings.json` to the same spelling. Other plugins' hooks (stop-gate,
compaction-context) pass their backend's checkout — `REPO_ROOT`, or main's
`current` link when that is a main slot (main-slots `durableCheckoutRoot`: the
agent outlives the slot, and a reclaimed slot's path made every Stop hook exit
127) — and a repo-relative script.

Imports only `infra/launcher/env-names` (a portable leaf: the env-name registry): the
portable `agent-launch` server barrel imports it.
