# registry

The check registry: the `check` collected-dir marker (`core/collected-dir.ts`),
the `check.generated.ts` codegen writes beside it (every
`plugins/<p>/check/index.ts`), and `loadChecks()` / `listAllChecks()` — every
registered check, validated, each paired with its module.

**Why it is not in `checks/core`.** An input-keyed check's cached PASS is keyed
on its code: the module-graph Merkle key of its `check/index.ts` closure
(`checks/core/check-code-key.ts`), which follows literal `import()`s. The
registry's `import()` reaches every check, so while `checks/core` re-exported
the loader, every check importing `checks/core` had all ~120 checks in its
closure, and any check's edit re-keyed every input-keyed check. Import this
barrel only from what loads the fleet: the `check` command, codegen's
exempt-rule ids, `exempt:manifests-valid`. The runner asserts it: a check whose
closure reaches another check's module fails loudly.
