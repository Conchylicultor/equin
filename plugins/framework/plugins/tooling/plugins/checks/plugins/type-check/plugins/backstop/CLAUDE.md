# backstop

The two-program type check's safety net. A `type-check` run re-checks only the
files with no valid stored result and what their changed names reach, and
reuses every other file's stored diagnostics and `.d.ts`
(`../../shared/name-run.ts`). Nothing in a check run can notice a key or an
affected set that misses something a file's check reads, so once a day this job
runs the worker in `dual` mode on main: the two-program check, then a full
check of a fresh whole program (`../../shared/full-check.ts`), compared file by
file.

- A divergence is logged (`logs/type-check-backstop.jsonl`) and filed as a
  `type-check-divergence` report (one row per file and kind), and a cold run
  rewrites the store. The fix is always to widen the key or the affected set,
  never to delete entries.
- Reproduce by hand with `../../scripts/dual-check.ts` on the trees before and
  after the commit in question.
- Main only (a scheduled job's default), in a supervised child, admitted like
  any worker (a background grant, then the `type-check-worker` slot). Not part
  of any build.

Design: `research/2026-10-21-global-type-check-two-programs.md`.
