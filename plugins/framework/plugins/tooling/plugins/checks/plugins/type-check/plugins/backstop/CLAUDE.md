# backstop

The keyed type check's safety net. A `type-check` run re-checks only the files
whose key moved and reuses every other file's stored diagnostics and signature
(`../../shared/keyed-check.ts`). Nothing in a check run can notice a key that
misses something a file's check reads, so once a day this job runs the worker
in `dual` mode on main: the keyed check, then a full check of a fresh program,
compared file by file.

- A divergence is logged (`logs/type-check-backstop.jsonl`) and filed as a
  `type-check-divergence` report (one row per file and kind), and the full
  check's results overwrite the store entry. The fix is always to widen the key,
  never to delete entries.
- Reproduce by hand with `../../scripts/dual-check.ts` on the trees before and
  after the commit in question.
- Main only (a scheduled job's default), in a supervised child, admitted like
  any worker (a background grant, then the `type-check-worker` slot). Not part
  of any build.

Design: `research/2026-10-18-global-tsc-recheck-follows-contracts.md`.
