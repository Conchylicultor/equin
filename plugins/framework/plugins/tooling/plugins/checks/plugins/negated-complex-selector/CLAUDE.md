# negated-complex-selector

Rejects a `:not()` whose argument is a **complex** selector — one with a
combinator, directly or through `:is()` / `:where()` — in what becomes a
stylesheet: plugin CSS, and Tailwind arbitrary variants (`[&:not(.x_*)]:p-2`,
`_` read as a space) in `.ts` / `.tsx`. A selector handed to `querySelector`
or `matches` costs no restyle and is not scanned; neither are comment lines.

## The cost it prevents

Chrome cannot narrow a class or attribute named inside a complex `:not()` to
the rule's subject: any change of it invalidates the whole subtree under the
element that changed. When that state lives high in the tree, every flip
restyles the whole document:

- `focus-ring`'s `:not(:where([data-input-modality="pointer"] *))` — 8,091
  elements per keyboard ⇄ pointer flip on `/agents`; 648 in the positive form
  (`ui-kit/e2e/input-modality-flip-cost.ts`).
- the action bar's `:not(.floating-bar-boundary *)` — ~20k per surface switch
  (fixed in 47fe5d8d63).

## The fix it points to

Name the state as an ancestor: `:where(:root:not([data-x])) .y` instead of
`.y:not([data-x] *)`, or a plain descendant rule (`.boundary .y`) that undoes
the base rule. Simple negations (`:not(.a)`, `:not([a], [b])`) are fine.
