# migration-metadata-consistent

Asserts the migration metadata under `plugins/database/plugins/migrations/data`
cross-references itself. Everything is keyed by the same `<tag>`
(`<YYYYMMDD>_<HHMMSS>_<sha8>__<slug>`):

- `J` = journal tags — `meta/_journal.json` `entries[].tag`
- `S` = `.sql` tags — `data/*.sql` (minus `.sql`)
- `L` = legacy tags — the keys of `meta/legacy-snapshots.json` (schema
  migrations from before the snapshot cutover, whose lineage lives there)

plus the snapshot ids every newer schema migration names in its
`-- singularity:snapshot` header.

Invariants:

- **`J === S`** — every journal entry has a backing `.sql`, and every `.sql` has
  a journal entry. Reported as two diffs: `orphanSql` (`S \ J`) and
  `orphanJournal` (`J \ S`).

  `J === S` is a **post-condition of `generateMigration`** (it regenerates the
  journal from the `.sql` filenames unconditionally), so on any built tree this
  holds by construction and the check is a **backstop** — for trees nobody built,
  and for the window between a rebase and the normalize pass. Remedy is therefore
  a plain `./singularity build`, never `--reset-migration`.
- **`L ⊆ S`** — every legacy entry maps to a real migration (`orphanLegacy`).
- **Header ids are unique** (`duplicateHeaderIds`) — two migrations naming one
  snapshot would make the DAG ambiguous.
- **"every `.sql` has a lineage" is intentionally NOT asserted.** Data/backfill
  migrations legitimately carry none (that DML-only contract is owned by
  `data-migration-dml-only`), so a `.sql` without one must never be flagged.

The pure verdict logic (`classifyMigrationMetadata(J, S, L, headerIds)`) is
exported and unit-tested in `check/index.test.ts`; the impure reads stay in
`run()`. It is a pure function of the working tree (no git/DB/drizzle), so it
uses the default tree-hash caching — no `cacheSignature`.

Why each existing migration check misses this gap:

- `migrations-in-sync` only runs `drizzle-kit generate` against `schema.ts`; it
  never maps journal → `.sql` (the orphan `.sql` slice moved here, so each check
  owns exactly one invariant).
- `snapshot-chain-intact` walks snapshot `id`/`prevId` links over the id-graph
  only — a legacy entry whose `.sql` is gone is still a valid chain link there.
- `migration-hashes-unique` only groups `.sql` filenames by `sha8`.
- `data-migration-dml-only` only inspects the bodies of data migrations.
