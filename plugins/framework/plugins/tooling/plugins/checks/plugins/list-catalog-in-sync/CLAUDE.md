# list-catalog-in-sync

Fails if a file of the list catalog drifts from what the plugins declare
(codegen's `list-catalog-gen.ts`, one collector per runtime over the build's
evaluated barrel records):

- **Web lists** — `list-catalog/web-lists/core/web-lists.generated.ts` (every
  declared web list: id, declaring plugin, key, meta) and
  `server-core/core/web-list-entries.generated.json` (every web list entry's
  fact, with its list and plugin). The server reads web lists from these
  (the apps, the first frame's themes, the reorderable lists' config
  directives), and every page is shipped them kept to its composition. When a
  list becomes reorderable, the failure also names the authored config
  override it will owe (`config/<declaring plugin path>/<key>.jsonc`), before
  any build — the build seeds it with a `// @review` marker.
- **Server lists** — `server-core/core/contributors.generated.ts` (which
  graph nodes contribute to which server list kind: a job process that
  starts only some plugins starts the contributors of the lists its job
  reads from it), `server-core/core/list-entries.generated.ts` (every server
  data list's entries) and `supervised-job/cli/job-reads.generated.ts` (the
  lists each supervised job's body reads).

Fix by running `./equin build` and committing the regenerated files.
