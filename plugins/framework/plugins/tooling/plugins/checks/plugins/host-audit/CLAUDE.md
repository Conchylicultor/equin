# host-audit

The hourly `checks.host-audit` job: runs
`./equin check --scope host --file-reports --no-cache` in main's checkout, in a
supervised child, main only. Each failing host-scoped check becomes one
`host-check` report (`plugins/reports/plugins/host-check`) through the report
outbox. The transcript goes to `logs/check-host-audit.jsonl`.

## Why it exists

A host check (`Check.scope: "host"`) judges state every checkout on the machine
shares — the data root under `~/.equin`, the code-signing identity. No checkout
can assert that state, and none should fail over it: a directory one agent
leaves under the data root is not another agent's to fix, or even to delete.
When a bare `./equin check` selected every scope, one leftover file turned every
agent's check red until someone removed it by hand (three times on 2026-11-05),
and agents read that red as a blocked push.

So a bare `./equin check` selects `CHECKOUT_SCOPES` (tree + deploy), and this
job is where a host verdict is delivered: to Reports, where it has an owner and
an Investigate button. `./equin check <id>` or `--scope host` still runs a
host check on demand.

`--file-reports` turns the exit code into "were the reports written": a run
whose failures all reached the outbox exits 0, so a found problem files one
`host-check` row, not also a job-failure crash. It refuses any scope but
`host`, because a tree or deploy failure belongs to the checkout that ran it.
