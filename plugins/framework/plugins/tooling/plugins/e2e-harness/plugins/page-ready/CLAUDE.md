# page-ready

When a page of the deployed app is ready to be captured, as ONE rule both
capture paths apply: the e2e harness (`screenshot.ts`, `snap`, every script's
waits) and the agent browser's host (`infra/mcp/browser`'s `capturePair`, which
may import no `e2e` barrel — hence a `core/` of its own).

- `waitForScreenReady(page)` — painted (re-captured until the screen is not one
  flat colour: `flatness`), then network idle, then no visible `aria-busy`
  loader. `blank` is a page that never painted — never a capture to hand back
  as evidence; `ready.stillBusy` names loaders still up at the deadline.
- `waitForNetworkIdle(page)` — the page's own requests, tracked from its first
  one (`trackPageNetwork` / `trackContextNetwork`), worker script loads aside
  (Playwright's `networkidle` never fires on this app — see the harness doc).
- `waitForNotBusy` / `busyRegions` — the visible `aria-busy` regions.
- `waitFor(read, ok)` / `ELEMENT_TIMEOUT_MS` — a condition wait with a deadline,
  not a sleep (`internal/wait.ts` has the measurements behind the budgets).
