# served-addresses

A served dist's address dir and the rule that bounds it, shared by every host
that serves one:

- **`retainAddresses` / `servedGraphOf`** — an address stays while a graph
  needing it (composed, served, or named by an open tab — the backend touches
  its record — this plugin's `machine/` half, in every served composition
  through the `served-baseline` row) was needed within a day. Run by the dev
  build before its publish (`framework/cli/build`'s artifact pipeline) and by a
  release's `launch` through `publishReleaseDist`. Read by the blocker scan.
- **`publishReleaseDist`** — a release host served from the dev layout
  (`web.live.<runId>` per release, one `web-addresses`, one `web-graphs`
  under the namespace's dir in the data root; the spec names the release's
  dist, no `web` link), so a ship, which prunes the replaced release's
  extraction, takes no file an open tab still loads.
- **`machine/`** — the touch: every graph a tab names gets its record's mtime
  bumped (at most hourly), anchored on the namespace's served-dist path.
- **`addressDirOf`** — the one spelling of `<dist>-addresses`
  (`dist-publish.ts`'s `distNames` uses it too).

A sub-plugin, not web-artifacts' own `cli/` barrel: that barrel carries the
pooled vite builder, which the release's compiled `launch` binary
(`infra/launcher/bin/launch.ts`) must not pull in. Design and the full rule:
web-artifacts' `CLAUDE.md`, "A served dist keeps serving every address…" and
"A release host serves every release a tab used recently".
