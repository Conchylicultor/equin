# http-router

## Every response says how long its handler took

`safeHandle` times each route handler (called → its response returned; a
streamed body's tail is not in it) and appends `Server-Timing:
equin;dur=<ms>;desc="<id>"` (`core/server-timing.ts`) — the 500 included, a
response with immutable headers re-wrapped. The browser records it on the
request's Resource Timing entry; the per-response `id` is how a client finds
that entry (`primitives/networking`'s `requestTimingOf` — the browser exposes
no request id). So a client can split a request's round trip into its own
wait, the network and the handler from stamps none of which its main thread
takes (the optimistic `confirm` sample; `perfs/latency-signal`). Every host
mounts this router, so every host stamps; only the page's own server's
requests are timed (`Transport.requestTiming`).

## Plugin reference

- Description: The one HTTP request router every host mounts: createRequestHandler turns "METHOD /path/:param" route pairs into a (req) => Promise<Response> — literal fast path, then :param matching in registration order, a default cache-control: no-store, a Server-Timing stamp of the handler's own time with a per-response id on every response (readServerTiming parses it back), and a logged generic 500 on a throw. A duplicate route key throws at construction.
