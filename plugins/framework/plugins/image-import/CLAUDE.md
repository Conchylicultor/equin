# image-import

What `import shot from "./x.png"` evaluates to, on every host: an
`ImportedImage` — `{ src, width, height }`. The size is the file's own, read
from its header when the module is built (`packages/image-size`), so whoever
draws the image gives its box that size before a byte of it arrives:

```tsx
import shot from "../shots/app-pages.jpg"; // ImportedImage
<img src={shot.src} width={shot.width} height={shot.height} loading="lazy" decoding="async" alt="…" />
```

(with `height: auto` in CSS when the width is scaled, so the ratio holds).

Who produces it — each through this plugin's `imageModuleCode`, so the shape
cannot differ between them:

- **The web build** (`tooling/web-artifacts`, `core/internal/image-assets.ts`):
  the file is emitted into the importing plugin's artifact, beside its
  modules, under its own name (the artifact dir is already content-addressed),
  and `src` is its URL, resolved against the chunk's own `import.meta.url`. Never base64 in the JS — vite's library
  mode would inline every asset, which put 395 KB of screenshots inside the
  website apps gallery's `index.js` and 2.8 MB of wallpapers inside the
  desktop's, downloaded and parsed on every route that loaded the plugin.
- **A Bun render** (`plugin-meta/barrel-import`'s `inlineAssetImports`, the
  crawlable snapshot): `src` is a `data:` URL — there is no served file.
- **jsdom tests** (`vitest.config.ts`): a `data:` URL too.

The types are ambient (`web-core/web/image-imports.d.ts`, referenced before
`vite/client` so they win). Only formats whose size the header gives are
importable (PNG, JPEG, GIF, WebP, BMP); an `.svg` / `.avif` / `.ico` import
fails the build — draw a vector inline (`?raw`) instead. A query (`?raw`,
`?url`, `?inline`) still means what vite says.

## Plugin reference

- Description: What `import shot from "./x.png"` evaluates to on every host: an ImportedImage — its URL and its pixel size, read from the file at build time so a page reserves the image's box before it loads. The web build emits the file beside the artifact (content-hashed, fetched like any image: cached, decoded off-thread, lazy-loadable), never base64 in the JS; a Bun render and a jsdom test get a data: URL. A leaf over packages/image-size, so web code can name the type without reaching the build.
- Core:
  - Uses:
    - `packages/image-size.ImageSize`
    - `packages/image-size.readImageSize`
  - Exports (types): `ImportedImage`
  - Exports (values):
    - `IMAGE_IMPORT_MIME`
    - `IMAGE_IMPORT_RE`
    - `imageDataUrl`
    - `imageModuleCode`
    - `importedImageSize`
- Cross-plugin:
  - Imported by:
    - `framework/tooling/web-artifacts`
    - `plugin-meta/barrel-import`
