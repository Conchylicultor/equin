# digest

The ONE test digest implementation: what a harvested `./equin test` verdict is
keyed by, and what Debug → Tests compares it with. `core/` and `cli/` only —
never `server/`: it is built on plugin-records' module graph, which must stay
out of every backend's closure (`boot:closure-digestable`). A backend that
needs the checkout's digests runs `./equin test-digest` as a supervised child.

```
digest(f) = recordKey(TEST_DIGEST_VERSION, runtime, npm resolutions,
                      runnerInputsKey(runner(f)), f, moduleGraph.keyOf(f))
runnerInputsKey(bun:test) = bunfig.toml + static closure of test/bun-preload.ts
runnerInputsKey(vitest)   = static closures of vitest.config.ts and test/setup.ts
```

`keyOf(f)` is the file's Merkle key (static AND dynamic imports). A runner
input counts its STATIC closure only: the preload's `await import(machine
registry)` would otherwise fold ~3.4k modules into every bun digest.

## Blind spots

What a digest cannot see — a change there leaves a verdict looking current:

- machine providers the bun preload loads dynamically;
- `import.meta.glob`;
- fixtures a test reads from disk;
- processes a test spawns;
- environment variables;
- the migrations a DB-backed suite applies;
- the `@composition-web-registry` alias (vitest).

Bump `TEST_DIGEST_VERSION` when what a digest means changes without any keyed
input changing.
