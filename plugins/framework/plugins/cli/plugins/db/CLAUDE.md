# db

`./equin db` — worktree database operations. A command GROUP: it routes,
and the declaration union makes "also runs" unspellable, so bare `db` prints its
subcommand help by construction.

## `db fork`

Forks the main (base) database into `[target]` (default: this worktree's
name). It exists for checkouts made with a bare `git worktree add`, outside
equin — those get no fork on creation, so they come up with no database at
all. Idempotent: a no-op when the DB already exists.

The interesting part is where it reads what a fork must NOT copy. Those
tables are declared by the plugins that own them (`ExcludeFromFork` /
`ExcludeSchemaDataFromFork`) — static data on their server definitions, so a
function of this checkout's code. `fork.ts` reads them off the code, with **no
running backend**: it spawns `cli/internal/declared-exclusions-probe.ts`, which
loads the plugin graph this checkout's backend would boot (server-core/cli's
`loadDeclaredGraph`: the load waves only — no collect, no `register`, no
barrier, no database) and writes `forkExclusionsFrom(plugins)` back as JSON.

- **A child process, on purpose.** Loading the graph declares a runtime
  namespace (modules resolve namespace-scoped paths at module eval). The
  `db fork` process must stay namespace-less: with one, its own DB connections
  would claim to report their ends through sinks nothing in a CLI drains.
- **Why not ask a backend.** It used to (this checkout's, else main's, over
  `GET /api/db/fork-exclusions`). `--replace` is the recovery path for a
  worktree DB that cannot boot, and on 2026-11-08 it could not run while main
  was crash-looping and then down — a recovery tool depending on the thing it
  recovers from. The endpoint is gone.
- **Still loud.** A module that fails to load fails the probe, an empty set
  throws (`forkExclusionsFrom`), an answer that does not parse is refused —
  all before anything is dropped. Forking with an empty set would copy every
  debug table and quietly hand back a ~1 GB database full of main's traces.

`cli/index.ts` is the data-only declaration; `cli/fork.ts` is the implementation
behind its lazy `import()`, and it is the half that reaches
`@plugins/database/plugins/admin/server`. Adding a second operation (drop, list,
backup — `database/plugins/admin/server` already exports them) is a file beside
`fork.ts` plus one entry in `subcommands`.
