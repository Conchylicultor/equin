# build

`./equin build` — the command the agent workflow runs on. It takes this
checkout from source to a running app at `http://<worktree>.localhost:<port>`.

## The two postures

One pipeline (`cli/internal/app-artifacts.ts`), two ways to run it:

- **Deploy** (the default) — codegen, migrations, the web dist, the backend
  restart, the gateway registration, the deploy receipt. Everything about the
  live dev cluster.
- **Hermetic** (`--hermetic --composition <name>`) — produce those compositions'
  artifact sets and touch no cluster at all: no Postgres, no DB fork, no
  gateway, no run ledger. This is the phase `release` shells into, which is why
  it must run on a bare host from a fresh `git clone`.

The posture branch is the **literal first statement** of `cli/run.ts`, ahead of
`markBuildInProgress` and every other arming call. That is what makes the
hermetic path's emptiness structural rather than a claim maintained by ~20
scattered `if (!hermetic)` guards — and it is what lets stage 2's exit 2
(drizzle prompt) and exit 1 (missing `--migration-name`) reach `release`
unrewritten and unburied.

## Layout

- `cli/index.ts` — the data-only declaration: name, description, and the ten
  flags, in commander's own syntax. Loads on **every** `./equin`
  invocation, so it may reach no npm package and no `web`/`server` barrel
  (`cli:command-declarations-light`).
- `cli/run.ts` — the action, reached through the declaration's lazy
  `import("./run")`. This is where `pg`, the plugin server barrels and the whole
  build pipeline load, i.e. only when `build` is the command actually running.
- `cli/internal/` — build-private machinery, reached from nowhere else in the
  repo: the shared artifact pipeline (`app-artifacts`), target resolution
  (`build-targets`), the deploy half (`deploy-namespace`), the atomic dist
  publish + leftover sweep (`dist-publish`), the hermetic driver
  (`hermetic-build`), the experimental marker, and the legacy in-checkout dist
  reaper.
- `plugins/build-steps/` — the hook plugins contribute build steps through
  (`build-step/index.ts` + `defineBuildStep`); `cli/run.ts` runs each phase
  with `runBuildSteps(phase, ctx)` and names no contributor.

## Main's build writes nothing git sees

Main builds only in a SLOT (`infra/git/main-slots`): a linked worktree checked
out at the one commit it builds, which no push writes into and nothing runs
from while it is built. A main build that was not handed one (the Build
button's, a hand-run one at the repo root) relays itself into one
(`cli/internal/slot-relay.ts`); one that reached its writers anywhere else
throws. There, `cli/internal/main-tree-guard.ts` is a DETERMINISM check: it
snapshots `git status` before the first writer and compares after the last one
(the formatter). Every generated file on main was already checked in sync by
the push that landed it, so a difference means the build read an input its
commit does not hold (a stray untracked file, typically) or is not
deterministic. The build **fails** and names every path it changed and every
untracked suspect. Nothing is restored — on a failed guard or on a throw: the
slot is never served from that build, and the next build that takes the slot
runs `git checkout --force` there. (When main built in the checkout `./equin
push` fast-forwards, a dirty file there aborted every push's `git merge
--ff-only` and failed every later main build — 2026-10-17, 2026-11-04,
2026-11-16 — so the guard used to restore to HEAD; see
[`research/2026-10-17-global-main-checkout-read-only-build.md`](../../../../../../research/2026-10-17-global-main-checkout-read-only-build.md)
and [`research/2026-11-16-global-main-slots.md`](../../../../../../research/2026-11-16-global-main-slots.md).)

**Plugin-move leftovers fail first, by name** (`cli/internal/moved-plugin-leftovers.ts`).
A move leaves a plugin's ignored build output at the old address, un-ignored
once its `.gitignore` has moved, so discovery reads it as a plugin. Before the
snapshot, main's build checks every ledger `from` address that git tracks
nothing under, prints its untracked files with the move, and exits 1. It
deletes nothing: whether a file is disposable output is the investigator's call.

`build` is deliberately **not** `detachable`: the orphan guard exiting it when
its invoking shell dies is what stops an abandoned build from sitting on the
build lock and a host grant. The detached self-restart build exempts itself
through `EQUIN_BUILD_DETACHED` instead.

`pg` is a dependency of this plugin rather than of the CLI host, because
`cli/run.ts` is its only importer here (`databaseReady` and `waitForPg` both
`await import("pg")`).
