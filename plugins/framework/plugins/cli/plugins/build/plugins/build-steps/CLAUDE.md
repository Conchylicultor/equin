# build-steps

The hook a plugin uses to contribute a step to `./equin build`, so the build
calls no plugin-owned step by name.

## Contributing a step

A plugin adds `build-step/index.ts`, default-exporting an array of
`defineBuildStep` values (from this plugin's `cli` barrel). Codegen collects
every such folder into `core/build-step.generated.ts` (`build-step` is a
collected dir, composition membership — a plugin the app excludes contributes
none). Nothing in the build names a step.

```ts
export default [
  defineBuildStep({
    id: "parcelWatcherAddon",          // the profiler span id; unique
    owner: "infra/file-watcher/parcel-addon",
    label: "parcel-watcher addon",
    phase: "dependencies",
    run: ({ root, log }) => linkParcelWatcherAddon({ root, log }),
  }),
];
```

A step's body typically lives in its plugin's `cli/` barrel; `build-step/` may
import what a CLI command body may (`cli`, `core`, `shared`, `data-dirs`,
`server`, `machine`, `deps`).

## Phases

A closed set (`BUILD_PHASES`, `core/`), each a fixed point of the build with
its own context, typed per phase (`BuildPhaseContexts`):

| phase | when | context |
|---|---|---|
| `dependencies` | after stage 1 — `node_modules` and every registry current, before anything deploys | `root`, `log` |
| `deployed` | after the checkout's own app is deployed (skipped when the build deploys only other compositions) | `root`, `log`, `namespace` |

A new phase is one entry in `BUILD_PHASES`, its context in
`BuildPhaseContexts`, and one `runBuildSteps(phase, ctx)` call in
`build/cli/run.ts`.

## Running

`runBuildSteps(phase, ctx)` runs the phase's steps one after another in
registry order (`dependsOn` first), each in its own `build:setup` profiler
span named by its `id` (so `build/step-baseline` judges it like any other
step). Loading is strict and a throwing step fails the build, its error naming
the step and owner: a step that silently did not run would read as a green
build. The registry is imported at the first call, never at module load —
stage 1 rewrites it inside the same process (`cli:codegen-manifests-not-frozen`).

The hermetic posture runs no step: both phases are deploy-posture points.
