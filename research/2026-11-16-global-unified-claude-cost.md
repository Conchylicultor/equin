# One Claude cost system

Task: task-1794741519-qtnn07. Filed by the user from the supervisors spend breakdown (task-1794733419-nfoy9e).

## Context

Claude cost is counted twice, by two independent readers of the same transcripts. Both use `foldUsageEntry` (`plugins/stats/plugins/cost/core/usage-fold.ts`).

| | `stats/cost` (Stats → Cost) | `conversations/usage` (Cost column, account spend, supervisors spend) |
|---|---|---|
| Scan | corpus index, `COST_USAGE_DIR/index.json`, day buckets | `conversation_usage_files` (DB), hour buckets, offsets and tail hashes |
| Coverage | every transcript | equin conversations only, plus `cli:` calls through the ledger |
| Stored | tokens (below/above the 200k tier) | frozen dollars (`cost_usd`, `claude_spend_hours`) |
| Pricing | today's table, applied on every read | the table at count time, frozen |
| Permanence | year-sharded `sessions-<YYYY>.json`, written by the daily job | rows outside the change feed, kept after a transcript is deleted |
| Dedup | per file | across the session chain (resume / fork), per file for subagents |

As a result:

- **Surfaces disagree.** Stats and the Cost column diverge after any price change.
- **Stats misses spend.** It never sees `claude --print` calls: they run with `persistSession: false`, so they leave no transcript.
- **Every append is read twice.**
- **New questions get a third shape.** Each new cost question has to pick a system or add one.

**Decisions (from the user):**

1. **Price in force then.** Store tokens only. Keep a *dated* price history, and price each hour with the version in force at that hour. A wrong price is corrected by editing the history, and the correction reaches every surface.
2. **Count every transcript.** Every transcript is attributed to a source: `conv:<id>`, `cli:<name>`, or `session:<claudeSessionId>` for a session equin did not launch.

## Design

### 1. The ledger: tokens, never dollars

The ledger lives in `plugins/infra/plugins/claude-cli/plugins/spend-ledger`, renamed **`usage-ledger`** with `./equin plugin move`. It stays under claude-cli because `record-call.ts` writes it, and conversations depends on claude-cli, not the other way round.

- **`claude_usage_hours`** replaces `claude_spend_hours`. The tables are written with `defineEntity`, so migrations are generated by `./equin build`.
  - Primary key: `(account_id, hour, source, model, speed)`.
  - Columns: the five token kinds (`input`, `output`, `cacheRead`, `cacheCreate5m`, `cacheCreate1h`), each split into `_below` / `_above`. This is the `DayBucket` shape from `stats/cost/core/buckets.ts`, so per-entry tiering survives.
  - `account_id` is `'unknown'` for history from before accounts were recorded. That is today's `unattributed`, and it now lives in a column rather than in the source.
  - Upsert: one `usageLedgerUpsert` that adds the deltas (the evolution of `spendLedgerUpsert`). Negative deltas are allowed, because a chain re-read can take tokens back (see `bucketDelta`).
- **Source** keeps the `conv:` and `cli:` grammar from `spend-ledger/core/internal/source.ts` and adds `session:<id>`. Each source has a side row, **`claude_usage_sources`** `(source, project_dir, is_repo, title)`, so Stats keeps its all/repo scope and its titles without reading the corpus.
- **Pricing**, in the child plugin `usage-ledger/plugins/pricing`. It moves `price-table.ts`, `litellm-fallback.*` and `core/pricing.ts` out of stats/cost.
  - `claude_price_versions(id, effective_from, source)` records a version. `source` is `litellm`, `fallback` or `correction`.
  - `claude_model_rates(version_id, model, speed, per-kind below/above rates)` holds the rates. `model` is the string as observed in the transcript. It is resolved in TS with today's `resolveModel` (exact, then prefix, then substring) when a version is recorded or a new model is first seen. The fuzzy match therefore runs once, never per read.
  - A daily refresh that changes any rate records a new version, effective from now. Past hours keep their price.
  - The first version is effective from `-infinity`, so all of today's history is priced at today's table. That is the only honest choice: LiteLLM has no history.
  - A correction is a version with `effective_from` in the past. It is written through a script or the Settings pane, never by the refresh.
  - **The one pricing function** is the view **`claude_spend_hours_v`**: usage hours joined with the rate of the newest version whose `effective_from` is at or before `hour`. It is a derived view (`database/derived-views`). An hour with no rate has `cost_usd IS NULL`. It is never `$0` (failure is a type). The existing `cost-unpriced-model` report is filed from it.
- **CLI calls** record tokens, not `total_cost_usd`. `run-claude-print.ts` reads `result.modelUsage` (per model) and `result.usage.cache_creation` (the 5m/1h split). `claude_cli_calls.cost_usd` stays as the call log's display value only.

### 2. One scanner: `conversations/usage` reads every transcript

`conversations/usage/machine` becomes the only reader of `~/.claude/projects`.

- **Scan state** moves to `claude_transcript_scans`, keyed by `path`. It replaces `conversation_usage_files`, with `conversation_id` nullable and a `source` column. It holds the offset and tail hashes only, no buckets and no dollars: the ledger holds the counts.
- **Triggers:**
  - The `onTranscriptWritten` subscription stays.
  - A transcript with no equin conversation is attributed to `session:<id>`.
  - The chain dedup (`chainSeen`) still applies to equin conversations. Every other transcript is deduped per file, as stats/cost does now.
- **Account:** `conversationRunningAccount`. A non-equin session gets the account active when it is read, the same rule as an exited agent.
- **Fold:** `foldUsageEntry` and `usage-fold.ts` move from `stats/cost/core` to `conversations/usage/core`, always at hour granularity. The day granularity and the `granularity` parameter are deleted.
- **Writes:** the scan writes ledger deltas and scan state in one `writeAtomically`, as `write.ts` does now.
- **Backfill job:** extended to transcripts that have no scan row.

### 3. Permanence: main's database is the archive

- Ledger rows are never deleted when a transcript vanishes. The ledger is a separate table from scan state, so nothing ties its lifetime to the file.
- **History import.** A one-shot, idempotent data migration (`database/migrations/plugins/phases`, a claimed data migration) imports the history.
  - Archive entries in `COST_USAGE_DIR/sessions-*.json` whose transcript is gone are imported as day buckets at 00:00 UTC, with `account_id = 'unknown'`. The source is `conv:<conversationId>` when the entry has one, otherwise `session:<sessionId>`.
  - Where a transcript still exists, its rows come from a rescan instead (backfill), at hour granularity.
  - The existing `claude_spend_hours` rows for `cli:` sources (dollars) cannot become tokens. Since 2026-11-13 they come to $0, so they are dropped.
- **Backup:** `backup/sources/cost-history` is replaced by the database backup that already covers main's DB. The source plugin is deleted once the import has been verified.
- **Release:** the release instance's scanner runs as its host singleton. That closes the "archive is written in dev only" gap.

### 4. Readers: all of them read `claude_spend_hours_v`

- **Cost column.** `conversations_ext_usage.costUsd` and `tokens` become a `derived-tables` rollup over `claude_spend_hours_v` for `conv:` sources, grouped by conversation. The rates table is a second source, so a correction re-maintains only the affected keys. It remains a sortable column.
- **Per-conversation cost stat.** The `conversations.usage` lookup reads the same rollup.
- **Account spend** (`claudeAccountSpendServed`) sums the view per UTC day.
- **Supervisors spend** (`spend-query.ts` `readSpendSources`) sums the view per source. Its filter of `unattributed` becomes `account_id <> 'unknown'`.
- **Stats → Cost.**
  - `answers.ts` keeps its four live values and their shapes, now computed with SQL over the view joined with `claude_usage_sources`. The `scope` param maps to `is_repo`.
  - The values become `source: "db"` and are notified by the ledger's change feed, so the 30 s directory watch is gone.
  - Tokens per day, model and session are columns of the same rows.
- **Known change:** a worktree's Stats page now shows its DB fork's snapshot, like every other DB surface, instead of the host-global files.

### 5. Deletions

- **`stats/cost` server:** delete `usage-index.ts` (the corpus index), `archive.ts`, `load-usage.ts`'s bundle, `refresh-job.ts`'s capture step (the price refresh moves to `pricing`), and `index.json`.
- **Tables:** drop the `conversation_usage_files` buckets and cost columns, and the whole `claude_spend_hours` table.
- **Backup:** delete `backup/sources/cost-history`.
- **Files:** `COST_USAGE_DIR` keeps only `price-table.json` as the fetch cache, until `pricing` holds it in the DB too. Then the data dir is deleted.

## Phases (each lands on its own)

1. **Ledger and pricing.** Rename `spend-ledger` to `usage-ledger`. Add the token columns, the sources table, the price versions and rates, and the priced view. CLI calls write tokens. The scanner dual-writes tokens alongside today's dollars. No reader moves yet.
2. **One scanner.** Add scan state per path, scan every transcript, and attribute `session:` sources. Move the fold to `conversations/usage/core`.
3. **History import and parity.** Run the data migration. Then run a one-off script that compares old and new totals: Stats per day/model against the view, and each conversation's old `cost_usd` against the rollup. The deviation must be under 0.5% (the same bar as `verify-vs-ccusage.ts`) before any reader moves.
4. **Readers.** Move the Cost column, account spend, supervisors spend and Stats → Cost to the view.
5. **Deletions.** Delete everything in § 5. Rewrite `stats/cost/CLAUDE.md` and the `conversations/usage` docs.

## Implementation notes

What landed, where it departs from the design above:

- **Fold location.** `foldUsageEntry`, the bucket shape and `isRepoProjectDir` moved to `usage-ledger/core`, not `conversations/usage/core`: the CLI recorder (claude-cli) and the verify script need them, and conversations depends on claude-cli, not the reverse.
- **Pricing split.** `usage-ledger/pricing` (portable: versions, rates, the view) and its child **`pricing/price-table`** (file + fetch + the vendored fallback, not portable). The daily refresh (`claude-cli.pricing.refresh`), the first-version warm-up and the `cost-unpriced-model` report kind live in price-table; it also owns the `cost-usage` data dir (`costUsageDir`), which keeps `price-table.json` and, read-only, the legacy archive shards.
- **`origin` column.** `claude_usage_hours` carries `origin` (`counted` | `imported`) in its key, so a scanner's take-back (a session adopted by a conversation, a source recounted whole) never reaches imported history.
- **History import as a job, not a SQL data migration.** It reads the archive files and the disk, so it runs as the one-shot `conversations.usage.history-import` job (host singleton, recorded in `claude_usage_history_imports`, advisory-locked). The archive reader (`loadCostArchive`) moved next to it in conversations/usage, read-only.
- **Dollar ledger drop, ordered for main.** `claude_spend_hours` is dropped by a schema migration whose claimed data migration (`…__usage_ledger_legacy_carryover.sql`) first copies (1) its `unattributed` dollars into **`claude_account_spend_carryover`** (no tokens behind them; the account-spend read adds them) and (2) each conversation hour's one account into `claude_usage_import_accounts`, which the import reads to attribute its remainders. Migrations run at boot before the job, so nothing reads the dropped table at runtime.
- **Triggers instead of `defineRollup`.** The Cost column (`conversations/usage` `cost-triggers.ts`, an entity extension) and Stats → Cost's two rollups (`stats/cost` `rollups.ts`: `claude_spend_days` per day/model/repo flag, `claude_spend_sources` per source) are maintained by hand-written statement-level triggers on the ledger, rates, versions (and sources' rows for the days), derived-tables' locking and guarded upsert by hand: a `derived-tables` rollup may only read declared tables, and the one pricing function is a view. Each has a reconcile warm-up keyed on its code digest. Stats values read the rollups, so a recompute is a few rows per day plus one per session.
- **Scan tables not folded.** `conversation_usage_files` keeps its buckets (the sync's deltas and the import read them); only `cost_usd` / `unpriced_models` were dropped. Folding it into `claude_transcript_scans` is left for later.
- **Deleted:** the corpus index, archive writer and capture, `load-usage.ts`, the `cost-archive-shrink` kind (no rows on main), `ledger-parity.ts`, `priceFile` / `totalsOf`, the `conversations.usage.reprice` job (main held no unpriced or legacy-tail rows), the sync's and CLI recorder's dollar writes, `backup/sources/cost-history` (the databases source backs up main's DB, ledger tables included; the archive files stay on disk). `verify-vs-ccusage.ts` now folds the corpus with the shipped `foldUsageEntry`.
- **Transcripts matched by session-relative path.** The data-root move had renamed every project dir under the legacy data root (734 dirs) while `conversation_usage_files` and the archive kept the old spelling: 58 transcripts on main had a row under each, ~220 archive entries read as gone. The import's coverage test, the sync's row matching (`rekeyStoredRows`: take over a row stored under another spelling, drop a second count with its tokens filed back) and a claimed data migration collapsing the 58 doubles all key a transcript by `transcriptKey` (`<sessionId>.jsonl` / `<sessionId>/subagents/…`). The import refuses a conversation still holding two rows for one transcript.
- **Day buckets attributed.** A conversation's legacy day bucket (filed at 00:00) takes the account every `claude_usage_import_accounts` hour of that day agrees on.
- **Import after the contract.** The job awaits `deferredContractSettled()` (database server barrel — a promise the boot hooks settle: no contract deferred, or its run committed; `failed` / `not-owner` throw), so the previous backend, still matching rows by path, is gone and the contract's re-run of the group's claimed data has collapsed whatever it added.
- **Follow-ups once main has recorded the import:** drop `claude_usage_import_accounts`; decide whether to delete the archive shards; fold `conversation_usage_files` into `claude_transcript_scans`.
