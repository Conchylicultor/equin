# Drop the legacy `slow_ops.callers` column

## Context

`26b4260f50` moved caller attribution off the `slow_ops.callers` JSON column into `slow_op_callers` (one row per op × caller), backfilled once by `20261013_154431_42970cde__slow_op_callers_backfill.sql`. The column was kept for one more push because migrations apply in the NEW backend's boot while the outgoing backend of a hot swap still serves, and that older backend named `callers` in its upsert (`research/2026-10-13-debug-slow-ops-live-collection-v2.md` § Migration, "Split out").

The parent change is on `main` (`origin/main` = `d4c2455311`, which includes it), so every serving backend on main already runs a recorder that neither reads nor writes `callers`. The column is now dead weight. This push removes it and everything that exists only because of it.

## Why it is safe now

- A generated `ALTER TABLE … DROP COLUMN` is classified **contract** (`database/plugins/migrations/core/internal/classify.ts:179`). Contract runs at the new backend's boot while the old backend still serves. The outgoing backend is now the parent's code, which does not name `callers`: its upsert is built from the drizzle table, and the cluster `SELECT` lists explicit columns.
- Fresh-DB replay stays valid. The backfill (which reads `s.callers`) is claimed by the earlier merged group `20261014_171817_73e8f008`. The drop is a new, later group.
- Worktrees still on pre-parent code are flagged by `fork-schema-drift` (`drop-column` is "hard-destructive") until they rebase. That is the intended mechanism, and nothing needs adding.
- The cluster fan-out already tolerates forks with and without the column (`plugins/cluster/shared/endpoints.ts`, explicit `.pick` mirroring `handle-cluster.ts`'s SELECT).
- live-state-snapshot fingerprints per resource definition. If `slow-ops.op`'s plan SQL changes, its snapshot row is simply recomputed.

## Changes

### Schema and code (`plugins/debug/plugins/slow-ops/`)

- `core/schema.ts`
  - Delete the `callers` field and its LEGACY comment from `slowOpFields`.
  - Delete `CallerBreakdownSchema` / `CallerBreakdown`. Their only use was that field.
  - Reword the `CallerRefSchema` comment, which currently says "identity subset of a CallerBreakdown". The new wording: who issued an operation, the identity the recorder folds into a `slow_op_callers` row.
  - Delete `SlowOpDetailSchema` / `SlowOpDetail`. Once `callers` is gone they are a pure alias of `SlowOpSchema`, and keeping the alias would preserve a concept that exists only because of the column.
  - Reword the `SlowOpSchema` comment: "full row, legacy callers included" becomes the full row, which is what the `slow-ops.op` lookup reads.
- `core/index.ts`: drop the re-exports of `CallerBreakdownSchema`, `CallerBreakdown`, `SlowOpDetailSchema` and `SlowOpDetail`.
- `core/resources.ts`: `slowOpById` uses `row: SlowOpSchema`.
- `plugins/pane/web/components/slow-op-detail.tsx`: import `type SlowOp` instead of `SlowOpDetail as SlowOpDetailRow` (`SlowOpBody({ op }: { op: SlowOp })`).
- `server/internal/tables.ts`: remove `callers: { default: [] }` from the `slow_ops` column defaults.
