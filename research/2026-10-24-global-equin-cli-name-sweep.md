# Agents only see `./equin` — the CLI-name sweep (Rename track, step 2)

## Context

This is step 2 of the "Rename Singularity to Equin" track (wiki page `block-dc049371-…`). Step 1 made `./equin` the CLI and left the old `singularity` entry as a one-line shim. `CLI_NAME` and `CLI_NAMES` live in `plugins/framework/plugins/cli/core/internal/cli-name.ts`, and the guards treat both names as one command. Step 1 also moved the root CLAUDE.md, the skills and the guard hints over to `./equin`.

Everything else still told agents to run the old `singularity` CLI: about 10,400 mentions in about 4,800 tracked files.

| Where | Mentions |
|---|---|
| `research/` | 6,150 |
| `plugins/` | 3,650 (CLAUDE.md prose, comments, hints, error text) |
| `docs/` | 49 |
| `gateway/` | 14 |
| `.claude/memory` | 17 |
| `prototypes/` and `sidequests/` | 26 |

Some of these are written by code generators, and some are commands the app spawns. **Goal:** an agent never reads or is told to run the old `singularity` CLI, and a check keeps it that way. The user chose to sweep `research/` as well, so the guard can cover the whole repo with no carve-out.

Out of scope: internal identifiers (step 5's decision), the `singularity` namespace and DB, `~/.singularity/`, `SINGULARITY_*` env vars, `@singularity/*` package names, the launchd label, the GitHub URL, the `~/singularity` checkout directory and `.git/singularity-merge-markers/`. Text already stored in the DB (old task descriptions, transcripts) is history and stays as it is.

## Approach

- `plugins/infra/plugins/deps/deps/internal/via-cli.ts:44`
- `plugins/infra/plugins/deps/plugins/npm/server/internal/npm-updater.ts:158`
- `plugins/infra/plugins/deps/plugins/updates/cli/internal/gates.ts:25-27`

- e2e scripts `database/admin/e2e/fork-bench.ts:136` and `upstream/e2e/migration-journey.ts:148`

Shell callers write `./equin`: `.githooks/post-rewrite:48`, `install.sh` (its checkout probe at `:48` tests for `equin`), `sidequests/clean-install/*.sh` and `sidequests/claude-web/session-picker.sh`.

### 2. Detectors that read commands accept both names

Old transcripts, and processes started by muscle memory, still say `singularity`. Three regexes hardcode the old word, so they already miss `./equin` runs (a bug Step 1 introduced):
- `debug/sentinel/server/internal/sample-math.ts:72`, which counts build, check and push processes from `ps`.
- `debug/browser-recordings/core/internal/recorded-call.ts:17` (`E2E_RUN_RE`).
- `conversations/…/artifacts/plugins/prototype/core/extract.ts`, which parses `prototype new` out of transcripts.

All three get their name from one exported fragment, `CLI_NAME_PATTERN`. It is added to `cli/core`, built from `CLI_NAMES` and regex-escaped, so the next rename is a one-line change. Their tests gain an `equin` case and keep a `singularity` case.

They interpolate `CLI_NAME` where `codegen/core → cli/core` creates no cycle (checked with `plugin-boundaries`); otherwise they use the literal `./equin`.

**`docgen.ts`:**
- `BEGIN` (`:45`), the `REFERENCE.md` intro (`:176`), and `COMPACT_HEADER` and `DETAILS_HEADER` (`:304`, `:309`).
- **Trap:** `renderPluginClaudeMd` finds the old block with `existing.indexOf(BEGIN)` on the full header text (`:414`). If only the text changes, the old block no longer matches, so every CLAUDE.md gets a second autogen block appended.

- Update `cli/plugins/git-artifacts/cli/regen-claudemd.test.ts`.

### 4. Mechanical sweep of all remaining prose and hint text

Run one `perl -pi` over `git ls-files` text files. It replaces the dot-slash form of the old name with `./equin`, but only where it stands alone as a command, so `../singularity-wt`, `singularity/` paths and `~/.singularity` are skipped.

Before writing anything, a dry run lists:
- every match whose next character is `.`, (a hostname versus the end of a sentence)
- every excluded near-miss

Both lists get reviewed. Command-position bare forms (`singularity build|check|push|run|start|…`, about 10 sites: Go comments, Caddy headers, sentinel docs, poll-detect test inputs) are fixed by hand.

What keeps the old spelling, on purpose (these are the guard's exemptions, §5):
- The root `singularity` shim.
- The legacy-name sentences in the root `CLAUDE.md`, `cli/CLAUDE.md` and `cli/package.json`.
- Alias-coverage cases in the guard tests (`parse-shell.test.ts`, `background-ops.test.ts`, which already loops over both names) and in the detector tests from §2.

`gateway/env.go:46` and `env_test.go:38` move to `./equin start`. Junk tracked `.merge_file_*` at the repo root are deleted, not rewritten.

### 5. Guard: the `cli:legacy-cli-name` check (rung 3)

A new check in `plugins/framework/plugins/cli/check/`, next to `manifest-freeze`:
- It fails on the dot-slash form of the old name in any tracked text file.
- It uses the `gitGrepList` scan from `tooling/checks/core/grep-code.ts`, so results stay cacheable. Prose counts as a violation too, so `grepCode`'s comment and string masking is not wanted here.
- Its hint says: write `./equin`, and `CLI_NAME` in code.
- Allowed occurrences are declared in `plugins/framework/plugins/cli/exempt/index.ts` (`kind: "sanctioned"`, with a reason): the shim, the legacy-name sentences and the alias tests. Nothing is allowlisted inside the rule.

### 6. Regenerate, then update the track

1. Run `./equin build`. It regenerates the `*.generated.ts` files, every CLAUDE.md autogen block, `docs/plugins-*.md`, `REFERENCE.md`s and the config origin and legend files.
2. Update the track page: Step 2 checked off, the status rewritten, a link to this doc.
3. File the next main task with `add_task`: Step 3, `equin.localhost` as the address the app hands out. It gets the page id and the Track Instructions id.

## Verification

- A repo-wide search for the dot-slash old name returns only the declared exemptions, and `./equin check cli:legacy-cli-name` passes. Planting the old spelling in a scratch file makes it fail.
- Run `./equin check` (all checks), especially:
  - `plugins-doc-in-sync`, `plugins-registry-in-sync` and `generated-artifacts-normalized`
  - `plugin-boundaries` (the new `cli/core` imports)
  - `type-check`
- Run `./equin test` on the guards, codegen, `cli/git-artifacts`, `config_v2`, `upstream`, `deps/updates`, `sentinel`, `browser-recordings` and `artifacts/prototype` plugins, and `go test` in `gateway/`.
- Confirm that a plugin CLAUDE.md has exactly one autogen block after the build: `rg -c 'AUTOGENERATED:BEGIN' plugins -g CLAUDE.md` is never above 1.
- Diff review against the merge-base (`git diff $(git merge-base HEAD main) --word-diff=porcelain`) to check that the change is only the token swap outside the §1–§3 code edits.
- Run a build from the app's Build button on this worktree's deploy. The build job now spawns `./equin build` and succeeds.
